# Critical review: lolly and lolly-work (2026-09-06)

Scope: the umbrella repo at `d358a99` with its submodules at the sibling checkouts (`lolly-web` `0ffc96a`, `lolly-tools` `daefe74`, `suse-lolly` `fd380e0`, `lolly-docs` `df2af01`, `lolly-cli` `806d76d`), and `lolly-work` at `f9cd208`. Every claim below was checked against code, not against docs. The YunoHost package in lolly-work is excluded at the author's request (still being built elsewhere).

Method: six parallel read-only audits (claims, engine, web shell, tool catalog, lolly-work security and claims, lolly-work console and API), plus local runs. `npm test` in lolly-work: 896 pass, 3 fail (all YunoHost, excluded), 14 skipped. The umbrella `npm test` and `npm run typecheck` could not be run cleanly here: the submodules had to be symlinked to sibling checkouts, which breaks module resolution for the CLI tests and the web typecheck, and `services/mcp`, `services/ca` and `shells/chrome-extension` were not checked out. The 104 root failures and the 5 `@tiptap/pm` type errors all trace to that scaffolding, not to the code. Node here was 22; lolly-work targets 24.

## 1. Summary

The architecture claims that matter most are true and enforced: the engine is DOM-free and brand-free (the purity script passes on all 193 modules), the HostV1 contract has never removed or changed a method across 181 minor versions, the CLI genuinely is URL mode over argv, catalog signing and runtime integrity checks exist, telemetry is absent, and C2PA manifests are real COSE-signed JUMBF, not a sidecar. Test discipline is unusually strong for a codebase this size.

The problems cluster in four places:

1. **Documentation has drifted from the code**, in both directions. Some docs undersell what exists (SOVEREIGNTY.md says catalog signing is unimplemented; it shipped). Some oversell (README format counts, "every export carries Content Credentials", the "complete" server-surface and privacy inventories). CLAUDE.md, which agents and contributors treat as ground truth, is wrong in at least ten checkable places.
2. **The "small platform-agnostic engine" is a 91K-line codec monolith** with a 7.4K-line core, no lazy loading inside it, and a web shell that is 3.7 times its size. The bundle budget is defended by a hand-tuned 13-group chunking regex rather than package boundaries.
3. **The tool catalog is inconsistent** in ways users see: 55 of 78 tools have untranslated inputs in all 26 locales, SUSE defaults leak into public community manifests, five SUSE tools are forks of community tools, and several tool names are opaque.
4. **lolly-work has a handful of real security gaps** (open redirect on sign-in return, unsandboxed pack hooks in every shipped config, an audit chain a DB holder can rewrite) and a console whose core governance surface is hidden behind a tab.
