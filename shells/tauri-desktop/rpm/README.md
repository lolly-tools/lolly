# Lolly - RPM packaging (openSUSE, via the Open Build Service)

Builds the Tauri desktop app as an RPM for **openSUSE Tumbleweed and Leap 16**, on
[OBS](https://build.opensuse.org/).

Leap 15.6 was dropped as a target (2026-08-29): the dependency tree needs Rust >= 1.88
and 15.6's default toolchain is older, so it would have needed devel:languages:rust
pinned in and a second toolchain story to maintain. Tumbleweed ships 1.97.1 and Leap 16
is current; that is the supported pair.

| File | Role |
|---|---|
| `lolly-desktop.spec` | The spec. Read its header comment first - it explains every unusual thing it does. |
| `make-sources.sh` | Produces every `Source:` the spec needs, ready to `osc add`. |
| `out/` | **Not committed** - where `make-sources.sh` writes. |

## Why this is not a normal "build from git" OBS package

OBS builds are **offline and hermetic**, and this app cannot be built that way from
a plain checkout. Three independent reasons:

1. **The frontend is the web shell.** `vite.config.js` roots the build at
   `shells/web`, substitutes four bridge modules, and copies the repo-root `tools/`
   and `catalog/` profile views in. `tauri-build` then embeds the whole `dist/` into
   the Rust binary via `generate_context!()`. Reproducing that inside OBS would mean
   node, npm, the umbrella repo's workspaces and every submodule.
2. **~600 cargo crates**, which offline cargo cannot fetch.
3. **`ort-sys` downloads ONNX Runtime from its own `build.rs`** using `ureq`. This is
   the one that bites hardest, because it fails *during* the build rather than at
   dependency-resolution time.

So the package is fed **prebuilt tarballs** generated by `make-sources.sh` on a
machine that can build, rather than driven by an OBS source service.

### How the ONNX Runtime problem is solved

`ort-sys`'s build script skips its download entirely when `ORT_LIB_LOCATION` is set:

```rust
if cfg!(feature = "download-binaries") && env::var(ORT_LIB_LOCATION).is_err() { ... }
```

`make-sources.sh` reads the download URL **and its SHA256 out of the vendored
`ort-sys` `dist.txt`**, so the tarball we ship is byte-identical to the one the crate
would have fetched and cannot drift from the pinned version. It contains
`onnxruntime/lib/libonnxruntime.a`, so the spec links it **statically** - the
resulting RPM has no `libonnxruntime` runtime dependency at all.

That last point is what lets one spec serve all three targets: none of them ship
onnxruntime in the OSS repo, so a shared-library approach would have needed a
per-distro answer. The spec has a `%check` that fails the build if the binary ever
does pick up a shared `libonnxruntime`, so this cannot regress silently.

## Building the sources

Needs network, **node 24** (see `.nvmrc`) and **Rust >= 1.88**.

```bash
pnpm install
export LOLLY_PROFILE=lolly-start           # public profile - see the warning below
pnpm run profile                           # confirm: prints `profile lolly-start`

cd shells/tauri-desktop
pnpm install --frozen-lockfile
rpm/make-sources.sh
```

Output lands in `rpm/out/`:

```
lolly-desktop-<version>.tar.zst   # src-tauri/ + prebuilt dist/ + packaging/
vendor.tar.zst                    # cargo vendor tree
cargo_config                      # points cargo at it
onnxruntime-x86_64-unknown-linux-gnu.tgz
onnxruntime-aarch64-unknown-linux-gnu.tgz
lolly-desktop.spec
```

> **Profile warning.** The active content profile decides which tools and catalog get
> baked into the binary. `brands/suse` is a **private** pack and must never reach a
> published RPM, so `make-sources.sh` refuses to run on the `suse` profile.

## Pushing to OBS

```bash
osc checkout home:<user>/lolly-desktop && cd home:<user>/lolly-desktop
cp /path/to/rpm/out/* .
osc addremove
osc commit -m "lolly-desktop <version>"
```

Enable these repositories in the project: **openSUSE_Tumbleweed** and
**openSUSE_Leap_16.0**.

### The Rust version constraint

The dependency tree requires **Rust >= 1.88** (`darling` 0.23, `icu_collections` 2.2
and `headless_chrome` 1.0 all declare it), and `Cargo.lock` is lockfile v4, needing
cargo >= 1.78. Tumbleweed is fine. If Leap's default `rust` is older, add
`devel:languages:rust` to the project's repository paths and change the spec's
`BuildRequires` to the versioned `cargo1.88` / `rust1.88` packages.

### Size

`dist/` is ~170 MB and is embedded in the binary, so both the source tarball and the
built RPM are large. `%global debug_package %{nil}` is set because debuginfo over a
binary with that much embedded data is enormous and useless.

## Verified build (2026-08-29)

Built successfully on **openSUSE Tumbleweed** in a container, which is what the
`pkgconfig()` BuildRequires were chosen for - one spec, no per-distro package names:

    lolly-desktop-1.0.0-0.x86_64.rpm    172 MB packaged / 228 MB installed

What that run confirmed, rather than assumed:

- every `pkgconfig()` BuildRequires resolved on Tumbleweed, and its Rust is 1.97.1,
  clear of the 1.88 floor the dependency tree imposes;
- the build was genuinely **offline** - no crate downloads in the log;
- `ORT_LIB_LOCATION` did its job: **no `libonnxruntime` in the package's Requires**,
  so the ONNX Runtime is statically linked and none of the three targets needs to
  ship it;
- both `%check` guards ran and passed;
- Requires are exactly `libwebkit2gtk-4.1`, `libjavascriptcoregtk-4.1`, `libgtk-3`,
  `libsoup-3.0` and glibc.

**Leap 16 is still unbuilt.** Tumbleweed clears the Rust floor comfortably (1.97.1 vs
the 1.88 the tree needs); Leap 16 should be checked before you rely on it.

### Do not build on tmpfs

Three builds were lost to this. On a machine where `/tmp` is tmpfs, a build tree there
is **resident memory**, and a cargo target dir for this package is several GB. It
surfaces first as rustc dying with `signal: 9, SIGKILL` and no diagnostic - which reads
like a compiler crash - and later as `Disk quota exceeded (os error 122)` once tmpfs
hits its ceiling. Neither message mentions tmpfs. Check with `df -h /tmp` and build
somewhere real.

## Building locally instead

To test the spec without OBS:

```bash
rpm/make-sources.sh
mkdir -p ~/rpmbuild/{SOURCES,SPECS}
cp rpm/out/*.tar.zst rpm/out/*.tgz rpm/out/cargo_config ~/rpmbuild/SOURCES/
cp rpm/out/lolly-desktop.spec ~/rpmbuild/SPECS/
rpmbuild -bb ~/rpmbuild/SPECS/lolly-desktop.spec
```

On a non-openSUSE host the `pkgconfig(...)` BuildRequires resolve to that distro's
packages, which is fine for a smoke test but is **not** a substitute for an actual
OBS build against the real targets.

## Relationship to the Flatpak

`../flatpak/` holds the **single source of truth** for the freedesktop metadata - the
`.desktop` entry, the AppStream metainfo and the hicolor icons. Both packagings
install those identical files; `make-sources.sh` copies them from there so the two
can never drift. They are app metadata, not Flatpak-specific.
