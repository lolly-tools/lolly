# Preserve meaning through the diagram workflow

1. Inventory source nodes, stable IDs, labels, edges, direction, groups and any
   dates or values. Distinguish a complete reconstruction from an overview.
2. Choose the semantic type and supported source. Preserve critical failure,
   retry and feedback paths. Do not invent relationships, quantities or dates to
   balance the picture. Unsupported source constructs require a disclosed
   extraction or Design composition, rather than an invented importer.
3. Read the open document's effective system. Map colours and type to declared
   roles. Preserve explicit source styling unless restyling was requested.
4. Validate input IDs and choices, then render. Use `lolly_look` or `lolly look`
   on a surface that supports the render, enlarging dense regions as necessary.
5. Check labels, direction, group membership, branch meaning, connector clearance
   and type at the intended displayed size. A categorical matrix is not a numeric
   heatmap; a funnel does not establish measured conversions.
6. Correct relevant input values or stable object IDs. Reinspect the affected
   area and return the requested export plus editable source.

Record preserved, renamed, merged, omitted and unsupported source objects when
recreating a diagram. An overview may omit deliberately, but must disclose those
choices. Current schema checks do not prove source fidelity or visual quality.
Automatic semantic diagnostics and additional diagram types remain future work.

For an input-model live adapter, read the current input definitions and revision,
submit the advertised input operation, and reread before recomputing a stale edit.
Do not send layer patches to an input adapter or assume that uploaded file bytes
are available through a document invitation.
