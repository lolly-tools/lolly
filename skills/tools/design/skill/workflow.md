# Compose and inspect a Design document

1. Read the brief and source content. Preserve the source's text, relationships,
   order and intended destination. Read the overall skill's design-system guide
   when setup or matching is requested.
2. Describe Design on the chosen surface. Use the exact `boxes` fields and stable
   IDs. For CLI/MCP authoring, use the documented authoring keys and text styles
   from the actual brief. A live layer adapter accepts its advertised operations.
3. Validate the document before rendering. Inspect the preview at its intended
   size, including long labels and transition boundaries for motion.
4. Check clipping, overlaps, readable text, contrast and fidelity to the source.
   Correct the affected IDs. Schema validity alone does not establish these facts.
5. Return the requested export and an editable link or `.lolly` file. A plain
   share link cannot carry local uploads; package permitted assets when needed.

The live context describes the open document's selected system, theme and version.
Do not replace that selection merely to match the connected server's profile.
For a stale revision, reread and recompute the change; retrying a transaction ID
with different content is invalid. Undo applies only to the agent's own most
recent supported history entry.
