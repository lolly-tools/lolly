# Lolly 1.1.0: the fancy one

**Draft release notes.** Release is planned for Friday, 2 October 2026. This is not a published app version. Package availability will be confirmed after the release builds pass verification.

Lolly 1.1.0 adds slide masters and motion authoring in Design, independent token choices and reviewed design-system updates, and clearer evidence and signed reports in Verify. Design and Snippet export animations as standalone HTML players as well as movies. More tools keep your work automatically in Projects and History, with a Trash for deleted items. Tools share one settings panel, the Catalogue becomes Assets, and Diagram Builder gains looks. The documentation has refreshed screenshots, more concept diagrams and a compact footer.

## Slides in Design

- **Slide masters.** **New slide from archetype**, **Apply archetype** and **Reset slide** lay a frame out from the design system's slide masters, with placeholders and page furniture as ordinary layers. Furniture arrives locked, and a layer you drew yourself is never moved by a re-layout.
- **PowerPoint with real layouts.** Frames built on a slide master export as real PowerPoint layouts with their text in placeholders, so Outline view and Reset Slide work in PowerPoint. The CLI now exports a Design document to PPTX without a browser.
- **Formatting comes with the text.** Bold, italic, colour, weight, monospace, underline, strikethrough and list levels from a source deck reach Design's text.
- **Emphasis for every text box.** Text from a template or an import gains an **Emphasis** row in the inspector: Bold, Italic and Underline for all of its text, in one undo step. Underline and strikethrough also survive editing that text on the canvas.
- **Live pages on a slide.** Add a web page box for supported video, map and design players, another Lolly tool or a Sandbox demo. The editor and presenter use the live frame where permitted; exported files use its poster. Sites in a received deck stay as pictures until trusted or loaded, and the presenter checks permissions before the show. On the web version, **Allow pages from any site** (Profile, Trusted sites) reloads Lolly on that device under a policy that can frame any https page; the same trust questions still apply.
- **Undo for big decks.** Design keeps its history compressed, so a deck with dozens of charts keeps its undo steps and its charts stay shapes rather than pictures.

## One panel for every tool

- **The same panel everywhere.** The Design inspector and every tool's settings sidebar now use one panel: one control height, labels above their controls, and a section caret that stays put. Sections follow one order in every tool: Content, Style, Layout, Presence, More. No tool had to change for this.
- **Clear the canvas.** On desktop, press `\` outside a text field to hide or show the side panels.
- **Pictures on the choices.** Backdrop's sixteen effects and Filter's ten each show an icon.
- **Work from the canvas.** In tools that mark their canvas objects, Design, Chart and Diagram Builder among them, click an object to edit it in place or go straight to the setting that controls it. Right-click it, or press the Menu key or Shift+F10, for a menu of its settings and choices. A setting an organisation has locked or hidden is not offered.
- **Drags that keep going.** Dragging a number or a strip carries on past the edge of the screen, with the pointer reappearing on the other side. This works with a mouse or a pen.
- **Tools on a phone.** The canvas keeps its width on small screens, fixing a layout conflict that could hide the tool entirely. Long sidebar titles wrap, and an unused Export panel closes when its companion panel goes away or the layout switches to a phone.

## Design systems with practical rules

- **Review what an import will change.** Intake separates source colours and font names from suggested palettes and generated modes. A local preview shows the proposed system before adoption, with a compatibility report for retained token data and an undo path for supported imports.
- **Keep the brand's vocabulary.** Use your brand's own names for colour, type and artwork roles. Explicit bindings connect those roles to tool fields without renaming them to Lolly's own interface roles.
- **Usage & rules.** Record allowed colours, font families, fixed artwork and text limits. Render a poster, title slide, content slide and Chart example from the same revision. PNG reports describe the measured inputs, source resources and output checks. A required failure blocks download; a missing required fact allows a visibly labelled draft.
- **Make a reusable poster.** A checked poster can become a portable `.lolly` tool with constrained choices, fixed artwork, bundled fonts, credits and its rule context. Unsupported required checks prevent creating that tool.
- **Optional organisation management.** In lolly-work, review the installed design-system sources and their impact before switching or retiring one. Policy editors can map published rules to installed tool inputs through reviewed, audited changes. Server exports check actual runtime input values, retain existing organisation restrictions and mark incomplete required coverage as DRAFT. These are scoped input checks, not visual or brand approval.

## Token workflows

- **Inspect the source.** Start's Tokens room shows retained definitions, inactive sets, authored and resolved values, aliases, override order and token dependents. **Inspect tokens** in a tool reads the version and choices captured by that render, including read-only systems.
- **Independent choices.** Choose a theme for each imported group, such as appearance and density. Preview writes nothing; adopting choices goes through review and Apply. Links and saved sessions retain the choices separately from the app's Light, Dark and Brand appearance.
- **Link values and keep custom edits.** Compatible tool inputs and supported Design properties can link to tokens. **Make custom**, **Restore link**, undo and saved sessions retain each property's link and intentional override. Geometry, paint and legacy text have direct adapters; whole typography, shadow and gradient composites still need additional adapters.
- **Review updates before applying.** Source edits, colour ramps, spacing scales, type scales and base/local/incoming comparisons produce reviewable candidates. Conflicts need an explicit choice, and an intervening edit invalidates Apply. Where available, compare an existing poster, slide or Chart before and after the change.
- **Published fonts keep their bytes.** New local font pins record the face, weight, slant and subsets. Replacing or deleting a pinned face keeps the published version's exact bytes available. Missing or changed pinned bytes fail visibly; platform fallback fonts remain outside this guarantee.

Read [Inspecting and reviewing design tokens](https://lolly.tools/info/build/token-workflows.html).

## Snippet comes to life

- **A window that appears to be used.** Animate a window opening, a mouse clicking into the text, a caret typing, a pause for reading and a click to close. Choose **Type and hold**, **Open, type and close**, **Accept a suggestion** or **Select and replace**, or build a sequence of up to 24 timed **Custom steps**. Suggestions and terminal output use text you supply.
- **Control the interaction.** Type with natural or steady keystrokes, by word or line, or as one paste. Select and replace a passage, or leave the replacement empty to delete the selected text. Set the mouse cursor size from 50% to 250%, show click rings and choose the window's entrance and exit. Rotation and horizontal or vertical tilt give the window perspective.
- **Long text stays readable.** Wrap long lines, fit the whole passage or scroll with the caret. The window and type size stay fixed during playback, and line numbers scroll with the text. Joined emoji and combining marks appear together. Fit mode also keeps long unwrapped lines and the caret inside the window with Linux fonts.
- **Ten new templates, with thirteen variants.** Light and dark code, a light text note, light and dark tilted windows, typing, autocomplete, replacement, a terminal walkthrough and a scrolling document. Variant chips change angles, themes, timing, replacement text or endings. Animated templates open on a readable still frame; press **Play** to watch.
- **Motion for your slides.** Preview and scrub the scene, then export MP4, WebM, GIF or animated WebP. The export duration can retime the whole interaction. Still exports show the finished text before the window closes, or a frame you choose. Existing still snippets keep their appearance.

## Motion in Design

- **Scenes on one timeline.** Place artboards in order, set their durations and transitions, and give scenes their own cameras. Moving a scene carries its layers' timing with it. Scene sound stays within its scene; an unframed soundtrack can span the film.
- **Shared beats and cues.** **Beat and cue timing** connects picture and sound to named cues or a tempo. Preview the affected layers before applying a change. Editing a bound field by hand detaches that binding without changing the others. Text also gains an explicit paragraph direction.
- **A player in one HTML file.** Design and Snippet export a standalone player with playback, seeking, sound controls and a reduced-motion poster. Supported fonts, images and sound are embedded for offline playback. Design scenes have navigation controls. Embedded video, Lottie and 3D playback in HTML remain unsupported and produce an explicit error.
- **Review exact moments.** Export stills at chosen timeline times, or a contact sheet, from the app, CLI or MCP. Several samples become a ZIP or a paged PDF. Raster samples use the movie compositor, including supported video, Lottie, animated SVG and 3D source clocks. Export a temporary movie range without changing the document's in and out marks.
- **Optional motion blur.** Flat SDR sequences can use 4, 8 or 16 shutter samples per frame. Sampling respects cuts and keeps the output and audio clocks fixed. Blur is off by default; more samples take longer to render. HDR and tilted scenes report unsupported combinations.
- **Check the delivered file.** **Check rendered file** in the preview, and `lolly inspect --motion` or MCP inspection, report measured dimensions, duration, frame rate and available audio checks. Reports distinguish failures, moments needing review and checks that could not run. CLI and MCP inspection use optional FFmpeg tools.
- **Check the text's glyphs.** Design's inspector and export checks now read the available font bytes for each rendered text run, including inline font changes. Missing coverage gives the layer and font to fix before export. Finding a font file alone no longer counts as proof that it contains the text's characters.

## Photos and Photoshop files

- **Levels and curves in Darkroom.** Darkroom 2.4 adds Levels for each channel and for all of them, **Auto** levels measured from each photo (also in batch), Curves you drag point by point, Black & White with a tint, Colour Balance and Dehaze. Each new step is part of the same colour pipeline as Darkroom's other adjustments.
- **More dither styles in Filter.** Filter 1.5 adds Atkinson and Bayer 2×2 and 8×8 dithering, fill patterns, error spread, back-and-forth scanning, a strength control, round or square dots and 8- and 27-colour palettes. Halftone adds Atkinson and a line screen. Existing looks render as before.
- **Photoshop files open editable in Design.** Type layers become text boxes with their font, size, colour, spacing, alignment and rotation, and italic, weight, colour, underline and strikethrough stay with each word. Shapes become shapes or paths with their fill and their stroke, dashes included. Solid colour layers, clipping and layer names come along, and other layers come in as pictures. Before anything is added, a list shows what cannot be kept, such as named layer effects, adjustment layers, smart objects and gradient or pattern fills.
- **Layers at full strength.** Layers opened from Photoshop and GIMP files into Design no longer arrive at 1% opacity.

## Assets

- **The Catalogue is now Assets.** `#/a`, `/a` and `/assets` open it, and existing `#/c`, `#/catalog` and `/c` links forward there.
- **One set of view options.** Tools, Utilities, Assets and Projects share one view options menu. Favourite a tool from its right-click menu or the selection bar. The favourites strips in Projects and Assets now offer **Unfavourite** and **Share** on right-click or a two-finger tap. Saved creations share a link, folders share a portable `.lolly` file, uploads share their bytes and swatches copy their colour.
- **Browse an emoji set.** An emoji set in Assets now shows its artwork, with a filter for the nine Unicode categories. Single-colour sets such as OpenMoji Black and Fluent High Contrast take the text colour, so they stay visible in a dark theme.
- **Selection downloads keep the visible treatment.** A ZIP uses each group's chosen icon colours or photo treatment, matching individual downloads and recording the derived artwork's credits.
- **Voice Recorder is a utility,** so it lists under Utilities.

## Links that keep your place

- **View choices have an address.** Search, filters, sorting and view options in Tools, Assets, Projects and Components stay in the URL. Settings links retain the selected section, search and open cards. Dashboard, the design system studio, History and Learning also keep their supported view state when you reload or use browser history.
- **Tool edits keep the rest of the link.** Changing an input preserves the output settings and design-system revision. Short aliases, vector fields and token references count as explicit input choices, so restoring a session does not overwrite them. Large encoded links retain their workspace state.
- **Share carries the work.** Content Share includes the authored inputs and output choices. Local selections, playhead positions, panels, dialogs and app appearance stay outside the shared content. `_appearance` controls the interface even on a tool whose own `theme` input controls its artwork.
- **Back closes the current overlay.** Address changes made while a dialog is open stay with the underlying view, so closing the dialog does not restore an older query. New links to another query in the same view close the overlay and retain their destination. Installed-app links and path shortcuts keep their queries too.

- **Storage and offline downloads share one layout.** Related rows sit in expandable groups, with sizes, download status and actions together. Storage row colours match the usage bar, and offline groups show how many offered parts are downloaded.

## Licence and credits on export

- **Choose a licence.** The export panel's **Content protection** group has a **Licence** choice: *None (all rights reserved)* by default, CC0 1.0, the Public Domain Mark 1.0, or one of the six Creative Commons 4.0 licences. The licence name and a link to its deed are written into the file's licence metadata where the format has those fields, and into its Content Credential. The choice is saved with the document, travels in a share link as `licence=` and is `--licence=` on the CLI.
- **What Lolly does not do with it.** Lolly writes the licence you chose. It does not check or enforce the terms, and it records a NonCommercial or NoDerivatives licence as declared without interpreting it. A tool with its own licence field, such as Claim, keeps that field and shows no second picker.
- **Captions** move into a video's Pro settings and appear once there is caption text.
- **Verify from an address.** **Add from URL…** downloads a file and checks it on your device. In the web app, images from other sites use Lolly's image relay; addresses the browser cannot fetch show an error.

Read [Exporting](https://lolly.tools/info/create/exporting.html) and [Creative rights and credits](https://lolly.tools/info/trust/creative-rights.html).

## Evidence and reports in Verify

- **See where a clue occurs.** Text and layout inspection locates findings in supported documents and images, groups repeated patterns and records what was read, skipped or unavailable. Select a finding to review its measurements and alternative explanations. Weak style clues do not establish authorship; AI involvement remains **Unestimated** without a qualified released calibration.
- **Keep the review with the evidence.** Notes can identify a brand requirement, quoted example or misdetected region without replacing the original assessment. JSON and readable exports retain locations, coverage and file/report digests; reloading checks the binding to the original file.
- **A signed PDF report.** **Report** exports the current preview, metadata, credential observations, located findings and completed production checks, with detailed JSON attached. Lolly verifies the report's signature before offering it. The signature protects the report, not a conclusion about the source's authorship.
- **The toolbar follows the file.** File, text, URL, inspection and report actions stay together, with extra actions under **More** on a phone. Advanced production requirements stay behind **Policy**. OCR and text models use the existing download consent; inspection adds no file upload or automatic retention.

Read [AI evidence in Verify](https://lolly.tools/info/trust/verify-ai-evidence.html).

## Check a file against requirements

- **Production checks in Verify.** Supply a requirements JSON file and, when needed, a reference file. Verify reports the measurements it can make, lists failed or unavailable checks and lets you download the report. A local review is recorded separately, with the reviewer's name and reasons for permitted appearance exceptions.
- **Requirements bound to the file.** Still and motion reports identify the exact output bytes and the checks that ran. Supported checks include file dimensions, readability, declared content and bounded reference comparisons; motion requirements add timing, frame and audio observations where a decoder is available. Unmeasured appearance remains unresolved.

## Your work, kept

- **More tools save as you work.** In the web app, document tools such as Chart, QR Code, Snippet, Text, Jump, Sandbox and Doc Studio now join Design in keeping work automatically. The first change files the creation in **Projects**, and later changes are kept after the tool finishes drawing. Reopen that creation from Projects after closing the tab.
- **Know when to save yourself.** Tools without automatic recovery explain how to keep the work beside their editing controls. Imported-file tools remind you to keep the originals, recording tools point to saving or downloading the take, and the native apps explain when a manual save is needed. Collaboration guidance distinguishes temporary history from history kept by an organisation.
- **Earlier versions within reach.** **History** offers automatic checkpoints, saved versions and named milestones, with **Open as a copy** to revisit one. If two tabs save the same creation, the displaced work remains under **Protected drafts**. Sync carries the current creation to other devices; version history stays in the browser where it was made.
- **History has a storage budget.** Old previews and automatic checkpoints make room as History fills up. **Settings → Storage** shows its size and offers **Remove automatic checkpoints older than 30 days**. A full History budget does not block saving the current work; the app explains when that save cannot also be kept as a version.
- **A Trash.** Deleting a saved session, a folder, an upload or a font in the app moves it to one Trash for 30 days, from Projects, Assets, Settings → Storage or a tool's list of saved sessions, with **Undo** straight after. **Restore** puts it back and **Delete forever** removes it. The command line and the terminal app still delete at once.
- **Leave without saving discards.** The edits since the last save are removed, and a creation that was never saved leaves Projects. History keeps its checkpoints. When a discard cannot run, the app says why and keeps the edits.
- **Clear all my data clears everything.** It turns off Sync, then removes everything Lolly keeps in this browser, downloaded AI models and offline copies included, and stops every other open Lolly tab first.
- **Imports add and never replace.** Import data… and Sync's **Bring it to this device** keep this device's folders, favourites, templates and settings and add what is new. Where a session or an upload is on both, the copy saved more recently is kept. A copy Sync keeps in your storage can be imported like a backup, and the import line says what came in and what stayed.
- **"This browser" where it means one.** The web app says "this browser" for things only the browser holds, and the apps say "this device".

Read [Find and recover your work](https://lolly.tools/info/create/find-your-work.html).

## Quicker and steadier

- **Exports match layered backgrounds.** SVG export retains a pseudo-element's background colour and gradient together, gives separate gradients separate IDs and keeps fully transparent gradient stops from introducing a black fringe. Pseudo-element positioning also follows its containing block and transform.
- **Agenda starts with Depth.** New agenda screens use the Depth backdrop by default, with regenerated previews for both brand profiles. Saved backdrop choices still apply.
- **iPhone and iPad startup.** The native app uses the scene lifecycle required by iOS 27 and a fixed window runtime, preventing a crash on launch in builds made with Xcode 27.
- **MilkDrop in the native apps.** Artist presets, including Geiss and Flexi, are bundled for offline use alongside the brand presets. Native builds check that every listed preset file is present.

- **Less work on screen.** Projects updates a 3D scene's tile in place instead of redrawing the whole view and skips work for tiles you cannot see. The favourites strip pauses its zoom off-screen. The timeline, Design's zoom and stage navigation no longer make the browser recalculate layout in the middle of an update, and motion hints apply only while something moves. The interface's own fonts preload whichever brand is active.
- **A neutral loading screen.** The first frame no longer shows Lolly green before the active design system is known; a deployment can set its own mark colour. The loading spinner no longer shifts sideways before it centres, and Cover Flow stays fanned while one view fades into the next.
- **Logos belong to their design system.** Uploading, replacing or removing a logo in one system keeps other systems' marks intact. Copies and brand packs carry the right logos, and a colour edit no longer restores an older logo.
- **Tools use the active system's logo.** Markdown Slides, Stationery, Link Card, Certificate and Multi-page PDF now read the selected design system's logo slots instead of searching catalogue tags. A missing mark shows a preview notice without borrowing another brand's artwork, and logos can be turned off.
- **Know which design system remains.** Removing a local design system tells you which system will be active afterwards. The supplied system shows whether it comes from an instance or the app, with its catalogue source and tokens asset. Removing a local copy leaves the supplied catalogue assets available; the self-hosting guide explains how an administrator changes them.
- **Keyboard browsing.** Arrow keys move between tool cards and asset tiles using their positions on screen.
- **Sandbox demos on slides.** **Copy for a slide** carries the demo's code into a Design web page box. Embedded and off-screen demos use their own inputs without reading or saving this device's Sandbox draft. External resources require consent or a Trusted sites entry; organisation restrictions still apply.
- **Unpack HTML.** Extract text, embedded images, fonts, vectors and colours from an HTML file without running its scripts or fetching linked resources. Layout previews are unavailable for this format.
- **Sandbox line numbers.** Code panes gain a gutter that stays aligned with the text and highlighting while scrolling, resizing or editing on a phone.
- **Tools appear on first load.** Tools and Utilities no longer open as an invisible grid on a fresh visit. Startup also leaves document-history compression out of the initial JavaScript download.
- **Opening a large document.** A saved document opened from Projects, Home or an opened .lolly file now shows a card with its name, its thumbnail and the step running, with a Cancel button. A long Design document shows how far its text has got ("Laying out text: 37 of 106") on a filling bar. Before, a long document left the screen blank for several seconds with no way out. Cancel or Escape stops the open and goes back to where you opened the document from, and Back during an open stops the loading too.
- **Large Design documents open faster.** Design used to lay out a document's text twice on open, once with the default emoji set and again with the document's own; it now lays it out once. Text layout itself also does less work for the same result, so a 19-page document's open needs about a third of the processor time it did.
- **Pages appear as they are ready.** A long Design document opens as soon as its first page is laid out, about 2 seconds for a 19-page document where the editor used to stay closed for about 6, and the remaining pages fill in while you look. The count of text still to lay out moves to the progress toast, and you can work in the document while the rest arrives.
- **Design's menus.** The right-click menu scrolls with a mouse wheel or trackpad and fits inside a short window, so the stacking and alignment buttons at its foot can be reached. A wheel over any menu or panel on the canvas now scrolls that menu or panel instead of moving the canvas. **Import a design** moves up the document menu to sit under **Save as a template**.
- **Words stay apart in PDF text.** Text read from a PDF keeps its word breaks: letters and spaces that some office PDFs lost now survive, and on two real office documents the count of run-together words fell from about 90 to none. Columns are found region by region, so a title across the page no longer hides the gutters below it.
- **Whole logos in PDFs.** Web PDF export now reads tightly packed SVG arc commands correctly, fixing torn shapes in logos such as Linux, GNU and Krita. Web and command-line PDF export use the same path reader.
- **Tabs keep each other's changes.** An older tab no longer overwrites another tab's changes to favourites, folders, templates or Trash when it saves the profile. Removed favourites stay removed, and a restored item keeps its folder, label and font roles.
- **Design template links keep their layout.** A link with `?template=` opens Design with the template's own layout.
- **A question during opening keeps the work.** A dialog that opened while a tool was still loading, such as the Photoshop import list, no longer reloads the tool when it closes and discards the import.

## For builders

- **Engine 1.241.** The engine moves from 1.217 to 1.241. Each minor is described in [the engine changelog](https://github.com/lolly-tools/lolly/blob/main/engine/CHANGELOG.md).
- **Production and brand rule contracts.** Shared still and motion requirements retain measurement coverage, protected runtime input digests and separate review decisions. Managed brand mappings reuse the local rule predicates and preserve the brand's role names. Repairs are limited to permitted inputs and stop if a previously passing check regresses.
- **Design rows.** `design:boxes` appends slide-master fields, token-link metadata and a web page link. Existing field positions and older links retain their meanings.
- **Dependencies.** Transformers.js moves from 3.8.1 to 4.3.0 for on-device models, the desktop app to Tauri 2.11.6 and mdns-sd 0.21.4, and the updater plugin to 2.12.0. Vite, HarfBuzz and other dependencies receive minor or patch updates, and the Docker images use newer Node bases.
- **Consistent dependency records.** Third-party notices and the software bill of materials reflect the updated packages. The bill of materials is generated from committed records with stable ordering, giving the same result on macOS and Linux.
- **Motion from scripts and agents.** Editable motion recipes cover kinetic titles, a product demonstration and a quiet explainer. CLI and MCP expose exact samples, contact sheets, temporary ranges, blur and delivered-file inspection. Cue compilation returns the affected layers for review before applying the ordinary editable fields.
- **MCP server 0.2.0.** Adds the 2026-07-28 protocol's stateless discovery and per-request metadata, while retaining supported legacy clients. HTTP validates method, name and version headers; stdio finishes in-flight requests at EOF. Local HTTP listens on loopback by default. Optional protocol sessions, subscriptions, tasks and client input requests are not advertised.
- **Token and evidence APIs.** CLI system commands inspect choices and definitions, generate candidates and compare upstream changes. CLI and MCP add byte-bound forensic inspection, with missing collectors reported explicitly. The optional token bridge keeps existing single-theme calls working.
- **Agents can look closely.** Three MCP tools: `lolly_look` draws a region of a render at full size with an optional labelled grid in canvas pixels, `lolly_sample_color` averages a disc of pixels and gives the nearest design-system colour by name, and `lolly_trace_edges` turns a picture's edges into Design path layers. The same three are CLI verbs, `lolly look`, `lolly sample` and `lolly trace`, which read a picture file or a render piped in. A preview the MCP server attaches to an SVG answer is drawn in a separate process, so an SVG that stops the rasteriser cannot stop the server. The edge tracer is adapted from Composa and Filter's new dither kernels from Compositor (both MIT), credited in the third-party notices.
- **An open MCP server on lolly.tools.** `https://lolly.tools/api/mcp` needs no token or sign-in. It is limited per address and by a daily compute and data budget, returns `503` with the time to 00:00 UTC once the budget is spent, and caps PNG output at 1600 x 1600 pixels of area. The /info home page gains **AI Instructions**: the MCP address, the CLI for larger work and the Lolly skill, in one paste. Read [MCP Server](https://lolly.tools/info/build/mcp.html).

## Planning for the future

- **The document model, as a draft for review.** A twelve-chapter draft specification describes what a Lolly document is. It treats a document as a complete tool held in four records: the tool's definition, one person's authored instance, the record of a run and the files that run produced. It sets out the rules those records must keep and the cases they will be tested against. ## Compatibility and support limits

Older documents keep their existing input and URL meanings. New Design fields are appended; older clients can read their existing fields but do not provide the new token-link or web-page behaviour.

**Web pages.** The hosted app permits a bounded set of external players; native apps may frame other HTTPS sites subject to consent and organisation policy. Sites can refuse framing, and browser support varies. Export retains the poster rather than the live page. Trusted sites are a shared preference for Design and Sandbox, not permission to bypass deployment restrictions.

**AI evidence.** Findings are clues with stated coverage, not proof of human or AI authorship. No calibrated authorship probability is released. Unsupported formats, unread pages and unavailable models remain explicit.

**Brand rules.** Local example checks cover the poster, title slide, content slide and Chart PNG outputs, plus the constrained reusable poster. Managed checks cover explicitly mapped runtime inputs. They do not establish general pixel, typography, geometry or logo-clear-space conformance. Three-way brand-pack reimport, guide-site export and hosted guide sites remain future work; token-source comparisons are available as described above. Brand packages whose custom roles refer to bundled resources require brand reader 3; older readers cannot open those packages.

**Languages.** Some newer controls, including token and evidence workflows and catalogue-source explanations, can fall back to English. Rebrand's translation wave is deferred. Existing translations remain available; this release does not claim complete translation coverage.

Automatic recovery and version history are available in the web app, outside live collaboration. They do not yet cover the desktop or mobile apps, 3D Studio, Darkroom, recording tools or utilities that process an imported file. Tools with no editable state do not keep a history.

Collaboration has its own history capability: private-session checkpoints are temporary, while an organisation can provide durable shared history. Neither is local automatic recovery. Keep a separate saved copy when you need the work after a temporary session ends.

Font checks report missing or unverifiable coverage; they do not install fonts or replace the design system's choices. Text that uses a system fallback can change when reopened or exported on another device. Add or choose a font with the required characters before relying on a portable source or HTML file.

Photoshop files with 32 bits per channel do not open. Shapes joined by subtract, intersect or exclude, gradient or pattern strokes, and text that mixes sizes come into Design as pictures or with the first size; the list before opening shows each one.

Motion blur currently covers flat SDR raster output. HDR, tilted scenes and structural vector blur remain outside that path. Browser file inspection does not measure true peak or scan every audio/video span; unavailable checks are reported as not run. A technical pass does not establish visual or creative quality.

**Rebrand is an early experiment.** Deck renovation remains buggy pre-alpha work, unsuitable for production. If you try it, use a copy or the sample deck, keep the original and expect incomplete results. The [guide](https://lolly.tools/info/create/rebrand.html) records its current workflow.

The licence choice declares terms. It is not a check that those terms allow what you publish, and it does not replace the credits a source asks for.
