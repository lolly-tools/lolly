# Lolly 1.1.0 build record

The fancy one. Packages and verification records are collected in `~/Build/lolly-releases/1.1.0/`, with `manifest.json` and `SHA256SUMS` recording each file's size, digest, signing and build route. The versioned packages and stable download links are published on lolli.li. The GitHub release is a draft and has not been published. Store submissions are unchanged.

## Reproduce

Set `LOLLY_PROFILE=lolly-start` and `LOLLY_EMBED_CATALOG=profile`, and supply `LOLLY_CATALOG_SIGNING_KEY` and `VITE_CATALOG_PUBLIC_KEY_JWK` from private credential storage. Build the macOS app with `pnpm run build:desktop` and Android with `pnpm -C shells/tauri-mobile run tauri android build --target aarch64`; the plain `build:android` script produces a universal APK for every CPU type.

On macOS 27 with Xcode 27, Rust 1.96 links proc-macro libraries that the macOS 27 loader rejects ("mis-aligned LINKEDIT string pool") when `MACOSX_DEPLOYMENT_TARGET` is 13.5, which Tauri sets from the minimum system version. The local builds used Rust 1.99 through `RUSTUP_TOOLCHAIN=1.99.0`. Tauri's DMG step also failed when run without a desktop session; the DMG was created with its `bundle_dmg.sh --skip-jenkins`, then signed, notarised and stapled. Android needs a JDK; JDK 21 was used.

Intel macOS distribution signing uses `macos/IntelEntitlements.plist` for the main executable and the CLI sidecar, `quicklook/QuickLook.entitlements` for both Quick Look extensions, and no entitlements for the bundled libraries and addon. Rosetta no longer verifies an Intel build: on macOS 27 a headless render hangs for the published 1.0.9 Intel app as well as for 1.1.0. Use `macos-intel-smoke.yml` with the uploaded DMG instead.

## Verification record

- The Apple silicon and Intel apps and DMGs are signed, notarised and stapled, and Gatekeeper accepts them. The Apple silicon app lists 67 tools and its packaged command line exports valid SVG, PNG and PDF; a Snippet SVG carries no `rgba()` paint. On an Intel runner the Intel DMG passes Gatekeeper and its stapled ticket, and the packaged app exports SVG, PNG and PDF.
- The installed Windows MSI and NSIS packages report 1.1.0 and pass the installed export checks.
- Both DEBs declare `libayatana-appindicator3-1`, WebKitGTK 4.1 and GTK 3, and carry a 270 MB `lolly-desktop` binary. The installed DEB and AppImage checks pass on x86_64 and ARM64, and the Flatpak smoke passes.
- The Arch package repacks the published x86_64 DEB, whose SHA-256 matches the PKGBUILD. The repository index lists `lolly-desktop-bin 1.1.0-1` only.
- Android APK and AAB carry the release certificate (SHA-256 `4B:8E:8C:40:B0:95:DA:4B:51:11:C7:88:B6:42:67:B3:21:65:EC:B9:6C:6E:D2:38:32:3F:F0:5C:A4:E1:E0:18`). Bundletool validation, ZIP integrity and 16 KB alignment checks pass. The packages contain ARM64 native libraries only; version code is `1001000`, minimum SDK is 24 and target SDK is 36.
- The web archive's catalog signature and all 2141 signed files across 67 tools verify against the pinned public key after extraction.

No physical Android device acceptance was performed. No npm package, store submission or YunoHost package update was published by this build task.
