# Lolly 1.1.2: the Colourway one

**Draft: not released.** These notes cover the 114 pull requests merged to `main` after [v1.1.1](https://github.com/lolly-tools/lolly/releases/tag/v1.1.1), up to `c9d1dc658` (2026-10-19). The engine moves from 1.261.0 to 1.280.0 and the tool-author core from 1.4.0 to 1.5.0. Each claim was checked against the code at that commit. Update this draft as more work merges, and delete the "Before publishing" list at the end before release.

Lolly 1.1.2 brings colourways: a design system can hold several lead colours, and each piece of work chooses one from a new **Design system** section in the tool sidebar. Exports now record the design system and colourway that made them. Design gains a Scale mode and two-finger transforms. Presentations can drive reveal.js and Slides.com decks from the clicker. 3D Studio and Darkroom now keep History. The on-device utilities can prepare a video clip with a report on how it was made, turn images into a PDF, read a document's words in reading order, convert spreadsheets with explicit choices and subset a font, and the export card now checks the delivered file against your settings. On a Lolly Work server, Assets gains a shared library with organisation metadata and reviewed search text. The blank starter design system gets warm surfaces, and lolly.tools now runs Lolly Demo, Lolly's own design system.

## Colourways and design-system choices

- **Colourways.** A design system can now hold several lead colours, called colourways, and each piece of work chooses one. A colourway sets the primary colour, the colour that sits on the primary and a partner colour, for both light and dark. A design system gets colourways from a token file that declares them; the [token workflows](https://lolly.tools/info/token-workflows.html#colourways) guide shows the format. A design system with one lead colour draws exactly as before. Brand Studio cannot add, rename or remove colourways yet.
- **A Design system section in tool sidebars.** A tool now shows a **Design system** section when a theme choice changes what the tool draws. Colourways show as colour dots, and the section opens when a colourway is on offer. Light and dark show as a **Mode** row with **Light** and **Dark**, in a section that starts folded. A tool that reads no design-system colour, such as most utilities, shows no section. In 1.1.1 only Design offered a theme choice, so most tools now show this section, even on a design system with no colourways.
- **The open tool follows the choice at once.** A switch redraws the open tool with no reload: linked colours, colours the tool read from the design system, and the colour picker's swatches all change, including in tools whose logic runs in a separate worker. The choice is saved with the session and travels in links as `_themes`. Design shows the same choices in the inspector's **Canvas** tab.
- **The app keeps its own colours.** The app's accent, tab icon and logo tint follow the design system's canonical colourway and your light or dark appearance, whatever colourway the open work uses.
- **Tools that use every colourway.** With two or more colourways, Chart 1.27.0 puts every colourway's lead first in its categorical palette, ahead of the other colours. Audiogram 2.8.0 and the visualisers draw on every lead, with one visualiser scheme per colourway. Gradient 1.3.0 shuffles from the leads first, and audio and text covers in Assets draw from them first. With one colourway or none, these tools draw as before.
- **Design document context.** In Design, **Style & look** in the inspector's **Canvas** tab shows which design system and version the document draws with. A chip reads **Chosen for this document** or **Follows the design system**, **Source and fallbacks** lists every theme choice, **Inspect tokens** opens a read-only token inspector and **Follow the design system** removes the document's own choices. The light and dark row now reads **Mode** (it read **Theme** in 1.1.1).
- **Brand Studio and colourways.** On a design system with colourways, Brand Studio edits the canonical colourway. **Rebuild the whole palette…** keeps every colourway: the canonical one follows the new starting colour and the others keep their own colours. A design system whose colourways Lolly cannot edit is not rebuilt, and the card gives the reason.

## The design system in your exports

- **Exports record the design system that made them.** The export panel has a new **Design system** card, ticked by default. It shows the exact words the file will carry, such as "Records: Acme · Colourway: Persimmon". The record holds the design system's name and id, its published version (never the working copy) and every theme choice except light or dark. Lolly writes the record into the Content Credential, as `lolly:` XMP properties in PNG, JPEG, WebP and JXL, in the SVG `<metadata>` block and as PDF keywords. With a colourway, the description reads "Made with https://lolly.tools : Chart (Persimmon colourway)".
- **Turning the record off.** Untick the card, or add `_madewith=0` to a link. The card is hidden for formats with no place for the record (CSV, JSON, calendar files, EPS, EMF, DXF and BMP) and for on-device utilities. Batch, Projects folder and 3D collection exports record nothing. **Change:** because the record is on by default, exports from the bundled design system now carry its name too ("Lolly Starter" in the neutral catalog).
- **Verify and Recreate read the record.** Verify lists **Design system** after Tool. Recreate reopens the recorded version and colourway, and switches design system only when this device holds one with the same id and name.

## Lolly's demo brand has landed

- **Warm surfaces for the blank starter.** The blank starter design system, which the web archive, container images, YunoHost package and apps ship, now sets the app's own surfaces: a warm paper page (`#fcfaf6`) in light and a warm charcoal page (`#171612`) in dark, where 1.1.1 had white and near-black navy. The Brand theme, High contrast, tool canvases and exports are unchanged. To return to the 1.1.1 surfaces, turn off **Interface follows the design system** in Settings, Appearance. A design system made from the 1.1.1 starter keeps the 1.1.1 look.
- **One Lolly green.** Lolly's own touches (the Made with Lolly badge, the Lolly mark on the Design rail and the web app manifest) now use Spearmint on the light theme and Green Apple on the dark and Brand themes, from Opal, Lolly's own palette. On the blank starter's Brand theme the badge's contrast goes from 2.29:1 to 4.5:1. The four Lolly marks are signed again; their earlier credentials had expired.
- **The /info site in Opal.** The documentation site swaps its earlier palette for Opal: Spearmint bands on light and Green Apple accents on dark. Links in article text are underlined, and several faint labels are easier to read.
- **Neutral edges at rest.** Cards, rings and tonal buttons wear the theme's neutral hairline while idle and take the accent on hover, focus or selection.
- **Dashed means drop.** Dashed outlines now mark only places where you can drop a file. Choose-a-file tiles (the **Add** tile under **My images**, each logo slot in the design system editor and **Remove background**'s **Choose a photo** step) now take a dropped file, with a short label such as "Drop to replace" while a file is over the tile. Empty states, loading tiles and other places that took no file lose their dashes.
- **A simpler upload area.** The upload area in Assets and in the design system editor is the same for mouse and touch: an upload icon, "Add files" and "drag & drop, tap or click". The format chips and the separate touch **Choose files** button are gone.
- **Fewer borders and smaller touches.** Component cards, the gallery search field and the profile menu use shadows instead of borders. Gallery tile titles are lighter. A page that shows only an error centres the message, and the browser address bar follows the page colour in use, including High contrast.
- **One section card, one fold motion.** The asset inspector's sections now use the same card surface as the tool sidebar's sections: the same bevel and shadow, the same caret and a 44 px closed height. Every section that folds, including the export panel's Password, Protection and Send to cards and the Design inspector's sections, now opens and closes with the input sections' size and fade motion. Reduce motion turns the motion off.
- **Checkerboards follow the theme.** The transparency checkerboards in the gallery and on object tiles now draw from the theme's own surfaces, object tiles sit on the muted surface and the cards in Settings lose their border for a tint.
- **No more tips strips in the gallery.** The gallery's tips strip and the "Your brand is loaded" intro strip are gone.
- **The featured strip scrolls natively on phones.** A swipe that starts on the handle under the featured strip is now the browser's own scroll, with momentum. Before, Lolly drove the page itself, and on an iPhone the page lurched as Safari's toolbar moved. The uncategorised strip in Projects gets the same fix.
- **Error text that reads.** Error messages use a red tuned for each theme, at 4.5:1 or better. On the dark and Brand themes the old red read as low as 1.4:1.
- **High contrast follows your brand.** With High contrast on, the focus ring takes the design system's accent when the accent reads at least 3:1, and a dark brand colour on the main button becomes a pale tint with a black label.
- **Accents that follow the theme.** The job count badge, the Undo button and its countdown, a playing sound preview, the highlighted word during read-along, the folder star and the Unpack drop zone drew the light theme's brand colour on the dark and Brand themes and nearly vanished. They now use the theme's own accent. Unpack's tab strip and page rail use the theme's surfaces.
- **Colours that drew nothing.** Design's insertion line and grid outlines for stack and grid frames show again, the in-app documentation reader has its rules and table frames back, and URL Screenshot's **Behind a sign-in?** panel in the desktop app has its border and button fill.
- **Swatch labels that read.** Swatch labels in the colour picker, Colour Lab and the design system editor now take white or black by APCA contrast. Before, many labels were black whatever the colour, so a dark green swatch could have a black name.
- **The Components cover follows your design system.** The "Colour is a good place to start" cover shows the active design system's colours instead of fixed greens, blue and orange.

## Design

- **Scale mode.** Design now has two ways to change size. **Resize**, the default, changes the box only, as before. **Scale** grows or shrinks the object with its content: font size, stroke width, corner radius, shadow, blur, padding, spacing and dash lengths all change by the same factor, and a selected artboard or layout container scales its members. Press `K`, choose **Scale mode** in the Lolly menu, or press and hold the **Pointer** button on the tool rail and choose **Scale**. `V` or Escape returns to Resize. Scale is off whenever a document opens.
- **Scale by a number.** With Scale on, or with several objects selected, click the size readout on the object bar to open the **Scale** popover: type a percentage, a width or a height, pick the point that stays still and choose **Apply** (1% to 10000%). The inspector's **Position & size** section gains a **Keep proportions** lock between W and H and a **Scale (%)** field, which always scales the content from the centre.
- **Keys during a drag.** Shift keeps proportions while you resize and turns in 15 degree steps while you rotate. Alt (Option) resizes or scales from the centre. Cmd or Ctrl turns snapping off while you resize or scale. A key takes effect as soon as you press or release the key. The shortcut sheet (`?`) has a new **Transform** group. **Change:** in 1.1.1, Alt during a resize also turned snapping off. Snapping now stays on with Alt; hold Cmd or Ctrl to resize without snapping.
- **`K` on the canvas now means Scale.** A bare `K` on the canvas did nothing in 1.1.1, although the animation guide said `K` added a keyframe. To add a keyframe from the keyboard, press `Shift+K` while the timeline has focus.
- **Grab anywhere along an edge.** Each side of a selection is now a resize strip along its whole length, and with a mouse or a pen there is a rotate zone just outside each corner. A press becomes a resize or a turn only when you drag, so a plain click still selects. A selection of several objects has edge handles too. On a touch screen the grab zones are large; turn on **Large grab areas** in the Lolly menu to get them with a mouse or a pen.
- **Two fingers on a selection.** On a touch screen, put two fingers on a selected object to pinch it larger or smaller, twist to turn the selection or move both fingers to carry the selection, as one undo step. Two fingers elsewhere still zoom and pan the view. **Change:** a pinch that starts on the selected object no longer zooms the view.
- **Steadier transforms.** A selected group's outline follows a drag, a press that changes nothing adds no undo step, a locked object shows its outline but no handles, and artboards no longer turn.
- **Link a whole typography token.** In a text layer's **Paragraph token links**, **Whole typography** sets font, size, weight, tracking and line height together, as one undo step. Lolly pins the exact font faces the token uses and refuses a nearer weight or another family. If a later theme needs a face that was not pinned, the text keeps its last values and the link reports the missing face. Design is now 1.51.0.
- **Zero and negative sizes link.** A number field can now link a dimension token of zero or less, such as letter spacing of `0px` or `-0.5px`. In 1.1.1 these tokens were refused.
- **The tool rail scrolls in short windows.** In a desktop window under about 550 px tall, the parked tool rail now fits between the bars and scrolls, so the Lolly menu no longer rides over the top bar.
- **Hidden auto layouts keep their size.** A hidden layout container set to **Hug** no longer shrinks to its padding.

## Presenting, saving and History

- **reveal.js and Slides.com decks follow the clicker.** Paste a Slides.com deck link into a **Web page** box and make the slide interactive: Up and Down then step through the deck while Next and Previous move the Lolly presentation. The speaker view shows the deck's slide number. A self-hosted reveal.js deck opts in by adding `postMessageEvents=true` to its own address. In the web app a Slides.com deck shows only after **Allow pages from any site**.
- **3D Studio and Darkroom keep History.** Both tools now save as you work and keep version history. The file you load (a 3D model or a LUT) is not kept: History and **Save** record its name, type and size, and a reopened creation tells you which file to load again. **Change:** in 1.1.1, **Save** in these two tools stored the loaded file itself. Work saved before this release still opens with its file until your next edit. Keep your original files.
- **History as a picture grid.** History now shows each creation as a tile led by its picture, with a **Grid** or **List** switch, one toolbar and slim day dividers. Select creations and choose **Move to Trash**, with Undo, or use a tile's menu (right-click or long-press) to resume, see versions, show the creation in Projects or move it to the Trash. A run of checkpoints of one creation is one tile with stacked pictures, the footer shows what History holds, unnamed creations show the tool's name and QR and chart thumbnails now draw. In 1.1.1 two creations filled a laptop screen and nothing could be removed.
- **The inviter keeps History in a private collab.** In a two-device private collaboration, the inviting device now keeps History while you work, with the other person's changes included. The joining device still works on a temporary copy.
- **A simpler leave dialog.** Leaving a tool with unsaved work now asks **Unsaved edits**, "Save now or abandon your changes.", with **Save & leave**, **Leave anyway** and **Cancel**, beside a small kangaroo. A team document's dialog uses the same buttons (its **Save** and **Stay** buttons are now **Save & leave** and **Cancel**). Translated into all 26 languages.
- **Save keeps its picture.** A **Save** pressed soon after a tool opened could store the creation with no preview, so its Projects tile and History entry stayed blank. 3D Studio showed this most.
- **Quieter reconnects in team rooms.** Reconnecting to a Lolly Work room no longer shows "Recovery copy could not be saved here", no longer announces an interrupted edit you already have and no longer brings back a recovery copy you removed.
- **Saved work keeps the exact catalog file.** When you place a catalog file, Lolly now records a SHA-256 fingerprint of the bytes it read, and saved work asks for those exact bytes. A replaced source file cannot change saved work; if the exact bytes are missing, the file shows as unavailable instead of the latest version. The asset details in Assets gain a **Source history** section.

## Export

- **Emoji in PDF exports.** Design text set in one of the emoji sets exported to PDF without its emoji, unless you had converted the text to paths. The artwork now reaches the PDF as vector shapes, for all seven sets.
- **Truer SVG artwork in PDF.** PDF export in the app now draws more of an SVG as vectors: clip paths, real transparency, linear and radial gradients (drawn as a 150 dpi picture before), arrowheads and other markers, blend modes, skew and mirrors. **Change:** an SVG that holds a mask, a filter, a pattern, a text path or a few other effects is now drawn whole as a 150 dpi picture instead of losing those parts. In a CMYK print export, such an SVG is no longer vector and the file loses its PDF/X claim.
- **Underlines in Design SVG and PDF.** Underlined words now export as outlines, with the line placed as the browser draws the line and gaps around descenders. Before, an underline sent the whole page to the slower fallback renderer in the app and to the browser tier in the CLI.
- **The export card checks the file you received.** After a download, the app reads the delivered file back and compares the file with your export settings: format, pixel or page size, clip length, a transparent background, CMYK colour for a print separation, HDR, Content Credentials and a PDF or ZIP password. A difference shows on the export card with the other export notes. Each value comes from the file itself, and a property the file cannot answer is never counted as a match. A credential that is present is reported as present, not as verified. Files over 256 MiB are not checked.

## On-device utilities

- **Trim 1.1 prepares a clip for sharing.** A new **Make** control chooses **Clip**, **Poster frame** or **Contact sheet** (6 to 25 frames with time labels). **Rotate** turns a video by 90° or 180°. **Sharing size** (1080p, 720p or 480p, never larger than the source) and **Size limit (MB)** make a smaller clip; a copy that already fits is kept, and a re-encode never goes above the source's bitrate.
- **Trim reports how the clip was made.** A report lists each track as copied, re-encoded (with the reason) or left out, and shows where the clip starts against the key frames, whether sound and picture stay in step, which way up the picture is and whether the size limit was met. **Cut** has three modes: **Exact** (the default), **Re-encode**, which is new and keeps nothing before the start, and **Fast**. An Exact MP4 or MOV cut is still a copy from the key frame before, with the earlier frames marked for players to skip; the report now states this, because some editors and upload sites show those frames. Trim 1.0 labelled these cuts "Re-encoded for exact boundaries", which was wrong.
- **Trim no longer drops a track silently.** When the browser cannot decode or encode a track you kept, Trim now refuses and gives the codec and the reason. Trim 1.0 wrote the clip without that track. Changing a video's container in Convert also says which track a copy would lose.
- **Pages 1.1 turns images into a PDF.** Choose PNG or JPEG images, alone or with PDFs, and each image becomes one page. Other image formats are converted to PNG first where the device can read them. A JPEG is placed without re-encoding and turned upright, and its Exif, XMP, IPTC and Content Credentials are left out. An 8-bit PNG keeps its exact pixels. **Image page size** sizes each page from the image's own resolution or fits the image on **A4** or **US Letter**, with an optional **Image margin (mm)**.
- **Pages shows what changes before download.** A **What changes** list reports what the operation does to bookmarks, annotations, links, form fields and signatures. Rotating a single PDF edits that file, so only a digital signature stops verifying. Every other operation builds a new PDF from copies of the pages: bookmarks are not carried over, links to other pages and form fields stop working, and the new PDF is unsigned.
- **Left-out pages stay out of the new PDF.** In 1.1.1, a page you deleted could still travel inside the new PDF as a hidden copy when a kept page linked to that page, and every signature value (signer, location, date and certificate) was copied too. Pages now cuts those references before each copy. **Change:** links to other pages are removed rather than remapped, even when the target page is in the new PDF.
- **Read and extract (new).** A new utility (in Utilities and in Search) takes a PowerPoint deck, a PDF or a Photoshop file of up to 120 MiB and gives its words, tables, charts, pictures and speaker notes page by page in reading order, on the device. Each block says where its words came from: written in the file, a scan's text layer or text recognition, with the model and its confidence. **Pages**, **Character budget** and **Recognised text** bound the extract. Copy the result, or download it as **Text**, **Markdown** or **JSON**. Macros, scripts and embedded files are never run or opened.
- **Two-column PDF pages read in column order.** A full-width title above two columns no longer makes Rebrand, `lolly read` and Read and extract read across the columns line by line.
- **Convert reads data the way you choose.** Converting a spreadsheet, CSV, TSV or JSON file shows **How to read this file**: the **Worksheet** (or **All worksheets**, which writes a ZIP with one file per sheet and a `manifest.json`), **Formulas** (**Saved results** or **Formula text**), **Columns separated by**, **Text encoding** and what the **First row** holds. Nothing is recalculated, so a date arrives as its stored serial number, and the report says so.
- **Conversion reads whole sheets.** **Change:** in 1.1.1, converting an Excel sheet stopped at 1,000 rows without saying so. Conversion now reads the whole sheet and refuses a sheet too large to read in full. Text that is not valid UTF-8 is read as Windows-1252 instead of gaining replacement characters, semicolon-separated files are detected and a quoted value keeps its line breaks. The Spreadsheet view gets the same fixes.
- **Strip Hidden Data 1.4 removes more DOCX properties.** Supported Word files can now also lose Template, Hyperlink base, the application name and version and the document statistics (editing time, pages, words, characters, lines and paragraphs), each as its own choice. A property that a Word field shows is kept, and files with charts, drawings or embedded objects keep the application name and version. **Change:** Prepare's default selection and `lolly prepare --strip-hidden-data` take every property offered, so they now remove these fields too.
- **Convert Font 1.1 shows what a font contains.** The card lists the outline format, family and style, weights, named styles and axes, glyph and character counts, the Unicode blocks covered and the font's embedding flags, described as "the font's own statement, not its licence".
- **Subset a font.** A new **Glyphs** choice keeps every glyph, **Basic Latin**, **Western European** or **Only the characters I type**. A subset works on TrueType outlines only and is checked against its output bytes. A font whose own flags restrict embedding or subsetting, or that states no permission at all, is not subset, and the export stops with the reason. A subset is never a rights grant.
- **SVG fitted to its artwork.** Convert and **Convert…** in Assets offer **SVG fitted to its artwork (.svg)**, which moves the viewBox to the painted artwork. Anything the scan cannot measure exactly, such as text, filters or animation, is refused with the reason.
- **Font collections open in the asset viewer.** A `.ttc` or `.otc` collection, refused in 1.1.1, now opens with a **Face** chooser, and **Add to my fonts** installs the chosen face. Type 1 fonts (`.pfa`, `.pfb`) are recognised, with a note to convert them to OpenType first.
- **Backups need far less memory.** **Export my data** now writes the backup a part at a time, and every part keeps its exact bytes and digest. In a Node measurement of a 192 MiB library, finishing the backup took about 125 to 150 MiB on top of the library, against about 850 MiB before. **Bulk from files** also writes its ZIP as each result is made. Restore still reads the whole backup into memory.
- **Photo looks on the GPU.** Gradient-map, greyscale and duotone looks on uploaded and embedded photos now bake on WebGPU, as LUT looks already did. Treated photos bake once more on first use. **Change:** when a bake fails, the photo shows an error instead of the untreated picture under the look's name.
- **Penpot legacy exports report their layouts.** When the pages of a Penpot legacy zip export declare flex or grid layouts, the Design import says how many came in as fixed positions and suggests the `.penpot` export to keep them editable.

## Creative rights

- **Template shares and brand packs follow the licence rules.** Sharing a template as a `.lolly` file and downloading a design system with **Brand + selected content** now decide which catalog art travels by the reviewed licence profiles that a session `.lolly` share already uses. **Change:** catalog art with no recorded licence, or with a licence the rules have not reviewed (such as NC, ND or a custom text), now stays behind as a reference, and `CREDITS.txt` gives the reason. A file you pick yourself in the brand download list still travels, and `CREDITS.txt` records that you chose to carry those bytes.
- **Derived files ask for their source's credit.** A crop, a colour grade, a framed copy, a **Download as** conversion or a video edit of a catalog work whose licence is recorded, but which has no Content Credentials of its own, now writes an unsigned source ingredient and the source's credit into the new file's Content Credentials. The app does not read these files back yet, so the credit is written but not confirmed. A source with its own credential keeps that credential, as before.
- **A file that cannot carry a required credit is not saved.** When a reviewed licence asks for a credit and the new file cannot carry one, the app stops with "The new file could not carry the credit its source asks for." **Change:** a **Download as** that asks for Content Credentials now fails when signing fails; before, the file was delivered unsigned with no message. In the Assets video editor, a lossless trim of a `.mov` or `.mkv` clip whose licence asks for a credit now saves a re-encoded MP4, because those containers cannot carry Content Credentials.
- **LUT looks are credited under their own licence.** A colour grade records its LUT as a separate work under the LUT's licence, never the picture's. A look at 0% intensity no longer records its LUT.
- **`.lolly` files list their dependencies.** A `.lolly` saved from the app now carries `portability.json`, which lists every dependency (the tool, assets, fonts, design system, templates and links) as embedded, available, linked, withheld or missing, with the reason. Addresses in the report lose any user name, password, query and fragment. The app does not show this list yet.

## Assets and shared libraries

- **A resizable asset inspector.** The details sidebar for every asset now resizes from 300 to 640 px: drag the divider, or focus the divider and use the arrow keys. Home collapses the sidebar to a narrow rail. Its sections expand and fold, Lolly remembers their state and the width, and **Checks** comes last with the provenance lamps. Long credential text now wraps.
- **A resizable Sources rail.** The Sources rail in Assets (fixed at 240 px before) now resizes from 180 to 480 px and keeps its width across reloads.
- **A shared library (needs Lolly Work).** When Lolly is connected to a Lolly Work server that offers shared browsing, Assets shows a **Shared library** section above your device assets, read 100 records at a time, with **Type**, **Tag** and source filters that run on the server. Selections stay selected across pages. The section appears only after the server confirms shared browsing; other servers show nothing new.
- **Organisation metadata and reviewed search text (needs Lolly Work).** A shared asset's details show **Source facts** apart from **Organisation metadata**, which members with edit rights can change. For an image, SVG or PDF, **Read text** extracts the words on your device; review them, then choose **Add reviewed text to shared search** to send up to 8,192 characters to Work. Nothing leaves the device before that step.
- **Shared project files (needs Lolly Work).** **Browse sources**, then **Shared projects**, lists the projects and folders you can open. **Add to project** offers **Copy to a shared project…**, which copies the file and its name. **Submit to the catalog** now works on a shared project file and asks for a **Library audience**: everyone in the workspace, or one of your groups.

## Batch and Multi-edit

- **Select rows.** Each Batch row has a checkbox, with Shift-click for a range and **Select all** across pages. **Edit input…**, **Duplicate**, **Remove**, **Render selected**, **Export selected CSV** and **Print selected rows** act on the selection, and **Undo remove** brings back removed rows. The grid now shows 50 rows per page.
- **Copy and paste cell ranges.** Select a rectangle of cells and press Ctrl+C or Command+C to copy tab-separated text and an HTML table for spreadsheets. Paste a rectangle, or paste one value to fill every selected cell.
- **The full format menu.** **Default format** now lists every format the catalog's tools offer and your browser supports, including BMP and SVGZ (1.1.1 offered a fixed list of eight). **Import CSV** asks whether to **Add rows** or **Replace batch**. Batch no longer offers SCORM, which failed on every row in 1.1.1; build courses with **Export course** in Projects.
- **Link a token across many documents.** In Multi-edit, the Shared card's **Input actions** menu links a token in every session that declares the input. In Batch, the Fill popover of number, text and choice columns has a **Design token** section. Both show each document's current and new value before anything is written.
- **Each session keeps its theme.** Batch rows and Multi-edit cards opened from saved sessions now keep the session's theme choices and token links, so a session saved in dark renders in dark. In 1.1.1 both used the design system's defaults. The Batch CSV gains an optional `_themes` column, and copying a token-linked cell gives the value shown instead of `[object Object]`.
- **Embedded tool links follow the document's theme.** A tool link placed inside a document now draws in that document's theme choices; a link's own `_themes` still wins. **Change:** in 1.1.1 an embedded tool always drew in the design system's defaults.

## First use and workspaces

- **No workspace question on first launch.** The desktop and mobile apps now open with the bundled tools and the same welcome as the web app. To connect to a workspace later, open **Settings**, then **Lolly instance**, then **Change**.
- **QR Code starts with an empty link.** QR Code 2.7.0 no longer fills in `https://lolly.tools`, and a cleared field no longer falls back to `https://example.com`, so a first export cannot scan to a site nobody chose. The canvas shows a calm empty state with the missing field named, and an export with nothing to encode stops with a short message such as "Add a link first" (the CLI prints the message and exits 1). **Change:** a QR Code link or script that relied on the default link now needs the link given.
- **A placed logo sets the colours.** Placing a logo used to give its first colour the primary role, so a logo that starts with a white shape made white the primary. Lolly now ranks the logo's colours like any artwork, ink before ground, and leaves pure white out as the canvas. A "Which is the main colour?" card under the Logos drop zone and at the top of Colours offers the likeliest answer: **Use these colours** adds them to the palette and points the primary at the main colour, and **Not now** keeps them in the tray. On a first-ever install the answer is applied at once, with Undo. PNG, JPEG and WebP logos are read too.
- **The design system's name is asked once.** A design system still on a placeholder name gets one "What is this design system called?" question, filled in from the logo's text where it can. The header shows the new name straight away, and a shared design system pack is named after it.
- **A calmer first run in Start.** The empty Overview offers four doors with the logo first, the starter neutrals in Colours start folded, the colour picker card opens next to **+ Add swatch**, **Font file** opens the Type comparison and Escape in the name field no longer leaves the studio.
- **One list of notifications.** The avatar menu has a single **Notifications** row, with no count at zero, in place of separate Notifications and Inbox rows. **All workspace messages** at the bottom of the list opens the full inbox. **Sign out everywhere** moves to its own row in Settings.
- **Guests get past the sign-in screen (needs Lolly Work).** A guest who joins through a Lolly Work guest link now passes the sign-in screen, limited by the server to that link's tool.
- **Open a workspace from a browser.** A browser's **Lolly instance** card now offers **Open a workspace**: enter the address and Lolly opens that workspace in the same tab. A bare host name is read as `https://`, and an `http://` address is refused.
- **App sign-in to a private workspace (needs Lolly Work).** In the desktop and mobile apps, sign-in to a private Work server now keeps its session, so the account and private catalog load. In 1.1.1 the app lost the session after sign-in.
- **Imported token files keep their themes.** A Tokens Studio file with a product theme group no longer links the primary colour to one core colour in every theme. Older Tokens Studio files that write `value` and `type` without `$` now import with a warning, and a file with no tokens says "No tokens found".
- **Design system fixes.** A logo set in live text no longer offers a Trim that would cut the wordmark. Switching design system shows "Using <name>." with **Undo**. A team project shared with some people says **Private project** or **Everyone in** its groups instead of **Shared project**, and a server error reads "The server could not send the latest tools" instead of **Offline**.
- **Phones start on PNG.** On a touch-only device, a tool that lists SVG first and also offers PNG, such as QR Code, now starts its export on PNG, which the camera roll and chat apps can open. A `?format=` link or a saved session still decides.
- **Starters use your colours at once.** A starter chosen after a tool opens now draws in the design system's colours on the first render. Before, QR Code's **Website link** starter drew near-black modules until the first edit. The same fix reaches the starters in twelve other tools, among them Audiogram, Backdrop, Diagram Builder and Wordmark.
- **Record and Wayfinding Signage keep their accent linked.** Opening either tool no longer replaces the accent's design-system link with a fixed colour. Record is now 1.4.4 and Wayfinding Signage 1.2.3.

- **Lolly Work.** The shared library, organisation metadata, reviewed search text, shared project copies, project-to-library submission and app sign-in need Lolly Work changes merged after Work 1.1.1. Against an older Work server the **Shared library** section stays hidden. Editing organisation fields and publishing indexed text need the `catalog.edit` grant. **Request source review** appears only on a Work instance that offers source review. Name the paired Work release here before publishing.
- **Asset index request.** The web app now asks for `/catalog/assets/index.json?paged=1`. Work answers with a bounded inventory; a static host ignores the query and serves the same file.
- **Exports carry a design-system record by default.** Hosted render links, CLI renders and MCP renders write the record unless `_madewith=0`, `--no-madewith` or `madeWith: false` is given. Where a design system is active, files will not match earlier exports byte for byte.
- **Warm surfaces on your instance.** Instances on the blank starter show its new warm surfaces. Each user can turn them off with **Interface follows the design system** in Settings, Appearance.
- **Which builds use Lolly Demo.** Only lolly.tools builds with the new `lolly-demo` profile. The web archive, YunoHost package, container images and apps build with `lolly-start`, which stays the Dockerfiles' default. Set `LOLLY_PROFILE=lolly-demo` to build Lolly Demo yourself. The reusable `release-frontend.yml` workflow takes a new `profile` input (default `lolly-start`).
- **/brand is in every build.** The brand standards page sits in the web shell's public files, so every build serves `/brand` through the existing `$uri/index.html` fallback. The page describes Lolly's own brand and links to Lolly Demo colourways that a `lolly-start` build does not have. - **Share cards redraw on the next build.** `build:web` reads share-card colours and the logo from the active catalog, and each card's signature includes them. The first build after upgrading redraws every card for your profile. A pack that ships `catalog/og/og.png` replaces the site's `/og.png`.

- **Documentation routes.** The public nginx configuration (`deploy/docker/public.nginx.conf` and the sovereign Helm profile's copy) and `vercel.json` route `/docs/manage/<page>` to `/info/manage/<page>.html`. If you keep your own copy, add `manage` to the list of sections. The public Caddy configurations now serve `/agents.md`, `/llms.txt`, `/llms-full.txt`, `/openapi.json`, `/.well-known/lolly.json` and `/robots.txt` from the documentation, and redirect `/docs`, `/documentation` and `/sitemap.xml` to `/info` (308).

## For tool authors and builders

- **Theme groups can say what they mean.** A `$themes` entry can carry `$extensions["com.suse.lolly"].axis` with a `kind` (`mode`, `colourway`, `expression`, `medium`, `contrast`, `density`, `campaign` or `brand`), `canonical`, `rotation` and a date `window`; a root `themeAxes` map states the same once. Lolly acts on `mode` and `colourway`, and a group with no kind resolves as before.
- **Behaviour change: theme requests.** `host.tokens.colors({ theme: 'light' })` now decides only the groups that declare that theme. Every other group takes its entry in an explicit `selection`, then the stored choice, then `activeThemes`, then the group's canonical option. In 1.1.1 a theme request reset every other group to its first option. A design system with one theme group resolves as before.
- **Reading colourways.** Optional `host.tokens.family(role?)` returns every colourway's colour for one role, canonical first, and `host.tokens.axes()` returns every theme group. With two or more colourways the canvas carries `--brand-lead-1` to `--brand-lead-<n>` and `--brand-lead-count`, and a colour input with `"palette": "colourway-leads"` offers the leads as swatches.
- **Hooks hear a theme switch.** After a live switch the runtime runs `onInput` once more with the id `__tokens`, whose patch updates computed values only. Do not return a colour under a declared colour input's id: that replaces the input's design-system link with a fixed value. Worker executors receive the new token snapshot through the optional `tokensChanged` hook. `onInput` also runs when `runtime.resolveRefs()` completes a linked value after mount.
- **Tools that keep their own colours.** A manifest may declare `"tokenAxes": { "colourway": "ignore" }` for any axis kind. The tool then renders in the canonical option of that kind and offers no choice for that kind. `lolly run` warns `THEME_CHOICE_IGNORED` when a link asks for another option. No shipped tool declares `tokenAxes` yet.
- **Colourway editing in the engine.** `liftToColourways`, `addColourway`, `renameColourway`, `reorderColourways`, `setCanonicalColourway`, `duplicateColourway` and `removeColourway` return an edited copy, or refuse an edit that would change how a remaining choice draws. `pickColourway` applies `canonical`, `cycle`, `by-key`, `shuffle` and `by-date` rules; no app flow applies these rules yet.
- **The design-system record.** `_madewith` is a new reserved URL parameter. The runtime adds `madeWith()`, `setMadeWith()`, `madeWithPreview()` and `lastExportMeta`; `designRecordCarrier(format, credential)` says where a format holds the record, and `readFileDesignRecord` reads one back. The CLI takes `--no-madewith` and prints "Recorded the design system: …" on standard error for each file. `lolly validate --rebuild` reports a `design-system` reason when the systems differ.
- **CLI theme runs.** `--themes` now gives every run an explicit selection. `--themes=all` exports each look once in the session's colourway or the canonical one, and a design system whose only themes are colourways exports each colourway.
- **MCP.** The MCP server adds `lolly_inspect_tokens`, which explains a token's value, theme choices, issues and references and writes nothing; the server now lists 22 tools. `lolly_render` and `lolly_build_url` take `madeWith: false`, and `lolly_render` reports the record it read back from the file.
- **Terminal app.** The terminal app's System view gains **Inspect tokens** (`t`), with theme choices, search and a trace view.
- **`lolly learning build` renders saved sessions.** The CLI now renders a saved tool session as a course source, page by page for paged documents (up to 200 pages). Sessions it cannot reproduce stop before any render with a reason. **Behaviour change:** source failures used to exit 1 and now keep their own exit code (2 or 3), and a build that needs a rights decision prints `ok: false` where it printed `ok: true` while exiting 4.
- **Design underlines from the CLI.** The CLI exports static Design frames with underlined words to SVG, SVGZ and PDF without the browser tier.
- **Core 1.5.0.** `@lolly-tools/core` 1.5.0 adds the `ExportReport` vocabulary, `TOKEN_AXIS_KINDS`, read-extract types and, in `canvas-interaction-v1`, transform claims that list fields and a `'scale'` preview kind. `CANVAS_INTERACTION_VERSION` stays 1.
- **Engine additions.** `revealDeckFrame(src)` reports whether a frame link asks a reveal.js deck for position reports. `penpotSvgLayoutFindings` reports flex and grid layouts declared in a legacy Penpot zip export's page SVGs, which import at their exported positions without layout rules. The engine imports Tokens Studio files that write `value`, `type` and `description` without `$`, with a warning, and so does `pnpm run ingest:brand`.
- **`host.fonts` (optional).** `inspect(bytes)` reads a TTF, OTF or WOFF file's names, outline format, weights, axes, named instances, coverage per Unicode block and decoded `OS/2.fsType`. `subset(bytes, { text })` refuses non-TrueType outlines and restrictive or missing embedding flags before any work, and re-reads the output before returning the subset. The web, desktop, CLI, TUI and MCP hosts attach the API, and `requires: ["fonts"]` is accepted in a manifest.
- **`host.pdf.fromImages` and organize effects.** `fromImages(images, { pageSize, margin })` puts one PNG or JPEG on each page. `host.pdf.organize` results gain an optional `effects` list for bookmarks, annotations, links, forms and signatures, each with a count and an outcome of `kept`, `removed`, `broken` or `invalidated`.
- **`host.media.trim` options and report.** Optional `output`, `image`, `sheetFrames`, `rotate`, `cut`, `maxShortEdge` and `targetBytes`, and a `report` with each track's outcome and the checks made on the written bytes. Only the web and desktop hosts implement `media.trim`, so Trim does not run in the terminal.
- **`lolly run --export-report=<path|->`.** After the last byte operation, the CLI compares what the run asked for with what the file holds and writes a JSON `ExportReport` bound to the output's SHA-256. Only explicit flags count as a request. Each difference prints a warning, so `--strict` exits 4. The engine exports `inspectOutput`, `verifyExport` and `exportRequestFromJob`.
- **`lolly read --extract` and `--ocr`.** `--extract` writes blocks in reading order with `--pages`, `--max-chars`, `--from` and `--markdown`; with `--json` the result is a `ReadExtractV1`. `--ocr` reads scanned pages with the local text recognition model and never downloads it; `lolly models fetch ocr` fetches the model.
- **Inventories change for scans.** `lolly read` and MCP `lolly_read` now list a searchable scan's own text layer as one hidden frame, so `lolly check --source` on such a scan compares those words too. Text read by recognition carries a `recognition` record, and inventories warn when a file carries macros, scripts or embedded files.
- **Data conversion choices.** `lolly files convert` takes `--sheet`, `--all-sheets` (needs a `.zip` output), `--cells=cached|formulas`, `--delimiter`, `--encoding` and `--header`, and MCP `files_convert` reads the same choices from `request.options`.
- **`.lolly` portability part.** `portability.json`, `manifest.portability`, `summary.portability` and `holdKind` on held-back asset rows are additive, and `minReader` does not change. A reader builds the same report for an older file from its manifest.

## Known limits

- **English-only strings.** Many new strings show in English in every language: the colourway and design-system record strings, Source history, the 3D Studio and Darkroom History notices, the reveal.js deck messages, the shared Assets screens, the asset inspector and Sources rail, Batch selection and copy, the new upload and drop labels, the new History grid labels and Start wording, the course export screens, the Trim, Pages, Read and extract and Convert Font controls, Convert's data choices and the export check notes. Trim's translated gallery descriptions still describe Trim 1.0. The upload area's **Choose files** button was translated, so touch users now see English where they saw their own language. The /brand page and the new Brand architectures and token workflows guides are in English only, and the translated copies of the exporting, collaboration and saved-work guides do not have the new sections yet.
- **Colourways are read, not authored.** Brand Studio edits only the canonical colourway and cannot add, rename or remove colourways. The blank starter has no colourways, so on a self-hosted instance colourways come only from an imported token file. No batch or series flow applies a colourway rotation rule yet.
- **Touch gestures.** Two-finger transforms and grab zones were tested with synthetic touch in a desktop browser, not on a physical tablet or phone.
- **Not yet in use.** Per-record device sync is built but the app still syncs device data as one snapshot.
- **Where source credits do not travel yet.** The catalog's Download original, bulk ZIP, Send, Copy image, Projects ZIP, backups, Rebrand, course packages and the terminal export deliver bytes without evaluating or carrying source credits.
- **App only.** Trim, Read and extract (the CLI has `lolly read --extract`), SVG fitted to its artwork, the font collection viewer and the GPU photo looks run in the app only.
- **xAPI recovery** lives in one browser profile: private browsing or clearing site data removes the record. Packages built before this release do not have recovery.
