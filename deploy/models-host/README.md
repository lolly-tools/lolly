# lolly-models - the on-device model host

A static Vercel project serving ONLY `/models/**` (the ~1.2 GB of ONNX model
files). The app deploys (bt -> lolly.tools, lolly-start -> lolly.art) exclude
`shells/web/public/models` from their upload (.vercelignore) and rewrite
`/models/:path*` here (vercel.json `rewrites`), so:

- every app ship stops re-uploading ~1.2 GB of unchanged model bytes;
- clients (web, the desktop shells fetching https://lolly.tools/models/...)
  keep their SAME-ORIGIN model URLs - the platform edge proxies, so no CSP,
  CORS, service-worker or speech-privacy-pin change was needed;
- the host is still just a URL: a future internal host (RKE2/MinIO/S3) takes
  over by changing the rewrite destination, nothing else.

The offline "Available offline" manager reads model URLs + sizes from
`precache.json`, which is scanned from the built dist. Because the app build no
longer has the model files on disk, the committed listing
`shells/web/models-manifest.json` (regenerated by
`node scripts/gen-models-manifest.ts` whenever a model is promoted) fills in the
`/models/**` entries at build time. Regenerate it AND redeploy this project in
the same change whenever a model file is added, replaced, or retired.

## Deploying (rare - only when the model set changes)

    node scripts/gen-models-manifest.ts        # refresh the committed listing
    bash deploy/models-host/deploy.sh          # hardlink-assemble + deploy

`models/` here is gitignored (it is a hardlink assembly of
shells/web/public/models, minus the .candidates staging dirs).
