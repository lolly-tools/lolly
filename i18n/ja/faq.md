# よくあるご質問

`/info` のランディングページのアコーディオンに表示される、よくあるご質問です。

**メンテナンス方法:** 以下の `##` 見出しがそれぞれ質問であり、その下（次の `##` まで）が回答です。
回答はサイトの他の部分と同じ軽量マークダウンを使います。段落は空行で区切ってください。
ここで質問を追加・削除・並べ替えたうえで、`npm run build:info`（または `npm run dev:web`）を
再実行してください。最初の `##` より上（このタイトルとこの注記）はビルドでは無視されます。

## /profile ページでオプトインすると何が起こりますか？

Lolly を初めて使うとき、どこに入力した内容もすべて完全に非公開です。あなたが意図してその情報をメディアや共有リンク（オンラインの場合）で外に出すまで、その状態が保たれます。

オプトインを選択すると、あなたが選んだプロフィール情報が制作物の中に封入され、出所としてあなたの名前が示されます。あなたが選ばない限り、何も含まれません。

Lolly は大量のコンテンツを生成します。リスクを防ぐため、私たちは厳格なデータ最小化の方針をとっています。

## Lollyは「バイブコーディング」で作られたのですか?

Lollyは、パブリッククラウドのフロンティア企業によるものを含む多様なモデルとベンダーを用いて、AI支援によるコーディング、AI支援による調査、そして多くの部分でAI支援によるコンテンツ制作を通じて開発されました。

本稿執筆時点で、Lollyのサプライチェーンには既知のセキュリティ脆弱性は一つも存在せず、CVEが確認された場合には迅速なセキュリティ対応を行うことをお約束します。

アーキテクチャは人間が設計し、コードは意図を持って丁寧に選定され、体験は人間がアートディレクションを行いました。

何よりも重要なのは、Lollyが世界中の真の専門家たちによる数十年にわたるオープンソースの技術革新を土台として築かれているということです。

Lollyのコードベースには、コードとドキュメントを一般的な読者にとって一貫性のあるものに保ち、体験を「脱スロップ化」するための決定論的なビルドゲートが存在します。これにより、出所を専有的・合成的に列挙することが困難になる可能性がありますが、それは意図したものではありません。

## モバイル版やデスクトップ版のアプリはどうすれば入手できますか？

誰でも自分のアプリを配布できます。そうしたアプリのツールや設定は、想定する利用者によって大きく異なるはずです。したがって、唯一のアプリというものは存在せず、あなた自身が作るか、関係のある誰かから渡されるかのいずれかです。

## なぜ「Lolly Tools」という名前なのですか？

**Lolly** は、自由が甘いものだからであり、またオーストラリア、ニュージーランド、イギリスでは lolly がお菓子を意味するからです。

**Tools** は、道具というものが、手に取られるまでじっと動かないからです。使っていないときに動くことはなく、使っている間にあなたを見張ることもありません。

## Lolly を導入する際に、どのようなハードルが想定されますか？

Lolly は、すでにファイルを生成しているあらゆる場所に組み込めます。CLI はアプリと同じエンジンなので、
深夜 2 時に走るパイプラインの出力が、人がブラウザーでプレビューした内容からずれることはありません。
導入の摩擦が技術的なものであることはまれで、多くは組織的なものです。次の点を想定してください。

**厳選されたブランドカタログを作成する必要があります。** Lolly はプラットフォームであり、
あなたのテンプレートが揃った完成品のパックではありません。*統制された展開*では、誰かが共有アセット
カタログ（恒久 ID としてのロゴ、パレット、フォント）を定義し、出力タイプごとにマニフェストと
テンプレートを書きます。ただし個人はそれを待つ必要はありません。オープンなアプリでは、誰でも
自分のファイルをカタログに取り込み、初日から Design でツールを作れます。

**貢献に git は必要ありません。** デザイナーはアプリの中で自分のツールやテンプレートを作り、
それを仲間と共有したり、既定で組み込んでもらうためにデプロイの所有者へ提出したりします。

**あえて範囲を絞っています。そのように位置づけてください。** Lolly は、一点物やヒーロー
コンテンツのためのものではありません。Lolly は*まさに*あなた個人の DAM であり、あなたのデザイン
システム、ツール、カタログによって内容を満たされ、強化されます。オープンキャンバス（Design）も
*確かに*備えていますが、そこでも色、書体、アセットは有効なデザイングローバルに従うため、自由な
配置もシステムの内側に収まります。Figma や Canva と比べれば、限定的に見えるでしょう。しかし
本来の姿、すなわち運用化された、反復的で大規模なアセット生成として評価すれば、競合するものは
ありません。位置づけの誤りが、最もよくあるつまずきです。

**制作する側の変更管理。** 既存のプロセスは、出力がブランドから外れていたとしても、今日それで
動いています。それをエンジンに向け直すことは再テストと再学習を意味し、「すでにファイルは作れている」が
移行しない口実になります。まずは、人目に触れる本番品質の出力を 1 つ置き換え、変更前と変更後を
並べて見せることから始めてください。

Lolly は、そのすべてを底上げします。


## ユーティリティはツールとどう違うのですか？

**簡単な答え →** ユーティリティは必ずしもレンダリングを必要とせず、そのため異なる UX を持てます。 

**本当の答え →** ユーティリティを Lolly Tools の中でホストできるようにしている理由は、データの持ち出しを思いとどまらせるための「利便性という防御層」をもう一段重ねるためです。 

なぜでしょうか。毎日のように、人々が**手元にある機密のコンテンツ**を、ささいな機械的処理を 1 つ行うためだけに、見ず知らずのウェブサイトへ渡していることが分かっているからです。

- 「**この PDF を圧縮**」 → 契約書や給与明細、取締役会資料を、素性の分からない相手にアップロードする。
- 「**HEIC を JPG に変換**」 → 個人の写真を、GPS の EXIF ごと広告収入で運営されるホストにアップロードする
- 「**この画像を切り抜く／サイズを変える**」 → 製品のスクリーンショットや未公開のアセットをアップロードする
- 「**この JSON を整形**」／「JWT をデコード」 → API のレスポンスやトークン、シークレットを整形ツールに貼り付ける
- 「**これらの PDF を結合**」 → **同じサーバーに決して同居させてはならない 2 つの文書**をアップロードする

これらのサイトと、その膨大な模倣サイト群は、**既定では信頼できません**。保持期間も、
管轄地域も、再委託先も不明で、渡されたものを手元に残すことに十分な動機がある広告・アフィリエイト型の
ビジネスモデルで運営されています。処理そのものはささいなものですが、**代償はコンテンツそのものです。** 

私たちは、卓越した利便性とサービスによって、ガバナンスをめぐる戦いに勝ちます。

## Lolly は Figma、Penpot、Illustrator、InDesign のファイルを編集してレンダリングできますか？

はい。**Design** を開いて **Import a design**（デザインの読み込み）をクリックしてください。Figma のネイティブ形式 **.fig**（Save local copy）、Penpot の **.penpot** エクスポート、Illustrator の **.ai** または **.pdf**、InDesign の **.idml**（File → Export → InDesign Markup）、そして **あらゆる SVG**（間口の広い入口で、ほとんどのデザインアプリが書き出せます）に対応します。アカウントもプラグインも、デザインアプリのライセンスも必要ありません。

レイヤーは、オープンキャンバス上に編集できるボックスとして読み込まれます。テキストは入力し直せるままで、シェイプはシェイプのまま、画像はあなた自身の画像ライブラリーに加わり、書体と色はブランドのグローバル設定に従います。保存すれば、そのレイアウトは Lolly を持つ誰もが中身を入れ替えられる、URL で指定できる再利用可能なテンプレートになります。読み込み時に再レンダリングされるライブツール（QR コード、チャートなど）を混ぜ込むこともできます。あとは Lolly の他のものと同じようにレンダリングされ、SVG、PDF、PNG などを、その URL から再現できます。[デザインの読み込み](/info/design-import.html)を参照してください。

## 作品をリンクではなくファイルとして共有できますか？

はい。リンクではすべてを運びきれないとき（自分の写真や長い文章など）、共有ダイアログは何が失われるかを正確に示し、代わりに **.lolly** ファイルを提示します。これは、デザインと、そこで使う画像と、選べばツール自体までを収めた 1 つのファイルです。どこまで持ち出すかを決めるのはあなたです。あなたの名前や詳細はプロフィールでオプトインした場合にのみ入り、ライセンスされたアートは自分で含めない限り除かれ、ツールを含むファイルを開いた人は、実行前にそれを信頼するかどうかを尋ねられます。[作品を共有する](/info/using.html#sharing-your-work)を参照してください。

## インターネットなしで、2 人が同じデザインを一緒に作業できますか？

はい。一方が招待（リンク、QR コード、または短いコード）を共有し、もう一方がそれを受け入れると、両方の端末が同じセッションをそのまま共有します。参加状況もフォーカスリングもすべて同期します。間にサーバーがないため、地下室でのスマートフォンのテザリングを含め、共有されたネットワークであればどこでも動作します。[一緒に作業する](/info/collaborate.html)を参照してください。

## SUSE ブランドのツールはどこへ行ったのですか？

すでに別のプライベートリポジトリーに置かれています。公開クローンは SUSE のブランドパックをまったく取得しないため、公開ビルドは中立の `lolly-start` プロファイルで動作します。これは、ブランドに依存しないコミュニティーツールと、あなた自身の内容で埋めていく空のブランドから成ります。SUSE は自社の商標を保護するために、独自のインスタンスを運用しています。

## なぜ無料なのですか？何か裏があるのでは？

**私たちは Lolly を自分たちのために作りました。** SUSE には、ブランドに沿った数千のファイルが必要でした。そのそれぞれに自社の名前が封じ込められ、しかも外部のサービスに何も渡さずに作られる必要がありました。そこで私たちは、そのすべてを端末上で行うツールを作り、私たちが作る他のものと同じようにオープンソースとして公開しました。毎日使っているからこそ、保守を続けています。**義務は一切ありません。** ここにあるものはすべて、私たちがいてもいなくても動きます。

この線引きは、約束ではなくライセンスによって引かれています。ローカルで動くものはすべて、永久に無料です。公開されたバージョンは取り消せないようにライセンスされており、誰かの成果物を再ライセンスしうる貢献者同意書も存在しません。全文は[ポジショニング](/info/positioning.html)を参照してください。

## SUSE はどこまでを非公開にしているのですか？（つまり、いつ梯子を外されるのか）

エンジン、シェル、スキーマ、そしてブランドに依存しないツールはオープンソースです。非公開のままなのは SUSE の商標とブランド付きツールの部分であり、それらはすでに分離されています。[lolly.tools](https://lolly.tools) にある公開インスタンスは、空のブランドで動作しています。

この境界は、約束ではなく構造として定まっています。公開された各バージョンはオープンソースであり、公開を取り消すことはできません。誰かの成果物を再ライセンスしうる貢献者同意書も存在せず、留保されているのは商標だけです。2023 年に別の企業がエンタープライズ Linux のソースを非公開にしたとき、SUSE はそのコードをオープンに保つために [OpenELA](https://openela.org) を共同設立しました。本プロジェクトは、その姿勢をそのまま受け継いでいます。

包み隠さず述べると、SUSE は自社の IT システムに Lolly を統合するための社内ツールを*実際に*整備しています。これは SUSE の社内構成の話であり、公開開発か非公開開発かという話ではありません。Lolly はまた、[Open Build Service](https://openbuildservice.org/) を通じてビルドされることを目指しており、安全なサプライチェーンの成果物は [SUSE Application Collection](https://apps.rancher.io/applications) から提供されます。
