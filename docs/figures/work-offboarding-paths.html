Where should your assets live next?

Start with open-source services you can run. Choose a path to see the steps and what carries across.

01Self-host Lolly Work RecommendedA governed library, with a supported cutover for old links

Run Lolly Work and PostgreSQL on infrastructure you control. Keep smaller libraries in PostgreSQL, or use your own Ceph, MinIO or other S3-compatible store for the files.

  1. Set up the instance, storage and a tested restore.
  2. Materialize permitted originals and check every required file.
  3. Cut over supported sources after acceptance; Lolly Work creates aliases for copied assets.

Source limits still apply. Orange Logic cannot cut over; CMP remains a connected source.

02Nextcloud / WebDAVA shared file library on a server your organisation runs

Keep the files in Nextcloud or another WebDAV server and connect that folder to Lolly Work as a read-only source.

  1. Export permitted originals and metadata from the DAM.
  2. Copy the files using your server's upload or file tools.
  3. Verify the copy, then connect and test Lolly Work access.

This is a separate export and copy. Lolly Work's materialize command does not write to a WebDAV source or create aliases to its new file identities.

03Git on your own forgeA curated catalog of files reviewed and versioned together

Use a self-hosted forge such as Gitea for a small, curated catalog with a manifest. Lolly Work reads the files from its raw-content endpoint.

  1. Export and review the files you can keep.
  2. Commit the files and a catalog manifest to your repository.
  3. Connect the Git source and verify every listed file.

Lolly Work does not push a DAM library into Git. Plan file sizes, metadata and replacement links separately.

Already have a hosted drive?

+Google Drive, OneDrive or DropboxAn optional export-and-upload route using a vendor-operated service

Export the DAM files, upload them with the drive's own tools, then connect the destination to Lolly Work. These connectors read files; Lolly Work has no direct migration writer for these drives.

  • Google DriveOne flat folder; native Google documents are skipped
  • OneDrive / SharePointOne folder level; no recursive listing
  • DropboxRecursive listing, including subfolders

Set access rules again and plan new references. A drive upload does not carry DAM history, approval workflows or old-address aliases.

For every path: keep required rights and history records, compare original files, and test access before retiring the DAM.
