# Lollyの仕組み

Lollyのツールには、ある種類のファイルのルールが収められています。レイアウト、書体、色、そして他の人が変更してよい部分です。お客様、同僚、スクリプト、AIエージェントがフィールドを入力すれば、どのファイルも正しく仕上がります。このページでは、誰が何をするかと、ツールから完成ファイルまでの4つのルートを示します。

## 1つのツール、あなたのルール、たくさんのファイル

ブランドのルールは、作るファイルごとではなく、ツールの中にあります。ツールを一度きちんと作れば、1枚のカードでも、十数言語の行が並ぶスプレッドシートでも、すべての出力が同じ書体、色、余白を引き継ぎます。

![入力欄が1つ埋まったワードマークツール: 書体、色、余白はツールを作った時点で決まっている](/info/shots/aud-rules-in-the-tool.svg)

100個目のファイルを作る人は、言葉を入力するだけです。作業をどう確認するか、誰が確認するかは、あなたが決めることです。Lollyは、確認する価値のあるものを小さくし、次のファイルをより速く作れるようにします。

## ツールに触れるのは誰か

組織の中で1枚のキャンペーンカードをたどると、3組の手が現れます。それぞれが前の人の仕事の上に積み重なります。

![デザイナーがツールにルールを一度設定し、開発者がスクリプトから実行し、誰でもフィールドを入力でき、どちらも完成ファイルを作る](/info/diagrams/concepts/asset-relay.svg)

::: timeline
- <!--i:pentool--> **デザイナーがルールを設定する。** Designでブランドの書体と色を使ってカードをレイアウトし、どのフィールドを開けておくかを選びます。これを一度行えば、カードを手作業でローカライズし直す人はいなくなります。
- <!--i:code--> **開発者がツールを拡張する。** 同じツールが、コマンドライン経由で夜間スクリプトの中で動作するため、デザインを開き直さなくても、新しいグラフや新しい言語版が届きます。
- <!--i:people--> **誰でも入力できる。** 機内でネットワークもなく、デザインの訓練も受けていない営業担当が、ツールを開いて明日の打ち合わせ用のカードを作ります。
:::

開発者の手順に出てきた新しいグラフは、このようなレンダリングです。データの文字列といくつかの設定から作られ、デザインファイルを開く人はいません。

![タイトル付きの積み上げ面グラフ。3つの系列が寒色系のパレットで帯状に塗り分けられ、軸、凡例、タイトルはすべて手作業ではなくテンプレートが配置している](/t/url-shot?url=%2F%23%2Ftool%2Fchart%3FchartType%3Darea%26stackMode%3Dstacked%26palette%3Dcool%26heading%3DProduct%2520mix%2520by%2520quarter%26full&width=1440&height=900&dpi=192&waitMs=2600&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-lifecycle-chart)

営業担当の気軽な1分が成り立つのは、デザイナーの配慮と開発者のスクリプトがあるからです。どの役割も、別々の製品ではなく、同じ1つのツールで作業します。

## ファイルまでの4つのルート

どのルートも、同じツールに対して同じエンジンを実行するため、スクリプトで作るファイルは、アプリでプレビューしたものと一致します。

![URLパラメーターとコマンドライン引数は同じ入力モデルになり、共通のランタイムと書き出しブリッジを通って実行される](/info/diagrams/concepts/one-render-path.svg)

- <!--i:people--> **アプリで1つずつ。** ツールを開き、フィールドを入力して**Export**を押します。[最初のファイルを作る](/info/make-something.html)で1つ作ってみましょう。
- <!--i:layers--> **アプリでまとめて。** [Batch](/info/batch.html#make-many-versions-of-one-design)(`#/batch`)は、貼り付けまたはインポートした表を受け取り、1行につき完成ファイルを1つレンダリングします。
- <!--i:cpu--> **スクリプトまたはAIエージェントから。** [CLI](/info/cli.html)はツールをヘッドレスで実行し、[MCPサーバー](/info/mcp.html)ではエージェントがツールを見つけて実行できます。ツールへのリンクにも入力値が含まれるため、リンクは完全なリクエストです。
- <!--i:server--> **組織のサーバー経由で。** [Lolly Work](/info/organisation.html)は、組織のサインインとツールのポリシーのもとでサーバー上でレンダリングし、再開可能なジョブを保持し、出力をダウンロードまたは承認済みの配信のために保管します。

ジョブがどのルートを使えるかは、ツールの形式とホストにできることによって決まります。ブラウザが必要な形式もあり、その場合コマンドラインはそれをブラウザ層に引き渡します。どの形式がどこでレンダリングされるかは、[CLIでレンダリングする](/info/cli-rendering.html)に一覧があります。

## どこで何が動くか

作成、編集、書き出しは、アカウントなしでお使いのデバイス上で動作します。同期や接続したサービスへのファイル送信のようにサーバーを必要とする機能は、その機能を使うときにだけ接続します。Lolly Workでは、共有プロジェクト、ライブのチーム編集、承認、サーバージョブは組織のサーバーを使います。この2つの比較は、[どこで何が動くか](/info/compare.html#what-runs-where)にあります。
