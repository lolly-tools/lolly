# Lollyの仕組み

Lollyのツールには、1種類のファイルに対するルールが含まれます。レイアウト、書体、色、他の人が変更できる部分です。あなたや同僚、スクリプト、AIエージェントがフィールドに入力すると、すべてのファイルがそのルールに従います。

<!--i:eti-repeat-->
## 1つのツール、決めたルール、多くのファイル

ブランドのルールはツールに組み込まれています。一度ツールを設定すると、カード1枚から12言語にわたるスプレッドシートの行まで、すべての出力に同じ書体、色、間隔が適用されます。

![フィールドが1つ入力されたワードマークツール。書体、色、間隔はツールの制作時に決まっている](/info/shots/aud-rules-in-the-tool.svg)

100個目のファイルを作る人も、文字を入力するだけです。作品をどのように確認し、誰が確認するかは、あなたが決めます。Lollyは確認する箇所を減らし、次のファイルをより速く作れるようにします。

## ツールに関わる人

組織内の3つの役割が、1枚のキャンペーンカードに関わります。

![デザイナーがツールにルールを一度設定すると、開発者はスクリプトから実行でき、誰でもフィールドに入力できる。どちらも完成したファイルを作れる](/info/diagrams/concepts/asset-relay.svg)

::: timeline
- <!--i:pentool--> **デザイナーがルールを設定します。** ブランドの書体と色を使ってLolly Designでカードをレイアウトし、入力可能にするフィールドを選びます。一度行えば、以後カードを手作業でローカライズする必要はありません。
- <!--i:code--> **開発者がツールを大量処理に使います。** 同じツールを、コマンドライン経由で毎晩スクリプトから実行します。誰もデザインを開き直さずに、最新のグラフや新しい言語版ができあがります。
- <!--i:people--> **誰でも入力できます。** ネットワークのない飛行機の中でも、デザインの訓練を受けていない営業担当者がツールを開き、明日の会議用のカードを作れます。
:::

開発者が作る最新のグラフは、このようなレンダリング結果です。データ文字列といくつかの設定から作られます。

![タイトル付きの積み上げ面グラフ。3つの系列を寒色の帯で表示し、軸、凡例、タイトルはすべて手作業ではなくテンプレートが配置している](/t/url-shot?url=%2F%23%2Ftool%2Fchart%3FchartType%3Darea%26stackMode%3Dstacked%26palette%3Dcool%26heading%3DProduct%2520mix%2520by%2520quarter%26full&width=1440&height=900&dpi=192&waitMs=2600&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-lifecycle-chart)

営業担当者が短時間で作れるのは、デザイナーのルールと開発者のスクリプトがあるからです。すべての役割が同じツールを使います。

## ファイルを作る4つの経路

どの経路も、同じツールを同じエンジンで実行します。そのため、スクリプトが作るファイルは、アプリでプレビューするものと一致します。

![URLパラメーターとコマンドライン引数は同じ入力モデルになり、共通のランタイムと書き出しブリッジを通る](/info/diagrams/concepts/one-render-path.svg)

- <!--i:people--> **アプリで1つずつ。** ツールを開き、フィールドに入力して**Export**を押します。[初めてのファイルを作る](/info/make-something.html)で、1つ作る手順を説明しています。
- <!--i:layers--> **アプリで一度に多数。** [Lolly Batch](/info/batch.html#make-many-versions-of-one-design) (`#/batch`)は、貼り付けた表やインポートした表から、1行につき1つの完成したファイルをレンダリングします。
- <!--i:cpu--> **スクリプトやAIエージェントから。** [CLI](/info/cli.html)はツールをヘッドレスで実行し、[MCPサーバー](/info/mcp.html)はエージェントによるツールの検出と実行を可能にします。ツールへのリンクには入力も含まれるため、リンクだけでリクエストが成立します。
- <!--i:server--> **組織のサーバー経由で。** [Lolly Work](/info/organisation.html)は、組織のサインインとツールのポリシーに従ってサーバー上でレンダリングし、再開可能なジョブを保持して、ダウンロードや承認済みの配信用に出力を保管します。

ジョブで使える経路は、ツールの形式とホストの機能によって決まります。ブラウザが必要な形式は、コマンドラインからブラウザ層に引き渡されます。各形式をどこでレンダリングするかは、[CLIでレンダリングする](/info/cli-rendering.html)に一覧があります。

## どこで何が動くか

制作、編集、書き出しは、アカウントなしでお使いのデバイス上で動作します。同期や接続したサービスへのファイル送信など、サーバーが必要な機能は、その機能を使うときだけ接続します。Lolly Workでは、共有プロジェクト、チームのライブ編集、承認、サーバージョブに組織のサーバーを使います。[どこで何が動くか](/info/compare.html#what-runs-where)で、この2つの部分を並べて説明しています。
