# Lolly とレンダリング API

_最終確認日: 2026年9月28日。_

現在、APIでテンプレートから画像を生成している場合、このページは、Lollyが同じ作業を、ご自身のデバイス、CI、ご自身のサーバーでどう行うかを示します。

## ホスト型レンダリングAPIがより優れている点

[Bannerbear](https://www.bannerbear.com/)と[Placid](https://placid.app/)は、独自のインフラ、連携、サポートを備えたマネージドサービスとして、レンダリングを提供します。リクエストを送れば、サーバーは他の誰かが運用します。

## 重なる部分

どちらも、テンプレートと入力をメディアに変えます。Lollyは、入力を[リンク](/info/url-mode.html)、[CLI](/info/cli.html)、バッチグリッド、サーバーのエンドポイントから受け取ります。

## 重なる作業をLollyがどう行うか

同じツールが、同じ入力から、ノートパソコン、CIジョブ、サーバーでレンダリングします。ローカルとCIでのレンダリングには、サービスは一切不要です。

![Batchの書き出し設定: ファイル名、既定の形式、単位、DPI、レンダリングする行数](/info/shots/use-batch-toolbar.svg)

サーバーでは、[Lolly Work](/info/compare.html#what-runs-where)がAPIの背後でLollyのエンジンを実行し、ツールの表示と入力のポリシーを適用します。その[復旧可能なレンダリングサービス](/info/work-renders.html)は、単一のジョブとバッチ、冪等な送信、ステータス、上限付きの再試行、キャンセル、保持される出力に対応し、永続ストレージが設定されていれば、中断された作業は再起動後に再開します。

サーバーには、高速なSVGとPNGの経路と、ブラウザを必要とするツール向けの任意のChromiumワーカーがあります。自動化はサービストークンでサインインし、完成した出力は[承認済みの配信](/info/work-delivery.html)を通して組織の送信先に届けられ、設定された署名アイデンティティが、対応する出力にContent Credentialsを追加します。

## サービスを運用するのは誰か

Lollyでは、個人がローカルでレンダリングするか、チームが自らのインフラでLolly Workを運用します。サーバージョブを送信すると、その入力と必要なアセットがそのインスタンスに送られ、これはデバイス上の経路とは異なります。耐久性のあるサービスには、永続的なデータベースと出力ストレージが必要で、ブラウザに依存するツールにはChromiumワーカーが必要です。どちらも[Lolly Workをインストールする](/info/work-install.html)で説明しています。

BannerbearとPlacidは、それぞれの所有者の商標です。このページは製品が重なる部分を説明するもので、どちらとも提携していません。
