# Lolly とレンダリング API

_最終確認日: 2026年9月28日。_

Lolly は、テンプレートとデータからアセットを、お使いのデバイス上、CI、または [lolly.work](https://lolly.work) のサーバー API を介して生成します。統合ソリューションは、自動レンダリングに加えて、組織の制作ジョブを取り巻く ID、ポリシー、配信もカバーします。

## 重なる部分

[Bannerbear](https://www.bannerbear.com/) と [Placid](https://placid.app/) は、API と連携機能を通じて、テンプレートから画像やその他のメディアを生成します。Lolly も、テンプレートと入力を組み合わせる同じ方式を採り、作業を送信する手段として [URL モード](/info/url-mode.html)、[CLI](/info/cli.html)、バッチグリッド、サーバーエンドポイントを備えています。

## lolly.work が提供するもの

lolly.work は、Lolly プロジェクト内の別個にデプロイされる組織向けサービスです。API の背後で Lolly エンジンを実行し、ツールの可視性と入力ポリシーを適用し、レンダリングされたファイルと署名付き共有リンクを提供します。その[復旧可能なレンダリングサービス](https://github.com/lolly-tools/lolly-work/blob/main/docs/renders.md)は、個別のジョブとバッチ、冪等な送信、ステータス、上限付きのリトライ、キャンセル、保持された出力に対応します。永続ストレージが設定されていれば、中断された作業はサーバーの再起動後に再開できます。

サーバーは、高速な SVG/PNG レンダリング経路と、ブラウザを必要とするツール向けのオプションの Chromium ワーカーを使用します。自動化はサービストークンで認証し、完了した出力は[ガバナンス付き配信](https://github.com/lolly-tools/lolly-work/blob/main/docs/delivery.md)を通じて組織の配信先に送信できます。署名 ID を設定すると、対応するサーバー出力で C2PA 署名が有効になります。

## サービスを運用するのは誰か

Bannerbear と Placid は、レンダリングを、独自のインフラストラクチャと連携機能を備えたマネージドサービスとして提供しています。Lolly では、個人がローカルでレンダリングすることも、チームが自らのインフラストラクチャで lolly.work を運用することもできます。Lolly のどちらのリポジトリも MPL-2.0 のオープンソースです。セルフホストにはレンダリング単位のソフトウェアライセンス料はかかりませんが、コンピュート、ストレージ、運用は計画すべき費用として残ります。

公開されている lolly.work サイトは評価用のサンドボックスであり、本番ホスティングを約束するものではありません。継続的なサービスには、永続的なデータベースと出力ストレージが必要です。ブラウザに依存するツールには Chromium ワーカーが必要です。これらの要件と現在の制約は、[インストールガイド](https://github.com/lolly-tools/lolly-work/blob/main/docs/install.md)と[ステータスページ](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md)に記載されています。

ローカルでのレンダリングと CI でのレンダリングは、組織向けサービスなしでも引き続き利用できます。サーバージョブを送信すると、その入力と必要なアセットがそのインスタンスに送信されます。これはデバイス上の経路とは別のものです。[統合ソリューションの概要](/info/compare.html)を参照してください。

Bannerbear と Placid はそれぞれの所有者の商標です。このページはソリューションが重なる部分を説明するものであり、いずれとも提携していません。
