# Lollyの比較

今日のクリエイティブツールがしていないことでLollyが行っていること、そしてLollyが意図的にそれらのツールに委ねていること。

ツールごとの詳細比較（Canva、Adobe、Figma、レンダリングAPI、オンラインコンバーターについてそれぞれ1ページ）は、[Lolly compared, tool by tool](/info/compare.html)を参照してください。各ページには、他のツールが優れている点とLollyが代わりに行っていることが記載されています。

> **パイロット状況：** Lollyはクローズドパイロットのプロトタイプであり、完成した製品ではなく、そのセキュリティは現在、エンタープライズ規模に備えたSUSEの厳格なインフラ強化を受けている最中です。[Adoption & Governance](/info/adoption-governance.html#status)ページで現状を扱っています。

## 今日のツール

以下の各リングは、ある製品クラスが**現時点で出荷されている状態として**（宣伝上ではなく）ある機能をどれだけ完全に提供しているかを採点したもので、各クラスはその最良の代表例で採点されています。Lollyも同じ物差しで採点されており、成熟度の1点だけで盤面唯一の赤いリングを取っています。行名を開くと、その採点の根拠がわかります。列は上部のOverall completeness行（採点対象行の平均、spend行は除く）でソートされています。

**採点上の注記。** Lollyの採点は、その公表している主張が成り立つことを前提としています。だからこそ成熟度がLollyの唯一の赤いリングなのです。クローズドパイロット、進行中のセキュリティ強化、まだ何も監査されていません。Researchはいくつかのセルを動かしました。

Canvaは行ごとに最良のファミリーメンバーで採点されています。Affinity（2025年10月に無償提供開始）とCavalryの両方を所有しているためです。オフラインおよびオンデバイスレンダリングはAffinity経由で75点です - デスクトップスイートですが、検証済みアカウントが依然必要でテレメトリを含みます。これはAdobeも同様に減点される理由です。一方、Canva自体のオフラインモードは事前同期済みのデザインのみを、単一デバイスで、限られた期間だけ編集できます。Autofillは50点です。実在はしますがEnterprise限定で、非同期、テキストと画像のみです。FigmaのMass generationはBuzzがスプレッドシート入力機能を出荷したこと（無料ベータ、2026年8月）で25点から50点に上昇しました。

盤面を支配するルールは一つです。あなたのコンテンツやアイデンティティに関わる行でのFull（100点）は、アカウント不要かつクラウド前提条件なしで使える機能が必要です。製品自体を説明する行（成熟度、使いやすさ）はこの対象外です。これはprovenanceでAdobeにコストを負わせます。出荷済みのC2PAとして最も広範なもの（Photoshop、Lightroom、Premiere、Firefly）はローカルとクラウドの両方で署名しますが、Adobeアカウントとアイデンティティなしには決して署名できないため、75点です。同じ理由でrender APIsのmass generationとautomationも頭打ちになっています。

Lollyのprovenance 75点は、オンデバイスかつオフラインの署名を反映しています。アーキテクチャとしてはより堅牢ですが未監査であり、アイデンティティまたは組織自身のCAが保証しない限り、デバイスキーは標準のバリデータでは未検証として扱われます。Penpotの50点は、公式のLolly Exportプラグインを通じて得られています。同じエンジンによる署名で、オプトインであり、Lolly自身のものとして開示されています。Penpotはまた、盤面唯一のスケール外リング、オンデバイスレンダリングで90点も獲得しています - ブラウザキャンバス、自分自身のソブリンなクラウド（ラップトップですら）への保存、非公開のエクスポート。サーバーへのホップだけがLollyとの違いです。Cloudinaryは独自の列を持ちます。メディアパイプライン（DAM、変換API、CDN）であり、C2PAを出荷している唯一のクラウド列です（50点。fl_c2paは配信時に署名し、あなたが作成したことではなくCloudinaryが配信したことを証明するためです）。

Live collaborationは逆方向に振れます。Figmaがスケールのベンチマーク（200人の編集者）を設定し、LollyのペアワイズでエアギャップされたピアツーピアはPartialです。Priceは推測であり、そう明記されています。実勢のシート構成に対するリスト価格の算術であり、意図的に幅を持たせています。調達のためではなくスケール比較のためです。Render APIsはconstraintsで75点です。テンプレートは固定されており、ブランドガバナンス層がありません。

ギャップはここです。今日出荷されているもので、constraints-firstかつオフラインで、アカウント不要、レンダリング経路にサーバーもない、というものは存在せず、誰もアカウント条項をコピーしていません。Lollyは今、独自のオープンキャンバスを出荷しています - **Design**、直接操作型の自由なキャンバスです - ただし、その上の色、タイプ、アセットもブランドのグローバル設定に準拠しており、自由な配置であってもconstraints-firstであり続けます。

Lollyが今も**そうではない**ものは、制約のないデザインスイートです。デザイナーは今後もIllustratorやFigmaでオーダーメイドの制作を続けるでしょう - そして、その作業がガバナンスの効いた再現可能なアセットになる必要が出てきたとき、Designツールの[Import a design](/info/design-import.html)が、完成したFigma、Penpot、Illustrator、InDesign、またはPDFファイルを、編集可能でブランドに準拠したボックスとしてキャンバスに取り込みます。

## 用途

- 運用化されたクリエイティブアセット（イベントタイル、バッジ、署名、アラート）の迅速な生成
- 色、タイプ、アイコン、画像といった要素がブランドのグローバル設定に準拠していなければならない場合の、オープンキャンバス（Design）での自由な配置
- 完成したFigma、Penpot、Illustrator、InDesign、PDFデザイン（Designツールの Import a design）を取り込み、Lollyのあらゆる形式で決定論的に編集・ガバナンス・再レンダリングできるようにする
- 「3つの項目を埋めて完成したアセットを得る」という一対多のフロー - `/pro`のバッチグリッドでスプレッドシート/CSVから一括実行する場合も含む（行を貼り付けまたはインポートし、行ごとに1つの完成アセットをzipでダウンロード）
- 常時稼働の、繰り返し発生するブランド化された出力
- 表現の自由度よりもブランド表現の一元管理が重要な場面

Deck Studioは、ここでの天井を測るのに良い指標です。データとして宣言されたスライドデッキ全体が、キャンバス上でライブにレイアウトされ、ネイティブで編集可能なPowerPointとしてエクスポートされます。

## 使うべきではない場面

- オーダーメイドやフラッグシップのヒーローコンテンツ（ビルボード、大型動画）
- 本当にデザイナーを必要とする独自のキャンペーン制作
- ブランドシステムを完全に離れる必要があるアイデーション - Lollyのオープンキャンバスも依然として色、タイプ、アセットをブランドのグローバル設定に準拠させます。それこそが要点です

## 確率的に革新し、決定論的にスケールする

多くの「AIクリエイティブ」の売り込みは、モデルを古い境界線の間違った側に置いています。写字生や装飾写本の彩飾師たちは、その境界線がどこにあるかをすでに定めていました。ラフスケッチでは自由に作業し、何を試してもよく、何も確定されません。それから印刷機に向かいます。印刷機が威圧的に感じられるのは、まさにそれが確定するものだからです。芸術が宿っていたのはスケッチのほうでした。印刷機はそれが世に広まる手段でした。二つの道具、二つの役割、それぞれ独自のやり方で創造的であり、印刷された作品を信頼できたのは、印刷機が刷るたびにその約束を守ったからです。

Lollyは印刷機であり、スケッチではありません。アイデーションには好きなものを持ち込んでください - モデルでも、デザイナーでも、紙ナプキンでも構いません。しかし、あるアイデアを1万個のアセットにしなければならない瞬間になったら、誰でも読み戻せる入力から、毎回同じようにレンダリングする何かを通す必要があります。上記の比較が本当に問うているのはそこです。誰がより優れたジェネレーターを持っているかではなく、誰が確定のステップを再現可能にしているか、です。

> クリエイティブなプロセスを信頼し、厳密さをもってスケールする。

## 承認するのはファイルではなくツール

他のすべてのツールは、後から確認しなければならない *ファイル* を生成します - Slackスレッドでのブランド担当者、免責事項に関する法務、修正のやり取り、再レビュー。Lollyは承認を**一段階上流**に移します。ブランドルール - 正確なHEXコード、ライセンスされたフォントファイル、裁ち落としの余白、スペーシング - はツールのHTMLとCSSにハードコードされているため、テンプレートはブランドから外れたアセットを *出力できません*。レイアウト自体が強制の役割を果たします。

つまり、出力を承認するのをやめて、それを生み出す**ツール**を承認するようになります。一度承認すれば、そのツールが生成するすべてのアセットは構造上あらかじめ承認済みです - どれだけの量になっても、人の介在もレビューサイクルも不要です。

これが決定論的エンジンが実際にもたらす変化です。それは従来の承認プロセスの高速版ではなく、そのプロセスをなくすものです。クリエイティブチームにとってこれは代替ではなくガードレールです - ボールを投げる(データ、コピー、画像)のは依然としてあなたであり、コードはすべての投球を溝に落とさないようにするバンパーレーンです。

![プロデューサーの仕事はこれだけです: 文字を入力すること。書体、色、スペーシングはツールが承認された時点ですでに決まっています](/t/url-shot?url=%2F%23%2Ftool%2Fwordmark%3Ftext%3DApproved&width=1440&height=900&dpi=192&waitMs=2000&walker=1&format=svg&dark=1&filename=aud-approve-the-tool)

| 従来のやり方でアセットを承認する | Lollyのやり方でツールを承認する |
|---|---|
| 完成したファイルを1つずつ確認する | ツールを一度だけ確認する |
| 依頼 → デザイナーが作成 → ブランドレビュー → 法務チェック → 修正 → 再レビュー | パラメータを1つ変更 → 完成アセット |
| デザイナー、ブランド担当者、法務、依頼者が全員関与 | プロデューサー1人だけ |
| アセット1件あたり数日 | アセット1件あたり数秒 |
| アセット10,000件 = レビューサイクル10,000回 | アセット10,000件 = ゼロ回(テンプレートはすでに承認済み) |

## これが独自に提供するもの

- **大胆なデザインの可能性を、文脈の中で安全に届ける。** ツールはハードコードされたガードレールの中で、冒険的なデザインのアイデアを表現できます。

- **完成アセットを直接返す、ソフトウェア定義のコンテンツ自動化。** 入力 → 完成ファイル。「デザインツールから保存して後処理する」という手順は不要です。
- **ツールがツールを組み合わせる。** あるツールは別のツールのレンダリング結果を埋め込み、1つの完成アセットの一部として返すことができます。ツール間のコード結合は一切なく、これはオープンキャンバスやDAMテンプレート製品のどれも提供していないプリミティブです。
- **ベンダーニュートラリティ。** 機能とコストを完全に管理できます。オープンソースエンジン。ツールとアセットはSaaSデータベースに閉じ込められるのではなく、gitで管理されるコンテンツです。

## コンテンツ主権

前のセクションが行き着く先には名前があります。主権です。あなたのメディアパイプラインは、あなたが所有するハードウェア上で動きます。あなたのブランド - トークン、フォント、ロゴ、それらを強制するツール - は、あなたが保持するファイルの中に、あなたが管理するバージョン管理の中に存在し、エクスポートボタン付きのベンダーデータベースの中にはありません。レンダリングは目の前のデバイス上で行われるため、アセットが存在するために第三者を経由することは一切なく、入力から完成ファイルまでの経路全体がオープンソースで検証可能です。すべてのSaaSデザインベンダーが明日消えても、Lollyのデプロイメントは何も気づきません。

これは、サブスクリプションよりも長く残るべき仕事を持つすべての人にとって重要です。フォトブックがそのノートパソコンの中に存在する親も、調達ルールの下にブランドライブラリを置く公的機関も同様です。組織にとって - 公的機関、規制産業、ブランドが装飾ではなく戦略的資産であるすべての組織にとって - 「自分たちのコンテンツはどこにあり、誰がそれを止められるのか」はガバナンスの問題であり、好みの問題ではありません。ここでの主権はコンプライアンスのために追加されたホスティング機能ではなく、アーキテクチャそのものの性質です。[プライバシーポリシー](/info/privacy.html)と[自分で検証する](/info/verify-yourself.html)のページは、その主張を鵜呑みにするのではなく確認できるように存在します。

この根底にあるのは、機能ではなくコミットメントとして述べられた1つの約束です。**あなたのデバイス上でレンダリングされるものは、永遠に無料です。** エンジン、シェル、ツール、フォーマット - オンデバイスのクリエイティブ経路全体がオープンソースであり、それはこの先も変わりません。この約束にはメカニズムがあります。一度リリースされたバージョンは取り消せないようにライセンスされており、後で作品を再ライセンスできるような貢献者契約は存在しません。この境界線は1文にまとめられます。あなたのデバイス上でレンダリングされるものはすべて、永遠に無料でオープンソースです。ネットワークをまたいで人とマシンを調整する仕事は、別のコントロールプレーンである[lolly.work](https://lolly.work)が担います。
