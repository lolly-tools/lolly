# Lolly Design System Setup

<a id="design-system-setup"></a>

**Lolly Design System Setup**は`#/start`にあり、ロゴ、色、書体を備えています。すべてのツール、ページ、書き出しは、それらを使って描画します。

ロゴをドロップすると、Lollyがその色を読み取ります。書体を選ぶか、会社がライセンスを持つフォントファイルをドロップします。変更はすべて、すぐにアプリ全体に反映されます。ロゴ、フォント、トークンはこのデバイスにとどまります。外部に接続するのはGoogle Fontを選ぶときだけです。Lollyは先に確認し、そのファミリーを一度だけ取得します。

デザインシステムに名前を付け、**Export**を押すと、1つの`.lolly`ファイルが得られます。ファイルを保管したり、別のデバイスで開いたり、同僚に渡したりできます。[Lolly Settings](/info/dashboard.html#design-system)は、使用中のシステムを読み取り専用で表示し、その表紙から編集用のこのページに戻れます。

<!--i:eti-clock-->
## 5分で自分のものにする

::: timeline
- <!--i:upload--> **Logos**のドロップ領域に**ロゴをドロップします**。Lollyが形と色を読み取ります。
- <!--i:palette--> **Use these colours.** ロゴのメインの色がプライマリーになり、ロゴの暗い無彩色がテキストの色になります。
- <!--i:font--> **Type**の**Choose a face**で、Google Fontまたは自分のフォントファイルを選びます。
- <!--i:pentool--> **システムに名前を付けます。** 最初の編集で独自のデザインシステムが作られ、Lollyは一度だけ名前を尋ねます。
- <!--i:download--> **Export**は、システム全体を1つの`LollyBrand-….lolly`ファイルとして書き出します。
:::

スタジオ上部のバーには、デザインシステム名が編集可能なフィールドとして表示されます。**Enter**は新しい名前を保持し、**Escape**は古い名前に戻します。最初の編集で**What is this design system called?**と尋ねられたとき、ロゴに文字があれば、Lollyはその語句を入力します。**Save name**は名前を保持し、**Not now**はバーに名前を入力するまで仮の名前を保持します。この名前はSettingsと切り替え時にシステムを示し、**Export**が書き出すファイルの名前にもなります。

## 各ルーム

スタジオは、決まった順序のないルームの集まりです。他のルームを済ませるまで待つ必要はありません。デスクトップでは、バーの下にルームが1列に並びます。スマートフォンでは画面下端のバーに移り、開いているルームが見える位置にスクロールします。パレットシートとトレイはそのバーの上にせり上がり、入力中はバーが脇によけます。キーボードでは、Tabで列に1回フォーカスが移り、矢印キー、Home、Endでルーム間を移動します。

![スタジオのバーと各ルーム: Board、Colours、Type、Logos、Tokens、Files、Sound、Rules、Skills](/t/url-shot?url=%2F%23%2Fstart&width=1440&height=900&dpi=192&waitMs=1600&cropSelector=.ds-top&waitSelector=.ds-room-nav&format=svg&walker=1&localize=1&dark=1&filename=brand-studio&try=1)

| ルーム | できること | リンクのキー |
|---|---|---|
| **Board** | システムの内容を確認し、各ルームに移動します | `overview` |
| **Colours** | 色を追加し、役割を与え、濃淡やパレットを作ります | `color` |
| **Type** | アプリ、ツール、すべての書き出しが参照する4つの書体を選びます | `type` |
| **Logos** | すべての向きと表現でマークを配置します | `logos` |
| **Tokens** | 角、間隔、影、その他すべての名前付きの値です | `tokens` |
| **Files** | ブランドが保持する画像、音声、モーションのファイルです | `catalogue` |
| **Sound** | 音によるアイデンティティ、用途ごとの音楽、声との関係を形にします | `sound` |
| **Rules** | ブランドが適用するルールを、実例で確認します | `usage` |
| **Skills** | 人とエージェントが読むための、ダウンロードもできるブランドの文書化された基準です | `skills` |

ルームへのリンクには`#/start?area=<key>`を使います。ルームのキーは変わらないため、Filesは`catalogue`、Boardは`overview`、Rulesは`usage`のままです。`?tab=`も以前の別名として引き続き使えます。不明なキーはBoardを開きます。

システム全体のアクションは**バー**にあります。**Add from…**はブランドを取り込みます([ブランドを取り込む](#bring-a-brand-in))。**Tray**は、スキャンで見つかり、まだ追加していないものを保持します。**Export**は、システムを1つのファイルに書き出します。**More**には、**Tokens (.json)**、**Fonts for Linux (.rpm)**、**Versions & publishing**、**Restore brand settings**、**Design systems**があり、最後のものはSettingsの切り替え用の一覧を開きます([デザインシステムを保管して移動する](#keep-and-move-your-design-system))。各アクションは、操作する対象ができると表示されます。スマートフォンでは、**Add from…**は**More**内に移り、**Export**はアイコンで表示されます。

デザインシステムがアプリ付属のものである間、バーの先頭には**Make it yours**があり、**Find a look**、**Add from…**、**Pick a colour**のメニューを開きます。システムが自分のものになると、**Export**が再びその位置に戻ります。

## Board

まだ何も選んでいない場合、Boardには4つの始め方があります。**Start from a reference**は、ロゴ、スクリーンショット、Webページ、デザインファイルを選ぶ取り込み元ピッカーを開きます。**Pick a colour**、**Choose a face**、**Add a logo**は、それぞれのコントロールを開きます。開くだけでは何も書き込まれません。その下の**Find a look**では、用意された色や書体を試せます。**Explore the tools**は最初からあります。

何かが自分のものになると、Boardは持っているものを、自分のものの数を先にして表示します。Coloursは色数を表示し、引き継いだものは薄い`· N starter`で示します。色の帯には自分の色が並び、細い線を挟んで、薄く表示された初期の色が続きます。Colourwaysは、各カラーウェイをその主役の色の小さなタイルで示します。Typeは各役割を一覧にし、各ファミリーをその書体で表示します(*Inter for headings*、その下の行に*Starter for the rest*)。Logosは埋まっているスロット数(または**Not set**)を示し、Tokensは角の半径を示し、ライブラリが空の間はFilesに**Nothing yet**と表示されます。各ブロックは、それぞれのルームを開きます。

Lolly Demoなど、アプリ付属の編集可能なデザインシステムでは、最初からBoardに色、カラーウェイ、書体、マークが表示され、見出しの横に**Came with this app**タグが付きます。その上の**Start here**には、**Find a look**、**Add from…**、**Pick a colour**があります。

### 初期のものと自分のもの

どのルームでも、**Starter**は、アプリに付属し、誰も選んでいないものを示します。新規インストールには色がなく、インクから紙までの無彩色の段階が1組だけあるため、誰かが選ぶ前から背景、テキスト、細い線を描画できます。

::: cols
## 初期のもの

- アプリに付属していたものです。インクから紙までの無彩色、初期の書体、既定の角の半径です。
- 薄く表示され、**Starter**タグが付き、色味はありません。
- 自分の色としては数えられません。無彩色は**Tokens**に**Neutrals · starter · 9**として置かれ、**Open**でColoursに1つの折りたたまれたグループとして表示されます(`#/start?area=color&group=neutral`)。
- 初期の色を使う役割には*"Starter Paper stands in"*と表示され、ピッカーには**Choose…**があります。

## 自分のもの

- 自分で選んだ、またはインストールしたものです。
- 本来の濃さで表示され、書体をインストールした場所ではカードに色が付きます。
- BoardとTokensで数えられます。
- 別の役割に従う役割には、**↳ follows Primary**と表示されます。
:::

引き継いだものに破線の枠は付きません。破線の枠は、ドロップ先を意味します。

## Logos

上部のドロップ領域、**"Drop marks here, or choose several at once"**は、ファイルを何個でも受け付けます。Lollyは各ファイルの形とインクの色を読み取ります。その後、ファイルは**Waiting for a slot**の下でチップとして待機します。*"Looks like the Horizontal primary"*など、どれに見えるかの説明、判定に使った計測値、**Place**ボタン(スロットが埋まっている場合は**Replace**)が表示されます。Lollyが確信を持てない場合は、チップにその旨が表示され、8つすべてを一覧にする**Change slot**が用意されます。ボタンを押すまでは何も配置されません。

余分な空白の余白があるマークには、先にトリミングが提案されます。提案に答えるか、Escapeを押して元のまま配置します。マークで同じグループの空いているスロットを埋められる場合、ルームは生成した**mono**版または**reverse**版を、*Generated*と表示したチップで提示します。

すべてのマークは、**向き**と**表現**の組ごとに1つずつ、8つの任意のスロットからなるグリッドに入ります。

- **向き:** Horizontal(ワードマークとシンボルを横に並べる)とVertical(積み重ねて、正方形や縦長のスペースに使う)です。
- **表現:** Primary、Primary reverse(暗い背景用)、Mono(単色)、Mono reverseです。

マークがないグループは、1行に折りたたまれます。グループを開くとスロットが見えます。スロットをクリックしてPNG、SVG、JPEG、WebPを追加するか、埋まっているスロットをクリックしてマークを置き換えます。空のスロットは、ファイルのドロップも受け付けます。横向きのマークは横長のタイル、縦向きのマークは正方形に入り、それぞれ想定された背景の上に、高さの4分の1の余白を取って置かれます。すべてこのデバイスにとどまります。

![HorizontalとVerticalを開いたロゴのスロット: 表現ごとに専用のスロットがあり、どのスロットも任意](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dlogos&system=new-design-system&width=1440&height=1600&dpi=192&waitMs=1600&drive=click%3A.be-logo-identity%3Edetails.be-logo-group--fold%3Anot%28.be-logo-group--custom%29%3Esummary%3Bwait%3A600&cropSelector=.be-logo-grid&format=svg&walker=1&dark=1&filename=bs-logo-slots)

- **Custom marks**は、アイコン、紋章、ファビコンなど、ブランド独自の名前で呼ぶマークです。
- **アイデンティティを追加する。** サブブランド、製品、イベントも、それぞれ完全なセットを持てます。**+ Add another logo**を押し、セットに名前を付けます。メインのセットは「Your logo」です。[ブランドアーキテクチャ](/info/brand-architectures.html)で、ロゴのアイデンティティをいつ使うかを説明しています。
- **Lollyがロゴの色を読み取ります。** ドロップ領域の下とColoursの上部にあるカードが、ロゴの色を一覧にし、**Which is the main colour?**と尋ねます。最も強い色が選ばれ、ロゴを書き出したときの背景の白は選ばれません。**Use these colours**は、それらをパレットに追加し、メインの色をプライマリーにします。ロゴに紙の上で読み取れる暗い無彩色がある場合、その無彩色がテキストの色になります。**Not now**は、それらをTrayに残します。新規インストールでは、Lollyが最も可能性の高い答えをすぐに適用し、カードに**Undo**と別のメインの色の選択肢が表示されます。SVGからは正確な色が得られ、PNG、JPEG、WebPからはマークの相当部分を占める色が得られます。

## Colours

ルームはデザインシステムとともに育ちます。最初に求められる判断は1つで、パレットが増えるにつれて、さらにコントロールが表示されます。

### 最初の色

独自の色がないシステムでは、初期の無彩色が専用の開いたグループに表示されます。ルームの上部には、破線で囲まれた貼り付けとドロップの領域があり、大きなチップ1つと入力欄1つが置かれています。領域内のどこに画像や色の一覧をドロップしても、Lollyが色を読み取ります。

- **チップがピッカーです。** **Pick a colour**は、入力欄の内容を初期値にして、スタジオのOKLCHカードを開きます。カードは、最初に色の名前と16進数値を表示します。色空間、ホイール、4つのダイヤル、アルファは**Fine-tune**の下にあり、**Cancel**と**Add colour**は下部にあります。**Add colour**を押すまでは、何もシステムに入りません。
- **入力欄はどの表記も受け付けます**。`#e0452b`、`rgb(224 69 43)`、`oklch(58% .19 32)`、色名を使えます。貼り付けた一覧はチップの列になり、1つずつ、または**Add all**でまとめて追加できます。
- **ほかにも2つの方法があります。** **Pick a colour from the screen**は、ブラウザにスポイトがある場合にそれを使い、**Take colours from an image**は、このデバイス上のスクリーンショットや写真を読み取ります。
- **Addが無効になることはありません。** 入力欄が空ならピッカーを開き、読み取れないテキストには、入力欄の下の行にその旨を表示します。

最初の色が**プライマリー**になります。チップに*"Primary is now Vivid Violet"*などと表示され、変更を確認できます。色を調整する**Fine-tune**もあります。


### パレットが増えるにつれて

幅の広い画面では、自分の色は**In context**プレビューの横に、小さい画面ではプレビューの上に並びます。プレビューには、自分のパレットを使ったポスター、チャート、インターフェースのカードが表示されます。初期の色は専用のグループにあり、システムが独自の色を持つと折りたたまれます。貼り付けとドロップの領域は、コンパクトな1行になります。ルームの上部に書き出しはありません。バーの**Export**またはTokensルームを使ってください。

### 色の役割: 色に付けられる名前

デザインシステムは色に名前を付け、それぞれの用途を示し、Lollyはその両方を読み取ります。**Colour roles**はColoursルームの上部にあります。**In context**は、変更をすぐに表示します。

![架空の繊維ブランドWefthouseの、独自の用語を使ったColour rolesの表: Indigo、Madder、Weldのカラーウェイチップに続き、Main、Accent、Supporting、Tertiaryがそれぞれライトとダークの色を備え、主役の色、組み合わせる色、名前だけで参照される色として読み取られる。表の下には、どの役割も満たしていない用途としてBackground、Text、Quiet text、Hairlinesが並ぶ](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dcolor&system=wefthouse&width=2720&height=2000&dpi=192&waitMs=1800&cropSelector=%5Bdata-be-roles-fold%5D&format=svg&walker=1&dark=1&filename=bs-colour-roles)

表には4つの列があります。スマートフォンでは各行がカードになり、ライトとダークが横に並びます。

| 列 | 内容 |
|---|---|
| **Role** | デザインシステム独自の用語。その場で編集でき、色の用途を説明する行があります |
| **Light**と**Dark** | 選択したカラーウェイの、その表示での色。名前または値と、コントラストを示します |
| **Lolly reads this as** | ツールがその役割で何をするかを、Lollyの用語で示します |

**Lollyによる役割の解釈。** 各解釈に割り当てられる役割は1つです。別の役割が持つ解釈を選ぶと、その解釈はこの役割に移ります。Lollyが単語から意味を推測することはありません。

| 解釈 | その解釈で使われる場所 |
|---|---|
| **Lead colour** | 大きな図形、ボタン、ツールが主に使う色 |
| **Partner colour** | ツールが2番目に使う色 |
| **Background** | ほかのすべての背面 |
| **Text** | 見出しと本文 |
| **Quiet text** | キャプションと小さな文字 |
| **Hairlines** | 罫線、枠線、区切り線 |
| **By name only** | ツールが自動でこの役割を選ぶことはありません。すべての色のフィールドとDesignで選択でき、選んだ色はリンクを保つため、カラーウェイに従います |

どの役割も割り当てられていない解釈は、デザインシステムの定義を保ち、ルームでは表の下に一覧表示されます。Primaryという名前の役割のように、解釈自体のidと同じidを持つ役割は、その解釈そのものであり、移動できません。

**チャートでの使用。** Lolly Chartの**Design system - colour roles first**パレットは、系列にデザインシステムの色の役割をその順序どおりに割り当て、その後にパレットの残りの色を使います。背景、テキスト、控えめなテキスト、細線として解釈される役割は除外されます。チャートはその色で背景と文字を描くためです。このパレットを選ぶまでは何も変わりません。色の役割がないデザインシステムでは、**Design system - ordered**としてパレットを描画します。

**値。** 値を押すと、その表示と選択したカラーウェイで使う、その役割の色を選べます。**Same as light**は、ダークの色を選ぶまで、ダークの値をライトの値に合わせます。**Aa**チップには、その色の上に置くためにLollyが選んだテキストが表示されます。値の下の行には、各表示でのテキストの読みやすさが**Text reads well**、**Large text only**、**Hard to read as text**で示されます。この評価は、その色の上のテキストだけを対象とします。その色は、図形や広い領域には使える場合があります。名前だけで参照される役割にも同じ文言が表示されますが、警告色は付きません。ツールが自動でその役割の上にテキストを置くことはないためです。ツールチップとピッカーには、APCA、WCAGの順で数値が表示されます。**Own text colour**は、ファイルにテキストの色が指定されている値を示し、そのテキストの色は保たれます。**Copied**は、別のカラーウェイまたはパートナー色からコピーされた、まだ誰も選んでいない値を示します。ピッカーの**Keep this colour**で値を確定します。

**出発点。** 独自の役割がないデザインシステムには、現在の名称であるPrimary、Secondary、Surface、Textが表示されます。どれかを変更するまで何も書き込まれません。**+ Add a role**は**Primary, Secondary**または**Main, Accent, Supporting, Tertiary**を提案するほか、任意の名称を入力でき、それぞれに与えられる解釈を表示します。最初の2つの名称が主色とパートナー色になります。ツールは同じ色で描画し続けます。主色が1つのシステムでは、最初のカラーウェイはその色の名前になります。

**名前の変更、並べ替え、削除。** 名前の変更で変わるのは名称だけで、その役割を使うものはすべて動作し続けます。役割のハンドルをドラッグするか、ハンドルでSpaceを押し、矢印キーで移動してからSpaceを押して配置します。**Remove**には、その役割をまだ使っているものが表示されます。ツールがその役割を読み取る場合、**Remove and keep those colours**は各解釈に現在の色を残します。組織のルール、ガイドグループ、ツールのフィールド、別のトークンがその役割を使っている場合は、その使用が変わるまで役割は保持されます。保存済みのDesignドキュメントも役割を名前で使うことがあり、Lollyはトークンファイルからその使用を確認できません。そのようなドキュメントでは、色が未解決と報告されます。

::: details 手書きのトークンファイルの役割
**手書きのファイル。** トークンファイル内で、どの役割にも宣言されていない色は、**In this file, with no role yet**に一覧表示され、それぞれに名称のフィールドと**Make a role**があります。どちらの場合も、名前での使用はそのまま機能します。名前に数字を含むトークンは役割にできません。ファイルに残り、パスによる使用はそのまま機能します。ファイル内のレコードが検証に通らない場合、表はコントロールなしで表示され、理由が示されます。
:::

**ルームのほかの部分でも同じ名称を使います。** チップ、スウォッチの**Use as**行、パレットの**Colour roles**グループは、すべてデザインシステムの名称を使います。色の役割のタイルを開くと、その値が表示されます。書き出したファイルに、役割について新たに記録されるものはありません。レンダリングの色が変わるのは、トークンが変わったためです。

**名称の行き先。** 名称と説明はデザインシステムとともに渡されます。エージェントは、デザインブリーフ、`lolly://tokens`、ブランドページの`AGENTS.md`で読み取ります。ターミナルでは`lolly system status`で表示されます。ブランドページは`brand.json`に一覧を記録し、役割ごとにコントラストのペアを測定します。DTCGとTokens Studioのファイルはすべてを保持し、`DESIGN.md`は名称と解釈を保持し、PowerPointのテーマはブランドの順序だけを保持します。全一覧は[ほかの形式での色の役割](/info/design-tokens.html#colour-roles-in-other-formats)にあります。名称は常にデザインシステムのデータとして引用され、指示として読み取られることはありません。

**色を選ぶ場所。** ツールとLolly Designのすべての色のフィールドでは、デザインシステムの役割が最初に、その順序どおりに、名称と用途を添えて一覧表示されます。役割の横の**Aa**は、その役割の上に置く色を選びます。ほかの色は**Other colours**に続き、カラーウェイ独自のコピー、上に置く色、すでに役割が割り当てられた解釈は含まれません。選んだ色は役割へのリンクを保ち、カラーウェイに従います。フィールドにはどのカラーウェイでもその名称が表示され、SettingsとTokensでも同じ名称が使われます。役割がないデザインシステムは、スウォッチのグリッドを保ちます。

### ツールが読み取るすべての色

ルームでは、**Colour roles**を閉じると、先頭に最初の選択に使うチップが並びます。各チップには役割の色と名前が表示されます。独自の名称がないシステムでは、**Primary**、**Secondary**、**Surface**、**Text**です。チップを押して、パレットのスウォッチから色を選びます。**Colour roles**の下部にある**Every colour a tool reads**には、すべての色が帯状に表示されます。

この帯には、ツールが読み取れる7色、Primary、Secondary、Surface、Text、Muted、Edge、On primaryが表示され、デザインシステムに独自の名称があればそれを使います。それぞれが、どのツールや書き出しでも同じ役割を果たします。設定が必須の色はなく、どの色でも割り当てられます。自由に選んだ3色で、よいシステムになります。数値表示は、背景に対するテキストの読みやすさを、APCAを先頭に示します。各行には、薄めていない独自の色、代わりに使うスターターの色、または**↳ follows Primary**が表示されます。

On primaryはPrimaryから導出され、**Derived**と表示され、ピッカーはありません。On primaryの横と**In context**の横にある**Light**と**Dark**の切り替えで、帯、パレット、プレビューに表示する外観を選びます。

アプリ自体のアクセントは、既定では**Settings → Appearance**の**Interface follows the design system**設定を通じて、デザインシステムに従います。この設定がオフの場合、アプリの操作部分はニュートラルな色のままです。どちらの場合も、ツール、キャンバス、書き出しはデザインシステムに従います。

**カラーウェイ。** デザインシステムには複数の主色を持たせ、作品ごとに選べます。**Colour roles**の先頭の**Colourways**行には、カラーウェイごとにチップが1つ表示され、正規のものには**Default**が付きます。**+ Add**は、パレットの色から新しいカラーウェイを作ります。チップを選ぶと、表、帯、パレット、プレビューがそのカラーウェイを表示します。選んだカラーウェイは、名前の変更、複製、削除、既定への設定ができます。カラーウェイがあるシステムでは、各カラーウェイに独自のPrimaryとSecondaryが必要で、背景に色を付ける場合には独自のSurfaceも必要です。これらの役割はスウォッチエディターで設定されたままになります。手順とトークン形式は[デザインシステムにカラーウェイを追加する](/info/colourways.html#add-colourways-to-a-design-system)で、実際の作品でのカラーウェイは[Lolly Demoを使う](/info/lolly-demo-in-use.html#colourways-on-real-work)で説明しています。各自が**Settings → Appearance**で自分のカラーウェイを選べます([自分のカラーウェイを選ぶ](/info/colourways.html#make-a-colourway-your-own))。

### 生成したパレットを確定する

操作は、**Rebuild the whole palette…**を開き、**Preview full rebuild**を押して始めます。確認画面には、割り当てどおりに残る役割の数、保持される独自の色の数、基準が変更されるか保持される濃淡カーブ、印刷用の固定値、非表示の濃淡、グラデーションのストップの数が表示されます。**Apply rebuilt palette**で確定し、**Cancel**では何も変わりません。その後、カードにはフォーカス済みの**Undo**が表示され、置き換え前に作られたチェックポイントでシステム全体を復元できます。

カラーウェイがあるシステムは、作り直してもすべてのカラーウェイを保持します。正規のカラーウェイは新しい開始色に従い、ほかのすべてのカラーウェイは独自の色、名前、順序、設定を保ちます。確認画面には、追従するカラーウェイと色を保つカラーウェイが一覧表示されます。カラーウェイがLollyの編集できない方法で記述されているシステムは、作り直されません。カードに理由が表示され、何も変わりません。

### 詳細設定のセクション

プレビューと役割の下には、4つの折りたたまれたセクションがあります。それぞれ`#/start?area=color&focus=<name>`で開けます。

- **Explore shades & harmonies** (`focus=generate`)。
- **Shade curves** (`focus=curves`)は、明度、彩度、色相(L / C / H)の個別のカーブで、濃淡の段階を点ごとに調整します。ドラッグすると濃淡が描き直されます。
- **Contrast** (`focus=contrast`): **Contrast-lock**は、選んだ背景に対してAPCAの目標値を満たすように濃淡を調整し、**Rotate hue**は濃淡全体の色相を色相環に沿って回転させます。
- **Print** (`focus=print`)は、Primaryの印刷時の色を、自動の値、固定したCMYKの組み合わせ、名前付きの特色インクから設定します。

### パレットと各スウォッチ

パレットには、色が折りたたみ可能なグループに分かれて並び、それぞれに**+ Add**があります。グループの作成と名前の変更ができます。役割によって2つ目のタイルが作られることはありません。役割が参照するタイルには、**Primary**などの役割名が表示されます。タイルの下にある**Colour chart**は、同じ色をOKLCHの**Wheel**(点をドラッグして色を変え、空いている場所をクリックしてスウォッチを追加)と、表示可能な範囲の境界を示す**Gamut**チャートに表示します。`#/start?area=color&focus=chart`でチャートが開きます。

スウォッチをクリックするとエディターが開きます。

- **Rename**でスウォッチの名前を変更します。
- **Set the colour**で、OKLCHのスライダー、または**Hex**、**HSL**、**RGB**、**CMYK**で色を設定します。値のフィールドは、選択中の色空間で読み書きします。ここでのCMYKは変換によって画面の色を設定します。インクの値を正確に固定するには、**Print substitutes**を使います。
- **Stored as**は、スウォッチの保存形式を**LCH**(既定、知覚に基づく広色域)、Hex、RGB、HSLから選びます。
- **Use as**はスウォッチに役割を与え、デザインシステムに独自の名称があればそれを使います。強調表示された役割をもう一度押すと、役割を解除します。
- **Print substitutes**(折りたたみ式): **CMYK**を**Auto**から正確なインク値に固定するか、**Name**(`PANTONE 186 C`など)、任意の**Book**、箔押し、エンボス、デボス、スポットニス、ソフトタッチ、型抜き、折り筋、ミシン目の**Finish**を指定して**Spot colour**を設定します。CMYK PDFまたはTIFFを書き出すと、印刷ではこれらの固定値が使われます。[カラープロファイル](/info/exporting.html#colour-profiles)をご覧ください。Print PDFでは、特色インクは専用の版で印刷されます。1回の書き出しですべての特色インクをプロセスカラーで印刷するには、[特色インクをプロセスカラーにする](/info/exporting.html#spot-inks-as-process)をご覧ください。
- **In other spaces**(折りたたみ式): 色空間ごとの値です。導出された値、または自分で指定した値があり、書き出しでは自分で指定した値が優先されます。

**スウォッチの削除**は安全です。導出された濃淡とテーマの役割は非表示になるため、それらを読み取るものの動作は壊れません。自分で追加した色は削除されます。

::: details 多数のスウォッチを扱う
通常、スウォッチには色、名前、16進数の値が表示されます。Selectを使うと、どの画面でも各スウォッチのチェックボックスとドラッグハンドルが表示され、キーボードフォーカスのあるタイルにもハンドルが表示されます。ハンドルをドラッグしてグループ内で並べ替えるか、ハンドルにフォーカスしてSpaceを押し、矢印キーを使い、もう一度Spaceを押して配置します。Escapeでキャンセルします。スマートフォンでは、パレットは1行に4色を表示します。グループ間で色を移動するには、エディターの**Group**コントロールを使うか、複数選択して**Move to**を使います。

選択専用の切り替えは必要ありません。最初のタイルを選ぶとバーとチェックボックスが表示され、最後の選択を解除すると消えます。

- **空いている場所をドラッグ**して長方形を描きます。触れたすべてのタイルが、グループをまたいで選択に加わります。折りたたまれたセクションからは何も加わりません。
- **Shiftを押しながらクリック**すると読み順の範囲を選択し、**Cmd/Ctrlを押しながらクリック**すると1つのタイルの選択を切り替え、通常のクリックではエディターを開きます。
- 各グループの見出しには**Select all**があり、タイルにフォーカスして**Cmd-A**を押すと、独自の色をすべて選択します。スターターの色は選択しません。
- グリッド内のTabの停止位置は1か所です。矢印キーで移動し、Shiftと矢印キーで選択を広げ、Spaceで選択を切り替え、Deleteで削除し、Escapeで選択を解除します。チャンネルを微調整するには、先に`l`、`c`、`h`を押します。
- タッチ画面では、タイルを長押しして選択を始め、タップして追加します。

バーには**{n} selected**、続いて**Move to**、**Give a role**(各色に順番に次の役割を割り当てます)、**Download**(選択した色を6つのパレット形式のいずれかでダウンロード)、**Duplicate**(それぞれのコピーを元の色の後ろに配置)、**Copy values**、**Delete**が表示されます。コピーが1つならエディターで開き、複数なら選択されたままになります。Cmd/Ctrl-Zを1回押すと、一括操作を元に戻します。
:::

### グラデーション

任意の**Gradients**パネルは、パレットからブレンドトークンを作ります。各グラデーションには、プレビュー、名前付きの2〜8個のストップ、角度があります。ストップはスウォッチを参照するため、スウォッチの色を変えるとグラデーションも追従します。ブレンドにはOKLCHを使います。

パレットのダウンロード(デザイントークン、CSS、SCSS、GIMP、Adobe Swatch Exchange)は、パレットの上部にあります。各形式は[パレットとフォントをどこへでも持ち出す](/info/using.html#take-your-palette-and-fonts-anywhere)で説明しています。

### 比較ステージ

ステージは、押したカードの下に開きます。カードは1行の帯に折りたたまれるため、スマートフォンの最初の画面にもステージが表示されます。Escapeでキャンセルし、カードにフォーカスを戻します。

1. カードの**Choose for**と役割名があるボタンを押します。
2. フォントファミリー名を入力して**Preview**を押すか、フィールドの下にある6つの**Pinned**ファミリーの1つを押します。
3. **Use this face**を押します。

トークンは、デザインシステムを支える名前付きの値です。色、書体、ロゴ、角の丸み、間隔などがあります。ツールは名前で読み取るため、ここでの変更はすべてのツールにすぐに反映されます。

![Tokensルーム。上部にはシステムの例とファイル操作があり、続いて種類ごとのトークン数を示すタイル、コントラストの数値を添えた色のペアが並びます](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dtokens&width=1440&height=740&dpi=192&waitMs=1600&format=svg&walker=1&dark=1&filename=brand-tokens)

- **上部**には、独自のシステムの例(*PrimaryはSpearmint、#033633*)とファイル操作が表示されます。**Download**(システムをデザイントークンとして、またはパレットをほかの5つの形式でダウンロード)、**Copy CSS**、JSONファイルを読み込む**Add from…**があります。
- **タイル**は種類ごとのトークン数を表示し、Colours、Type、Logos、Shape and spacing、More、All tokensの各セクションに移動します。空のスターターに付属していたものだけを持つセクションには、**Starter**タグが付きます。アプリに付属するシステムは、タグなしで独自の内容を数えます。スマートフォンでは、タイルは3つずつ2行に折り返されます。
- **Colours**は、ツールが組み合わせて使うペア(背景上のテキスト、Primary上の色、背景上の控えめな色)から始まり、ライトとダークのAPCAの数値を表示し、基準を満たさないペアには**Weak contrast**を表示します。その後に、すべての色のグループが続きます。濃淡はチップの1行にまとまり、ほかの色には値と、`{color.brand.spearmint}`などのツールが使う参照が表示されます。参照を押すとコピーできます。**Edit in Colours**は、Coloursルームでグループを開きます。[色の役割](#colour-roles-what-the-colours-are-called)があるデザインシステムでは、**Colour roles**が先頭になり、各役割がシステム独自の名称と順序で1回ずつ表示されます。役割は、カラーウェイと表示の組み合わせごとに色を保持します。それらの色は独立した色としてではなく、役割とともに一覧表示されます。変更はColour rolesの表で行います。
- **Type**と**Logos**には、各役割の書体と各ロゴスロットが一覧表示され、独自のものがあれば**Edit in Type**と**Edit in Logos**が表示されます。
- **Shape and spacing**には、**Rounded corners** (`shape.radius`)と**Spacing rhythm** (`space.base`)があります。それぞれ、スライダーを動かすまでは*Lolly default*、動かした後は*Yours*と表示され、すぐに保存され、元に戻せます。
- **More tokens**は、間隔、サイズ、線の太さ、不透明度、回転、単純な数値、影を追加し、標準の[デザイントークン](/info/design-tokens.html)として保存します。
- **App appearance (advanced)**は、Lolly自体の画面が使う色、サイズ、影を一覧表示します。**Inspect every token (advanced)**は、保存された任意の値を検索、編集でき、各変更を適用前に確認できます。ここでは、各カラーウェイの色の役割の値が、その役割とともに一覧表示されます。役割のトークンを選ぶと、カラーウェイごとの行に、ライトとダークが並んで表示されます。件数の行には、役割が保持する値の数が表示されます。読み取り専用のデザインシステムでも、同じ一覧が表示されます。

空のセクションには、**Pick a colour**、**Choose a face**、**Add a logo**が表示されます。

## ファイル

ロゴ以外の、ブランドで使うファイルをドロップします。**ベクター**、**画像**、**音声**、**モーション**のファイル(動画、Lottie、アニメーション)です。[Assets](/info/using.html#assets-your-library)にセクション別に表示され、すべてのツールのアセットピッカーにも表示されます。ファイルはこのデバイスに保持されます。

## サウンド

**Sound**は聴いて選びます。ルームを開くと、最初の3つのサウンド、**Calm**、**Steady**、**Bright**が表示されます。それぞれに、ジャンルの色を使ったカードと再生ボタンがあります。1つ再生すると短い抜粋が聴け、別のものを再生すると先のものは止まります。**Choose**は、そのサウンドをすべての用途のサウンドにします。4つ目のカードの**Mixed**は、用途ごとに異なるサウンドを割り当てます。ExplainにはCalm、DemonstrateにはSteady、PlayにはBrightです。再生ボタンは3つを順番に再生します。**Save sound**を選ぶまで何も保存されません。保存すると、サウンドはこのデザインシステムの一部となり、ほかのルームと同じ履歴にチェックポイントが作られます。サウンドがないデザインシステムは、これまでどおりに動作します。

用途は、サウンドが流れる場面です。最初は**Explain**、**Demonstrate**、**Play**があります。各用途は、専用の再生ボタンを持つチップです。チップの上の**Music**または**With narration**で、チップが音楽だけを再生するか、声の背景で再生するかを設定します。選んだ用途には、その目的と音楽が、たとえば「温かみ · 84 bpm · Rhodes、うねるベース、くすんだドラムキット」のように平易な言葉で表示されます。すべての用途は、選んだサウンドのジャンル、テンポ、楽器を使います(Mixedの場合は、それぞれ独自のものを使います)。各用途は独自の曲とバランスを保ちます。Explainはメロディーが声を妨げないようにし、Playはメロディーを前面に出します。Mixedと1つのサウンドを切り替えても、両方が保たれます。自分で追加した用途は、Mixedでのサウンドを保持します。デザインシステムは、どちらを選んだかを記録します。**Add a use**は用途を追加し、その場で名前を入力できます。**Make main**は、ほかに指定がないときに再生する用途を選びます。**Another tune**は、同じ設定で新しい曲を再生します。

**Edit in the music generator**は、その用途の設定で[音楽ジェネレーター](/info/generated-music.html#the-music-generator)を開き、誰のサウンドを編集中かを上部の行に表示します。**Save to this use**は設定をルームに戻し、**Cancel**は何も変えずに戻ります。離れている間も、ルームの未保存の選択は保持されます。その間に別のタブで誰かがサウンドを保存した場合は、新しい保存が優先され、自分の編集は適用されません。

**Voice**は、その用途の声、話す速さ、声の背景に流す音楽の音量を選びます。**Hear the voice with the music**は両方を再生します。**More**には、発話中の音量低下、試す文(ルーム内にとどまります)、発音のメモ(1行に1つ、表記 = 読み)、声についてのメモがあります。プレビューは、ローカルの音声モデルと、シーケンスの書き出しと同じミキシングを使います。プレビューはフェードアウトし、曲としての終わりは作られません。

**Notes and signature**には、その用途で聴き取るポイントと、サウンドシグネチャーを保存します。シグネチャーは、独立した音声ファイルとして保持する、固定のオープニングまたはエンディングです。シーケンスにシグネチャーを配置してください。生成される音楽にシグネチャーが含まれることはありません。このバージョンのLollyで確認できない要件があると、その用途の新しい音楽は作成できません。

**Details**には、ブランドの個性(サウンドに求める印象、変えないもの、避けるもの)と試聴レビューを保存します。**Record a listening review**は、レビュー担当者の名前、日付、メモを、保存済みのサウンドのバージョンに紐づけて保持します。何かを変更すると、サウンドは再び下書きになります。レビューが対象とするのはそのバージョンであり、後でそのサウンドから作られるすべての曲ではありません。新しい作品は、送り出す前にそれぞれ聴いてください。

**Make a music project**は、その用途を音楽ジェネレーターでプロジェクトとして開き、用途、サウンドのバージョン、正確な設定を保持します。そこで**New tune**を使うと、サウンドを保って新しい曲を作ります。設定を変更した場合、**Put the sound back**でサウンドに戻り、**Keep as my own**で独立した曲として続けられます。どちらかを選ぶまで、そのプロジェクトをサウンドから作られたものとして保存したりダウンロードしたりすることはできません。共有リンクに含まれるのは音楽の設定だけです。プロジェクトと保存した曲はサウンドのメモも保持しますが、共有リンクと音声ファイルの公開クレデンシャルには含まれません。ジェネレーターの将来のバージョンでも正確に同じ音声を残す必要がある場合は、レンダリングした録音を保持してください。

## ルール

**Rules**は、利用者が変更できるもの、固定するもの、Lollyが確認できるものを設定します。

![Lolly DemoのRules。4つの組織のルールにそれぞれChecked in DesignとRequiredまたはAdvisoryが付き、その下に、例をレンダリングできる状態のTry your design system in useがあります](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dusage&width=1440&height=1200&dpi=192&waitMs=2400&cropSelector=%23start-panel-usage&format=svg&walker=1&dark=1&filename=bs-usage-rules)

**Brand rules**にはルールが一覧表示されます。**Add rule**(または**Add your first rule**)は、短いフォームを開きます。

- 独自の言葉による**Rule name**。たとえば*Beaconのアクセント*です。
- **Check**: **Colour choices**、**Font choices**、**Fixed artwork**、**Text length**と、使用するブランドの役割。その役割には独自の名前が使われます。
- 適用先の**Example**(Poster、Title slide、Content slide、Lolly Chart)、**Mode**、**Required**か**Advisory**かの指定。
- **Reviewed by**、続いて**Save draft**または**Approve & save**。

承認は、このデバイスに自分の判断を記録します。承認済みの必須ルールは再利用可能なポスターを制約し、チェックの対象は例のPNGだけです。ほかのツールは変わりません。

デザインシステムのトークンファイル内のルールは、承認済みの色の組み合わせ、テキストの太さと配置、背景ごとのロゴなども含め、ここに**Checked in Design**として一覧表示されます。Lolly Designは、書き出しパネルの**Before you export**カードでレイヤーごとに確認し、`lolly check`は保存済みのLolly Designドキュメントに対して同じ確認を行います([書き出す前に](/info/design.html#before-you-export))。このビルドにチェッカーがないルールは、提供されたまま保持され、**Unchecked**と表示されます。

Lolly Demoには、承認済みの組織のルールが4つあります。見出しをすべて大文字にすることはありません。このルールは必須なので、`lolly check`はすべて大文字の見出しをエラーとして報告します。ほかの3つは推奨です。本文は左揃えにします。基本のマークは明るい背景に、反転したマークは暗い背景に置きます。破線はドロップする場所を示します。

**Try your design system in use**は、**Render & check examples**で現在のリビジョンから4つの例をレンダリングします。**Mode**を選び、**Try your own text**で見出し、補足テキスト、スライドのテキストを試します。各例には測定内容が報告され、**See checks & sources**と**Download check report**があります。**Make reusable poster**は、固定のレイアウトと承認済みの入力の選択肢を持つ`.lolly`をダウンロードします。例はローカルのものです。チェックを実行しても、公開や承認は行われません。

固定のブランドを含むビルドは、*This brand is set*の下に、同じルールと例を読み取り専用で表示します。

## スキル

**Skills**には、使用中のデザインシステムの[ブランドスキル](/info/brand-skills.html)が一覧表示されます。人とAIエージェントのために、分野ごとに1つずつ文書化したブランドの基準です。各行には、分野、ブランド自身による状態(**Draft**または**Approved**)、スキルが公開か内部用か、リビジョンが表示されます。行を選ぶと、スキルをその対応範囲とともに読めます。対応範囲はスキルの各行とトークンを比較し、Lollyが確認するもの、矛盾するもの、一致するもの、指針だけのものを示します。

**Download skill (.zip)**は、エージェントツール向けにスキルをAgent Skillsフォルダとして書き出し、カタログのリンクはこのLollyを指します。**Copy as one file**は、チャットウィンドウ用に同じテキストをクリップボードに置きます。独自のスキルがないデザインシステムには、基本のスキルが表示されます。Lollyが読み取りのたびに、そのトークンと組織のルールから作成するものです。このルームはスキルを読み取り、編集することはありません。

## ブランドを取り込む

**Add from…**をバーで選ぶと、形式ではなく、手元に何があるかを尋ねるピッカーが開きます。

- **Design tokens or a design file**: DTCGまたはTokens StudioのJSON、Penpotのプロジェクト、トークンセットのzip、Lollyのデザインシステムパック、SVG、`DESIGN.md`、ブランドページのフォルダ。
- **PDF**: デッキまたはガイドラインのファイル。このデバイス上で色、マーク、埋め込まれた書体を読み取ります。
- **Logo or screenshot**: このデバイス上で画像を読み取り、パレットを提案します。読み取るのは色であり、書体やレイアウトではありません。
- **Saved web page**: 1つのHTMLファイルとそのCSSファイル、または貼り付けたHTMLやCSS。最大20ファイル、2 MBです。提供したテキストだけを読み取り、リンク先のリソースは取得せず、スクリプトは実行しません。
- **Font file**: TTF、OTF、WOFF。Typeルームを開き、そこで書体をインストールします。
- **Website**: 1ページから色と書体を読み取ります。このタイルは、ページを読み取れるデバイスにだけ表示され、使用する読み取り手段を示します。このデバイスのアプリ、または自分としてサインインしたバックグラウンドタブのブラウザ拡張機能です。URLを入力するだけではフィールドが埋まるだけで、取得ボタンを押すと同意になります。

デザインファイルのソースを選ぶと、次のカードに対応形式がアイコンのタイルで一覧表示されます。カード全体が1つのドロップ先です。スタジオにファイルをドロップすることもできます。

![インポートカード。対応形式が先頭にアイコンのタイルで並び、カード全体が1つのドロップ先になっています](/t/url-shot?url=%2F%23%2Fstart%3Fsource%3Dfile&width=1440&height=900&dpi=192&waitMs=1600&css=.start-import-modal%20.modal-msg%2C.start-import-modal%20.modal-title%7Bdisplay%3Anone%7D&cropSelector=.start-import-drop&walker=1&format=svg&dark=1&filename=bs-brand-import-formats)

- **Lollyのデザインシステムパック** (`.lolly`、または従来の`.zip`)は、1ステップでインストールされます。
- **Penpot**の書き出し(`.penpot`)は、そのデザイントークンを取り込みます。
- **Design Tokens** (W3C DTCG)または**Tokens Studio**のファイル(`.json`)は、そのトークンを取り込みます。読み手に指示の無視を求める説明、権限を主張する説明、コードの実行を求める説明は除外され、インポート時にその場所が示されます。
- **通常のSVG**は色を読み取り、その中から選べます。最初の色がPrimaryになります。
- **`DESIGN.md`** (`.md`)は、記述されたとおりのトークンで**Try these colours**に進みます。文章はブランドスキルの下書きとして保持でき、カードには、指示の無視やコードの実行を読み手に求める行、権限を主張する行が示されます。Skillsルームで**Keep this skill**を押すまで、エージェントとブランドページに下書きは表示されず、保持したスキルも内部用のままです。
- **ブランドページのフォルダ**は、フォルダとして選択、ドロップ、またはzipで渡すと、同じ確認画面に進みます。すべてのファイルをフォルダの`brand.json`と照合し、1つでも一致しないファイルがあると、フォルダ全体を拒否します。インポートではトークンを追加します。ロゴとフォントはフォルダ内に残ります。

::: warning 指示のチェックは行ごとに読み取ります
トークンファイルの説明から指示を除外するチェックは行ごとに読み取るため、別の言い回しを見逃します。知らない相手から受け取ったファイルは、トークンを適用する前に読んでください。
:::

Lollyは、提供されたファイルからブランドページを読み取ります。別のサイトのアドレスを取得することはありません。

### 独自の色の名称を持つファイル

トークンファイルや`DESIGN.md`は、main、accent、supporting、tertiaryなど、独自の名称を色に使えます。Lollyがそのような名称を見つけると、適用前の確認画面に各名称を一覧表示します。表示されるのは、名称、各表示での色、元のトークン、Lollyが提案する解釈です。Lollyはモデルを使わず、名称だけを短いリストと照合して解釈を提案します。リストにない名称は、ブランド独自の**By name only**として取り込まれます。どの名称も、名前の変更、用途の指定、別の解釈の割り当てができ、チェックを外して名前付きの色のまま保持することもできます。

**Install with these roles**は役割を書き込み、**Install without roles**はファイルを受け取ったままインストールします。そのような名称がないファイルは、このステップを省略します。Lollyが書き出したものなど、独自の役割を明示するファイルは、記述どおりに役割を表示し、変更せずにインストールします。後でColoursルームで編集できます。ターミナルには確認画面がありません。`lolly system import`は、明示されたレコードを保持し、ほかのファイルの名称は名前付きの色として残します。

### 参照資料を確認する

ロゴ、スクリーンショット、ウェブサイト、保存したページは、**Try these colours**を開きます。提案された色を使った例、変更できる**Main colour**、新しいシステムの名前が表示されます。説明欄には、適用時に起こることが示されます。使用中のトークン設定を、生成されたパレットと既定のスタイルで**置き換え**、フォントとライブラリのファイルを**保持**し、以前のシステムは**復元**できます。**Apply suggested settings**はチェックポイントを作り、ライトとダークのパレットを適用します。**Restore brand settings**で以前の設定に戻せます。**Change reference**は別のソースを選びます。

::: details 参照資料から読み取るものとデザインコンテキストのレポート
**Palette, source details and individual choices**は、読み取った内容、見つかったフォント名、プレビューのコントラストを表示します。フォント名は提案だけです。書体はTypeでインストールします。ソースの詳細には、確認できた場合、タイポグラフィ、間隔、パディング、角の値が含まれ、確認できないものには**Not observed**が付きます。保存したページやネイティブ機能によるウェブサイトの読み取りでは、宣言されたスタイルが報告されますが、ページで使われていない場合があります。ブラウザ拡張機能は、表示されている要素の一部から測定したスタイルを報告できます。これらは観察結果です。何もインストールされず、ソースの間隔が独自の間隔を置き換えることもありません。**Choose individual items in the tray**は、個々の項目を保持します。**Download design context**は、観察結果、提案されたトークン、ソース情報のJSONレポートを保存します(提供されたHTMLやCSSのSHA-256を含みます)。レポートに生のページテキストは含まれず、署名付きのContent Credentialでもありません。
:::

PDFとデザインファイルのインポートには、それぞれ専用の確認コントロールがあります。**Tray**内の項目は、その種類の素材を扱うルームで追加するまで、何も変えません。`#/start?source=<kind>`は、指定したソース(`file`、`pdf`、`image`、`font`、`url`、`page`)でピッカーを開き、`?import`は通常の一覧を開きます。

### 外観を探して比較する

BoardまたはSettingsのデザインシステム一覧から**Find a look**を開きます。このデバイスに保存したシステムや、再利用できるいくつかのLollyの例を閲覧し、名前、色のタグ、宣言されたフォントで検索できます。**Closest to my current palette**は、測定された色の類似度で並べ替え、同順位の場合はフォントの一致を優先します。品質のスコアではありません。

外観をクリックすると、実際の使用例でプレビューできます。プレビューでは何も変わりません。カードの**Use this look**は、その外観を適用します。保存済みのシステムは使用中のシステムになり、編集は行われません。例の色は、通常のチェックポイントの後で、開いているデザインシステムに取り込まれます。システムのロゴ、フォント、そのほか例が定義していないものは、そのまま保たれます。**Compare looks**は、各カードにチェックボックスを追加します。2つ選ぶと並べて比較できます。**Restore brand settings**は、以前の外観を復元します。保存済みのシステムには、**Details and design context**の下に編集可能な**Search tags**があります。例はLolly独自の配色で、スクレイピングで集めたものはなく、アカウントも必要ありません。

## デザインシステムを保存して移す

### デバイス間でブランドを移す

**Export**は、1つの**`LollyBrand-….lolly`**ファイルを書き出します。トークン、フォント、ロゴ、テーマの設定と、インポート時に確認される整合性マニフェストを含みます。1.0.7より前のWebリリースでは、ファイルの拡張子は`.zip`でした。Lollyは今もその拡張子を受け付けます。**Tokens (.json)**は、リポジトリ、ビルドのステップ、別のトークンツール向けに、フォントやロゴを含まないプレーンなデザイントークンのドキュメントを書き出します。

取り込むには、**Add from… → Design tokens or a design file**を使うか、スタジオにファイルをドロップします。アカウントやクラウドなしで、同僚からブランドを受け取ったり、別のインストール先に持ち込んだりできます。ブランドの受け手が別の組織に所属する場合に、ほかに何を送るかは[パートナーと作業する](/info/partners.html)で説明しています。コマンドラインからブランドを取り込むには、[`ingest:brand`](/info/configuration.html#brand-packs)をご覧ください。

**Fonts for Linux (.rpm)**は、追加したフォントをインストール可能なRPMにまとめます。自分でアップロードしたフォントがある場合、Lollyはまず再配布できることの確認を求めます。

### 以前の設定に戻す

バーの**More**を開き、**Restore brand settings**を選び、日付付きのチェックポイントを選択して**Restore**を押します。使用中のブランドの色、書体の設定、ほかのトークンが復元されます。フォントと画像のファイルはそのままです。Lollyはまず現在の設定を**Before restore**として保存するため、ブラウザを閉じた後でも復元を取り消せます。最新の20個のチェックポイントがこのデバイスに保持されます。スタジオに**Saving…**と表示されている間の編集も、再読み込み後に残ります。保存が終わらなかった変更は、カードから復元できます。

### バージョン

公開済みのバージョンは、このデバイスに保持される**永続的な名前付きのコピー**です。変わることがないため、(`designv`で)そのバージョンを固定したツールやリンクは、同じものを描画し続けます。独自のものを含むシステムでは、バーの**More**メニューに**Versions & publishing**が表示されます。初めて公開すると、ルームに**Versions**が加わります。`#/start?area=versions`でVersionsが開きます。

::: warning 公開済みのバージョンは永続的です
削除機能はまだなく、パネルにもその旨が表示されます。公開は元に戻せませんが、復元は元に戻せます。*Restore latest from this version*は通常の編集であり、すぐに**Undo**が表示されます。
:::

**互換性カードでは削除が先頭に表示されます**。トークンを削除するとツールが壊れるためです。

**Publish only**は、ツールが追従するものを変えずにバージョンを保持します。**Publish and make active**は、ツールとアプリをそのバージョンに従わせます。**Follow the latest again**は、すべての編集をすぐに反映する状態に戻します。

### ブランドページを公開する

[ブランドページ](/info/brand-page.html)は、人とエージェントのための1つのアドレスです。ロゴ、色、書体、例を載せたページと、同じ情報を持つファイルを提供します。Versions & publishingの**Publish a brand page**には、ライブのページと、その横に次のものが表示されます。

- **Goes public**: すべてのファイルを、サイズ付きでグループ別に表示します。
- **Held back**: 除外されたものと、その理由です。ライセンスの記録がないロゴは、ロゴ名にチェックを入れるまで除外されます。フォントファイルには、再配布を認めるライセンスの記録が必要です。ファイルを除外する場合、ページにはアウトライン化された見本が表示されます。内部用のブランドスキルは表示されません。
- **What was checked**: カラーウェイとモードごとの色のペア、および組織のルールです。これらは測定結果であり、判定ではありません。
- **In your words**: 使用に関する声明と連絡先です。ページには自分で書いた内容がそのまま載り、Lollyはライセンスや法的な主張を追加しません。スイッチでフッターの「Made with Lolly」の行を非表示にできます。
- **On exports**: [このデザインシステムの書き出しにページのアドレスを記録する](/info/brand-page.html#lead-back-from-your-files)スイッチです。自分でオンにするまでオフのままで、`https`のアドレスが必要です。パックやコピーとともには渡されません。ロックされたデザインシステムでは、管理者が決めるため、このスイッチは表示されません。

**Download folder**は、選んだ場所でホストできるように、フォルダをZIPとして保存します。フォルダをホストするまで何も公開されません。ターミナルでは、`lolly system publish --out=<dir>`が同じフォルダを書き出します。ブランドページを配信するインスタンスには、そのアドレスへの**Publish to**もあります。明示的に1回押すと、インスタンスに承認の流れがある場合はそれを通ります。管理対象のデザインシステムは、管理者が許可した場合だけ公開できます。

### エージェントを接続する

**Connect an agent**は同じ場所にあり、貼り付けるテキストを提供し、各選択肢で何ができるかを示します。

- プロジェクト内の**`AGENTS.md`**: エージェントがシステムの名前とルールを読み取ります。描画は行わず、サーバーも必要ありません。
- **Lolly's public server**: ここで開いているシステムに関係なく、Lolly Demoで描画します。キーは必要ありません。
- **Your instance**: インスタンスが持つシステムで描画し、環境変数からサービストークンを読み取ります。シートには変数名が表示され、トークンが表示されることはありません。

使用中のシステムで描画するホスト済みサーバーがない場合、シートにその旨が表示されます。

## デザインシステムを管理する

システムの切り替え、追加、削除には、**Settings → Preferences → Design systems**を開きます。**Open**はシステムを選択してここで開きます。**Make a new one**はローカルのシステムを作成し、名前のフィールドに入力できる状態で開きます。デバイス全体で、一度に使用中になるシステムは1つです。ブランドに独自のデザインシステムが必要かどうかは、[ブランド構成](/info/brand-architectures.html)が判断に役立ちます。

**システムの提供元。** デプロイ先のカタログが提供するシステムには、**Came with this app**、またはインスタンスに接続したアプリでは**From this instance**と表示されます。**Catalogue source**を展開すると、提供者、トークンのアセットと名前空間、既知のバージョンまたはチェックサムを確認できます。更新に失敗した場合は、キャッシュされた内容にラベルが付きます。

**管理対象のシステムは読み取り専用です。** カタログがシステムをロックしている場合、そのシステムには**Managed by this instance**(インスタンスのないデスクトップアプリでは**Managed by this app**)と表示されます。管理対象のシステムも使用とダウンロードはできます。ここで開くと、読み取り専用の注記と**Make an editable copy**、**Switch**が表示され、続いて色の役割とトークンが編集コントロールなしで表示されます。管理対象のシステムが先にあった場合でも、独自のローカルシステムは編集可能なままです。固定のブランドを1つ持つビルドは、Lolly Design System Setupの*This brand is set*を開き、ブランドのトークンと使用ルールを読めます。

**それ以外の提供されたシステムは、どれも自由に**非表示、編集、リセットできます。lolly.toolsのLolly DemoとLolly Starterも含まれます。編集しても名前は保たれ、行に**Edited here**と表示されます。メニューの**Reset to original**は、このデバイスで行った変更を破棄します。空のスターターは例外です。初めて変更すると独自のデザインシステムが作られ、Lollyが名前を1回尋ねます。[Lolly Demoを使う](/info/lolly-demo-in-use.html#switch-to-your-own)では、独自のシステムが何を置き換えるかを示しています。

### デザインシステムを削除する

システムのメニューから**Remove**を選びます。確認画面には、削除後にどのシステムが使用中になるかが表示されます。保存済みのセッション、アップロード、別のシステムと共有している素材は残ります。

提供されたシステムを削除しても、そのシステムが非表示になるだけです。カタログのアセットは残り、**Bring back**で再表示でき、ほかのすべてのシステムを削除すると自動で戻ります。インポートまたは編集したコピーを削除しても、提供されたシステムやそのロゴ、フォントは削除されません。コピーが使用中だった場合は、提供されたシステムが再び使用中になります。使用中のホスト済みコピーを削除すると、そのコピーの接続だけが解除されます。別途選んだインスタンスは、選択されたままです。

::: details サーバーが提供するデザインシステムを変更する
サーバーが提供する内容の変更は、管理者の作業です。運用者が元のカタログを変更して再デプロイするか、Lolly Workの管理者がサーバーの変更を確認して適用します。ここでの編集は、1つの例外を除いてローカルにとどまります。`brand.edit`を付与されたLolly Workインスタンスでは、管理対象のシステムにもそのインスタンス向けの**Edit for**が表示され、編集用のコピーを開きます。**Versions**のそのインスタンス向けの**Send to**は、色、カラーウェイ、色の役割、ブランドページのアドレスを送り返します。[スタジオからこのインスタンスを編集する](/info/work-design-system-administration.html#edit-this-instance-from-the-studio)では、編集で変更できるものと、インスタンスがその変更を配信する仕組みを説明しています。[カタログのデザインシステムを削除する](/info/configuration.html#removing-a-catalogue-design-system)と[設定](/info/configuration.html#supplied-and-local-design-systems)をご覧ください。
:::

## アプリの外でデザインコンテキストを使う

**Download design context**は、トークンのドキュメント、解決済みの色、宣言されたフォントファミリー、アセットのid、記録されていればソースの根拠、対応範囲、明示的なルールを保存します。フォントファイルや所有権の証明は含みません。コマンドラインは、サーバーなしでファイルを読み取ります。`lolly system import`はそれをターミナルのデザインシステムにし、`lolly system check`は保存されたコンテキストに照らしてLolly Designの入力を確認します。インポートは[デザインシステムを持ち込む](/info/cli.html#bring-your-design-system)で、チェックは[コマンドが使うデザインシステム](/info/cli-decks.html#which-design-system-a-command-uses)で説明しています。MCPクライアントは、`lolly://design-context`から同じブリーフを読み取ります([MCP Server](/info/mcp.html))。
