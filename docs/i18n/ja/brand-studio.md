# ブランドスタジオ

`#/start`にある**Brand Studio**は、ブランド(ロゴ、色、書体、その他のトークン、保管するファイル)を形作る唯一の場所です。ここで一度設定すれば、すべてのツール、ページ、エクスポートはレビューによってではなく*構造上*それに従います。

変更は行うと同時に**アプリ全体でライブプレビュー**されるため、色やフォントを確定する前に、それがあらゆる場所に反映される様子を確認できます。すべてオンデバイスです。ブランドのファイルとトークンがあなたのマシンから外に出ることはありません(Google Fontsを選ぶと、同意ダイアログの後にそのファミリーだけをGoogleから一度取得します)。ブランドは1つの[brand pack](#move-a-brand-between-devices)ファイルとして持ち運べます。

> **これはエディターです。ダッシュボードは鏡です。** ダッシュボード(`#/d`)の**Design system**タブはブランドを読み取り専用で*表示*するだけです。*編集*はここ`#/start`で行います。後で色を変更したい場合は、Brand Studioに戻ってきてください。

## ルーム

スタジオは、側面のレールに並んだ一連の**ルーム**で構成されています - 手順ではありません。何にも番号は振られておらず、何も他のものによって制限されておらず、どのルームにたどり着いても正当です。

- **Overview** - ハブです。今何が存在するかを一目で確認でき、各ルームへの入口があります。
- **Colours** - 色を1つずつ追加し、役割を割り当てたり、1色からパレット全体を生成したりします。
- **Type** - アプリ、ツール、すべてのエクスポートが参照する4つの書体です。
- **Logos** - あらゆる向きと処理を施したあなたのマークです。
- **Tokens** - 角の丸み、間隔、影、その他のシステムです。
- **Files** - ブランドが保持する画像、音声、モーションのファイルです。

電話では同じリストがヘッダーの下に固定された横並びのチップ帯になります。ルームを切り替えても何も再読み込みされません - エディターはすべてのパネルをマウントしたままにしており、要求されたものを表示するだけです。

`#/start?area=<key>`で**ルームへのディープリンク**が可能です。キーは`overview`、`color`*(URLではアメリカ式のスペルであることに注意)*、`type`、`logos`、`tokens`、`catalogue`(Filesルーム - パネルキーは永続的な契約なので、URLは旧名のままです)、`versions`です。`?tab=`は同じものを指す長年のエイリアスで、今も解決されるため、古いリンクやブックマークは引き続き機能します。認識されないものはデッドエンドにならず、Overviewを開きます。

**レールの下端**には、1つのルームではなくデザインシステム全体に属するアクションが固定されています。

- **Add from…** - ファイル、PDF、画像、フォント、ウェブサイトからブランドを取り込むためのソースピッカーです。下記の[Bring a brand in](#bring-a-brand-in)を参照してください。
- **Tray** - スキャンで見つかったものの、まだ確定していない候補です。スキャンが実際に何かを保持するまでは非表示のままで、保持した場合は件数が表示されます。その行で**Add**を押すまでは、中の何もあなたのブランドを変更しません。
- **Export** - デザインシステム全体を1つの`LollyBrand-….lolly`として書き出します。
- **Tokens (.json)** - リポジトリ、ビルドステップ、他のトークンツール向けの、単独のプレーンなdesign-tokensドキュメントです。
- **Restore brand settings** - インポートやブランド設定の置き換えの前に保存されたチェックポイントに戻ります。
- **Versions** - デザインシステムの名前付きコピーを公開、有効化、復元します。公開すべき独自のものができるまでは非表示です(または`?area=versions`リンクで名指しで要求された場合)。

## Overview

Overviewは最初のルームで、2つの顔を持っています。

**まだ何も選んでいない**状態では、**Make it yours**と表示されます。**Start from a reference**は、ロゴ、スクリーンショット、ウェブページ、デザインファイル用のソースピッカーを開きます。**Pick a colour**、**Choose a face**、**Add a logo**は、それぞれの既存のコントロールを直接開きます。どの経路も選択から始まります。開くだけでは何も書き込まれません。**Explore the tools**はいつでも利用できます。

自分のものが何かひとつでもできると、同じルームは**今あるもの**を示すようになり、あなたが作った件数が先頭に来ます。Coloursは、デザインシステムが持つ色の数を示し、継承された色が表示されている場合に限り、控えめな`· N starter`を添えます。その横のストリップには、あなたが選んだ色が先に並び、続いて細い区切り線と、色あせたスターターの色が並びます。Typeはロールごとに示されます(*見出し用のInter*、その下に*残りはStarter · SUSE, SUSE Mono*)。Logosは埋まっているスロット数、または**Not set**を示します。Tokensは角の丸みを示し、動かすまでは*starter*とタグ付けされます。Filesは、ライブラリが空の間**Nothing yet**と表示します。どのブロックもそのルームへの入口です。ここにあるのは件数だけで、進捗バーも完了カードも一切ありません - このスタジオでは何も義務付けられていません。

## Logos

まずはマークの入ったフォルダーを上部のドロップゾーンに丸ごと投入することから始めます。**"Drop marks here, or choose several at once"**は、手持ちのファイルを一度にいくつでも受け付けます。各ファイルはその形状とインクが読み取られ、**Waiting for a slot**の下に、判断内容を示すチップとしてキューに入ります - *"Looks like the Horizontal primary"*のように、根拠にした測定値とともに**Place**ボタン(そのスロットが既に埋まっている場合は**Replace**)が付きます。確信が持てない場合、チップはその旨を率直に示し、代わりに8つすべてを一覧にした**Change slot**を提示します。何かを押すまでは何も配置されません。

そのキューをめぐって2つのことが起こります。余分な余白のあるマークには、まず**トリムの提案**が示されます - それに回答するか、Escapeを押すと元のファイルがそのまま入ります。また、あるマークが空の兄弟スロットを満たせる場合、ルームは派生した**mono**版または**reverse**版を、*Generated*と表示された独自のチップとして提示します。これは、別の方法でそのスロットを埋めると再び消えます。

その下には、すべてのマークが最終的に収まるグリッド - **orientation × treatment**のスロットがあります。

- **Orientations:** Horizontal(ワードマーク+シンボルを横一列に)とVertical(縦に積み重ね、正方形や縦長のスペース向け)。
- **Treatments:** Primary、Primary reverse(暗い背景向け)、Mono(単色)、Mono reverse。

これで8つの任意スロットになります。スロットをクリックしてPNG、SVG、JPEG、WebPを追加できます。埋まっているスロットをクリックすると置き換えられます。どのスロットも任意で、すべてこのデバイス内にとどまります。

![ロゴマトリックス - 上部に各orientation、各treatmentが独自の破線スロットとして並び、すべて任意です](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dlogos&width=1440&height=1600&dpi=192&waitMs=1600&cropSelector=.be-logo-grid&format=svg&walker=1&dark=1&filename=bs-logo-slots)

- **Custom marks** - ブランド独自の名前を付けたマーク(アイコン、紋章、favicon)を**Custom marks**の下に追加します。名前を付けてファイルを選ぶだけです。
- **More identities** - サブブランド、製品、イベントは独自のロゴ一式を持てます。**+ Add another logo**を使って名前を付けてください。メインの一式は単に"Your logo"です。
- **Upload an SVG and Lolly reads its colours.** 新規インストールでは、ロゴからプライマリカラーを静かに設定し、その旨を伝えます。既存のブランドでは、代わりにその色を提案として提示します - Coloursルームで*"Found in the logo: #…"*と、その横に**Use as primary**ボタンが表示され、採用するか却下するか選べます。

## Colours

このルームはデザインシステムとともに成長します。まだ必要になっていないものはページに現れないため、最初の訪問は1つの決定だけで済み、残りはパレットの成長とともにやってきます。

### 最初の色

自分の色を持たないデザインシステムは、中央に1列だけの画面で始まります: **Start with one colour**、大きなライブチップ、フィールド、そしてロール、シェード、印刷設定はシステムが育つにつれて登場するという控えめな一文です。

- **チップがピッカーです。** それを押すと、スタジオ独自のOKLCHカードがチップの上に開き、フィールドが保持している内容(名前、ホイール、4つのダイヤル、アルファ、**Stored as**)を引き継ぎます。足元には**Cancel**と**Add colour**があります。ダイヤルをドラッグするとチップが塗られ、その場でフィールドが書き換わりますが、**Add colour**を押すまではデザインシステムには何も届きません。
- **フィールドはどんな表記でも受け付けます** - `#e0452b`、`rgb(224 69 43)`、`oklch(58% .19 32)`、あるいはプレーンな色名です - そして色の*リスト*をまるごと入力すると、1つずつ追加できるチップの列になります。
- **その横にはさらに2つの入口があります。** スポイト(それを持つブラウザでは)は画面から色を取り込み、**From an image**はこのデバイス上のスクリーンショットや写真を読み取り、見つかった色を提示します。
- **Addは決して無効になりません。** フィールドに読み取れるものが何もない場合はピッカーが開きます。これは通常、空のまま押したことを意味します。解析できないテキストの場合は、無効なボタンの代わりに、フィールドの下にその旨を伝える一文が表示されます。

最初の色は**primary**になり、追加に応えたチップがそれを伝えます - *"プライマリは今、鮮やかなバイオレットです"* - その横には**Fine-tune**があります。

### スターター

**スターター**とは、選ばれたのではなくアプリに最初から付属していたものすべてを指す言葉です。新規インストールには色がまったくありません: あるのは1本のニュートラルランプ、紙を通したインクだけで、誰も何も決めていない段階でも、サーフェス、テキスト、細い罫線が描画されるようにしています。これらのニュートラルは足場のようなものなので、色として数えられず、パレットペインにも描かれません。[Tokens](#tokens)ルームに**Neutrals · スターター · 9**として存在し、**Open**を押すとColoursペインで1つの折りたたまれたタグ付きグループとして表示されます(`#/start?area=color&group=neutral`)。

同じ言葉がすべてのルームに現れます: スターターの色に乗っているロールは*"スターターのPaperが代わりに表示されています"*と表示され、そのピッカーは**Choose…**を提示します。スターターの書体は**スターター**タグを身にまとい、色味は付きません。スターターの角の丸みはOverview上にタグ付けされます。継承された素材が破線の枠で描かれることは決してありません。ここでは破線の枠がドロップターゲットを意味するためです。

### パレットが育つにつれて

あなたの色は、広い画面では**In context**プレビューの横に並び、小さい画面ではその上に積み重なります。プレビューには、あなたのパレットを使ったポスター、チャート、インターフェースカードを表示できます。スターターの色は、あなたが追加した色とは別に、独自の折りたたみ可能なグループにとどまります。

個々の色を追加するか、シェードのセットを追加し、それぞれに役割を割り当て、必要なときに上級セクションを開いてください。カラーチャート、グラデーション、ダウンロードのコントロールはパレットとともにとどまります。

### ロール - ツールが読み取るもの

**Roles**はスウォッチの上に重なるレイヤーで、どの色がすべてのツールとエクスポートでそれぞれの役割を演じるかを決めます。Rolesは任意です(自由な3色だけでrolesを持たないデザインシステムも十分に良いものです)。どのスウォッチにも役割を割り当てられ、コントラストの読み取りは背景に対して測定され、まずAPCAが用いられます。

行は3通りの表示のいずれかで示されるため、ストリップは誰も下していない決定を主張することはありません:

- そのロールを担う自分の色があり、フル強度で表示されます;
- **スターターの*Paper*が代わりに表示されています** - 控えめな表示で、そのピッカーには**Choose…**があります;
- **↳ プライマリに従う** - そのロールは自分の色ではなく、プライマリを介して解決されます。

パレットにシェードができると、ストリップはツールが読み取れる7つのスロットすべてに広がります: Primary、Secondary、Surface、Text、Muted、Edge、On primaryです。On primaryはプライマリから導出され、**Derived**と表示され、ピッカーはありません。

**アプリ自身のアクセントカラーはトークンではなく設定です。** 既定では、インターフェースはデザインシステムに従い、クロームのアクセントはプライマリカラーを採用します。これは[プロフィール](/info/profile.html)の外観設定の1つ - **インターフェースはデザインシステムに従います** - で、オフにするとクロームはニュートラルのままになります。ツール、キャンバス、エクスポートはどちらの場合も影響を受けず、フォントと角の丸みは、この設定のオン・オフにかかわらずデザインシステムに従います。

### エキスパート用ウィング

構成プレビューとカラーロールの下には、4つの折りたたまれたセクションがあります。必要なものを開いてください。それぞれ`#/start?area=color&focus=<wing>`としてディープリンク可能で、ルームが他に何を表示していてもそれを開きます:

- **Explore shades & harmonies**(`focus=generate`) - 1色から完全なシェードのセットへ。下記で説明します。
- **Shade curves**(`focus=curves`) - ランプをポイントごとに作り直します。明度、彩度、色相にはそれぞれ独自のカーブがあり、L / C / Hで切り替え、下のシェードはドラッグに応じてライブで再生成されます。
- **Contrast**(`focus=contrast`) - **Contrast-lock**は選んだ背景に対してAPCAの目標値を満たすようランプの色調を調整し直し、各ステップは自身の色相と彩度を保持します。**Rotate hue**はランプ全体をホイール上でまとめて回転させ、各シェードは明度と彩度を保持します。
- **Print**(`focus=print`) - プライマリカラーが印刷でどうなるか: 自動の画面値、または固定されたCMYKビルド、あるいは指定のスポットインクです。

### 1色から、パレット全体へ

**Explore shades & harmonies**の中で、**Starting colour**を選びます。Lollyは、エンジンが他の場所でも使っているのと同じ知覚的な色の数学(OKLCH)を使って、マッチするシェードを提案します。提案を調整するには:

- **Scheme** - Mono、Complement、Analogous、Triad - セカンダリカラーがプライマリとどう関係するかを設定します。
- **Shades** - 3から20までのスライダー(デフォルト5)で、各ランプが生成するステップ数を制御します。
- **Fine-tune**(折りたたみ) - **UI intensity**(Muted / Deep)、**Contrast**(Comfort / High)、**Text on brand**(Auto / Light / Dark)。

開始色やコントロールを変更しても、変わるのは提案だけです。シェードをクリックするとその色が追加され、**Add 5 shades**を押すとグループ全体が追加されます(件数はShades設定に従います)。既存の色とロールはそのまま残ります。取り消すと追加が取り消されます。

**Primary**、**Neutral**、**Secondary**の各行に、提案されたシェードが表示されます。**Theme preview**を開くと、明暗の例とそれぞれのコントラスト読み取り値を確認できます。そこでNeutralまたはSecondaryのステップを選ぶと、提案されたテーマの基準点を調整できます。パレット全体の再構築は、この下で別途レビューされる操作のままです。

### パレットを作成する(ハーモニージェネレーター)

**Find matching colours**の中で、ハーモニージェネレーターはプライマリカラーから調和するアクセントカラーを提案します。**ハーモニー**を選びます - **補色**、**近似色**、**トライアド**、**テトラード**、**アナロガス**(これは独自の**アクセント**数、2から5、そして10°から45°の色相**角度**を伴います) - そして各候補には自動生成された分かりやすい名前と**+ Add**ボタンが付いてきます。1つ追加すると、その色は即座にパレットに入ります。1回の操作で1つのトークンです。**In context**は、追加した色をサンプルの構成でプレビューします。

### 生成したパレットを確定する

提案された色やシェードグループを追加しても、パレットの残りはそのまま保たれます。完全に置き換えるには、**Rebuild the whole palette…**を開き、**Preview full rebuild**を押します。レビューは変更内容を説明します: 割り当てた通りに保たれるロールの数、自分で追加した色のうち保持される数、再アンカーされるシェードカーブの数、再ピン留めされる印刷ロックの数、非表示のまま残る隠しシェードの数、色を保ったままのグラデーションストップの数です。

そのカードで**Apply rebuilt palette**を押すと確定され、**キャンセル**は何も変更せずに離脱します。実行後、カードにはすでにフォーカスされた**Undo**が用意されます - そしてスワップの*前*にデザインシステム全体のチェックポイントが取得されるため、「元に戻す」ことは復元であり、失われた午後にはなりません。

### パレット、チャート、各スウォッチ

パレットには、デザインシステムの色が折りたたみ可能なグループでリストされ、それぞれに独自の**+ Add**コントロールが付きます。作業を整理するために、グループを作成したり名前を変更したりできます。ロールが2枚目のタイルを作ることは決してありません: 1つのトークンは1つのタイルであり、ロールが指すタイルには代わりに小さな角のマーク(**P**、**S**、**Su**、**T**)が付きます。タイルの下にある**Colour chart**は、同じスウォッチの2つのビューに折りたたまれています - **Wheel**(OKLCHホイール - ドットをドラッグして色を変え、ドットをクリックして編集するか、空いている場所をクリックして新しいスウォッチを追加)と、表示可能な範囲が実際にどこで終わるかを示す**Gamut**チャートです。`#/start?area=color&focus=chart`は、`?wheel`が常にそうしてきたように、直接カードを開きます。

![パレットペイン。すべてのグループが折りたたみ可能で、ダウンロードピルが下端に配置されている](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dcolor%26focus%3Dgenerate%26seed%3D%2523e0452b&width=1440&height=1000&dpi=192&waitMs=1800&drive=click%3A%5Bdata-be-add-ramp%3D%22primary%22%5D%3Bwait%3A1200&cropSelector=.be-split-side&walker=1&format=svg&dark=1&filename=bs-palette-pane)

![OKLCHホイール - 角度が色相、外側への距離が彩度、グレーは側面のライトネスレールに沿って並ぶ](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dcolor%26focus%3Dgenerate%26seed%3D%2523e0452b&width=1440&height=900&dpi=192&waitMs=2400&css=.start-head%2C.be-pal%2C.be-gradients%7Bdisplay%3Anone%7D&drive=click%3A%5Bdata-be-add-ramp%3D%22primary%22%5D%3Bwait%3A1200%3Bclick%3A%5Bdata-be-chart%5D%20summary%3Bwait%3A900&cropSelector=.be-pal-wheel&walker=1&format=svg&dark=1&filename=bs-colour-wheel)

任意のスウォッチをクリックすると、そのエディタが開きます。

- **名前を変更**します。
- **色を設定**- ピッカーは知覚的な**OKLCH**スライダーで開き、**16進**、**HSL**、**RGB**、**CMYK**のモードがあります。値フィールドは有効なスペースで読み書き*両方*を行うため、16進を貼り付けたりインク割合を入力したりできます。CMYKを入力すると変換によって*画面上の*色が設定される点に注意してください - 正確なインクを固定するには、下の印刷ロックを使用してください。
- **保存形式**- スウォッチをどう永続化するかを選びます: **LCH**（デフォルト - 知覚的で広色域、編集に最適）、16進、RGB、HSL。正確な従来型の16進値やsRGB値に合わせて固定する必要がある場合は、これを上書きしてください。
- **用途**- ロールパネルに戻らずに、このスウォッチにブランドロールの1つを直接割り当てます。（ロール自身のタイルにはこれがありません - ロールはロールを取れません。）
- **印刷代替**（折りたたみ）- 色の印刷挙動をロックします。
  - **CMYK**- **自動**から**ロック**に切り替えて、自動sRGB→CMYK変換を正確なインク値（C/M/Y/K、0〜100）で上書きします。
  - **スポットカラー**- **なし**から**設定**に切り替えて、スウォッチをスポットカラーに固定します。**名前**（例: `PANTONE 186 C`）、任意の**ブック**、任意の**仕上げ**（デフォルトは通常インク）を指定します。インクがまったくインクではない場合 - 箔押し、エンボスやデボス、部分ニス、ソフトタッチ、型抜き、折り目、ミシン目などに使います。
- **他の色空間で**（折りたたみ）- 同じ考え方をさらに広げたもの: 各行はこのスウォッチが表現できる色空間であり、正準値から導出されるか、あなたが自分で指定するかのいずれかで、指定したものはエクスポート時に優先されます。

これらの印刷ロックは、CMYKのPDFやTIFFをエクスポートするときに印刷所が使用するものです - [エクスポート](/info/exporting.html#colour-profiles)を参照してください。

**スウォッチを削除する**のは安全です。派生したランプのステップとテーマロールは*非表示*になります（背後のトークンは引き続き解決されるため、下流で何も壊れません）。一方、自分で追加した色は完全に削除されます。

### 多数のスウォッチを扱う

各スウォッチには専用のドラッグハンドルがあります。ドラッグすると同じグループ内で色の並び替えができ、あるいはハンドルにフォーカスしてSpaceを押し、矢印キーで移動し、もう一度Spaceを押して配置することもできます。Escapeでキャンセルします。並び順はスタジオを再度開いても保持され、取り消すこともできます。色をグループ間で移動するには、スウォッチエディタの**Group**コントロールを使うか、複数の色を選んで**Move**を使います。トークン名とロールの参照はそのまま保たれます。

パレットペインでの選択はジェスチャーであり、モードではありません。最初に押すべきボタンはなく、バーは最初に選択されたタイルとともに現れ、最後のタイルが選択解除されると消えます。

- **ペインの空いている部分をドラッグ**すると矩形が描かれ、触れたタイルはすべて、グループの境界をまたいでも選択に加わります。折りたたまれたセクションは何も提供せず、一度も動かないドラッグは選択を解除します。
- **Shift-click**は読み順で範囲を選択し、**Cmd/Ctrl-click**は1枚のタイルを切り替え、通常のクリックはそのタイルのエディタを開きます。
- どのグループヘッダーにも**Select all**があり、タイルにフォーカスした状態での**Cmd-A**は、デザインシステムが持つすべての色を選択します - スターターの色は決して含みません。
- グリッドには1つのタブストップがあります。矢印キーで移動し、Shift+矢印で選択を拡張し、Spaceでタイルを切り替え、Deleteで選択を削除し、Escapeで解除します。(矢印はフォーカスを動かすだけです。チャンネルを微調整するには、先に`l`、`c`、`h`のいずれかを押してください。読み取り値がそう案内します。)
- タッチスクリーンでは矩形はありません。タイルを長押しすると選択が始まり、タップで追加します。グループごとの**Select all**が残りをまかないます。

バー自体には**{n} selected**と表示され、続いて**Move to**(既存のグループ、またはメニュー内で名前を付ける新しいグループ)、**Give a role**(選択した色が順番に次のロールを取っていくため、4枚のタイルを1回の操作で4つのロールすべてに割り当てられます)、**Download**(6種類のパレット形式のいずれかで選択範囲を書き出し)、**Copy values**(保存されている表記で色ごとに1行)、そして**Delete**が並びます。Move toとGive a roleは、パレットに動かせるシェードがあるときにのみ表示されます。1回のCtrl/Cmd-Zで、40件の移動、ロールの割り当て、削除といった一括操作全体を取り消せます - そして削除は、何を保持したかを伝えます。選択がこのルームでは削除できないタイルにも及ぶことがあるためです。

### グラデーション

任意の**グラデーション**パネルは、背景やアクセント用に、パレットからブレンドトークンを作成します。ブランドがグラデーションを使わないなら完全にスキップしてください。各グラデーションにはプレビュー、名前付きストップ(2〜8個)、角度があります。重要な挙動: **ストップはスウォッチを参照する**ため、そのスウォッチの色を変えるとグラデーションも追従します。補間はきれいなブレンドのためOKLCHで行われます。ストップを削除するとランが短くなります。

### パレットを他所へ持ち出す

パレットペインの下端に配置されたフローティングピルは、パレット全体を**デザイントークン(JSON)**、**CSS変数**、**CSSクラス**、**SCSS変数**、**GIMPパレット(.gpl)**、**Adobe Swatch Exchange(.ase)**としてダウンロードします - ブランドをそのままIllustrator、Figma、GIMP、スタイルシートに投入できます。ペインのスクロール領域の外に置かれているため、パレットがどれだけスクロールしても定位置を保ち、パレットにシェードができると表示されます。([アセット](/info/using.html#assets-your-library)からパレットをダウンロードすることもできます。)

## タイプ

このルームも同じように成長します。まだ自分の書体を持たない状態では、1枚のカードと1つの決定だけです: **プライマリ**は、現在それを担っている書体で読みやすいサイズに設定され、名前の横に**Starter**タグが付き、塗りつぶされた**書体を選択**ボタンと、*"選択するまで何もインストールされません。"*という一文があります。カードの下には*"見出し、コード、イタリックは、選択するまでプライマリに従います"*とあり、**Choose them separately**を押すと、残りの3枚のカードがこの訪問中ずっと表示されます。

![まだ書体が選ばれていないTypeルーム - 読みやすいサイズの1枚のカード、その上のStarterタグ、そして塗りつぶされたChoose a face](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dtype&width=1440&height=740&dpi=192&waitMs=1800&format=svg&walker=1&dark=1&filename=brand-type)

1つの書体を選ぶと、ルームは**4つのロールカード**、Fontsリスト、そしてライブサンプルへと展開します。この4つの書体は、アプリ、ツール、すべてのエクスポートが実際に参照するものです:

- **プライマリ**- 本文コピー、ボタン、すべてのツール。
- **見出し**- `h1`/`h2`用のディスプレイフェイス。
- **コード**- コードやデータ用のモノスペースフェイス。
- **イタリック**- 強調、引用、脇注のための本物のイタリックコンパニオン。

見出し、コード、イタリックは、割り当てるまでそれぞれプライマリにフォールバックするため、フォント1種類のブランドはここで何も決める必要がありません。

**色が付いているのは、あなたが選んだ印です。** カードが色付けされるのは、そのフェイスをインストールした場合のみです。スターターのフェイスは、パレットの継承グループが身にまとうのと同じ**Starter**タグを、控えめな色合いで、色付けなしでまといます。そして誰も選んでいないロールは、あたかも選ばれたかのようにプライマリの名前を繰り返す代わりに**↳ プライマリに従う**と表示されます。ボタンは、自分のフェイスでは**変更**、それ以外では**フェイスを選ぶ**と表示されます。カード上の操作は何も確定しません: ボタンは、そのロールに絞った**比較ステージ**を開きます。

![明らかになった4つのロールカード - それぞれが担当するフェイスで設定され、誰も選んでいない場合はStarterタグが付き、Italicはプライマリに従う](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dtype&width=1440&height=1000&dpi=192&waitMs=2600&drive=click%3A%5Bdata-be-typemore-toggle%5D%3Bwait%3A600&cropSelector=.be-typecard-grid&walker=1&format=svg&dark=1&filename=bs-type-specimen)

### 比較ステージ

![そのカードの下に開いた比較ステージ - 検索欄、ピン留めされたファミリー、そして1行のストリップに折りたたまれたカード群](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dtype%26focus%3Dstage&width=1440&height=740&dpi=192&waitMs=1800&format=svg&walker=1&dark=1&filename=bs-type-stage)

このステージはダイアログではなく**ルーム内にインラインで**、押したカードのすぐ下に開きます。開いている間、カードはロールとフェイスだけの1行ストリップに折りたたまれるため、スマートフォンでも最初の画面にステージが収まります。Escapeでキャンセルすると、開いた元のカードにキーボード操作が戻ります。

書体を選ぶのに必要な操作は3回だけです:

1. カードで**書体を選択**します。
2. ファミリー名を入力して**Preview**を押します - または、フィールドの下にある6つの**Pinned**ファミリーのいずれかを1回押します。カードはすでに読み込み中の状態で表示され、まだ見ていないフェイスの代わりにインターフェースのフェイスが表示される代わりに、サンプルが表示される場所にはスケルトンバーが現れます。
3. **Use this face**を押します。

**同意は、あなたが押した操作に対して一度だけ求められます。** プレビューが初めてGoogle Fontsにアクセスするとき、ダイアログが何が起こるかを伝えます: *Googleはファミリー名とあなたのIPアドレスを知ります。そのファイルはこのデバイスに保存され、オフラインで使用されます。これはスタジオの中で唯一、第三者にアクセスするステップです。* **Google から取得**を押すと処理が進み、その選択は記憶されます。**キャンセル**を押すとカードには*"取得していません。Googleには何も送信されていません。"*と表示され、その場に有効な**Google から取得**が残るため、気が変わったときもカード上で1回押すだけで済みます。どのカードも無効なボタンを表示することはありません: どんな状態であっても、その1つのプライマリボタンが次に何をすべきかを伝えます。

**ステージにフォントファイルをドロップする**と、すぐにプレビューされます - 自分のマシンから**TTF**、**OTF**、**WOFF**を、これはすでに所有しているライセンス済みの企業書体のための経路です。そのドロップゾーンが、このルームで唯一のファイルの入口です。

いずれの方法でも、フェイスはこのデバイスに留まり、アプリ内で、あなたのツールで、そしてすべてのエクスポートでレンダリングされ、永遠にオフラインで機能し、デザインシステムファイルと一緒に移動します - レンダリング時に何も取得されません。Google Fontsにあるものはすべてオープンライセンス(OFL/Apache/UFL)で提供されています。

### このデバイスのフォント

**Fonts**パネルには、このデバイスが持つすべてのフェイスと、それが担うロールが一覧表示されます。追加したフェイスは**In the design system**の下に先頭で並び、それぞれにロールと削除ボタンが付き、Primaryを担っているものにはバッジが付きます。スターターのフェイスは、その後に1つの折りたたまれた行として続きます - *Starter · SUSE, SUSE Mono · 選択するまでPrimaryとCodeを担当* - 控えめな表示で、削除ボタンも昇格させる手段もありません。どちらも誰かが下した決定ではないためです。**Add a face**は、範囲指定なしで同じ比較ステージを開きます。

下部の**Type roles**パネルには、各ロールのライブサンプルが表示されます - プライマリでの本文とUI、上位見出し用の任意のディスプレイフェイス、強調用のイタリック、コードとデータ用のモノ - それぞれの横にファミリーとその状態(*Inter*、*SUSE · starter*、*SUSE · follows Primary*)が添えられ、セット全体を一度に確認できます。

## トークン

デザインシステムの残りの部分を、コードに触れずに編集できます。

![トークンルーム - 角丸スライダーに加え、スペーシング、サイジング、シャドウ、その他のシステム](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dtokens&width=1440&height=740&dpi=192&waitMs=1600&format=svg&walker=1&dark=1&filename=brand-tokens)

- **角丸**- アプリ全体のカード、ボタン、パネルが従う単一の半径スライダー(0〜1.5rem)。
- **Neutrals**- 新規インストールに付属する紙を通したインクのランプで、**Neutrals · スターター · 9**として9つのステップとColoursペインへの**Open**とともに一覧表示されます。スターターのニュートラルを管理できる唯一の場所であり、ランプが生成された瞬間に、継承ではなく*starter*タグが付きます。
- **その他のトークン**- **スペーシング**、**サイジング**、**線幅**、**不透明度**、**回転**、プレーンな**数値**、**シャドウ**を追加・編集します。タイプを選び、名前を付け(*Gutter、Card shadowなど*)、値を設定します。これらは標準の[デザイントークン](/info/design-tokens.html)(DTCG)として保存され、ブランドと一緒に移動します。

## ファイル

ブランドが保持するファイル - ロゴを除く - をここにドロップします: **ベクター**、**画像**、**音声**、**モーション**(動画、Lottie、アニメーション)アセット。これらは[アセット](/info/using.html#assets-your-library)に入り、セクションごとに整理され、すべてのツールのアセットピッカーですぐに使えるようになります。すべてこのデバイスに留まります。(レール上のラベルはこのルームを**ファイル**と表記していますが、URLキーは`catalogue`のままです。パネルキーは永続的な契約であるためです。)

## ブランドを取り込む

レール下部の**追加元…**は、2段階のピッカーを開きます。最初の段階では、フォーマットではなく、あなたが*何を持っているか*を尋ねます。

- **デザイントークンまたはデザインファイル**- DTCGまたはTokens StudioのJSON、Penpotプロジェクト、**トークンセットのzip**、Lollyデザインシステムパック、またはSVG。
- **PDF**- デッキやガイドラインファイル。このデバイス上で、色、マーク、埋め込まれた書体を読み取ります。
- **ロゴまたはスクリーンショット**- 画像から提案パレットが作られ、このデバイス上で読み取られます。何もアップロードされません。これは色を読み取るものであり、画像内の書体やレイアウトではありません。
- **保存済みウェブページ**- 1つのHTMLファイルとそのCSSファイルを選ぶか、HTMLまたはCSSを貼り付けます。合計20ファイル、2MBまでです。読み取られるのは提供されたテキストのみで、リンクされたリソースは取得されず、スクリプトも実行されません。この経路は拡張機能やデスクトップアプリがなくても機能します。
- **フォントファイル**- TTF、OTF、WOFF。Typeルームが開き、そこでフェイスがインストールされます。
- **ウェブサイト**- 1ページ分を、その色とタイプについて読み取ります。このタイルは、実際にページを読み取れるデバイスにのみ表示されます。誰も押せないものを宣伝する無効なタイルは、タイルがまったくないより悪いからです。表示される場合は、どの読み取り手段が使われるかを明確に示します: このデバイス上でアプリによって取得されるか、あなたとしてサインインしたバックグラウンドタブでブラウザ拡張機能を通じて読み取られます。URLを指定するだけではフィールドが*事前入力*されるだけです - 取得ボタンが同意にあたるため、誰かが送ってきたリンクだけで読み取りが始まることは決してありません。

デザインファイルのソースを選ぶと、第2段階は下のカードです。受け付けるフォーマットが優先順にアイコンタイルとして先頭に並び、カード全体が1つのドロップターゲットです - カード上のどこをクリックしても、ファイルをドラッグしても構いません。ファイルをスタジオに直接ドロップすることもできます。

![インポートカード - 受け付けるフォーマットが優先順にアイコンタイルとして並び、カード全体が1つのドロップターゲットになっている](/t/url-shot?url=%2F%23%2Fstart%3Fsource%3Dfile&width=1440&height=900&dpi=192&waitMs=1600&css=.start-import-modal%20.modal-msg%2C.start-import-modal%20.modal-title%7Bdisplay%3Anone%7D&cropSelector=.start-import-drop&walker=1&format=svg&dark=1&filename=bs-brand-import-formats)

各デザインファイルが提供するもの:

- **Lolly design-system pack**(`.lolly`; 旧式の`.zip`も引き続き受け付けられます) - 1ステップでインストールされます;
- **Penpot**エクスポート(`.penpot`) - そのデザイントークンを取り込みます;
- **Design Tokens**ファイル(`.json`) - W3C DTCG;
- **Tokens Studio**ファイル(`.json`) - Tokens Studio;
- **プレーンなSVG**(`.svg`) - Lollyがその色をスキャンし、どれを残すか選ばせます。最初のものがプライマリになります。

ロゴ/スクリーンショット、ウェブサイト、または保存済みページは**Your suggested design system**を開きます。提案された色を使った例を確認し、必要であれば別の**Main colour**を選び、システムに名前を付けます。**Use this design system**を押すと、生成されたライトとダークのパレットが適用され、Overviewに戻ります。既存のフォントはそのまま残ります。これはアクティブなシステムの色やその他のトークン設定を置き換えます。まずチェックポイントの取得が成功する必要があります。**Restore brand settings**で以前の設定に戻せます。

**Source details and individual choices**は、何が読み取られたか、検出されたフォント名、そしてプレビューのテキスト/アクションのコントラストを示します。また、**Choose individual items in the tray**と**Download design context**も提供します。JSONレポートには観察結果、提案されたトークン、ソース情報が含まれます。保存されたHTML/CSSには、提供されたテキストのSHA-256が含まれます。生のページテキストは含まれず、署名済みのContent Credentialでもありません。フォント名は提案にすぎません: フォントを選んでインストールする場所は、引き続きTypeです。

PDFやその他のデザインファイルのインポートは、既存のレビューコントロールをそのまま使います。**Tray**に保持された項目は、その素材の種類を所管するルームを通じて追加されるまで、何も変更しません。

`#/start?source=<kind>`は指定したソース(`file`、`pdf`、`image`、`font`、`url`、`page`)でピッカーを開き、`?import`はプレーンなリストで開きます。

## デバイス間でブランドを移動する

レール下部の**エクスポート**は、単一の**`LollyBrand-….lolly`**を書き出します - トークン、フォント、ロゴ、テーマ設定に加え、戻す際に検証される整合性マニフェスト付きです。1.0.7より前のWebリリースでは、同じペイロードを`.zip`と名付けていました。この旧式の表記も引き続き受け付けられます。その横の**Tokens (.json)**は、プレーンなデザイントークンドキュメントだけを単独で書き出します。フォントもロゴもなく、トークンのみです。これはリポジトリ、CIステップ、他のトークンツールが実際に読み取るものです。

それを戻すには、**追加元… → デザイントークンまたはデザインファイル**（上記）を使うか、スタジオへのドラッグ&ドロップで行います。これは、同僚がブランドをあなたに渡す方法、あるいはあなたが2台目のインストールへブランドを持ち込む方法です - アカウントもクラウドも不要です。コマンドラインからブランドを取り込むには、代わりに[`ingest:brand`](/info/configuration.html#brand-packs)を参照してください。

## 以前の設定を復元する

レール下部の**Restore brand settings**を選び、日付の付いたチェックポイントを選択して、**Restore**を押します。これは、アクティブなブランドの色、タイプ設定、その他のブランドトークンを復元します。フォントと画像ファイルはそのまま残ります。

Lollyは、チェックポイントを適用する前に、現在の設定を**Before restore**として保存します。そのチェックポイントを選ぶと、ブラウザを閉じて再度開いた後であっても、復元を元に戻せます。最新の20件のチェックポイントがこのデバイスに保持されます。ストレージが読み取れない場合や現在の設定を保存できない場合は、ダイアログが問題を報告するので、再試行できます。

## バージョン

レールの下部にある**Versions**は、デザインシステムが動き続ける標的であることをやめる場所です。公開すると、このデバイスに保存される**恒久的で名前の付いたコピー**が得られます。それ以降は変更されないため、それを固定したツールは常に同じものを描き続けます。パネルは、公開すべき自分のものが存在するまでは非表示のままなので、一度も公開しないスタジオがコントロールを目にすることはありません。

何かを押す前に知っておくべき3つのことがあり、パネルは押す前にこの3つすべてを提示します(押した後ではなく)。

- **バージョンは恒久的です。** 削除機能はまだないため、パネルには何が保持されているか、そしてそれが保持され続けることが明記されており、嘘をつくボタンを用意することはありません。
- **削除は互換性カードの先頭に表示されます。** 追加・変更されたトークンはニュースですが、*削除*されたトークンはツールを壊すものなので、真っ先に名指しでそう呼ばれます。
- **公開は取り消せませんが、復元は取り消せます。** *Restore latest from this version*はヘッドに対する通常の編集にすぎないため、スタジオの取り消しスタックに乗り、パネルはすぐに**Undo**を提供します。

**Publish only**、または**Publish and make active**を選べます。違いは、ツールとアプリが今後そのバージョンに従うか、それとも最新の編集に従い続けるかです。**Follow the latest again**を選ぶと、すべての編集が行われた瞬間にライブに反映されます。`#/start?area=versions`はパネルを直接開きます。

## ブランドが固定されている場合

一部のビルドは、SUSE Brandのような**ロックされたデザインシステム**を出荷します。それを開くと、**編集可能なコピーを作成する**と**切り替え**を備えた読み取り専用のメモが表示されます。元の色、フォント、トークンはそのまま維持されます。ロックされたシステムがそのデバイス上で最初のものであっても、あなた自身のローカルシステムは編集可能なままです。プロフィールでは、**Open**でシステムを選んでそのスタジオを開き、**Make a new one**でローカルシステムを作成し、名前欄にフォーカスした状態で`#/start`を開きます。

## ルックを見つけて比較する

OverviewまたはProfileのデザインシステム一覧から**Find a look**を開きます。このデバイスに保存されたシステムと、いくつかの再利用可能なLollyの例を閲覧できます。名前、カラータグ、宣言されたフォントで検索します。**Closest to my current palette**は、測定された色の類似度で並べ替え、同点の場合はフォントファミリーの一致で決めます。品質のスコアではありません。

1つのルックを選んでレビューするか、2つ選んで比較します。レビューボタンは小さな画面でも利用できます。ルックを選んでも何も変わりません。**Use this saved system**は既存のデザインシステムレジストリを切り替えます。**これらのカラーを使用**は、通常のチェックポイントとインストールの流れを通じて例を適用し、現在のフォントは維持します。**Restore brand settings**で以前のルックに戻せます。

**Details and design context**の下で、保存済みのシステムには編集可能な**Search tags**とコンテキストのダウンロードがあります。例には独自のLollyカラーレシピが使われています。リモートでスクレイピングされたインスピレーション集も、必須のアカウントもありません。

## ソースの根拠を読む

ソースレビューの任意の詳細では、観察されたタイポグラフィ、間隔、パディング、角の値が示されます。保存されたHTML/CSSやネイティブなウェブサイトの読み取りは宣言値を報告しますが、それがレンダリングされたページで実際に使われているとは限りません。ブラウザ拡張機能は、そのビューポートとブラウザの色設定とともに、可視要素の限られたサンプルから測定されたスタイルを報告できます。古い拡張機能は引き続き宣言値で動作します。欠けているフィールドは**Not observed**と表示されます。

これらは観察結果であり、自動的なスタイル設定ではありません。フォントファイルは参照スキャンによって取得もインストールもされず、ソースの間隔があなた自身のものを黙って置き換えることもありません。件数はサンプル内での出現回数を表すものであり、信頼度や品質ではありません。

## デザインシステムに対して構成をチェックする

Designで**Export**を開き、**書き出す前に**を開きます。このチェックは、レンダリングと同じ有効なデザインシステムのバージョンを使用します。作成された色、トークンのエイリアス、フォントの選択、画像アセットIDを比較します。カスタム値は意図的である場合もあります。宣言されたブランドアセット以外の画像はレビュー項目であり、禁止された画像ではありません。

具体的な色やフォントの提案がある場合、そのボタンはその1つのレイヤーだけを変更します。通常の**元に戻す**で元の値に戻せます。ロックされた、または変更されたレイヤーは、古い提案によって上書きされません。ソースの根拠が欠けている場合は、一致とは別に扱われます。レンダリングされたコントラストとテキストのレイアウトは、既存の組み込みチェックによって確認されます。グラデーション、エフェクト、入れ子になったツールのコンテンツ、権利、主観的な品質は、ブランド比較では評価されません。チェックは**ダウンロード**をブロックしません。

## デザインコンテキストをローカルで使う

**Download design context**には、トークンドキュメント、解決済みの色、宣言されたフォントファミリー、アセットID、記録されている場合のソースの根拠、カバレッジ、明示的なルールが含まれます。フォントファイルや所有権の証明は含まれません。リファレンスレビューには、提案されたトークンと観察結果も含まれます。

CLIは、サーバーなしでどちらのダウンロードも読み取れます:

```bash
lolly system import ./lolly-design-context.json
lolly system context --output=design-context.json
lolly system check ./design-inputs.json --file=design-context.json
```

`system check`は、`boxes`配列を持つDesignの入力、またはコンパイル済みのDesignドキュメントを受け付けます。構成を変更することなく、提案された修正を報告します。ブラウザのレイアウトやレンダリングされたコントラストを測定することはできません。既存のMCPリソース**lolly://design-context**は、設定済みのローカルMCPプロセスを通じて、有効なシステムのコンテキストを公開します。新しいホスト型サービスもAPIキーも必要ありません。
