# Lolly Design System Setup

<a id="design-system-setup"></a>

ロゴ、色、書体は1か所にあるべきもので、そうすればすべてのツール、ページ、書き出しがそれらで描画されます。その場所が`#/start`の**Lolly Design System Setup**です。

お持ちのものから始めてください。ロゴをドロップすると、Lollyがその色を読み取ります。書体を選ぶか、会社がライセンスを持つフォントファイルをドロップします。変更は、アプリ全体にすぐ反映されます。ロゴ、フォント、トークンは、このデバイスにとどまります。外部に接続する唯一の手順がGoogleフォントの選択で、Lollyは先に確認を求めてから、そのファミリーを一度だけ取得します。

見た目が整ったら、デザインシステムに名前を付けて**Export**を押します。保管用、別のデバイスで開く用、同僚に渡す用の、1つの`.lolly`ファイルが得られます。[Lolly Settings](/info/dashboard.html#design-system)には、現在のシステムが読み取り専用で表示され、その表紙からここへ編集のリンクが戻ります。

## 5分で自分らしく

::: timeline
- <!--i:upload--> **ロゴをドロップする。** **Logos**のドロップゾーンにドロップします。Lollyがその形と色を読み取ります。
- <!--i:palette--> **これらの色を使う。** ロゴの主要な色がプライマリになり、ロゴの濃いニュートラルがテキストの色になります。
- <!--i:font--> **書体を選ぶ。** **Type**で、Googleフォントか、お持ちのフォントファイルを選びます。
- <!--i:pentool--> **システムに名前を付ける。** 最初の編集でご自身のデザインシステムが作られ、Lollyが名前を一度だけ尋ねます。
- <!--i:download--> **Export**は、システム全体を1つの`LollyBrand-….lolly`ファイルとして書き出します。
:::

スタジオの上部のバーにはデザインシステムの名前があり、名前はいつでも変更できるフィールドです。**Enter**で新しい名前を保持し、**Escape**で元の名前に戻します。最初の編集で**What is this design system called?**と尋ねられたとき、ロゴが言葉を綴っている場合は、そこから取った言葉が入力されています。**Save name**は名前を保持し、**Not now**は、バーに入力するまで仮の名前を保持します。名前は、Settingsとシステムを切り替えるときのシステムのラベルになり、**Export**が書き出すファイルの名前にもなります。

## ルーム

スタジオは、順序の決まっていないルームの集まりです。番号は付かず、他の何かを待つこともありません。デスクトップでは、ルームはバーの下の1本の帯に並びます。スマートフォンでは、親指が届く下端のバーに移り、開いているルームが見える位置にスクロールされます。パレットのシートとトレイはそのバーの上に現れ、入力中はバーが脇によけます。キーボードでは、Tabで帯に一度だけ移動でき、矢印キー、Home、Endでルーム間を移動します。

![スタジオのバーとルーム: Board、Colours、Type、Logos、Tokens、Files、Rules、Skills](/t/url-shot?url=%2F%23%2Fstart&width=1440&height=900&dpi=192&waitMs=1600&cropSelector=.ds-top&waitSelector=.ds-room-nav&format=svg&walker=1&localize=1&dark=1&filename=brand-studio&try=1)

| ルーム | そこですること | リンクキー |
|---|---|---|
| **Board** | システムが持つものを確認し、各ルームへの入口がある | `overview` |
| **Colours** | 色を追加し、役割を与え、シェードとパレットを作る | `color` |
| **Type** | アプリ、ツール、すべての書き出しが読む4つの書体を選ぶ | `type` |
| **Logos** | あらゆる向きと処理でマークを配置する | `logos` |
| **Tokens** | 角丸、余白、影、その他すべての名前付きの値 | `tokens` |
| **Files** | ブランドが保持する画像、音声、モーションのファイル | `catalogue` |
| **Rules** | ブランドが適用するルールを、実際の例で確認する | `usage` |
| **Skills** | 人とエージェント向けに書かれたブランドの基準を、読んでダウンロードする | `skills` |

ルームへは`#/start?area=<key>`でリンクします。ルームのキーは恒久的な契約なので、Filesルームはキー`catalogue`、Boardは`overview`、Rulesは`usage`を保持し、`?tab=`も古い別名としてまだ動作します。不明なキーはBoardを開きます。

**バー**には、1つのルームではなくシステム全体に対する操作があります。**Add from…**はブランドを取り込み([ブランドを取り込む](#bring-a-brand-in))、**Tray**は、スキャンで見つかったもののまだ追加していないものを保持します。**Export**はシステムを1つのファイルとして書き出し、**More**には**Tokens (.json)**、**Fonts for Linux (.rpm)**、**Versions & publishing**、**Restore brand settings**、**Design systems**があります。**Design systems**は、切り替えを行うSettingsの一覧を開きます([デザインシステムを保管して移す](#keep-and-move-your-design-system))。それぞれ、操作の対象があるときに表示されます。スマートフォンでは、**Add from…**は**More**の中に移り、**Export**はアイコンで表示されます。

## Board

まだ何も選んでいない場合、Boardは始め方を4つ提示します。**Start from a reference**は、ロゴ、スクリーンショット、Webページ、デザインファイルのソース選択画面を開き、**Pick a colour**、**Choose a face**、**Add a logo**は、それぞれのコントロールを直接開きます。開いても何も書き込まれず、**Explore the tools**は最初から表示されています。

何かがご自身のものになると、Boardは、持っているものを、ご自身のものの数を先頭にして表示します。Coloursは色の数を示し、継承された色が表示される場合は、控えめに`· N starter`が付きます。そのストリップでは、ご自身の色が先に、続いて細い線、その後に薄く表示されたスターターの色が並びます。Colourwaysは、各カラーウェイを主要色の小さなタイルで示します。Typeは役割別に読み取れ、各ファミリーをそれぞれの書体で表示します(*Inter for headings*、その下の行に*Starter for the rest*)。Logosは埋まったスロットの数(または**Not set**)を示し、Tokensは角丸を示し、Filesはライブラリが空のあいだ**Nothing yet**と表示します。どのブロックも、そのルームを開きます。

Lolly Demoのように、アプリに付属していて編集できるデザインシステムには、最初からこれらがすべてあります。Boardには、その色、カラーウェイ、書体、マークが表示され、見出しの横に**Came with this app**タグが付きます。

### スターターとご自身のもの

**Starter**は、選んだものではなく、アプリに付属していたものすべてを指す言葉です。新規インストールには色がまったくなく、インクから紙までの1本のニュートラルなランプだけがあり、誰かが何かを決める前でも、サーフェス、テキスト、ヘアラインが描画できます。同じ言葉が、すべてのルームで継承された素材を示します。

::: cols
## Starter

- アプリに付属していたもの: インクから紙までのニュートラル、スターターの書体、既定の角丸。
- 控えめに、**Starter**タグが付き、色味はありません。
- ご自身の色としては数えられません。ニュートラルは**Tokens**に**Neutrals · starter · 9**として存在し、**Open**はそれをColoursに、折りたたまれた1つのグループとして表示します(`#/start?area=color&group=neutral`)。
- スターターの色の上にある役割は*"Starter Paper stands in"*と表示され、ピッカーに**Choose…**があります。

## Yours

- ご自身で選んだ、またはインストールしたもの。
- 通常の強さで、書体をインストールした場合は色味付きのカードで表示されます。
- BoardとTokensで数えられます。
- 別の役割に従う役割は、プライマリの名前を繰り返さず、**↳ follows Primary**と表示されます。
:::

継承された素材が破線の枠で描かれることはありません。ここでは破線の枠がドロップ先を意味するためです。

## Logos

マークのフォルダを、上部のドロップゾーンにまとめて入れてください。**"Drop marks here, or choose several at once"**は、いくつでもファイルを受け付けます。各ファイルは形とインクを読み取られ、**Waiting for a slot**の下で、外観を示すチップとして待機します。たとえば*"Looks like the Horizontal primary"*のように、使った計測値と**Place**ボタン(スロットが埋まっている場合は**Replace**)が付きます。判断に自信がない場合、チップはその旨を示して**Change slot**を提案し、8つすべてを一覧にします。何かを押すまでは、何も配置されません。

余白が余分にあるマークには、先にトリミングの提案が出ます。答えるかEscapeを押すと、元のまま入ります。マークが空いている兄弟スロットを埋められる場合、ルームは、派生した**mono**または**reverse**版を、*Generated*と記されたチップとして提案します。

すべてのマークは、**向き**と**処理**ごとに1つずつの、8つの任意のスロットのグリッドに収まります。

- **向き:** Horizontal(ワードマークとシンボルを横に並べる)、Vertical(正方形や縦長のスペース向けに縦に積む)。
- **処理:** Primary、Primary reverse(暗い背景用)、Mono(1色)、Mono reverse。

まだマークのないグループは1行に折りたたまれ、開くとそのスロットが表示されます。スロットをクリックするとPNG、SVG、JPEG、WebPを追加でき、埋まっているスロットをクリックするとマークを置き換えます。すべてはこのデバイスにとどまります。

![HorizontalとVerticalを開いたロゴスロット: 各処理がそれぞれ独立したスロットで、すべてのスロットは任意](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dlogos&width=1440&height=1600&dpi=192&waitMs=1600&drive=click%3A.be-logo-identity%3Edetails%3Anth-of-type%281%29%3Esummary%3Bclick%3A.be-logo-identity%3Edetails%3Anth-of-type%282%29%3Esummary%3Bwait%3A600&cropSelector=.be-logo-grid&format=svg&walker=1&dark=1&filename=bs-logo-slots)

- **Custom marks**は、アイコン、紋章、ファビコンなど、ブランドが独自の名前で呼ぶマークです。
- **More identities。** サブブランド、製品、イベントは、それぞれ独自の完全なセットを持てます。**+ Add another logo**を押して、セットに名前を付けます。メインのセットは「Your logo」です。ロゴのアイデンティティが適切な構成要素となるのはいつかは、[ブランドアーキテクチャ](/info/brand-architectures.html)で示しています。
- **Lollyはロゴの色を読み取ります。** ドロップゾーンの下、およびColoursの上部にも、ロゴの色を一覧にしたカードがあり、**Which is the main colour?**と尋ね、最も強い色(書き出された背景の白ではなく)がすでに選択されています。**Use these colours**は、それらをパレットに追加し、主要な色をプライマリにし、ロゴに紙の上で読める濃いニュートラルがある場合は、それをテキストの色にします。**Not now**は、それらをTrayに残します。新規インストールでは、最も可能性の高い答えがすぐに適用され、カードは**Undo**または別の主要な色を提案します。SVGは正確な色を与え、PNG、JPEG、WebPは、マークの実質的な割合を占める色を与えます。

## Colours

ルームはデザインシステムとともに成長します。最初の訪問では決定は1つで、残りはパレットが育つにつれて現れます。

### 最初の色

自分の色がまだないシステムでは、スターターのニュートラルがそれ専用のグループで開いた状態で表示され、ルームの上部には破線の貼り付け・ドロップ欄があります。大きなチップ1つと入力欄1つです。画像や色のリストを欄のどこにドロップしても、Lollyはドロップした内容から色を読み取ります。

- **チップがピッカーです。** **Pick a colour**を押すと、スタジオのOKLCHカードが開き、欄にある内容が初期値になります。最初に色の名前と16進値、色空間、ホイール、4つのダイヤル、アルファは**Fine-tune**の下にあり、下部に**Cancel**と**Add colour**があります。**Add colour**を押すまで、システムには何も反映されません。
- **欄はどの表記も受け付けます。** `#e0452b`、`rgb(224 69 43)`、`oklch(58% .19 32)`、または色名です。リストを貼り付けると、1つずつ、または**Add all**でまとめて追加できるチップの列になります。
- **ほかに2つの入り口があります。** **Pick a colour from the screen**は、ブラウザにスポイトがあればそれを使い、**Take colours from an image**は、このデバイス上のスクリーンショットや写真を読み取ります。
- **Addが無効になることはありません。** 欄が空のときはピッカーが開き、読み取れないテキストには、その旨を示す1行が欄の下に表示されます。

最初の色が**プライマリ**になり、チップが*"Primary is now Vivid Violet"*のようにそのことを確認し、色を調整する**Fine-tune**が付きます。


### パレットが育つにつれて

ご自身の色は、広い画面では**In context**プレビューの横に、小さい画面ではその上に並びます。プレビューには、ポスター、グラフ、インターフェースカードがご自身のパレットで表示されます。スターターの色は折りたたみグループにとどまり、システムが自分の色を持つと折りたたまれ、貼り付け・ドロップ欄は1行のコンパクトな表示になります。書き出しはバーの**Export**とTokensルームにあるため、ルームのヘッダーにはありません。

### Colour roles: 色の呼び名

デザインシステムは、その色が何と呼ばれ、それぞれ何のためにあるかを示し、Lollyはそれを読み取ります。**Colour roles**はColoursルームの先頭にあります。広い画面では**In context**がビューを分け合うため、変更はポスター、グラフ、インターフェースカードにその場で反映されます。

![Lolly Demo自身の言葉によるColour rolesの表: カラーウェイのチップ、続いてLead、Partner、Paper、Ink。それぞれにライトとダークの色があり、メインカラー、パートナーカラー、背景、テキストとして読み取られる。表の下には、どのロールも担っていない読み取りとしてQuiet textとHairlinesが並ぶ](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dcolor&width=2720&height=2000&dpi=192&waitMs=1800&cropSelector=%5Bdata-be-roles-fold%5D&format=svg&walker=1&dark=1&filename=bs-colour-roles)

表は4列で、スマートフォンでは各行がカード1枚になり、ライトとダークが並んだまま残ります:

| 列 | 内容 |
|---|---|
| **Role** | デザインシステム自身の言葉。その場で編集でき、その色が何のためにあるかを示す1行が付く |
| **Light**と**Dark** | 選んだカラーウェイの、その見た目での色。名前または値と、コントラストが付く |
| **Lolly reads this as** | ツールがそのロールをどう扱うか。Lolly自身の言葉で書かれる |

**Lollyがロールを読み取る方法。** 1つの読み取りは1つのロールにだけ割り当てられるため、別のロールが持つ読み取りを選ぶと、その読み取りはこちらに移ります。Lollyが言葉から意味を読み取ることはありません。

| 読み取り | そこから決まること |
|---|---|
| **Lead colour** | 大きな形、ボタン、ツールが主役にする色 |
| **Partner colour** | ツールが次に選ぶ2つ目の色 |
| **Background** | ほかのすべての背後に置かれる |
| **Text** | 見出しと本文 |
| **Quiet text** | キャプションと注意書き |
| **Hairlines** | 罫線、枠線、区切り線 |
| **By name only** | ツールが自分からこのロールを選ぶことはありません。すべての色の欄とDesignで選べ、Designでは選んだ色がリンクされたままなので、カラーウェイに追従します |

どのロールも担っていない読み取りは、デザインシステムが定義したままで、ルームは表の下にそれらを一覧します。Primaryというロールのように、読み取り自身のIDと同じIDを持つロールは、その読み取りそのものであり、移動できません。

**値。** 値を押すと、そのロールの、その見た目での、選んだカラーウェイの色を選べます。**Same as light**は、ダークの値が独自の色を選ぶまでライトの値に追従するようにします。**Aa**チップは、その色の上にLollyが選ぶテキストを示し、値の下の1行は、そのテキストの読みやすさを見た目ごとに示します: **Text reads well**、**Large text only**、**Hard to read as text**。これは色の上のテキストについての話で、色自体への評価ではありません。図形や広い面には、その色を使えます。名前のみで読まれるロールは、警告色なしで同じ言葉を表示します。ツールが自分からその上にテキストを置くことはないためです。言葉の根拠となる数値は、APCAが先、WCAGが後で、ツールチップとピッカーにあります。**Own text colour**は、ファイルがテキストの色を定めている値を示し、その色が維持されます。**Copied**は、別のカラーウェイまたはパートナーカラーから来て、まだ誰も選んでいない値を示し、ピッカーの**Keep this colour**で値が確定します。

**出発点。** 独自のロールがないデザインシステムには、現在の言葉であるPrimary、Secondary、Surface、Textが表示されます。変更するまで何も書き込まれません。**+ Add a role**は、**Primary、Secondary**または**Main、Accent、Supporting、Tertiary**を候補として、または入力した任意の言葉を、それぞれが得る読み取りとともに提示します。最初の2語がメインカラーとパートナーカラーになります。ツールは同じ色で描画し続け、メインカラーが1つのシステムでは、最初のカラーウェイはその色にちなんで名付けられます。

**名前の変更、並べ替え、削除。** 名前の変更は言葉だけを変えるので、そのロールを使うものはすべて動作し続けます。ロールはハンドルでドラッグするか、ハンドルでSpaceを押し、矢印キーで移動してSpaceで置きます。**Remove**は、そのロールをまだ使っているものを示します。ツールが読み取っている場合、**Remove and keep those colours**は、各読み取りに現在描画している色を残します。ハウスルール、ガイドグループ、ツールの欄、ロールを使う別のトークンは、その使用が変わるまでロールを保持します。保存済みのDesign書類もロールを名前で使えますが、Lollyはトークンファイルからそれを見られません。使っている書類は、その色を未解決として報告します。

**手書きのファイル。** トークンファイルが持つ色のうち、どのロールにも宣言されていないものは、**In this file, with no role yet**の下に一覧され、それぞれに言葉の入力欄と**Make a role**が付きます。どちらでも、名前で動作し続けます。名前に数字を含むトークンはロールにできないため、ファイルに残り、パスで動作し続けます。ファイル内の検証を通らない記録は、コントロールのない表を示し、その理由を伝えます。

**ルームのほかの部分も同じ言葉を使います。** チップ、スウォッチの**Use as**行、パレットの**Colour roles**グループはすべてデザインシステムの言葉を使い、カラーロールのタイルを開くとその値が開きます。書き出したファイルにロールについて新しく記録されるものはありません。レンダリングの色が変わるのは、トークンが変わったためです。

**言葉の行き先。** 言葉と説明は、デザインシステムとともに移動します。エージェントはデザインブリーフ、`lolly://tokens`、ブランドページの`AGENTS.md`で読み取り、ターミナルは`lolly system status`で表示し、ブランドページは`brand.json`にそれらを載せ、ロールごとにコントラストのペアを1つ測定します。各書き出し形式は、収まる範囲を保持します: DTCGとTokens Studioのファイルはすべてを保持し、`DESIGN.md`は言葉と読み取りを保持し、PowerPointのテーマはブランドの順序だけを保持します。完全な一覧は[他の形式でのカラーロール](/info/design-tokens.html#colour-roles-in-other-formats)にあります。言葉は常にデザインシステムのデータとして引用され、指示として読まれることはありません。

**色を選ぶ場所。** ツールとLolly Designのすべての色の欄は、デザインシステムのロールを、その独自の順序で先頭に表示し、各言葉と、その色が何のためにあるかを見せます。ロールの横の**Aa**は、そのロールの上に置く色を選びます。残りは**Other colours**の下に続き、カラーウェイ独自のコピー、オン・カラー、ロールがすでに担っている読み取りは含まれません。選んだ色はロールにリンクされたままカラーウェイに追従し、欄はどのカラーウェイを選んでも言葉を表示し続け、SettingsとTokensもその言葉を使います。ロールのないデザインシステムは、従来どおりのスウォッチのグリッドを保ちます。

### 役割: ツールが読むもの

**Colour roles**を閉じているとき、最初の判断がチップとしてルームの先頭に並び、それぞれが、そのロールを担う色とその名前を示します。独自の言葉がないシステムでは、**Primary**、**Secondary**、**Surface**、**Text**です。チップを押すと、パレット自身のスウォッチから色を選べます。**Colour roles**の末尾にある**Every colour a tool reads**に、全体のストリップがあります。

**ロール**は、すべてのツールと書き出しで、どの色がどの役を担うかを示します。任意です(ばらばらの3色でロールなしでも、まったく問題のないシステムです)。どの色にもロールを付けられ、読み出し表示は、サーフェスに対してテキストがどう読めるかを、APCAを先にして示します。各ロール行は、ご自身の色を最大の強さで、代役を務めるスターターの色を、または**↳ follows Primary**を表示します。

ストリップには、ツールが読める7つのロールすべてが表示されます: Primary、Secondary、Surface、Text、Muted、Edge、On primary。デザインシステムが独自の言葉を持つ場合は、その言葉で表示されます。On primaryはPrimaryから導かれ、**Derived**と表示され、ピッカーはありません。その横の**Light**と**Dark**のスイッチ、そして**In context**の横のスイッチは、ストリップ、パレット、プレビューがどちらの見た目を表示するかを選びます。

アプリ自身のアクセントは、既定でデザインシステムに従います。これが**Settings → Appearance**の**Interface follows the design system**設定です。この設定をオフにすると、アプリのクロームはニュートラルのままになりますが、ツール、キャンバス、書き出しは、どちらの場合もデザインシステムに従います。

**カラーウェイ。** デザインシステムは複数のメインカラーを持て、制作物ごとに選ばれます。**Colour roles**の先頭にある**Colourways**行は、カラーウェイごとに1つのチップを表示し、標準のものに**Default**が付きます。**+ Add**は、パレットの色の1つから新しいカラーウェイを始めます。チップを選ぶと、表、ストリップ、パレット、プレビューがそのカラーウェイを表示します。選んだカラーウェイは、名前の変更、複製、デフォルトにする、削除ができます。カラーウェイを持つシステムでは、すべてのカラーウェイに独自のプライマリとセカンダリが必要で、カラーウェイが背景に色味を付ける場合は独自のサーフェスも必要なので、これらのロールはスウォッチエディターで設定されたままになります。手順とトークン形式は[デザインシステムにカラーウェイを追加する](/info/colourways.html#add-colourways-to-a-design-system)に、実際の作業でのカラーウェイは[Lolly Demoの使用例](/info/lolly-demo-in-use.html#colourways-on-real-work)にあります。

### 生成したパレットを確定する

**Rebuild the whole palette…**を開き、**Preview full rebuild**を押します。確認画面には、割り当てたとおりに残る役割の数、残るご自身の色の数、再アンカーされるか維持されるシェードカーブ、印刷ロック、非表示のシェード、グラデーションのストップの数が示されます。**Apply rebuilt palette**で確定し、**Cancel**では何も変わりません。その後カードにはフォーカス付きの**Undo**が表示され、入れ替え前に作られたチェックポイントでシステム全体を復元できます。

カラーウェイを持つシステムは、再構築しても、すべてのカラーウェイを保持します。正規のカラーウェイは新しい開始色に従い、他のすべてのカラーウェイは、独自の色、名前、順序、設定を保ちます。確認画面には、どのカラーウェイが従い、どれが色を保つかが一覧になります。編集できない方法でカラーウェイを符号化しているシステムは、Lollyは再構築せず、カードがその理由を示して、何も変わりません。

### エキスパート向けセクション

プレビューと役割の下に、折りたたまれた4つのセクションがあります。それぞれ`#/start?area=color&focus=<name>`で直接開きます。

- **Explore shades & harmonies**(`focus=generate`)。上で説明したとおりです。
- **Shade curves**(`focus=curves`)は、ランプを点ごとに調整し、明度、彩度、色相のカーブ(L / C / H)が別々にあり、ドラッグするとシェードが再描画されます。
- **Contrast**(`focus=contrast`): **Contrast-lock**は、選んだ背景に対するAPCAの目標に達するように、ランプのトーンを調整し、**Rotate hue**はランプ全体を色相環に沿って回転させます。
- **Print**(`focus=print`)は、プライマリが印刷でどうなるかを設定します。自動の値、固定したCMYKの組成、名前付きのスポットインクです。

### パレットと各スウォッチ

パレットは色を折りたたみグループに一覧し、それぞれに独自の**+ Add**があります。グループは自由に作成、名前変更できます。ロールが2つ目のタイルを作ることはありません。ロールが指すタイルは、代わりにロールの名前(**Primary**など)を表示します。タイルの下の**Colour chart**は、同じ色をOKLCHの**Wheel**(点をドラッグして色を変更、空きスペースをクリックしてスウォッチを追加)と、表示可能な範囲の限界を示す**Gamut**チャートに表示します。`#/start?area=color&focus=chart`でチャートを直接開けます。

スウォッチをクリックして、そのエディターを開きます。

- スウォッチの名前を変更します(**Rename**)。
- OKLCHスライダー、または**Hex**、**HSL**、**RGB**、**CMYK**で色を設定します。値の欄は、有効な色空間で読み書きします。ここでのCMYKは、変換によって画面上の色を設定します。正確なインクを固定するには、**Print substitutes**を使ってください。
- **Stored as**は、スウォッチの保存方法を選びます: **LCH**(既定。知覚的で広色域)、Hex、RGB、HSL。
- **Use as**は、スウォッチに直接ロールを与えます。デザインシステムが独自の言葉を持つ場合は、その言葉で表示されます。強調表示されたロールをもう一度押すと、ロールが解除されます。
- **Print substitutes**(折りたたみ): **CMYK**を**Auto**から正確なインク値にロックするか、**Name**(`PANTONE 186 C`など)、任意の**Book**、箔押し、エンボス、デボス、スポットニス、ソフトタッチ、または型抜き、折り線、ミシン目の**Finish**を持つ**Spot colour**を設定します。印刷機は、CMYKのPDFまたはTIFFを書き出すときにこれらのロックを使います。[カラープロファイル](/info/exporting.html#colour-profiles)を参照してください。
- **In other spaces**(折りたたみ): 色空間ごとの値で、導出されたものも、ご自身で指定したものも可能です。指定した値は書き出し時に優先されます。

**スウォッチの削除**は安全です。導出されたシェードとテーマの役割は非表示になるだけなので、それらを読むものが壊れることはなく、追加した色は削除されます。

::: details 多数のスウォッチを扱う
各スウォッチにはドラッグ用のハンドルがあります。ドラッグしてグループ内で並べ替えるか、ハンドルにフォーカスを当ててSpaceを押し、矢印キーで移動して、もう一度Spaceで置きます。Escapeでキャンセルします。スマートフォンでは、パレットは1行に4色を表示し、ハンドルはすべての色の下に行として出るのではなく、Selectモードで表示されます。グループ間で色を移動するには、エディターの**Group**コントロールを使うか、複数を選択して**Move to**を使います。

選択に別のスイッチは要りません。バーとチェックボックスは、最初のタイルを選択すると現れ、最後のタイルの選択を外すと消えます。

- **空いている場所をドラッグ**して長方形を描くと、触れたすべてのタイルが、グループをまたいで選択に加わります。折りたたまれたセクションは何も追加しません。
- **Shiftクリック**は読み順での範囲を選び、**Cmd/Ctrlクリック**は1つのタイルを切り替え、通常のクリックはエディターを開きます。
- 各グループのヘッダーには**Select all**があり、タイルにフォーカスがある状態での**Cmd-A**は、スターターの色を除く、ご自身のすべての色を選びます。
- グリッドのタブストップは1つです。矢印で移動し、Shift+矢印で拡張し、Spaceで切り替え、Deleteで削除し、Escapeで解除します。チャンネルを微調整するには、先に`l`、`c`、`h`を押します。
- タッチ画面では、タイルを長押しして選択を始め、その後タップして追加します。

バーには**{n} selected**、続いて**Move to**、**Give a role**(各色が順に次の役割を受け取る)、**Download**(選択範囲を6つのパレット形式のいずれかで)、**Duplicate**(各色のコピーを元の後ろに配置)、**Copy values**、**Delete**が表示されます。コピーが1つの場合はそのままエディターで開き、複数の場合は選択されたままです。Cmd/Ctrl-Zを1回押すと、一括操作全体が元に戻ります。
:::

### グラデーション

任意の**Gradients**パネルは、パレットからブレンドトークンを作ります。各グラデーションには、プレビュー、2〜8個の名前付きストップ、角度があります。ストップはスウォッチを指すため、スウォッチを再着色するとグラデーションが追従します。ブレンドはOKLCHで行われます。

パレットのダウンロード(デザイントークン、CSS、SCSS、GIMP、Adobe Swatch Exchange)は、パレットのヘッダーの、見出しの横にあります。各形式は[パレットとフォントをどこへでも持ち出す](/info/using.html#take-your-palette-and-fonts-anywhere)で説明しています。

### 比較ステージ

ステージは、押したカードの下のルーム内で開き、スマートフォンの最初の画面にステージが収まるように、カードは1行のストリップに折りたたまれます。Escapeでキャンセルし、フォーカスはカードに戻ります。

1. カードの**Choose for**と役割を押します。
2. ファミリー名を入力して**Preview**を押すか、欄の下にある6つの**Pinned**ファミリーのいずれかを押します。
3. **Use this face**を押します。

**同意が求められるのは一度だけです。** プレビューが初めてGoogleフォントに到達するとき、ダイアログが次のように説明します。*Google learns the family name and your IP address. The file is then kept on this device and used offline. ### このデバイスのフォント

**Fonts**パネルは、このデバイス上のすべての書体と、それが担う役割を一覧にします。追加した書体は**In the design system**の下に先頭で表示され、それぞれの役割と削除があります。スターターの書体は、控えめな折りたたまれた1行として続きます。**Add a face**は、任意の役割の比較ステージを開きます。**Type roles**パネルは、各役割のライブの見本を、そのファミリーと状態(*Inter*や*Inter · follows Primary*など)とともに表示します。

## トークン

トークンは、デザインシステムの背後にある名前付きの値です。色、書体、ロゴ、角丸、余白など。ツールはそれらを名前で読むため、ここでの変更はすべてのツールに一度に届きます。

![Tokensルーム: システムの例とファイル操作のあるヘッダー、各種類のトークンを数えるタイル、続いてコントラスト表示付きの色のペア](/t/url-shot?url=%2F%23%2Fstart%3Ftab%3Dtokens&width=1440&height=740&dpi=192&waitMs=1600&format=svg&walker=1&dark=1&filename=brand-tokens)

- **ヘッダー**には、ご自身のシステムからの例(*Primary is Spearmint, #033633*)と、ファイル操作があります。**Download**(システム全体をデザイントークンとして、またはパレットを他の5つの形式で)、**Copy CSS**、JSONファイルを読み戻す**Add from…**です。
- **タイル**は各種類のトークンを数え、そのセクションにジャンプします。Colours、Type、Logos、Shape and spacing、More、All tokensです。各セクションが持つものを数えます。空のスターターのものだけを持つセクションには**Starter**タグが付き、アプリに付属するシステムは、タグなしで自身の素材を数えます。スマートフォンでは、タイルは3つずつ2行に折り返されます。
- **Colours**は、ツールが組み合わせるペア(サーフェス上のテキスト、プライマリ上、サーフェス上のミュート)から始まり、ライトとダークのAPCA値が表示され、足りないペアには**Weak contrast**の印が付きます。その後にすべての色グループが続きます。ランプは1行のチップとして、その他の色は値と、`{color.brand.spearmint}`のようにツールが使う参照とともに表示されます。参照を押すと、その参照がコピーされます。**Edit in Colours**はグループをColoursルームで開きます。[色のロール](#colour-roles-what-the-colours-are-called)があるデザインシステムでは、**Colour roles**が最初に表示され、各ロールがシステム独自の言葉と順序で1回ずつ並びます。ロールはカラーウェイと見た目ごとに色を保持し、それらの色は独立した色として現れず、ロールとともに保たれます。変更は**Colour roles**表で行ってください。
- **Type**と**Logos**は、各役割の書体と各ロゴスロットを一覧にし、ご自身のものがあれば**Edit in Type**と**Edit in Logos**が付きます。
- **Shape and spacing**には、**Rounded corners**(`shape.radius`)と**Spacing rhythm**(`space.base`)があります。それぞれ、スライダーを動かすまでは*Lolly default*、動かした後は*Yours*と表示され、すぐに保存され、元に戻せます。
- **More tokens**は、余白、サイズ、線の太さ、不透明度、回転、単なる数値、影を追加し、標準の[デザイントークン](/info/design-tokens.html)として保存されます。
- **App appearance (advanced)**は、Lolly自身の画面が使う色、サイズ、影を一覧にし、**Inspect every token (advanced)**は、保存されている任意の値を検索、編集し、変更ごとに先にレビュー用に表示します。そこでは、各カラーウェイにおけるロールの値がロールとともに一覧表示されます。ロールのトークンを選ぶと、カラーウェイごとに1行、ライトとダークを並べて表示され、件数の行にロールが保持する値の数が示されます。読み取り専用のデザインシステムでも同じ一覧が表示されます。

何も入っていないセクションには、空白を埋める方法が提示されます。**Pick a colour**、**Choose a face**、**Add a logo**です。

## Rules

**Rules**は、ブランドの選択を実際に働かせます: 人が変更できること、固定されたままのこと、Lollyが確認できること。

![Lolly DemoのRules: 4つのハウスルール。それぞれにChecked in Lolly DesignとRequiredまたはAdvisoryの印があり、続いて例をレンダリングできる状態のTry your design system in use](/t/url-shot?url=%2F%23%2Fstart%3Farea%3Dusage&width=1440&height=1200&dpi=192&waitMs=2400&cropSelector=%23start-panel-usage&format=svg&walker=1&dark=1&filename=bs-usage-rules)

**Brand rules**は、ルールを一覧にします。**Add rule**(または**Add your first rule**)で短いフォームが開きます。

- ご自身の言葉による**Rule name**。*Beacon accents*など。
- **Check**: **Colour choices**、**Font choices**、**Fixed artwork**、**Text length**のいずれかと、使うブランドロール(ご自身が付けたロールの名前で)。
- 適用先の**Example**(Poster、Title slide、Content slide、Lolly Chart)、**Mode**、そして**Required**か**Advisory**か。
- **Reviewed by**、続いて**Save draft**または**Approve & save**。

承認は、このデバイス上でのご自身の判断を記録します。承認済みの必須ルールは再利用可能なポスターを制約し、チェックの対象は例のPNGのみです。他のツールには影響しません。

デザインシステムがトークンファイルとともに持ち込むルール(承認済みの色の組み合わせ、テキストの太さと配置、サーフェスごとのロゴなど)は、ここに**Checked in Lolly Design**として一覧されます。Lolly Designは、書き出しパネルの**Before you export**カードでレイヤーごとにそれらを確認し、`lolly check`は保存済みのLolly Design書類に対して同じことを行います([書き出す前に](/info/design.html#before-you-export))。このビルドに確認機能のないルールは、渡されたまま保持され、**Unchecked**と表示されます。

Lolly Demoには、承認済みの4つのハウスルールがあります。見出しを大文字で組むことはありません。このルールは必須で、`lolly check`は大文字の見出しをエラーとして報告します。ほかの3つは助言です。本文は左揃えです。プライマリのマークは明るいサーフェスに、反転のマークは暗いサーフェスに置きます。破線は「ここにドロップ」を意味します。

**Try your design system in use**は、現在のリビジョンから4つの例を**Render & check examples**でレンダリングします。**Mode**を選び、見出し、補足テキスト、スライドのテキストに**Try your own text**を使います。各例は測定した内容を報告し、**See checks & sources**と**Download check report**があり、**Make reusable poster**は、固定レイアウトと承認済みの入力項目がファイルとともに移動する`.lolly`をダウンロードします。例はローカルです: チェックを実行しても、何も公開も承認もされません。

固定されたブランドとともに出荷されるビルドは、同じルールと例を、*This brand is set*の下に読み取り専用で表示します。

## Skills

**Skills**は、有効なデザインシステムの[ブランドスキル](/info/brand-skills.html)を一覧にします。ブランドの書かれた基準で、分野ごとに1つあり、人とAIエージェント向けです。各行には、分野、ブランド自身のステータス(**Draft**または**Approved**)、スキルが公開か社内向けか、そしてリビジョンが表示されます。行を選ぶと、スキルがカバレッジとともに読めます。カバレッジは、スキルの各行をご自身のトークンと突き合わせて、Lollyが確認するもの、食い違うもの、一致するもの、ガイダンスにとどまるものを示します。

**Download skill (.zip)**は、スキルをエージェントツール用のAgent Skillsフォルダーとして書き出し、カタログのリンクはこのLollyを指します。**Copy as one file**は、同じテキストをチャットウィンドウ用にクリップボードへコピーします。独自のスキルを持たないデザインシステムには、ベースラインが一覧されます。これは、ベースラインが読まれるたびに、Lollyがトークンとハウスルールから書き起こすものです。このルームはスキルを読むだけで、編集はしません。

## ブランドを取り込む

バーの**Add from…**は、形式ではなく、お持ちのものを尋ねるピッカーを開きます:

- **Design tokens or a design file**: DTCGまたはTokens StudioのJSON、Penpotプロジェクト、トークンセットのzip、Lollyデザインシステムパック、SVG、`DESIGN.md`、ブランドページのフォルダー。
- **PDF**: デッキまたはガイドラインのファイル。このデバイス上で、色、マーク、埋め込まれた書体を読み取ります。
- **Logo or screenshot**: 画像から提案パレットになり、このデバイス上で読み取られます。読み取るのは色であり、書体やレイアウトではありません。
- **Saved web page**: HTMLファイル1つとそのCSSファイル、または貼り付けたHTMLやCSS。最大20ファイル、2 MB。ご自身が渡したテキストだけを読み取ります。リンクされたリソースは取得されず、スクリプトも実行されません。
- **Font file**: TTF、OTF、WOFF。書体をインストールするTypeルームが開きます。
- **Website**: 1ページから色と書体を読み取ります。このタイルは、ページを読み取れるデバイスにだけ表示され、どのリーダーを使うかを示します: このデバイスのアプリ、またはサインインした状態でバックグラウンドタブを使うブラウザ拡張機能です。URLを指定しても入力欄が埋まるだけで、取得ボタンを押すことが同意になります。

デザインファイルのソースを選ぶと、次のカードが、対応する形式をアイコンタイルとして一覧にし、カード全体が1つのドロップ先になります。ファイルをスタジオに直接ドロップすることもできます。

![インポートカード - 受け付けるフォーマットが優先順にアイコンタイルとして並び、カード全体が1つのドロップターゲットになっている](/t/url-shot?url=%2F%23%2Fstart%3Fsource%3Dfile&width=1440&height=900&dpi=192&waitMs=1600&css=.start-import-modal%20.modal-msg%2C.start-import-modal%20.modal-title%7Bdisplay%3Anone%7D&cropSelector=.start-import-drop&walker=1&format=svg&dark=1&filename=bs-brand-import-formats)

- **Lollyデザインシステムパック**(`.lolly`、または従来の`.zip`)は、1ステップでインストールされます。
- **Penpot**のエクスポート(`.penpot`)は、そのデザイントークンを取り込みます。
- **Design Tokens**(W3C DTCG)または**Tokens Studio**のファイル(`.json`)は、そのトークンを取り込みます。読み手に指示を無視するよう求める、権限を主張する、コードの実行を求める、といった説明は除外され、取り込みはそれがどこにあったかを示します。これは1行ずつの確認で、ほかの言い回しは見逃すため、知らない人からのファイルは、トークンを適用する前に自分で読んでください。
- **プレーンなSVG**は、選べる色を探すためにスキャンされ、最初の色がプライマリになります。
- **`DESIGN.md`**(`.md`)は、トークンが書かれたままの状態で**Try these colours**に進みます。その散文は下書きのブランドスキルとして保持でき、カードは、読み手に指示を無視する、権限を主張する、コードを実行するよう求める行にフラグを立てます。エージェントとブランドページは、Skillsルームで**Keep this skill**を押すまで下書きを見ることはなく、保持したスキルは内部用のままです。
- **ブランドページのフォルダー**は、フォルダーとして選ぶ、ドロップする、またはzipにすることで、同じレビューに進みます。すべてのファイルがフォルダーの`brand.json`と照合され、一致しないものが1つでもあると、フォルダー全体が拒否されます。トークンを追加します。ロゴとフォントはフォルダーに残ります。

Lollyは、ご自身が渡したファイルからブランドページを読み取ります。ほかのサイトのアドレスを取得することはありません。

### 独自の色の言葉を持つファイル

トークンファイルまたは`DESIGN.md`は、色に独自の言葉(main、accent、supporting、tertiaryなど)を使えます。Lollyはそのような言葉を見つけると、何かを適用する前に、レビューで1つずつ一覧します: 言葉、見た目ごとの色、元のトークン、Lollyがそれを何として読むか。Lollyはこれらの読み取りを言葉だけから、短いリストに照らして提案し、モデルは使いません。リストにない言葉は、ブランド独自のものとして**By name only**で届きます。言葉の名前を変える、何のためのものかを書く、別のものとして読ませる、またはチェックを外して名前付きの色のままにする、のいずれもできます。

**Install with these roles**はそれらを書き込み、**Install without roles**はファイルを届いたままインストールします。そのような言葉のないファイルには、新しいステップは表示されません。Lollyが書いたものなど、独自のロールを明示しているファイルは、それを書かれたままに表示して変更せずインストールし、その後Coloursルームで編集できます。ターミナルにはレビューがないため、`lolly system import`は明示された記録を保持し、ほかのファイルの言葉は名前付きの色のままにします。

### 参照をレビューする

ロゴ、スクリーンショット、Webサイト、保存したページは**Try these colours**を開きます。提案された色による例、変更できる**Main colour**、新しいシステムの名前です。ボックスには、適用で何が起こるかが明記されます。有効なトークン設定を、生成されたパレットと既定のスタイルで**置き換え**、フォントとライブラリのファイルは**保持**し、以前のシステムは**復元**できます。**Apply suggested settings**はチェックポイントを作った後にライトとダークのパレットを適用し、**Restore brand settings**で以前の設定を戻せます。**Change reference**は別のソースを選びます。

**Palette, source details and individual choices**には、読み取った内容、見つかったフォント名、プレビューのコントラストが表示されます。フォント名はあくまで提案で、書体をインストールするのは引き続きTypeです。ソースの詳細には、観測された範囲で、タイポグラフィ、間隔、パディング、角の値が含まれることがあり、観測されなかったものは**Not observed**と表示されます。保存したページやネイティブのWebサイトの読み取りは、宣言されたスタイル(ページが使っていないこともある)を報告し、ブラウザ拡張機能は、表示されている要素のサンプルから測定したスタイルを報告できます。これらは観測であり、何もインストールされず、ソースの間隔がご自身の設定を置き換えることもありません。**Choose individual items in the tray**は個々の項目を保持し、**Download design context**は、観測、提案されたトークン、ソース情報(提供されたHTMLやCSSのSHA-256付き)のJSONレポートを保存します。レポートには生のページテキストは含まれず、署名付きのContent Credentialではありません。

PDFとデザインファイルのインポートには、独自のレビューコントロールがあります。**Tray**内の項目は、その種類の素材を担当するルームで追加するまで、何も変更しません。`#/start?source=<kind>`は、ソース(`file`、`pdf`、`image`、`font`、`url`、`page`)でピッカーを開き、`?import`は通常の一覧を開きます。

### 外観を探して比較する

BoardまたはSettingsのデザインシステム一覧から**Find a look**を開きます。このデバイスに保存されたシステムと、再利用できるいくつかのLollyの例を閲覧し、名前、色のタグ、宣言されたフォントで検索できます。**Closest to my current palette**は、測定した色の類似度で並べ、同点の場合は一致するフォントで決まります。品質のスコアではありません。

見た目をクリックすると、文脈の中でプレビューされます。プレビューで何も変わりません。各カードの**Use this look**で、その見た目を使います。保存済みのシステムは有効なものになりますが、何も編集されません。例の色は、通常のチェックポイントを経て開いているデザインシステムに入り、そのロゴ、フォント、例が定義しないものはすべてそのまま残ります。**Compare looks**は各カードにチェックボックスを追加し、2つを選んで並べて比較できます。**Restore brand settings**は、以前の見た目に戻します。保存済みのシステムには、**Details and design context**の下に編集可能な**Search tags**があります。例は、Lolly独自のオリジナルの配色であり、収集したコレクションはなく、アカウントも要りません。

## デザインシステムを保管して移す

### ブランドをデバイス間で移す

**Export**は、**`LollyBrand-….lolly`**ファイルを1つ書き出します。トークン、フォント、ロゴ、テーマ設定と、読み戻すときに検査される整合性マニフェストです。1.0.7より前のWebリリースは、同じファイルを`.zip`と呼んでいましたが、その表記も引き続き受け付けられます。**Tokens (.json)**は、フォントもロゴも含まない、通常のデザイントークンのドキュメントだけを書き出します。リポジトリ、ビルドステップ、別のトークンツール向けです。

読み戻すには、**Add from… → Design tokens or a design file**を使うか、ファイルをスタジオにドロップします。これが、同僚からブランドを受け取る方法であり、2つ目のインストールにブランドを持ち込む方法で、アカウントもクラウドも不要です。受け取る人が別の組織で働いている場合に、ほかに何を送るかは、[パートナーとの協業](/info/partners.html)で説明しています。コマンドラインからブランドを取り込むには、[`ingest:brand`](/info/configuration.html#brand-packs)をご覧ください。

**Fonts for Linux (.rpm)**は、追加したフォントをインストール可能なRPMにパッケージします。ご自身でアップロードしたフォントが含まれる場合、Lollyは先に、再配布してよいことの確認を求めます。

### 以前の設定を復元する

バーの**More**を開き、**Restore brand settings**を選び、日付付きのチェックポイントを選択して、**Restore**を押します。現在のブランドの色、書体設定、その他のトークンが復元され、フォントと画像のファイルはそのままです。Lollyは、先に現在の設定を**Before restore**として保存するため、ブラウザを閉じた後でも復元を取り消せます。このデバイスには、直近20個のチェックポイントが保持されます。

### バージョン

公開されたバージョンは、このデバイスに保持される**恒久的な名前付きのコピー**です。変更されないため、それを固定する(`designv`で)ツールやリンクは、いつも同じものを描画し続けます。ご自身のものがあるシステムでは、バーの**More**メニューに**Versions & publishing**が並び、最初の公開後は**Versions**がルームに加わります。`#/start?area=versions`で直接開きます。

- **バージョンは恒久的です。** まだ削除はなく、パネルにもその旨が書かれています。
- **削除は互換性カードの先頭に表示されます。** ツールを壊すのは、削除されたトークンだからです。
- **公開は取り消せませんが、復元はできます。** *Restore latest from this version*は通常の編集で、すぐに**Undo**が提示されます。

**Publish only**は、ツールが従うものを変えずにバージョンを保持し、**Publish and make active**は、ツールとアプリがそのバージョンに従うようにします。**Follow the latest again**は、編集するたびにすぐすべてを反映します。

### ブランドページを公開する

[ブランドページ](/info/brand-page.html)は、人とエージェントのための1つのアドレスです。ロゴ、色、書体、例を表示するページと、その横に同じ事実を載せたファイルがあります。Versions & publishingの下にある**Publish a brand page**は、公開中のページと、ページの横に次を表示します:

- **Goes public**: すべてのファイルをグループ別に、サイズ付きで。
- **Held back**: 出さなかったものと、その理由。ライセンスの記録がないロゴは、ロゴの名前にチェックを入れるまで出ません。フォントファイルには、再配布を許すライセンスの記録が必要で、ファイルを出さない場合、ページはアウトライン化した見本を表示します。内部のブランドスキルが表示されることはありません。
- **What was checked**: カラーウェイとモードごとの色のペア、そしてハウスルール。これらは測定値であり、判定ではありません。
- **In your words**: 使用に関する記述と連絡先。ページは書かれたものをそのまま印刷し、Lollyはライセンスや法的な主張を加えません。スイッチで、フッターの「Made with Lolly」の行をオフにできます。
- **On exports**: [ページのアドレスをこのデザインシステムの書き出しに記録する](/info/brand-page.html#lead-back-from-your-files)スイッチ。オンにするまでオフで、`https`のアドレスが必要で、パックやコピーとともに移動することはありません。ロックされたデザインシステムでは、管理者が決めるため、スイッチは表示されません。

**Download folder**は、ご自身が選ぶ場所でホストするためのZIPとしてフォルダーを保存し、ホストするまで何も公開されません。ターミナルでは、`lolly system publish --out=<dir>`が同じフォルダーを書き出します。ブランドページを提供するインスタンスは、そのアドレスへの**Publish to**も提供します。これは明示的な1回の操作で、承認の連鎖がある場合はそれを経ます。管理されたデザインシステムは、管理者が許可した場合にのみ公開されます。

### エージェントを接続する

同じ場所にある**Connect an agent**は、貼り付けるテキストを渡し、各オプションでできることを示します:

- プロジェクト内の**`AGENTS.md`**: エージェントはシステムの名前とルールを読みます。描画はせず、サーバーも要りません。
- **Lollyの公開サーバー**: ここで開いているシステムに関係なく、Lolly Demoで描画します。キーは要りません。
- **ご自身のインスタンス**: インスタンスが持つシステムで描画し、サービストークンを環境変数から読み取ります。シートは変数の名前を示し、トークンを表示することはありません。

自分のシステムで描画するホスト型サーバーがない場合、シートはそう伝えます。

## デザインシステムを管理する

**Settings → Preferences → Design systems**を開いて、システムを切り替え、追加、削除します。**Open**はシステムを選択してここで開き、**Make a new one**はローカルのシステムを作成し、名前の欄を準備した状態で開きます。有効なシステムは、デバイス全体で一度に1つです。ブランドに独自のデザインシステムが必要になる場面の判断は、[ブランドアーキテクチャ](/info/brand-architectures.html)が助けになります。

**システムの出どころ。** 配備のカタログが提供するシステムは**Came with this app**、またはインスタンスに接続したアプリでは**From this instance**と表示されます。**Catalogue source**を展開すると、提供元、そのトークンアセットと名前空間、わかっているバージョンまたはチェックサムが表示されます。更新に失敗した場合、キャッシュされた素材にはその旨が示されます。

**管理されたシステムは読み取り専用です。** システムは、カタログがそれをロックしている場合、**Managed by this instance**(インスタンスのないデスクトップアプリでは**Managed by this app**)と表示されます。使用とダウンロードはできます。ここで開くと、**Make an editable copy**と**Switch**のある読み取り専用の注記が表示され、続いて編集コントロールのないカラーロールとトークンが表示されます。ご自身のローカルのシステムは、管理されたものが先にあった場合でも編集可能なままです。固定された1つのブランドを持つビルドでは、Lolly Design System Setupは*This brand is set*で開き、ブランドのトークンと使用ルールを読めます。

**提供されるそれ以外のシステムはすべてご自身のもの**で、非表示、編集、リセットができます。lolly.toolsのLolly DemoとLolly Starterも含みます。編集してもその名前は保たれ、行に**Edited here**と表示され、メニューの**Reset to original**は、このデバイスで行った変更を破棄します。空のスターターは例外で、そこでの最初の変更は、ご自身のデザインシステムを始めることになるため、Lollyは新しいシステムの名前を一度だけ尋ねます。ご自身のシステムが何を置き換えるかは、[Lolly Demoを使う](/info/lolly-demo-in-use.html#switch-to-your-own)で確認できます。

### デザインシステムを削除する

システムのメニューから**Remove**を選びます。確認画面には、その後どのシステムが有効になるかが示されます。保存済みセッション、アップロード、他のシステムと共有している素材は残ります。

提供されたシステムを削除すると、非表示になるだけです。そのカタログアセットは残り、**Bring back**で再び表示され、他のすべてを削除した場合は自動的に戻ります。インポートまたは編集したコピーを削除しても、提供されたシステム、そのロゴ、フォントは削除されず、コピーが有効だった場合は、提供されたシステムが再び有効になります。有効なホスト型コピーを削除すると、そのコピーの接続だけが解除され、別に選んだインスタンスは選択されたままです。

サーバーが提供するものの変更は、管理者の作業です: 運用者がソースカタログを変更して再デプロイするか、Lolly Workの管理者がサーバーの変更をレビューして適用します。ここでの編集はローカルにとどまりますが、例外が1つあります: `brand.edit`を付与されたLolly Workインスタンスでは、管理されたシステムに、編集用のコピーを開く**Edit for**そのインスタンスも表示され、**Versions**の**Send to**そのインスタンスは、その色、カラーウェイ、カラーロール、ブランドページのアドレスを送り返します。編集で変更できることと、インスタンスが変更を提供する仕組みは[スタジオからこのインスタンスを編集する](/info/work-design-system-administration.html#edit-this-instance-from-the-studio)にあります。[カタログのデザインシステムを削除する](/info/configuration.html#removing-a-catalogue-design-system)と[設定](/info/configuration.html#supplied-and-local-design-systems)も参照してください。

## アプリの外でデザインコンテキストを使う

**Download design context**は、トークン文書、解決済みの色、宣言されたフォントファミリー、アセットID、記録がある場合はソースの根拠、カバレッジ、明示されたルールを保存します。フォントファイルや所有の証明は含まれません。コマンドラインはサーバーなしでファイルを読みます: `lolly system import`はそれをターミナルのデザインシステムにし、`lolly system check`は保存済みのコンテキストに対してLolly Designの入力を確認します。取り込みは[デザインシステムを持ち込む](/info/cli.html#bring-your-design-system)に、確認は[コマンドが使うデザインシステム](/info/cli-decks.html#which-design-system-a-command-uses)にあり、MCPクライアントは`lolly://design-context`から同じブリーフを読みます([MCPサーバー](/info/mcp.html))。
