# 組織でLollyを使う

組織は、独自のLollyを運用できます。同じアプリに、組織が選んだツールとデザインシステムを載せたものです。このページでは、そこへの接続方法、サインイン、接続後に何が変わるかを説明します。

::: note 組織から必要なもの
組織のLollyのWebアドレス、または組織が作成した`.lolly`セットアップファイルです。lolly.tools単体は組織に接続しません。
:::

## ブラウザで

組織から案内されたアドレスを開きます。ページにサインインを求められたら、**Sign in**を押し、開いたサインインページの指示に従ってください。その後は通常のLollyと同じように動作し、組織のツールとデザインシステムが使えます。

lolly.toolsから始めることもできます。**Settings**を開き、**Lolly instance**カードの**Open a workspace**を押して、アドレスを入力し、**Open this instance**を押します。ブラウザは組織自身のアドレスに移動します。ブラウザは、lolly.toolsから別のLollyのツールを読み込めないためです。

## デスクトップ・モバイルアプリで

アプリは、同梱のツールで起動します。接続するには、**Settings**を開き、**Lolly instance**カードで**Change**を押します。シートに**Where should Lolly get its tools?**と表示されます。

1. **Lollyインスタンスに接続**を選びます。
2. 組織のWebアドレスを入力し、**確認して接続**を押します。
3. **このインスタンスを使う**を押します。次の画面**データをインポート(任意)**は、Lollyのバックアップから保存済みの作業を持ち込みます。何もなければ**スキップ**を押します。
4. アプリから求められたらサインインします。

接続したインスタンスのツールは、アプリ自身のツールと同じ信頼のもとで実行されるため、信頼できるインスタンスにのみ接続してください。組織によっては、代わりにアプリを接続してくれる`.lolly`セットアップファイルを送ってくる場合もあります。

後で切り替えるには、もう一度**Change**を使うか、同じカードの**Leave**を使います。

### コードでサインインする

デスクトップアプリとモバイルアプリでは、組織のLollyがコードによるサインインに対応している場合、サインイン画面に短いコードも表示されます。**Open sign-in in browser**を押し、サインインして、そこでコードを承認します。または、すでにサインインしているスマートフォンやパソコンで、表示されたアドレスを開き、コードを入力します。コードの有効期間は約10分です。

## そこでの違い

- **一部のコントロールはあらかじめ設定されています。** 組織が管理するコントロールには、**Managed by**と組織名、または**Managed by your organisation**と表示されます。固定されたコントロールは変更できず、メニューには選択肢の一部しか表示されないことがあり、**Set by**で始まる行は、どのルールがなぜ適用されるのかを示すことがあります。一部のコントロールは、まったく表示されません。
- **一部のデザインシステムはロックされています。** 組織が提供するデザインシステムにはロックが表示され、読み取り専用のままです。変更を試すには、**Settings → Preferences → Design systems**で編集可能なコピーを作成します。
- **一覧に出るのは組織のツールだけです。** 組織が提供していないツールは、まったく表示されません。
- **共有プロジェクト。** 組織があなたとプロジェクトを共有している場合、**Projects**に**Team projects**タイルが表示されます。これらのセッションは組織のサーバー上にあります。開いて作業するか、利用できる場合は**Share**から[ワークコラボ](/info/collaborate.html#work-collabs-with-lolly-work-optional)を始めます。
- **一部の書き出しには承認が必要な場合があります。** 組織が承認を求めている場合は、**Download**の代わりに**Request approval**が表示され、ツールが提供する形式が少なくなることがあります。

### 何がどこに残るか

::: cols
## このデバイス上

- ご自身の保存内容([同期](/info/sync.html)をオンにしない場合)
- ご自身で作成したデザインシステム
- 作成してダウンロードしたものすべて

## 組織のサーバー上

- サインインのIDとデバイス情報
- チームプロジェクト、共有セッション、ワークコラボでのライブ編集
- 共有ライブラリにアップロードしたアセット
- 承認リクエストと承認済みの配信
- 組織が有効にしている場合の利用イベント
:::

サーバーが保存する内容と、そのデータを管理する人は、[プライバシー](/info/privacy.html#organisation-services-with-lolly-work)に一覧があります。

## Lolly Workが加えるもの

組織のサーバーでは、同じオープンソースプロジェクトの組織向けソフトウェアである**Lolly Work**が動作しています。ご自身だけでアプリを使う場合は、ワークアカウントもLolly Workも必要ありません。

::: details Lolly Workが追加できること
組織は、Lollyと並べて[Lolly Work](https://github.com/lolly-tools/lolly-work)をホストし、有効にする機能を選びます。

- **サインインとアクセス。** 組織のシングルサインオン、グループに基づく権限、管理対象のプロフィール項目。管理者はSCIMでアカウントのプロビジョニングと無効化ができます。
- **共有作業。** チームプロジェクト、共有セッション、[ワークコラボ](/info/collaborate.html#work-collabs-with-lolly-work-optional)。組織のサーバー経由でライブ編集を行います。
- **共有アセットライブラリ。** アップロードしたアセット、コレクション、接続したライブラリ。アクセスルール、バージョン、レビューを備えます。
- **レビューと配信。** 承認ステップ、有効期限や取り消しのある管理対象リンク、組織が許可する送信先への配信。
- **管理。** インスタンスのテレメトリポリシーに基づく利用状況レポートと、管理対象のアクションの監査記録。

サービスを設定する場合は、[デプロイ](/info/deployment.html#organisation-services-with-lolly-work)から始めてください。[lolly.work](https://lolly.work)の公開デモはサンドボックスです。残しておきたい作業には、組織自身のアドレスを使ってください。
:::

## 退出する

**Settings**の**Lolly instance**カードにある**Leave**は、組織のデザインシステム、ツール、カタログを削除します。ご自身の作品は残ります。組織のツールで作ったものは、再接続するまで開けなくなります。

組織に保存したものは、そのアクセスポリシーと保持ポリシーのもとで、組織に残ります。このデバイスから退出したり消去したりしても、サーバー上のそのコピーは削除されません。組織自身のアドレスでブラウザを使っている場合は、退出するものがありません。代わりに別のアドレスを開いてください。

## 誰に尋ねるか

何が組織のサーバーに届くか、誰が組織の共有プロジェクトを見られるか、どの設定が固定されているかは、組織の判断です。組織のLollyを運用している人に尋ねてください。[プライバシー](/info/privacy.html)には、Lolly自身があなたのデータをどう扱うかが記載されています。
