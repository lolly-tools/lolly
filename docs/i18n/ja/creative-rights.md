# 創作物の権利とクレジット

他の人が作った優れた作品は、ライセンスの専門家にならなくても、その作品を作った人の名前をひそかに落とすことなく、使えるべきです。そのためLollyは、描画するすべての作品の出所を保持し、記録されたライセンスを読み、実際の利用に対してそのライセンスが何を求めるかを判断します。そしてプログラムでできる部分を行い、あなたにしかできない部分を伝えます。

::: note ここにある内容は法的助言ではありません
あなたのプロジェクトについての法的判断でもありません。Lollyは事実を記録し、ライセンス自体の法的文書から読み取った少数のルールを適用し、その判断過程を示します。条件付きのライセンスは、通常の、認められた選択肢です。問題のあるアセットとして表示されることはありません。
:::

<!--i:eti-smile-->
## どこで関係するか

日常的な例は絵文字セットです。TwemojiはCC BY 4.0なので、絵文字を含む見出しを書き出すと、そのアートワークの出所クレジットが付きます。OpenMojiの両セットはCC BY-SA 4.0なので、字形の1つをブランドに合わせて色変更すると翻案に当たり、その翻案を共有するには、互換性のあるライセンスを一度選ぶ必要があります。Fluent (MIT)、Noto、Blobmoji (いずれもApache 2.0)も登録されており、それぞれ確認済みのライセンスに従って処理されます。

セットの選択が妨げられることはなく、選択コントロールにはライセンスが表示されます。同じルールが、カタログのイラスト、LUT、フォント、その他の記録された作品にも適用されます。

## 分けて扱う3つの事実

「CC BY 4.0」、「この利用にはクレジットが必要」、「クレジットは今ダウンロードしたファイルに含まれる」は、それぞれ別の記述です。Lollyはこれらを分けて扱います。

- **証拠**は、出所が表明した内容を、誰が述べ、どこで読んだかとともに、見つかったとおりに記録したものです。後のインポートで以前の記録が上書きされることはありません。
- **義務**は、1つの利用、1つの配信経路、1つの対象者について、確認済みのルールがその証拠から導くものです。
- **配信**は、完成したバイト列を読み戻して測定した、実際に含まれているものです。Lollyがクレジットを含むと表示するのは、配信されたファイルから読み取り処理がクレジットを見つけた後だけです。

## 表示される内容と必要な対応

書き出しパネル、Lolly Verify、コマンドライン、機械向けの結果には、同じ文言が表示されます。おおむね目にする頻度の高い順に並べています。

| 表示される内容 | 意味 |
|---|---|
| 出所のクレジットが含まれます。 | クレジットは準備されており、その経路でクレジットを運べます。まだ何も書き込まれていないため、これは成功のメッセージではありません。 |
| このファイルのメタデータにクレジットが含まれています。 | 配信されたバイト列を読み戻し、クレデンシャルを検証し、必要な出所がすべてクレデンシャル内に見つかりました。 |
| クレジットとクレデンシャルはダウンロードパッケージに含まれています。 | クレジットは成果物の付随ファイルとして渡されます。他の人に渡すときも、一緒に保ってください。 |
| この翻案を共有する場合、互換性のあるライセンスが必要です。 | ShareAlikeの出所が変更され、その結果は私的利用以外に使われる予定です。選択は1回の操作で済み、配置するたびにダイアログが出ることはありません。 |
| このクレジットを投稿の説明に追加してください。 | 選んだ経路はクレデンシャルも読めるクレジットも運ばないため、クレジットのテキストはご自身で貼り付けてください。 |
| 記録されたCC0による権利放棄の下では、クレジットは必須ではありません。 | この権利放棄は何も求めません。それでも、任意のクレジットを用意します。 |
| 出所のライセンスが記録されていません。 | この出所には何も記録されていません。埋めるべき情報の欠落であり、作品に対する否定的な判断ではありません。自由に他者へ渡せる証拠には決してなりません。 |
| 条件は記録されていますが、まだ解釈されていません。 | 識別子は認識され、その条件は一覧になっていますが、ここにはそれを解釈するルールがありません。自動的な許可も禁止もありません。 |
| 2つのライセンス宣言が一致しません。 | 2つの記録に異なるライセンスが記され、どちらの許諾が適用されるかは選ばれていません。 |
| 配信されたファイルにクレジットが含まれていません。 | クレジットを含める予定でしたが、読み戻しても見つかりませんでした。ファイルはそのまま手元に残ります。もう一度書き出すか、クレジットのテキストを手動で使ってください。 |

Lollyは、作品に権利の主張がないとも、法的に安心して使えるとも伝えません。製品のどこにも、ライセンスについて一括して問題なしと示す緑のバッジはありません。どちらもプログラムでは確認できないことです。

## あなたに委ねられること

- **ライセンスの選択はあなたのものです。** ファイルを自分の作品として申告するとき、以前は1つだった状態を3つに分けます。公開ライセンスの宣言なし、明示的な全権利留保の表示、実際の公開ライセンスによる許諾です。Lollyが権利の行を書くのは後の2つだけで、プロフィールから書くことはありません。
- **あなたの作品のライセンスを勝手に変更しません。** 出所の条件と、あなた自身の出力に関する宣言は、別々の記録です。ShareAlikeの条件は、それが規律する翻案に適用され、あなたが作った他のすべてに自動的に及ぶものではありません。
- **私的な作品はそのまま使えます。** 共有時に適用される条件は、共有を予定した時点で提示します。ここにあるものがインポートの禁止になることはなく、自分のファイルを扱う前にライセンスの質問票に答える必要もありません。
- **判断は、その判断の根拠となる事実とともに記憶されます。** 記録する選択には、その対象となった作品、利用方法、経路、対象者のフィンガープリントが付けられます。セット、加工方法、形式、対象者を変えると、もう一度尋ねられます。「ライセンスを無視する」という一括スイッチはありません。警告をクリックして閉じても、クレジットを届けたり、許諾を与えたりすることはできないからです。
- **あなたの情報と第三者のクレジットは分けて扱います。** 自分の個人メタデータを削除しても、クレジットされた作者は削除されません。また、必須のクレジットが、あなたの連絡先を書き出す理由になることはありません。

## それぞれの場所でLollyが行うこと

- **カタログ。** 作品の詳細には、出所と作者、正式なライセンス名とその下に保持された元の表記、記録があればコピーできるクレジット、利用時の要件を示す1行が表示されます。タイルは要件を示し、書き出しが完了したとは決して表示しません。
- **書き出しパネル。** レンダリングに記録済みの作品が使われると、Content protection内にSource creditsカードが現れ、書き出す作品自体に選ぶLicenceの横に表示されます。状態、Detailsの先にあるクレジットのテキスト、Copy creditボタン、判断が必要な場合のインラインカードが表示されます。判断を求めるダイアログで操作が止まることはなく、対応が残ったダウンロードもそのまま進みます。
- **ファイル。** 記録済みの作品を配置した書き出しは、異なる作品ごとに1つのContent Credentialsの出所素材を記録します。これは公開アドレスにある元のバイト列と結び付けられ、作者、ライセンスとそのリンク、出所、リビジョン、変更内容を含みます。Lollyは、自身が確認した内容に署名します。元の作者に代わって主張に署名することは決してなく、Lolly Verifyはどちらが行われたかを示します。
- **パッケージ。** `.lottie`アニメーションなど、クレデンシャルを格納できないダウンロードには、パッケージ内に`CREDITS.txt`と`credits.json`としてクレジットが含まれます。これらは書き込み後に読み戻されますが、署名付きクレデンシャルがあるとは表示しません。
- **書き込み後。** クレジットを含むと表示する前に、配信されたバイト列を読み戻します。検証できなかったクレデンシャルは、届けられたクレジットとして数えません。
- **編集可能な`.lolly`ファイル。** 確認済みのライセンスに出所の再配布の許可が記録されている場合、その行に所有者自身の条件がある場合、または作品の権利について何も記録されていない場合に、バイト列が含まれます。最後のケースでは、ライセンスも権利記録も帰属表示もありません。この場合、送り手にはライセンスが記録されないまま含まれる作品が表示され、`CREDITS.txt`はファイルを開く人に、再利用前に条件を確認するよう求めます。記録されたライセンスがまだ解釈されていない作品は含めず、ライセンスなしで権利者が記録されている作品や、カタログの記録を読めなかった作品も含めません。保留されたコンテンツも意図的に含めることはでき、その場合はあなたの選択だったことをクレジットファイルに記録します。パックの`CREDITS.txt`には、何がどのライセンスで含まれ、何がどの理由で保留されたかを一覧にします。
- **Lolly Verify。** Sourcesパネルには、ファイルが記録するすべての出所が、算出された要約、クレジット、Copy creditボタン、要求したときだけ開くOpen sourceリンク、調査範囲の限界とともに一覧になります。Check for this useの質問は、利用方法を選んだ場合だけ現れ、回答のために外部から取得するものはありません。
- **メタデータの削除時。** 削除によってファイルから失われる出所クレジットの数を伝え、クレジットのテキストと、クレジットを別ファイルにしたクリーンなファイルを提供します。削除後のバイト列に再びクレデンシャルを付けることはありません。

**所有者自身のマーク。** 所有者がロゴをオープンライセンスで公開することはまれです。権利記録に`own-work`と所有者と条件が記されている行は、`.lolly`ファイルや[ブランドページ](/info/brand-page.html#publish-your-own-marks)に含められます。「所有者が公開、オープンライセンスではありません」として、ファイルの横に条件を添えて渡されます。これはカタログに記載された内容を読んだものです。Lollyはマークの所有者を確認しません。所有者がない、条件が空欄、または宣言がない記録は引き続き保留され、そのような記録のない他者のマークも同様です。

::: details Lollyが確認したライセンス
ルールのバージョンは`rights-rules-2026-11-05.1`です。各ルールはライセンス自体の法的文書から読み取られ、根拠となった条項は、ここ、および`engine/src/rights-profiles.ts`内のルールの横に引用されています。バージョンと移植版は記録されたまま保持されます。CC BY 3.0の宣言は、アプリの選択肢が4.0を優先するからといって4.0と報告されることはなく、元のバージョンを保ちます。

| ライセンス | Lollyで可能な利用に求められること | 出典 |
|---|---|---|
| CC BY 4.0 | 作者、題名、著作権表示、ライセンス名とリンク、出所のリンク、変更の表示を、出所がそれぞれ提供している場合に記載します。商用利用も含め、除外される利用はありません。 | [法的文書](https://creativecommons.org/licenses/by/4.0/legalcode.en)、2(a)(1)節および3(a)節 |
| CC BY-SA 4.0 | 同じクレジットです。加えて、翻案を共有する場合は、互換性のあるライセンスで公開します。CC BY-SA 4.0、Free Art License 1.3、GPL-3.0-or-laterで、GPLとの互換性は一方向のみです。この3つはCreative Commonsの一覧からデータとして保持され、名前で照合することはありません。 | [法的文書](https://creativecommons.org/licenses/by-sa/4.0/legalcode.en)、3(a)節および3(b)節、[互換ライセンスの一覧](https://creativecommons.org/compatible-licenses/) |
| CC0 1.0 | 何も求めません。この権利放棄に条件はないため、Lollyは任意のクレジットを用意しますが、必須とは決して表示しません。 | [権利放棄](https://creativecommons.org/publicdomain/zero/1.0/legalcode.en)、2節および3節、クレジットに関する[CC FAQ](https://creativecommons.org/faq/) |
| CC-PDDC | 何も求めません。記録するのは表明そのものと、その表明者です。証明とは一方当事者による記述であり、証拠そのものではないためです。 | [権利放棄と証明](https://creativecommons.org/licenses/publicdomain/)の各段落 |
| Apache License 2.0 | 出所の告知とNOTICEファイルの帰属表示テキストを、配布する作品に添えます。実行時の利用には何も求めません。ライセンスが告知文を求めているのに作品にそれが含まれていない場合は、情報の欠落として報告します。 | [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0)、4節、条件1から4 |
| MIT | 著作権表示と許諾の告知を、複製物と重要な部分に添えます。実行時と参照の利用には何も求めません。 | [MIT](https://opensource.org/license/mit)、許諾の告知に関する条件 |
| ISC | MITと同じ内容を、より短く述べています。著作権表示と許諾の告知を複製物に添えます。実行時と参照の利用には何も求めません。 | [ISC](https://opensource.org/license/isc-license-txt)、許諾の告知に関する条件 |
| SIL OFL 1.1 | フォントでテキストを描画しても、そのテキストには何も求めません。フォントファイルを他者に渡す場合は、ライセンス、著作権表示、予約名のルールを添えます。 | [OFL 1.1](https://openfontlicense.org/open-font-license-official-text/)、条件2、3、5、ドキュメントに関する[OFL FAQ](https://openfontlicense.org/ofl-faq/) |

**記録済みですが、解釈はしていません。** CC BY-NC、CC BY-ND、NC-SAとNC-NDの組み合わせは認識され、条件が一覧になりますが、ここにはそれを解釈するルールがありません。条件を示す1行とともに`licence.unknown`を報告します。価格やアカウントから商用かどうかを判断することはできず、組み合わせた文書はそれぞれ、ルールで解釈する前に個別の確認が必要です。

さらに3つの正直な回答がありますが、どれも許諾ではありません。

- `LicenseRef-`識別子は、そのまま返されます。保存された定義を指し、その表記を理由にプロプライエタリとみなすことはありません。
- 認識されない宣言は解析されずに返され、元のテキストが保持されます。
- `A OR B`は権利者が提示した選択肢なので、すべての候補を返し、どれも選択しません。`A AND B`は累積して適用されますが、これらのルールは2つのプロファイルを一緒に解釈せず、そのことを記録します。
:::

::: details コマンドラインとMCP
評価に必須のクレジットまたは問題がある場合、レンダリングは標準エラー出力に`Rights:`ブロックを表示します。状態、問題ごとに`code - summary`形式の1行、配信されたファイルを読み戻した結果、貼り付け用のクレジットテキストが含まれます。

```
Rights: actions-required
  licence.adaptation-choice - If you share this adaptation, it needs a compatible licence.
  Credential intact. It records 1 source. The exporter recorded it; the source did not sign a credential of its own.
  Credits included in this file's metadata.
  "water wave (OpenMoji Color 17.0.0)" by Vanessa Boutzikoudi (OpenMoji), CC BY-SA 4.0 https://creativecommons.org/licenses/by-sa/4.0/, source https://raw.githubusercontent.com/hfg-gmuend/openmoji/f9fc506a3f913be9897ab0181d611d4c910a4104/color/svg/1F30A.svg, changes: recoloured.
```

ここではクレジットがファイルに含まれていますが、ファイルを共有する前にライセンスについての判断がまだ必要です。

| 状態 | 意味 | 終了コード |
|---|---|---|
| `ready` | 人による対応を待っているものはありません。 | 0 |
| `actions-required` | ファイルを共有する前に判断が残っています。ファイルはそのまま書き込まれます。 | 4 |
| `use-not-covered` | 確認済みのルールによると、この利用はライセンスの対象外です。 | 4 |
| `unknown` | 問題は情報の欠落だけです。ライセンスが記録されていないか、条件が解釈されていません。 | 0 |
| `delivery-failed` | 評価ではなく、受領記録によってのみ設定されます。含める予定だったクレジットが、配信されたバイト列に見つかりませんでした。書き出しパネルにはこの状態が表示されます。CLIは代わりに、読み戻しの行で同じ事実を報告します。 | 表示されません |

終了コード4は、保護チェックが拒否したときに、このCLIがすでに返しているコードです。「別のランナーで再試行」を意味する3ではありません。ライセンスの判断は、どのランナーでも必要なままだからです。

`--rights=private`は、このレンダリングを誰にも配信しないことを示します。ブロックは引き続き表示され、クレジットもコピーできるままです。適用されなくなるのは共有時の条件で、配信したという主張は記録されません。条件を無視するフラグはなく、`--rights=ignore`は使用方法のエラーです。

問題のコードは安定した機械可読の値で、翻訳された文言に依存しません。`attribution.source-missing`、`attribution.delivery-missing`、`licence.adaptation-choice`、`licence.use-not-covered`、`licence.grant-conflict`、`licence.unknown`、`source.redistribution-unknown`、`credential.ingredient-missing`です。

MCPでは、`lolly_verify`は、要約、記録済みの出所ごとの1行、明示された限界を含む`rights`ペイロードを返します。ブラウザを使わない`lolly_render`は、`status`、`issues`、`credits`、`fingerprint`と、バイト列を読み戻して測定した`creditsInFile`フラグを返します。
:::

::: details ルールの所在
エンジンの5つのモジュールはすべて純粋です。ネットワーク、時計、ファイルシステムを使いません。ルールのデータはバージョン管理されてリポジトリ内にあり、外部から取得することはありません。

| モジュール | 含まれるもの |
|---|---|
| `engine/src/rights-profiles.ts` | 識別子の表、最小限のSPDX式リーダー、出典付きの確認済みプロファイル、クレジットに表示できるリンクの唯一のルール。 |
| `engine/src/rights-evaluate.ts` | 分類、問題、帰属表示の計画、フィンガープリント。決定論的で、同じ事実なら順序が違っても同じ答えになります。 |
| `engine/src/rights-attribution.ts` | 読めるクレジット、付随ファイル、出所素材、書き込み後に測定した受領記録。 |
| `engine/src/rights-companion.ts` | パッケージのクレジット(ZIP形式のダウンロード内にある`CREDITS.txt`と`credits.json`)の読み戻し。署名付きクレデンシャルがあるとは主張せず、クレジットを確認します。 |
| `engine/src/rights-report.ts` | 検証済みのクレデンシャルを、Lolly Verifyが尋ねる3つの質問として読み戻したもの。 |

`tests/fixtures/rights/`内の期待値ファイルは、評価器の出力ではなく、ライセンスの文書から作成しています。そのREADMEには、各期待値の根拠となる条項が引用されています。
:::

## まだ対応していないこと

- **送信先への到達は確認しません。** Lollyはキャプションを用意します。コネクターがリクエストを受け付けても、クレジットが読者に届いた証拠にはなりません。また、後のアップロード、スクリーンショット、トランスコードで隠れたメタデータが保持されるとは、ここでは一切保証しません。
- **ネイティブのメタデータのクレジット欄には、計画から書き込みません。** クレジットはContent Credentialsと読めるテキストとして渡されます。IPTCとXMPの出所ごとのクレジット欄には、まだ帰属表示の計画から値を入れていません。
- **訂正と撤回は未実装です。** 記録された作品に欠けている作者やローカルの訂正を追加する操作、および記録を撤回する操作には、インターフェースがありません。
- **接続先のプロバイダーには未対応です。** 購入したストック素材、個別の許諾、プロバイダーのアカウントにはインポート経路がないため、その許諾はご自身の申告としてのみ記録できます。
- **組織のポリシーは、これらの結果と統合されていません。** 現在、書き出しポリシーとライセンス条件は別々であり、組織の承認は権利者の許諾ではありません。
- **いくつかの配信経路は、まだこの処理経路に含まれていません。** カタログのオリジナルのダウンロード、一括ZIP、Send、Copy imageは、これらのクレジットをまだ評価せず、含めることもありません。切り抜き、カラーグレーディング、フレーム付きのコピー、Download asによる変換、動画編集は対応しています。ライセンスが記録され、自身のContent Credentialsを持たない出所は、クレジットを添えた署名なしの出所素材として含まれます。LUTには自身のライセンスでクレジットが付き、画像のライセンスとして扱われることはありません。出所が求めるクレジットを格納できないファイルは保存されません。これらのファイルを読み戻す処理はまだないため、クレジットは書き込まれますが、確認はされません。Retouch、単一画像の背景除去とアップスケーリング、音声抽出では、出所自体のクレデンシャルだけが保持されます。
