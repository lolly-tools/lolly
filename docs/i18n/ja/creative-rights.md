# クリエイティブの権利とクレジット

他の人が作った優れた作品を、ライセンスの専門家にならなくても、そしてその作り手を黙って省くことなく、使えるべきです。そこでLollyは、描画するすべての作品の出どころを保持し、記録されたライセンスを読み、実際に行っている使い方にそのライセンスが何を求めるかを判断し、プログラムにできる部分を行い、あなたにしかできない部分を伝えます。

これはいずれも法的助言ではなく、プロジェクトに対する判断でもありません。Lollyは事実を記録し、ライセンス自身の法的文言から読み取った少数のルールを適用して、その過程を示します。条件のあるライセンスは、通常の、許可された選択です。壊れたアセットとして示されることはありません。

## 目にする場所

絵文字セットが身近な例です。TwemojiはCC BY 4.0なので、絵文字を含む見出しは、アートワークのクレジットが付いたまま書き出され、あなたがすることは何も残りません。2つのOpenMojiセットはCC BY-SA 4.0なので、グリフをブランドの処理で再着色することは翻案にあたり、その翻案を共有するときには、互換性のあるライセンスを一度選ぶ必要があります。Fluent(MIT)、NotoとBlobmoji(どちらもApache 2.0)も登録されており、それぞれが確認済みの自らのライセンスで解決されます。

セットの選択がブロックされることはなく、セットのコントロールは、選ぶ場所でライセンスを示します。同じルールは、カタログのイラスト、LUT、フォント、その他の記録された作品にも適用されます。

## 分けて保たれる3つの事実

「CC BY 4.0」「この利用にはクレジットが必要です」「クレジットはあなたが今ダウンロードしたファイルの中にあります」は3つの異なる主張であり、Lollyはこれらを分けて保ちます。

- **Evidence(証拠)**は、ソースが宣言したことで、見つかったとおりに、誰が言ったか、どこで読み取られたかとともに記録されます。後からのインポートが、以前の記録を上書きすることはありません。
- **Obligation(義務)**は、1つの使い方、1つの配信経路、1つの受け手について、確認済みのルールがその証拠から導くものです。共有に際して適用される条件は、私的に作業している間は、条件付きのままです。
- **Delivery(配信)**は、完成したバイト列が実際に運ぶもので、読み戻して測定されます。Lollyは、リーダーが配信されたファイルの中にクレジットを見つけた後にだけ、クレジットが含まれていると言います。

## 表示されること、そしてすべきこと

書き出しパネル、Verify、コマンドライン、機械可読の結果には、同じ言葉が現れます。目にする頻度のおおよその順です。

| 表示 | 意味 |
|---|---|
| Source credits will be included. | クレジットが用意され、その経路はクレジットを運べます。まだ何も書き込まれていないため、これは成功のメッセージではありません。 |
| Credits included in this file's metadata. | 配信されたバイト列が読み戻され、クレデンシャルが検証され、必要なすべてのソースがクレデンシャルの中に見つかりました。 |
| Credits and credentials are in the download package. | クレジットは、成果物とともに、付属ファイルとして運ばれます。他へ渡すときは、一緒にしておいてください。 |
| If you share this adaptation, it needs a compatible licence. | ShareAlikeのソースが変更され、結果は私的な利用以外に向かっています。選択は、配置ごとのダイアログではなく、1回の操作です。 |
| Add this credit to the post description. | 選んだ経路にはクレデンシャルも読めるクレジットもないため、クレジットのテキストはご自身で貼り付けます。 |
| No required credit under the recorded CC0 dedication. | 宣言は何も求めません。それでも、儀礼的なクレジットが提案されます。 |
| Source licence not recorded. | このソースについて何も記録されていません。これは埋めるべき空白であり、作品に対する指摘ではありません。作品が自由に渡してよいという証拠には決してなりません。 |
| Conditions recorded, not yet interpreted. | 識別子は認識され、その条件が一覧されていますが、ここにはそれを読むルールがありません。自動的な許可も、自動的な禁止もありません。 |
| Two licence declarations disagree. | 2つの記録が異なるライセンスを指しており、どちらの許諾が適用されるかを選んだものがありません。 |
| The credits are not in the file that was delivered. | クレジットは約束されていましたが、読み戻しで見つからず、ファイルはまだお客様のものです。もう一度書き出すか、クレジットのテキストを手作業で使ってください。 |

Lollyは、「copyright verified」「legally safe」「fully cleared」「rights cleared」とは決して言わず、製品のどこにも、単一の緑のライセンスバッジはありません。これらの言葉は、どんなプログラムにも確認できないことを主張するものになるためです。

## あなたの手元に残るもの

- **ライセンスの選択はあなたのものです。** ファイルを主張すると、かつては1つだった3つの状態が分かれます。公開ライセンスが宣言されていない、明示的な全権利留保の通知、そして実際の公開ライセンスの許諾です。Lollyが権利の行を書くのは、後の2つだけで、プロフィールから書かれることはありません。
- **あなたの作品が、あなたに代わって再ライセンスされることはありません。** ソースの条件と、あなた自身の出力の宣言は、別々の記録です。ShareAlikeの条件は、それが関わる翻案に適用され、あなたが作ったそれ以外のすべてに自動的に適用されるわけではありません。
- **私的な作品は使えるままです。** 共有に際して適用される条件は、共有が視野に入ったときに提起されます。ここでの何かがインポートの禁止になることも、ライセンスのアンケートがお客様と、お客様自身のファイルの間に立ちはだかることもありません。
- **判断は、その事実に紐付いて記憶されます。** 記録するすべての選択には、それが対象とした作品、使い方、経路、受け手のフィンガープリントが付きます。セット、処理、形式、受け手のいずれかを変えると、質問がもう一度行われます。「ライセンスを無視する」という一括のスイッチはありません。警告をクリックして消しても、クレジットが届くことも、許可が与えられることもないからです。
- **ご自身の詳細は、第三者のクレジットとは別です。** ご自身の個人メタデータを削除しても、クレジットされたアーティストが削除されることはなく、必須のクレジットが、ご自身の連絡先を書き出す口実になることもありません。

## 各場所でLollyがすること

- **カタログで。** 作品のシートには、その出どころと作者、元のラベルを下に残した正式なライセンス名、記録されている場合はコピーできるクレジット、使うことが何を求めるかを示す1行が表示されます。タイルは要件を示し、書き出しが完了したと主張することはありません。
- **書き出しパネルで。** レンダリングが記録された作品を使うと、Content protection内に、ご自身の書き出しのために選ぶLicenceの隣へ、Source creditsカードが現れます。状態、Detailsの奥にあるクレジットテキスト、Copy creditボタン、判断が必要なときのインラインのカードが表示されます。判断が、ブロックするダイアログになることはありません。対応が残ったままでも、ダウンロードは進みます。
- **ファイルで。** 記録された作品を配置した書き出しは、作品ごとにContent Credentialsのソース素材を1つ書き込みます。それは公開アドレスにある元のバイト列に結び付けられ、作者、ライセンスとそのリンク、出どころ、リビジョン、変更点を運びます。Lollyは自らが観察したものに署名します。上流のアーティストに代わって主張に署名することは決してなく、どちらが起きたかはVerifyが示します。
- **パッケージで。** `.lottie`アニメーションなど、クレデンシャルを持てないダウンロードは、パッケージ内の`CREDITS.txt`と`credits.json`としてクレジットを運びます。これらは書き込み後に読み戻され、署名付きクレデンシャルがあるとは主張されません。
- **書き込み後に。** クレジットが含まれていると言う前に、配信されたバイト列が読み戻されます。検証に失敗したクレデンシャルは、クレジットが配信されたとは数えられません。
- **編集可能な`.lolly`ファイルで。** バイト列が運ばれるのは、確認済みのライセンスがソースを渡す許可を記録している場合だけです。パックの`CREDITS.txt`には、運ばれたもの、そのライセンス、保留されたものとその理由が一覧されます。記録のないライセンスは保留されます。保留された内容を意図的に含めることもでき、クレジットファイルにはそれがご自身の選択であることが記録されます。
- **Verifyで。** Sourcesパネルは、ファイルが記録するすべてのソースを、算出した要約、クレジット、Copy creditボタン、求めたときにだけ開くOpen sourceリンク、検査した範囲の明示された限界とともに一覧にします。**Check for this use**の質問は、使い方を選んだときにだけ現れ、その質問に答えるために何かが取得されることはありません。
- **メタデータを削除するとき。** 削除では、ファイルがもう運ばないソースのクレジットの数が示され、クレジットのテキストが提案され、クレジットを別ファイルにしたクリーンなファイルが提案されます。削除されたバイト列が、再びスタンプされることはありません。

::: details Lollyが確認したライセンス
ルールのバージョンは`rights-rules-2026-09-13.2`です。各ルールはライセンス自身の法的文言から読み取られ、その出どころの節は、ここと`engine/src/rights-profiles.ts`のルールの隣に引用されています。バージョンと移植版は記録されたまま保持されます。CC BY 3.0の宣言は、アプリの選択画面が4.0を好むからといって4.0として報告されることはなく、自らのバージョンを保ちます。

| ライセンス | Lollyにできる使い方に求めるもの | 出典 |
|---|---|---|
| CC BY 4.0 | 作者、タイトル、著作権表示、ライセンス名とリンク、出どころのリンク、変更の表示。それぞれ、ソースが提供している場合に。商用利用を含め、除外される使い方はありません。 | [Legal code](https://creativecommons.org/licenses/by/4.0/legalcode.en)の第2条(a)(1)と第3条(a) |
| CC BY-SA 4.0 | 同じクレジット。さらに、翻案を共有する場合は、互換性のあるライセンスで公開されます。CC BY-SA 4.0、Free Art License 1.3、GPL-3.0-or-laterで、これは一方向のみです。これら3つはクリエイティブ・コモンズの一覧からのデータとして運ばれ、名前で一致させることはありません。 | [Legal code](https://creativecommons.org/licenses/by-sa/4.0/legalcode.en)の第3条(a)と第3条(b)。[互換ライセンスの一覧](https://creativecommons.org/compatible-licenses/) |
| CC0 1.0 | 何もありません。宣言に条件はないため、Lollyは儀礼的なクレジットを提案しますが、必須として示すことはありません。 | [宣言](https://creativecommons.org/publicdomain/zero/1.0/legalcode.en)の第2条と第3条。クレジット表記に関する[CC FAQ](https://creativecommons.org/faq/) |
| CC-PDDC | 何もありません。記録されるのは主張そのものと、それを行った人です。証明は一方の当事者の陳述であり、証拠ではないためです。 | [宣言と証明](https://creativecommons.org/licenses/publicdomain/)の各段落 |
| Apache License 2.0 | ソースからの通知とNOTICEファイルの帰属テキストが、配布される作品とともに運ばれます。実行時の使用は何も求めません。通知テキストを求めるライセンスで、作品がそれを持たない場合は、不足として報告されます。 | [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0)の第4条、条件1〜4 |
| MIT | 著作権表示と許諾表示が、コピーと実質的な部分とともに運ばれます。実行時と参照の使用は何も求めません。 | [MIT](https://opensource.org/license/mit)の許諾表示の条件 |
| SIL OFL 1.1 | フォントでテキストを描画することは、そのテキストに何も求めません。フォントファイルを渡すと、ライセンス、著作権表示、予約名のルールが付いて回ります。 | [OFL 1.1](https://openfontlicense.org/open-font-license-official-text/)の条件2、3、5。ドキュメントに関する[OFL FAQ](https://openfontlicense.org/ofl-faq/) |

**記録されるが、解釈されないもの。** CC BY-NC、CC BY-ND、NC-SAとNC-NDの組み合わせは認識され、その条件が一覧されますが、ここにはそれらを読むルールがありません。これらは、条件を挙げた行とともに`licence.unknown`を報告します。商用の文脈は、価格やアカウントから読み取れず、組み合わされた各文言は、ルールがそれを読む前に個別のレビューが必要です。

さらに3つの、正直な回答があります。いずれも許可を意味するものではありません。

- `LicenseRef-`の識別子は、そのまま返ります。保存された定義を指し、綴りのせいで専有扱いになることはありません。
- どれにも認識されない宣言は、解析されないまま返り、元のテキストが保持されます。
- `A OR B`は権利者が提示した選択肢であるため、すべての選択肢が返り、どれも選択されません。`A AND B`は累積的であり、これらのルールは、2つのプロファイルをまとめて読むのではなく、それを記録します。
:::

::: details コマンドラインとMCP
評価に必須のクレジットまたは問題がある場合、レンダリングは標準エラーに`Rights:`ブロックを出力します。状態、`code - summary`の形式での問題ごとの1行、配信されたファイルが何として読み戻されたか、貼り付けるクレジットのテキストを含みます。

```
Rights: actions-required
  licence.adaptation-choice - If you share this adaptation, it needs a compatible licence.
  Credential intact. It records 1 source. The exporter recorded it; the source did not sign a credential of its own.
  Credits included in this file's metadata.
  "water wave (OpenMoji Color 17.0.0)" by Vanessa Boutzikoudi (OpenMoji), CC BY-SA 4.0 https://creativecommons.org/licenses/by-sa/4.0/, source https://raw.githubusercontent.com/hfg-gmuend/openmoji/f9fc506a3f913be9897ab0181d611d4c910a4104/color/svg/1F30A.svg, changes: recoloured.
```

ここではクレジットはファイルに入っており、ファイルを共有する前にライセンスの判断がまだ必要です。ファイルはどちらの場合も書き出されます。

| 状態 | 意味 | 終了コード |
|---|---|---|
| `ready` | 人の判断を待っているものは何もありません。 | 0 |
| `actions-required` | ファイルを共有する前に、まだ判断が残っています。ファイルはそのまま書き出されます。 | 4 |
| `use-not-covered` | レビュー済みのルールが、このライセンスはこの利用をカバーしないと示しています。 | 4 |
| `unknown` | 唯一の問題は欠落です。記録されなかったライセンス、または解釈されない条件です。 | 0 |
| `delivery-failed` | 評価によってではなく、受領記録によって設定されます。約束されていたクレジットが、配信されたバイト列の中に見つからなかったことを示します。エクスポートパネルはこれを表示し、CLIは代わりに読み返しの行で同じ事実を報告します。 | 出力されません |

終了コード4は、保護的なチェックが否と言ったときに、このCLIがすでに返すコードです。3ではありません。3は「別のランナーで再試行」を意味しますが、ライセンスの判断はどのランナーでも待っているためです。

`--rights=private` は、このレンダリングが誰にも配信されないことを表明します。ブロックはそれでも出力され、クレジットもコピーできる状態のままです。取り下げられるのは共有に適用される条件であり、配信の主張は一切記録されません。条件を無視するためのフラグは存在しません。`--rights=ignore` は使用エラーです。

問題コードは安定していて機械可読で、翻訳された文言とは独立しています。`attribution.source-missing`、`attribution.delivery-missing`、`licence.adaptation-choice`、`licence.use-not-covered`、`licence.grant-conflict`、`licence.unknown`、`source.redistribution-unknown`、`credential.ingredient-missing`です。

MCPでは、`lolly_verify`が、要約、記録されたソースごとの1行、明示された限界を含む`rights`ペイロードを返します。ブラウザなしの`lolly_render`は、`status`、`issues`、`credits`、`fingerprint`と、バイト列の読み戻しで測定された`creditsInFile`フラグを返します。
:::

::: details ルールの置き場所
エンジンの5つのモジュールで、すべて純粋です。ネットワーク、時計、ファイルシステムを使いません。ルールのデータはバージョン付きでリポジトリにあり、取得されることはありません。

| モジュール | 保持するもの |
|---|---|
| `engine/src/rights-profiles.ts` | 識別子の表、最小限のSPDX式リーダー、引用付きの確認済みプロファイル、クレジットが表示してよいリンクの1つのルール。 |
| `engine/src/rights-evaluate.ts` | 分類、問題、帰属プラン、フィンガープリント。決定的で、同じ事実を別の順序で与えても同じ答えになる。 |
| `engine/src/rights-attribution.ts` | 読めるクレジット、付属ファイル、ソース素材、書き込み後に測定される受領記録。 |
| `engine/src/rights-companion.ts` | パッケージのクレジット(ZIPベースのダウンロード内の`CREDITS.txt`と`credits.json`)の読み戻し。署名付きクレデンシャルを主張せずに、クレジットを確認する。 |
| `engine/src/rights-report.ts` | 検証済みのクレデンシャルを、Verifyが尋ねる3つの質問として読み戻したもの。 |

`tests/fixtures/rights/`の期待値ファイルは、評価器の出力ではなく、ライセンスの文言から書かれており、そのREADMEには、各期待値の根拠となる節が引用されています。
:::

## まだできないこと

- **確認済みの送信先はありません。** Lollyはキャプションを用意します。コネクターがリクエストを受け付けたことは、クレジットが読み手に届いた証拠ではなく、後のアップロード、スクリーンショット、トランスコードが非表示のメタデータを保つことは、ここでは約束されません。
- **ネイティブなメタデータのクレジット欄は、プランから書かれません。** クレジットは、Content Credentialsと読めるテキストで運ばれます。IPTCとXMPのソースごとのクレジット欄は、まだ帰属プランから入力されません。
- **訂正と取り下げはまだ作られていません。** 記録された作品への作者の不足分やローカルの訂正の追加、記録の取り下げには、インターフェースがありません。
- **接続されたプロバイダーはまだ作られていません。** 購入したストック、独自の許可、プロバイダーのアカウントにはインポートの経路がないため、その許諾は、ご自身の陳述としてしか記録できません。
- **組織のポリシーは、これらの結果と組み合わされません。** 書き出しのポリシーとライセンスの条件は現在別々であり、組織の承認は、権利者の許可ではありません。
- **いくつかの配信経路はまだこの経路上にありません。** カタログの原本のダウンロード、一括ZIP、Send、画像のCopyは、これらのクレジットをまだ評価も運びもしません。切り抜き、カラーグレーディング、フレーム付きのコピー、Download asの変換、動画編集は行います。ライセンスが記録されていて自身のContent Credentialsがないソースは、そのクレジットとともに、署名なしのソース素材として運ばれ、LUTはそれ自身のライセンスでクレジットされ、画像のものとして扱われることはなく、ソースが求めるクレジットを運べないファイルは保存されません。それらのファイルをまだ読み戻すものはないため、クレジットは書き込まれていますが、確認されてはいません。Retouch、単一画像の背景除去とアップスケール、音声の抽出は、ソース自身のクレデンシャルだけを保ちます。
