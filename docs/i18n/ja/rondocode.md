# Lolly Rondocodeの曲

<a id="rondocode-songs"></a>

rondocodeの曲は、コードで書く音楽です。シンセ、パターン、ミックスを入力しながら再生できます。Lollyは動画のBGMとして曲を再生でき、**Rondocode**ユーティリティでは曲を書いて音声として書き出せます。どちらも、ファイルのContent Credentialsに曲を記録します。

<!--i:eti-music-->
## Lollyで曲を再生する

アセットピッカーは、`.rondo`または`.rondo.json`ファイル、あるいは貼り付けた`rondocode.com`の共有リンクとして曲を受け取ります。曲は、そのクリップが指定する長さで再生されます。動画の書き出しの**BGM**にしたり、Neurospicy Modeのアンビエントプレーヤーで再生したりできます。

曲のコードはLollyのサンドボックスで実行され、ネットワークもファイルへのアクセスもありません。ライブマイクや、音声モデルがない状態での歌唱など、レンダリングで再生できない部分は、アセットの詳細に一覧表示されます。

ターミナルでは、`lolly mix`が曲をサウンドトラック全体として受け取ります。[CLIのレンダリング](/info/cli-rendering.html)をご覧ください。

<!--i:eti-code-->
## 曲を書いて書き出す

**Utilities**から**Rondocode**ツールを開くと、rondocodeのライブエディターで曲を書き、入力しながら聴けます。**WAV**、**MP3**、**M4A**、**Opus**、**FLAC**、ステムをまとめたZIP、**MIDI**、または再生中の音の録音として書き出します。ターミナルでは、`lolly rondocode --export=mid`が同じMIDIファイルを書き出します。**Export length**は、音声の書き出しの長さを秒数で設定します。曲のファイル(`.rondo.json`)は、何も追加されていない、書いたとおりのコードです。

曲は`sing()`で歌詞を歌えます。ダウンロードした音声モデルが、デバイス上で歌声を作ります。合成された歌声を含むファイルは、必ずその歌声をAI生成として宣言します([AI機能](/info/ai-features.html)をご覧ください)。

## クレデンシャル内の曲

rondocodeの曲を再生する動画や音声の書き出しは、Content Credentialsに各曲をソースとして記録します。

- 曲の名前;
- `.rondo.json`ファイルのSHA-256;
- レンダリングの方法: Lollyのサンドボックス内の`vm`実行クラスであること、レンダラーのバージョンとシード、レンダリングで再生できなかった部分。

曲のコードから計算された音楽には、アルゴリズムによるメディアという印が付くため、Lolly VerifyはAIとしてフラグを立てません。書き出し前には、**Download**の下の行に、クレデンシャルが記録する曲が一覧表示されます。書き出し後には、同じ行に、配布されたファイルを読み取って分かったことが報告されます。記録を含めない場合は、**C2PA Credentials**のチェックを外します。静止画には音がないため、曲は記録されません。静止画には曲は記録されません。`lolly mix`と[MCPサーバー](/info/mcp.html)も同じ記録を書き込みます。

## Rondocodeユーティリティのファイル

デバイス上のほとんどのユーティリティは、すでに自分が所有しているファイルを変換するため、クレデンシャルを書き込みません。Lolly Rondocodeは新しい音声を作るため、書き出すすべての音声ファイルに、その曲をソースとして記録するContent Credentialsが含まれます。WAV、MP3、M4A、Opus、FLAC、ステムZIP内の各ステム、再生中の音の録音が対象です。

- エディター自体のレンダリングは、専用フレーム(`frame`実行クラス)内で実行され、エディターのバージョンを記録します。
- CLIや共有リンクによるレンダリングは、`vm`クラスで実行され、レンダラーのバージョンとシードを記録します。
- WAVでは、RIFFコメントにも同じ内容を記載します。

曲が歌う場合、AIの宣言は機械可読です。クレデンシャルのデジタルソース種別は、学習済みモデルで作った複合メディアとなり、記録には歌唱部分が一覧表示されます。さらに、モデルごとに1つのC2PA AI開示が、歌唱の処理に使われた各モデルを識別します。Supertonic-3のテキスト読み上げ、wav2vec 2.0の音素アライナー、ContentVecエンコーダー、RVCの音声モデルが、Lollyがホストする際の取得元のリポジトリとコミットとともに記録されます。

### MIDIファイルに含まれるもの

MIDIファイルはStandard MIDI Fileのフォーマット1です。最初のトラックにはテンポと4/4拍子が入り、その後にシンセごとのトラックが、そのシンセの名前で続きます。各ノートは、開始位置、長さ、ベロシティを保持します。ベース、ストリングス、パッド、ピアノなど、楽器として解釈できる名前のシンセには、対応するGeneral MIDI音色が割り当てられ、ドラムを表す名前はチャンネル10に入ります。12音でないチューニングは、最も近い半音に丸められ、ピッチベンドが付きます。

MIDIファイルには、シンセの設定、フィルター、エフェクト、バス、サンプル、歌声を保持できないため、DAWは独自の音源でノートを再生します。テンポは、曲の1秒当たりのサイクル数から、1サイクルを4拍の1小節として読み取ります。曲自体の拍子は、レンダラーが返す内容に含まれないためです。

MIDIファイルにはクレデンシャルの格納場所がないため、ファイル内のテキストイベントに申告を含め、書き出しパネルでその旨を伝えます。パネルは、書き出し前にこれらすべてを説明します。書き出すたびに、エディターは保存されたファイルを読み戻し、その読み取りで分かったことだけを報告します。

Content Credentialsが一般に記録する内容については、[ファイルを書き出す](/info/exporting.html#content-credentials-c2pa)をご覧ください。
