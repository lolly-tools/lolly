# Lolly とブランドポータル

_位置づけの更新: 2026年10月31日。ベンダーの機能例の確認: 2026年9月28日。_

組織が承認済みのアセットをBynder、Frontify、Marq、Brandfolderで管理している場合、このページは、それをLollyとLolly Workの組み合わせと比較します。人がブランドのアセットをどう見つけ、そこから新しいファイルをどう作るかです。

## 既存のポータルを使い続ける

既存のDAMは、引き続き記録の原本にできます。Lolly Workのカタログコネクターは、そのライブラリの選択した一部をLollyで使えるようにし、人々は組織のルールのもとで新しいファイルを作ります。アクセスは、DAMがサポートするソースの制約とLolly Workの公開ルールに従い、最終的な出力のレビューは別の判断です。

[既存のDAMとLollyを使う](/info/use-with-dam.html)は、責任と限界を説明しています。[SUSEのBrandfolderの経験](/info/suse-brandfolder.html)には、計画された移行の前に、管理者の変更管理を支えた統合が成功したことが記録されています。ソースをつないだままにするのも、サポートされた選択肢です。

Lollyの目的は[コンテンツ主権](/info/content-sovereignty.html)であり、制作の制御と、システムを選ぶ自由を含みます。Lolly自身のライブラリと承認は、それらを自前で運用することを選ぶ組織を支えます。[DAMベンダーと導入パートナー向けのLolly](/info/dam-partners.html)は、つないだワークフローが既存の記録システムにどう価値を加えられるかを説明しています。

## 確立されたポータルがより優れている点

確立されたポータルは、マネージドホスティング、サポート、充実したアセット管理のワークフローを提供します。たとえば[FrontifyのエンタープライズDAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management)は、アセットの検索、アクセス制御、承認ワークフロー、配信を組み合わせています。Lollyのスタックはより新しく、その承認の連鎖は、任意に分岐するワークフローではなく、順次的です。配備の制限は[Lolly Workのステータスとロードマップ](/info/work-status.html)に記録されています。

## 重なる部分

どちらも、承認済みのアセット、ロックされたテンプレート、アクセス制御、レビュー、配信をカバーします。Lollyはファイルを作ります。テンプレート、デザイントークン、許可された入力が、何を変更できるかを定め、レンダリングはデバイス上にとどめられます。Lolly Workは、組織が管理するインフラ上に、アイデンティティ、共有ストレージ、ポリシー、承認、レポートを加えます。

## LollyとLolly Workが提供するもの

| ニーズ | Lolly + Lolly Work |
|---|---|
| サインインとプロビジョニング | OIDCシングルサインオン、複数のIDプロバイダー、SCIM 2.0によるユーザーのプロビジョニングとグループメンバーシップ、既存のセッションを取り消すアカウントの無効化。SAMLのみのIDプロバイダーは、KeycloakなどのOIDCブリッジ経由で接続できる。 |
| 承認済みテンプレート | Lollyがテンプレートの編集可能な入力を定義し、Lolly Workが、値をロックしたり、選択肢を制限したり、コントロールを隠したりする、グループの表示と入力のポリシーを適用する。 |
| 共有アセットライブラリ | インスタンスが所有するアップロード、コレクション、カスタムメタデータ、アクセス制御付きのカタログと、既存のDAMやストレージのライブラリを読み取るコネクター。 |
| レビュー | 順序付きの承認ステップ、対象となる承認者グループ、定足数のルール、職務の分離。レビューは、カタログへの提出と組織の送信先への配信を管理できる。 |
| アセットの履歴と可用性 | インスタンスが所有するアセットのバージョンとロールバック、保持とホールド、予約公開、期限、取り消し。接続されたプロバイダーは、自身のソースの履歴を保持する。 |
| ライセンスとクレジット | Lollyは、ファイルが使う各ソースのライセンスを記録し、必要なクレジットを用意する。何を記録し、クレジットがどこに書かれるかは、[クリエイティブの権利とクレジット](/info/creative-rights.html)で説明している。権利のクリアランスは行わない。 |
| レポート | アセットの使用回数とダウンロード回数、ツールと書き出しの活動、ダッシュボード、監査証跡。利用状況の帰属は配備のテレメトリポリシーに従い、既定の帰属設定では同意が必要。 |
| 配信 | 有効期限があり取り消し可能なリンク、共有コレクション、ゲストアクセス、設定された組織の送信先への配信。 |
| 公開ブランドページ | Lollyは、Lolly Design System Setupまたはコマンドラインから、静的な[ブランドページ](/info/brand-page.html)を書き出す。人向けにはロゴ、色、書体、ルール、実例、エージェント向けにはトークン、`DESIGN.md`、スキルを含む。フォルダはご自身でホストするか、管理者がLolly Workで[ブランドページのホスティング](/info/work-design-system-administration.html#host-a-brand-page)をオンにする(既定ではオフ)。 |

[カタログとコンテンツ](/info/work-catalog.html)、[承認](/info/work-approvals.html)、[ポリシーとガバナンス](/info/work-governance.html)では、これらの機能とその設定を説明しています。

## 組み合わせたワークフローを評価する

[イベントカード制作の手順](/info/dam-production.html)を使って、ご自身のライブラリでソースへのアクセス、許可された編集、出力のレビュー、配信を試してください。すべての比較に共通する制限は、[どこで何が動くか](/info/compare.html#what-runs-where)に一覧があります。ソースの接続だけでは、ベンダーとのパートナーシップや、すべてのテナントへの適格性は成立しません。

ケイパビリティの比較は[Lollyの位置づけ](/info/positioning.html)をご覧ください。ベンダー名は比較される製品を識別するためのもので、Lollyはそれらと提携していません。
