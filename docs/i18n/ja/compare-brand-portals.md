# Lolly とブランドポータル

_最終確認日: 2026年9月28日。_

Lolly と [lolly.work](https://lolly.work) を合わせると、チームがブランドポータルに求める制作とガバナンスのワークフロー、つまり承認済みアセット、ロックされたテンプレート、アクセス制御、レビュー、配布をカバーできます。ブランドアセットの探し方と新しいアセットの作り方を選ぶ際には、この統合ソリューションを Bynder、Frontify、Marq、Brandfolder と比較してください。

## 制作と組織向けサービス

Lolly のエンジンとアプリがファイルを作ります。テンプレート、デザイントークン、許可された入力が、ユーザーが変更できる内容を定義し、レンダリングはユーザーのデバイス上に留められます。単体の Lolly にアカウントは不要です。

lolly.work は同じプロジェクト内の組織向けサービスで、[別のリポジトリ](https://github.com/lolly-tools/lolly-work)で保守され、Lolly と併せてデプロイされます。ID、共有ストレージ、ポリシー、承認、レポートを追加します。どちらの部分も MPL-2.0 のオープンソースです。この分離により、個人は Lolly を単独で使用でき、組織は自らが管理するインフラストラクチャ上で統合ソリューションを運用できます。

## 統合ソリューションが提供するもの

| 要件 | Lolly + lolly.work |
|---|---|
| サインインとプロビジョニング | OIDC シングルサインオン、複数の ID プロバイダー、SCIM 2.0 によるユーザープロビジョニングとグループメンバーシップ、既存のセッションを失効させるアカウント無効化。SAML のみの ID プロバイダーは、Keycloak などの OIDC ブリッジ経由で接続できます。 |
| 承認済みテンプレート | Lolly がテンプレートの編集可能な入力を定義し、lolly.work がグループごとの可視性と、値のロック、選択肢の制限、コントロールの非表示を行う入力ポリシーを適用します。 |
| 共有アセットライブラリ | インスタンス所有のアップロード、コレクション、カスタムメタデータ、アクセス制御付きカタログ、および既存の DAM やストレージのライブラリを読み取るコネクター。 |
| レビュー | 順序付きの承認ステップ、承認資格を持つ承認者グループ、定足数ルール、職務分掌。レビューはカタログへの提出や組織の配信先への配信を管理できます。 |
| アセットの履歴と利用可否 | インスタンス所有アセットのバージョン管理とロールバック、保持とホールド、公開スケジュール、有効期限、失効。接続されたプロバイダーは、それぞれ独自のソース履歴を保持します。 |
| レポート | アセットの使用数とダウンロード数、ツールと書き出しのアクティビティ、ダッシュボード、監査証跡。使用状況の帰属は、デプロイのテレメトリポリシーに従います。デフォルトの帰属設定では同意が必要です。 |
| 配布 | 有効期限付きで失効可能なリンク、共有コレクション、ゲストアクセス、設定済みの組織の配信先への配信。 |

[lolly.work 運用者ガイド](https://github.com/lolly-tools/lolly-work/tree/main/docs)に、これらの機能とその設定が記載されています。これらは利用可能な機能であり、Lolly の周囲に別のシステムを構築する必要がある機能ではありません。

## ポータルのワークフローを選ぶ

既存のポータルは、マネージドホスティング、サポート、広範な DAM ワークフローを提供します。たとえば [Frontify のエンタープライズ DAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management)は、アセットの検索、アクセス制御、承認ワークフロー、配布を組み合わせています。必要とするレビューと権利のワークフローを具体的に比較してください。Lolly はメタデータ、アクセス、利用可否の制御を提供しますが、法的なクリアランスやライセンス上の義務には、引き続き組織のプロセスが必要です。承認チェーンは順次型であり、任意の分岐を伴うワークフローはモデル化しません。

Lolly スタックはまだ新しく、[lolly.work ステータスページ](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md)にそのデプロイ上の制約が記録されています。特に、公開されている lolly.work サイトは評価用のサンドボックスです。継続的に運用する組織のデプロイには、永続ストレージと運用者が必要です。セルフホストにはユーザー数あたりのソフトウェアライセンス料はかかりませんが、インフラストラクチャと管理には引き続き費用がかかります。

既存の DAM を信頼できる情報源として残すこともできます。lolly.work のカタログコネクターは、承認済みアセットを Lolly で利用できるようにし、ユーザーは組織のルールのもとで新しいファイルを作成します。これは統合の選択肢です。組織がそれらのワークフローを自ら管理したい場合には、Lolly 独自のライブラリと承認機能を利用できます。

機能の比較については[Lolly の比較](/info/positioning.html)を、このセットの残りのページについては [Lolly をツール別に比較](/info/compare.html)を参照してください。ベンダー名は比較対象の製品を示すものであり、Lolly はそれらのベンダーとは提携していません。
