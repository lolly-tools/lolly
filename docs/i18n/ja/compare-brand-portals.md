# Lollyとブランドポータル

_位置付けの更新日: 2026年10月31日。ベンダーの機能例の確認日: 2026年9月28日。_

組織が承認済みのアセットをBynder、Frontify、Marq、Brandfolderで管理している場合、このページでは、そのポータルとLollyおよびLolly Workを比較します。ブランドアセットの探し方と、それを使った新しいファイルの作り方を扱います。

<!--i:eti-folder-shared-->
## 既存のポータルを使い続ける

既存のDAMを、正式な記録の保管元として使い続けられます。Lolly Workのカタログコネクターは、そのライブラリから選んだ部分をLollyで利用可能にし、利用者は組織のルールに従って新しいファイルを作ります。アクセスは、DAMが対応する出所側の制約と、Lolly Workの公開範囲のルールに従います。最終出力のレビューは、別の判断です。

[既存のDAMとLollyを使う](/info/use-with-dam.html)では、責任の分担と限界を説明しています。[SUSEのBrandfolder利用経験](/info/suse-brandfolder.html)には、計画された移行に先立ち、管理者による変更管理を支えた統合の成功例が記録されています。

Lollyの目的は、制作の管理権とシステムを選ぶ自由を含む[コンテンツ主権](/info/content-sovereignty.html)です。独自のライブラリと承認機能は、それらの機能を自ら運用することを選ぶ組織に向けたものです。[DAMベンダーと導入パートナーのためのLolly](/info/dam-partners.html)では、連携したワークフローが既存の正式な記録システムにどのように価値を加えられるかを説明しています。

<!--i:eti-award-->
## 実績のあるポータルが優れている点

実績のあるポータルは、マネージドホスティング、サポート、広範なアセット管理ワークフローを提供します。[Frontifyの企業向けDAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management)は、アセットの検索、アクセス制御、承認ワークフロー、配布を組み合わせています。Lollyのシステムは、まだ歴史が浅いものです。承認の流れは順次進み、任意には分岐できません。[Lolly Workの現状とロードマップ](/info/work-status.html)に、導入上の制限を記載しています。

<!--i:eti-blend-->
## 共通する範囲

どちらも、承認済みアセット、ロックされたテンプレート、アクセス制御、レビュー、配布に対応しています。Lollyはファイルを作ります。テンプレート、デザイントークン、許可された入力によって、変更できる範囲が決まり、レンダリングは利用者のデバイス上で行えます。Lolly Workは、組織が管理するインフラストラクチャ上に、ID管理、共有ストレージ、ポリシー、承認、レポートを追加します。

## LollyとLolly Workが提供するもの

| 必要なもの | Lolly + Lolly Work |
|---|---|
| サインインとプロビジョニング | OIDCのシングルサインオン、複数のIDプロバイダー、SCIM 2.0によるユーザーのプロビジョニングとグループ所属、既存のセッションを失効させるアカウントの無効化。SAMLのみのIDプロバイダーは、KeycloakなどのOIDCブリッジ経由で接続できます。 |
| 承認済みのテンプレート | Lollyがテンプレートの編集可能な入力を定義します。Lolly Workはグループごとの表示範囲と、値のロック、選択肢の制限、コントロールの非表示を行う入力ポリシーを適用します。 |
| 共有アセットライブラリ | インスタンスが所有するアップロード、コレクション、カスタムメタデータ、アクセス制御されたカタログに加え、既存のDAMとストレージのライブラリを読むコネクター。 |
| レビュー | 順序付きの承認ステップ、承認資格のあるグループ、定足数のルール、職務の分離。レビューは、カタログへの提出と組織の送信先への配信を管理できます。 |
| アセットの履歴と利用可能性 | インスタンス所有のアセットのバージョンとロールバック、保持と保全、利用期間の予約、有効期限、取り消し。接続されたプロバイダーは、元データの履歴をそれぞれ保持します。 |
| ライセンスとクレジット | Lollyは、ファイルが使う各出所のライセンスを記録し、必要なクレジットを用意します。[創作物の権利とクレジット](/info/creative-rights.html)では、何を記録し、どこにクレジットを書き込むかを説明しています。権利処理は行いません。 |
| レポート | アセットの利用回数とダウンロード数、ツールと書き出しのアクティビティ、ダッシュボード、監査証跡。利用を誰に帰属させるかは、その導入環境のテレメトリポリシーに従います。帰属の既定設定には同意が必要です。 |
| 配布 | 有効期限と取り消しがあるリンク、共有コレクション、ゲストアクセス、設定された組織の送信先への配信。 |
| 公開ブランドページ | Lollyは、Lolly Design System Setupまたはコマンドラインから、静的な[ブランドページ](/info/brand-page.html)を書き出します。人向けにはロゴ、色、書体、ルール、例を、エージェント向けにはトークン、`DESIGN.md`、スキルを含みます。そのフォルダをご自身でホストするか、管理者がLolly Workの[ブランドページのホスティング](/info/work-design-system-administration.html#host-a-brand-page)を有効にします。この機能は既定ではオフです。 |

[カタログとコンテンツ](/info/work-catalog.html)、[承認](/info/work-approvals.html)、[ポリシーとガバナンス](/info/work-governance.html)では、これらの機能とその設定を説明しています。

## 組み合わせたワークフローを評価する

[イベントカードの制作手順](/info/dam-production.html)を使って、ご自身のライブラリで、出所へのアクセス、許可された編集、出力のレビュー、配信を試してください。[何がどこで動くか](/info/compare.html#what-runs-where)には、すべての比較に共通する制限を一覧にしています。出所との接続だけで、ベンダーとの提携や、すべてのテナントでの適合性が確認されるわけではありません。

[Lollyの比較](/info/positioning.html)には、機能の比較があります。ベンダー名は比較対象の製品を示すためのものです。Lollyはそれらのベンダーと提携していません。
