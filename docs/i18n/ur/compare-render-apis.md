# Lolly اور رینڈرنگ APIs

_آخری جانچ: 5 نومبر 2026۔_

اگر آپ آج API کے ذریعے ٹیمپلیٹس سے تصاویر بناتے ہیں تو یہ صفحہ بتاتا ہے کہ اگر آپ وہ پروڈکشن خود چلائیں تو کیا بدلتا ہے: اپنی ڈیوائس پر، CI میں یا اپنے کنٹرول کے سرور پر۔ [ہوسٹڈ رینڈر API سے منتقل ہوں](/info/work-move-from-render-api.html) اس کا طریقہ ہے۔

## ہوسٹڈ رینڈرنگ APIs کیا بہتر کرتی ہیں

[Bannerbear](https://www.bannerbear.com/) اور [Placid](https://placid.app/) منظم سروسز ہیں، اور یہ ایک حقیقی فائدہ ہے۔ آپ درخواست بھیجتے ہیں اور سرورز کوئی اور چلاتا ہے، انہیں چالو رکھتا ہے اور لوڈ سنبھالتا ہے۔

- **چلانے کو کچھ نہیں۔** نہ سرور، نہ ڈیٹا بیس، نہ اسٹوریج، نہ اپ ڈیٹس، نہ گنجائش کی منصوبہ بندی۔
- **ہوسٹڈ ٹیمپلیٹ ایڈیٹر** جس میں ڈھالنے کے لیے تیار ٹیمپلیٹس ہیں۔
- **ایک API سے آؤٹ پٹ کی مزید اقسام۔** دونوں ویڈیو اور PDF endpoints شائع کرتے ہیں، اور Bannerbear اینیمیٹڈ آؤٹ پٹ، WebP اور AVIF، اسکرین شاٹس اور AI بیک گراؤنڈ ہٹانا بھی دستاویز کرتا ہے۔
- **ان کے اپنے انضمام اور سپورٹ۔**

اگر آپ یہی انتظام چاہتے ہیں تو وہ سروسز درست انتخاب ہیں۔

## سیلف ہوسٹنگ آپ کو کیا دیتی ہے

- **آپ کا مواد آپ کے سسٹمز پر رہتا ہے۔** ان پٹس، ایسیٹس اور آؤٹ پٹس اس انفراسٹرکچر پر ہیں جو آپ نے چنا۔ ڈیوائس پر یا CI میں رینڈرنگ کو کسی سروس کی ضرورت نہیں۔
- **اصول ٹول میں رہتے ہیں۔** رنگ، ٹائپ، لوگوز اور مقفل ان پٹس آپ کے [ڈیزائن سسٹم](/info/brand-studio.html) سے آتے ہیں، اس لیے کال کرنے والا صرف وہی بدل سکتا ہے جس کی آپ اجازت دیں۔ [Lolly Work](/info/compare.html#what-runs-where) ہر درخواست پر ٹول کی نمائش اور ان پٹ پالیسیاں لاگو کرتا ہے۔
- **ہر جگہ وہی ٹول۔** ٹول لیپ ٹاپ پر، CI جاب میں یا سرور پر انہی ان پٹس سے رینڈر ہوتا ہے، اور لوگ ایپ میں وہی ٹول ایڈٹ کر سکتے ہیں۔
- **ایسے ریکارڈ جو آپ کے پاس ہیں۔** [Render receipts](/info/work-renders.html#evidence-and-identity)، آڈٹ ٹریل، اور Content Credentials جہاں آپ دستخط کی شناخت ترتیب دیں۔
- **اوپن سورس اور کوئی میٹر نہیں۔** آپ کوڈ چلاتے ہیں، اور آپ اپنے انفراسٹرکچر کی ادائیگی کرتے ہیں۔

آپ وہ کام اپنے ذمے لیتے ہیں جو وہ سروسز آپ کے لیے کرتی ہیں۔ پائیدار سرور کو مستقل ڈیٹا بیس اور آؤٹ پٹ اسٹوریج چاہیے، اور جن ٹولز کو براؤزر چاہیے انہیں Chromium worker۔ [Lolly Work انسٹال کریں](/info/work-install.html) دونوں بیان کرتا ہے۔

## کام کیسے ملتے ہیں

| کام | ہوسٹڈ رینڈرنگ API | Lolly |
|---|---|---|
| ڈیٹا سے ٹیمپلیٹ بھرنا | API درخواست جو ٹیمپلیٹ اور اس کی layers کا نام لے | [URL](/info/url-mode.html)، [CLI](/info/cli.html) یا [سرور API](/info/work-automation-api.html) جو ٹول اور اس کے ان پٹس کا نام لے |
| جدول سے بہت سی فائلیں | Batches اور collections | آپ کی ڈیوائس پر [Batch](/info/batch.html)، یا سرور پر [render batches](/info/work-renders.html#batches-with-durable-rows) |
| نتیجے کا انتظار یا polling | Polling، یا ہم وقت آپشن | پائیدار رینڈرز جنہیں آپ poll کرتے ہیں، یا فوری رینڈر |
| ختم ہونے پر webhook کال کرنا | ہاں | آپ کے اجازت یافتہ origins کو [دستخط شدہ callbacks](/info/work-renders.html) |
| متحرک تصویر کا URL | ہاں | [Share links اور `/render` URLs](/info/url-mode.html) |
| ٹیمپلیٹ ایڈٹ کرنا | ہوسٹڈ ایڈیٹر | آپ کی ڈیوائس پر [Design](/info/using.html) |
| ایجنٹس | دونوں MCP سرور شائع کرتے ہیں | [MCP](/info/mcp.html)، Lolly Work پر ٹوکن کی پالیسی کے تحت تنظیمی endpoint کے ساتھ |

Lolly کی اپنی آؤٹ پٹ اقسام [Exporting](/info/exporting.html) میں درج ہیں۔ آج Work سرور پر پائیدار رینڈرز SVG، PNG، JPG اور PDF بناتے ہیں، اور [ویڈیو ڈیوائس، CLI اور MCP پر رہتی ہے](/info/work-renders.html#production-still-checks-and-permitted-repairs)۔

## کیا ساتھ جاتا ہے، اور کیا نہیں

| | Bannerbear V5 | Bannerbear V2 | Placid |
|---|---|---|---|
| آپ کی درخواستیں | Work کی migration API وہی شکل لیتی ہے | وہی | وہی |
| آپ کے ٹیمپلیٹس | قابل ترمیم دستاویزات کے طور پر **Import** ہوتے ہیں، سوائے ان layer اقسام کے جن کی کوئی تصدیق شدہ schema نہیں | صرف فیلڈ نام اور پری ویو۔ ہر ایک دوبارہ بنائیں | صرف فیلڈ نام اور پری ویو۔ ہر ایک دوبارہ بنائیں |
| موجودہ متحرک URLs | معاون نہیں | معاون نہیں | دستخط شدہ URLs host بدلنے کے بعد بھی چلتے ہیں، آپ کے پرانے نجی ٹوکن کے ساتھ |
| Webhooks | رجسٹرڈ webhooks معاون نہیں | `webhook_url` کام کرتا ہے | `webhook_success` کام کرتا ہے |
| WebP اور AVIF آؤٹ پٹ | نام لے کر مسترد | پیش نہیں | WebP نام لے کر مسترد |
| اینیمیشنز، ویڈیوز، collections، اسکرین شاٹس | migration API پر نہیں | migration API پر نہیں | migration API پر نہیں |

یہ سب ہر وینڈر کی عوامی دستاویزات سے بنایا گیا ہے اور کسی لائیو اکاؤنٹ پر چلا کر نہیں دیکھا گیا۔ اگر آپ کے پاس ایک ہے تو [منتقلی کی گائیڈ](/info/work-move-from-render-api.html#check-it-on-your-own-account) میں مختصر جانچ فہرست ہے۔

منتقلی سب یا کچھ نہیں نہیں ہے۔ آپ ایک ٹیمپلیٹ منتقل کر سکتے ہیں اور باقی جہاں ہیں وہیں رکھ سکتے ہیں، اور [Lolly چھوڑنا](/info/work-move-from-render-api.html#leave-lolly-too) بھی اتنا ہی کھلا ہے: ٹولز سادہ فائلیں ہیں اور CLI انہیں بغیر سرور کے رینڈر کرتا ہے۔

## سروس کون چلاتا ہے

Lolly کے ساتھ فرد مقامی طور پر رینڈر کرتا ہے، یا ٹیم اپنے انفراسٹرکچر پر Lolly Work چلاتی ہے۔ سرور جاب جمع کرانا اس کے ان پٹس اور ضروری ایسیٹس اس انسٹینس کو بھیجتا ہے، جو آن ڈیوائس راستے سے مختلف ہے۔

Bannerbear اور Placid اپنے مالکان کے ٹریڈ مارکس ہیں۔ یہ صفحہ ان کی عوامی دستاویزات سے بیان کرتا ہے کہ پروڈکٹس کہاں ملتی ہیں، اور کسی سے وابستہ نہیں ہے۔
