# Lolly کا آرکیٹیکچر

![Lolly آئیکن - بڑی سبز اور سفید لالی پاپ ٹافی](/info/icon.svg)

یہ صفحہ Lolly کا کوڈ بدلنے والوں کے لیے ہے: انجن، شیلز اور ٹول پیکس کیسے مل کر کام کرتے ہیں، ریپوزٹری میں ہر ایک کہاں ہے اور ہر تبدیلی کن طے شدہ اصولوں کی پابند ہے۔ Lolly کیا کرتا ہے اور اسے کون استعمال کرتا ہے، یہ جاننے کے لیے پہلے [Lolly کیسے کام کرتا ہے](/info/how-lolly-works.html) پڑھیں۔

[`engine/README.md`](https://github.com/lolly-tools/lolly/blob/main/engine/README.md) انجن کے ہر ماڈیول کی تفصیل دیتا ہے اور کوڈ سے بنتا ہے۔ [خطرات کا ماڈل & اعتماد کی حدود](/info/threat-model.html) اسی آرکیٹیکچر کو اعتماد کی حدود کے لحاظ سے دیکھتا ہے اور بتاتا ہے کہ انجن کن چیزوں کو غیر معتبر سمجھتا ہے۔

<!--i:eti-layers-->
## مجموعی خاکہ

اوپر ٹولز ڈیٹا کی صورت میں ہیں۔ درمیان کا انجن کسی پلیٹ فارم کے بارے میں کچھ نہیں جانتا۔ نیچے کے شیلز ایک ہی معاہدے کو نافذ کرتے ہیں اور کیٹلاگز مواد فراہم کرتے ہیں۔

![ٹولز مشترک انجن کو مینی فیسٹ، ٹیمپلیٹ اور ہکس فراہم کرتے ہیں۔ ویب، Tauri اور ٹرمینل شیلز HostV1 کیپیبلٹی برج نافذ کرتے ہیں اور کیٹلاگز سے ٹولز اور ایسیٹس پڑھتے ہیں۔](/info/diagrams/concepts/platform-layers.svg)

جس چیز کو آپ خالص ڈیٹا اور Handlebars میں بیان کر سکتے ہیں، وہ **انجن** میں آتی ہے۔ جو چیز DOM، فائل سسٹم، نیٹ ورک یا کسی براؤزر یا آپریٹنگ سسٹم API سے رابطہ کرتی ہے، وہ **ہوسٹ** میں آتی ہے، جو برج کا شیل والا حصہ ہے۔ انجن اوپن سورس ہے۔ کسی مخصوص برانڈ کے بارے میں جاننے والی کوئی چیز انجن میں نہیں جاتی۔

<!--i:eti-folder-shared-->
## ریپوزٹری کی ساخت

Lolly ایک ہی ریپوزٹری ہے۔ نیچے کی ہر ڈائریکٹری عام ڈائریکٹری ہے، سوائے `brands/suse` کے: یہ SUSE ٹول پیک اور کیٹلاگ والا **نجی** git سب ماڈیول ہے، جسے پبلک کلون نہیں لاتا۔ مواد کا پروفائل (`profiles.json`) طے کرتا ہے کہ بلڈ کون سے پیکس پڑھے گا۔ ہر پروسیس اپنا پروفائل خود طے کرتا ہے اور کوئی گلوبل سوئچ نہیں ہے۔ [بلڈ گائیڈ](/info/build-guide.html) میں کلون کمانڈ اور نجی پیک کے اندر تبدیلی کمٹ کرنے کا طریقہ ہے۔

| ڈائریکٹری | اس میں کیا ہے |
|---|---|
| `engine/` | پلیٹ فارم سے آزاد بنیادی حصہ: لوڈر، رن ٹائم، ان پٹس، ٹیمپلیٹس، URL موڈ، اکائیاں اور فارمیٹ ماڈیولز |
| `shells/` | ویب ایپ، Tauri ڈیسک ٹاپ اور موبائل ایپس، CLI، TUI اور براؤزر ایکسٹینشن |
| `packages/` | دیگر چیزوں کے ساتھ ٹول مصنف کا SDK (`@lolly-tools/core`)، Node شیل کے مشترک حصے اور دستاویزات کا رینڈرر |
| `community/` | کسی برانڈ سے غیر وابستہ ٹولز اور مشترک ایموجی پیکس |
| `brands/` | برانڈ پیکس: `lolly-demo` (Lolly Demo، وہ ڈیزائن سسٹم جس پر lolly.tools چلتا ہے)، `lolly-start` (خالی ابتدائی پیک) اور نجی `suse` |
| `services/` | اختیاری MCP، سرٹیفکیٹ اور Penpot سروسز اور ان کا مشترک سرور کوڈ |
| `schemas/` | ٹول مینی فیسٹس، ایسیٹ اندراجات اور ایسیٹ حوالوں کے لیے JSON Schema |
| `scripts/`, `tests/`, `docs/`, `api/` | بلڈ اور کیٹلاگ اسکرپٹس، انجن کا ٹیسٹ سوئٹ، یہ دستاویزات اور تیار کیے گئے سرورلیس بنڈلز |

::: details انجن اور شیل کی وہ فائلیں جو پہلے سامنے آتی ہیں
```
engine/src/
  index.ts          public surface: loader, runtime, template, inputs, url-mode
  loader.ts         fetches and validates tool files
  runtime.ts        orchestrates one mounted tool, from load to export
  template.ts       Handlebars hydration and annotateTemplate
  inputs.ts         manifest to runtime input model
  url-mode.ts       URL to input state and back
  validate.ts       JSON Schema validation of manifests
  compose.ts        nested tool renders (composes)
  embed.ts          portable lolly.tools embed URLs
  bridge/host-v1.ts type re-export of the @lolly-tools/core contract

shells/web/src/
  main.ts           boot and routing
  bridge/           the web implementations of the host APIs
  catalog/sync.ts   boot-time catalog sync and offline cache
  views/            the gallery, tool, projects, free canvas and the other views
  pro/              Batch (#/batch)

shells/cli/         bin/lolly.ts (entry), src/run.ts (headless render), src/bridge.ts
shells/tui/         src/main.tsx (the full-screen app), src/bridge.ts
```
:::

::: note ریپوزٹری کی روٹ میں `tools/` یا `catalog/` ڈائریکٹری نہیں ہے
`packages/node-shell/src/content-roots.ts`، `profiles.json` کی مدد سے بتاتا ہے کہ "ٹول `<id>` کہاں ہے" اور "کیٹلاگ کہاں ہے"۔ `tools/` اور `catalog/` کا اصل جوڑا صرف بلڈ آؤٹ پٹ، مثلاً `dist/`، RPM پے لوڈ یا کنٹینر امیج میں لکھا جاتا ہے، کیونکہ براؤزر ان دونوں پاتھس کو HTTP کے ذریعے حاصل کرتا ہے۔
:::

## Lolly کہاں چلتا ہے

ہر انٹرفیس وہی انجن اور وہی ٹول فائلیں استعمال کرتا ہے۔

- **ویب ایپ۔** ایک پروگریسو ویب ایپ۔ اس کا سروس ورکر ٹولز اور ایسیٹس کیش کر لے تو یہ آف لائن کام کرتی ہے۔ اسے اکاؤنٹ کی ضرورت نہیں اور اسٹیٹ ہر ڈیوائس کے IndexedDB میں رہتا ہے۔ ایک ہی ریسپانسیو لے آؤٹ ڈیسک ٹاپ اور فون پر کام کرتا ہے۔ فون پر کنٹرولز ایک شیٹ بن جاتے ہیں اور ایکسپورٹ کنٹرولز تیرتے ہوئے پل سے کھلتے ہیں۔
- **ڈیسک ٹاپ اور موبائل ایپس۔** اسی ویب ایپ کے Tauri پیکجز، مقامی فائل ڈائیلاگز، فائل سسٹم میں اسٹیٹ اور مکمل آف لائن استعمال کے ساتھ۔
- **CLI۔** `lolly <tool-id> --input=value --output=file.png` اسی انجن کو ہیڈلیس DOM میں لوڈ کرتا اور فائل لکھتا ہے۔ یہ دوسرے ٹرانسپورٹ پر URL موڈ ہے۔ [CLI](/info/cli.html) دیکھیں۔
- **TUI۔** فل اسکرین ٹرمینل ایپ جس میں کی بورڈ بنیادی ذریعہ ہے۔ یہ CLI کا برج دوبارہ استعمال کرتی ہے اور محفوظ سیشنز ڈسک پر رکھتی ہے: ڈیسک ٹاپ ایپ انسٹال ہو تو اس کے فولڈر میں، ورنہ `~/.lolly` میں۔ یہ صرف تب محدود دائرے والا ہیڈلیس براؤزر شروع کرتی ہے جب کسی فارمیٹ کو اس کی ضرورت ہو۔ [TUI](/info/tui.html) دیکھیں۔

## آرکیٹیکچر کے طے شدہ اصول

یہ فیصلے طے ہو چکے ہیں۔ کوڈ بیس کا ہر دوسرا فیصلہ ان پر منحصر ہے، اس لیے ان میں سے کسی کو بدلنا ایک بڑا کام ہے۔

### 1. وضاحتی ٹولز، ضرورت پر ہدایتی کوڈ کی گنجائش کے ساتھ

ٹول ایک مینی فیسٹ (`tool.json`)، ایک ٹیمپلیٹ (`template.html`) اور اختیاری `hooks.js` پر مشتمل ہوتا ہے۔ **مینی فیسٹ ان پٹس متعین کرتا ہے**۔ ان پٹس کبھی ٹیمپلیٹ کے Handlebars ٹوکنز سے اخذ نہیں کیے جاتے۔ زیادہ تر ٹولز صرف مینی فیسٹ اور ٹیمپلیٹ ہوتے ہیں، اس لیے غیر ڈویلپرز بھی انہیں لکھ سکتے ہیں۔

![Street Map کے کنٹرولز کا ڈھیر: شہر کا ڈراپ ڈاؤن، تھیم کا انتخاب، موٹائی کے سلائیڈرز اور رنگ کے ٹرگرز، ہر ایک مینی فیسٹ کی ایک لائن سے بنا ہے](/t/url-shot?url=%2F%23%2Ftool%2Fstreet-map%3Fcity%3Damsterdam&width=1440&height=900&dpi=192&waitMs=2400&walker=1&format=svg&css=%23tool-canvas%7Bdisplay%3Anone%7D&cropSelector=%23tool-inputs&dark=1&filename=ov2-street-map-controls)

قدریں حساب کرنے والے ٹولز، مثلاً QR انکوڈنگ یا چارٹ کی شکل بنانے والے، ہکس شامل کرتے ہیں: لائف سائیکل کے نام والے فنکشنز جنہیں رن ٹائم کیپیبلٹی برج فراہم کر کے کال کرتا ہے۔ ہکس مختلف پلیٹ فارمز پر چلنے کا معاہدہ ہیں، سیکیورٹی سینڈ باکس نہیں۔ وہ مقررہ وقت کی حد میں چلتے ہیں۔ جن ٹولز کے ہکس پیج گلوبلز سے آزاد ثابت ہوں، ان میں `isolate: true` ہوتا ہے اور وہ Worker میں چلتے ہیں۔ [ٹول ہکس](/info/tool-hooks.html) میں لائف سائیکل اور وقت کی حدیں ہیں۔ [خطرات کا ماڈل](/info/threat-model.html) بتاتا ہے کہ صفحے کے اندر چلانے والا ایگزیکیوٹر کیا محدود کرتا ہے اور کیا نہیں۔

### 2. ٹولز اور ایسیٹس ڈیٹا ہیں، بنڈل کیا ہوا کوڈ نہیں

ویب اور Tauri ایپس شروع ہوتے وقت ٹول اور ایسیٹ کیٹلاگز لاتی ہیں، انہیں کیش کرتی ہیں اور کیش میں موجود چیزوں سے کام کرتی ہیں۔ نئے ٹول یا ایسیٹ کے لیے نئی ایپ ریلیز کی ضرورت نہیں۔ ایسیٹ بائٹس کی SHA-256 چیک سم بنائی جاتی ہے۔ ایسیٹ کا `id` اور `version` طے کرتے ہیں کہ کیش کب غیر معتبر ہوگا۔

### 3. ٹولز کو صرف کیپیبلٹی برج کی API نظر آتی ہے

ٹولز اپنے ٹیمپلیٹ سے باہر DOM کو کبھی نہیں چھوتے، براہ راست `fetch` کال نہیں کرتے اور فائل سسٹم نہیں پڑھتے۔ وہ ورژن والے `host.*` میتھڈز کال کرتے ہیں۔ معاہدہ ٹول مصنف کے SDK `@lolly-tools/core` میں `packages/core/src/host-v1.ts` میں متعین ہے۔ کوئی تیسرا فریق انجن پر انحصار کیے بغیر SDK کے مطابق بنا سکتا ہے۔ `engine/src/bridge/host-v1.ts` اس کی ٹائپس دوبارہ ایکسپورٹ کرتا ہے۔

| لازمی API | یہ کیا کرتی ہے |
|---|---|
| `host.profile` | صارف کی تفصیلات؛ `bindToProfile` کے ذریعے ان پٹس پہلے سے بھرتی ہے |
| `host.assets` | کیٹلاگ کی کوئریز، ایسیٹ تلاش کر کے حاصل کرنا اور ہوسٹ کا پکر |
| `host.state` | ان پٹ سلاٹس محفوظ اور لوڈ کرنا: ویب پر IndexedDB، Tauri میں فائل سسٹم، CLI میں میموری |
| `host.clipboard` | پلیٹ فارم کے فال بیکس کے ساتھ کلپ بورڈ پر متن یا تصویر لکھنا |
| `host.export` | رینڈر ٹارگٹ کو راسٹرائز یا سیریلائز کرنا اور ڈیوائس پر فائل تبدیل کرنے کا راستہ |
| `host.log` | درجوں کے ساتھ ہوسٹ کو لاگ بھیجنا |

ہر دوسری API اختیاری ہے اور مزید سہولت دیتی ہے: `tokens`، `text`، `color`، `geom`، `pdf`، `compose`، `media`، `recorder` اور بہت سی دیگر۔ مینی فیسٹ کا `requires` وہ اختیاری APIs درج کرتا ہے جنہیں اس کے ہکس پہلے جانچے بغیر کال کرتے ہیں۔ جس ہوسٹ میں ان میں سے کوئی نہ ہو، وہ ٹول ماؤنٹ کرنے سے انکار کرتا ہے۔ باقی کی دستیابی ہکس خود جانچتے ہیں۔ کچھ، مثلاً `recorder`، کو ڈیوائس کی ایسی صلاحیت بھی چاہیے جسے ٹول متعین کرتا ہے۔ `packages/core/src/host-v1/apis.ts` ان سب کو درج کرتا ہے اور [Host API](/info/host-api.html) ہر ایک کی دستاویزات دیتا ہے۔ میتھڈ شامل کرنا مائنر ورژن ہے۔ کسی کو ہٹانا یا بدلنا میجر ورژن ہے، اور v2 آنے پر v1 کام کرتا رہتا ہے۔

### 4. ایسیٹ ids ہمیشہ کے لیے ہیں

`lolly/logo/primary` ایک معاہدہ ہے۔ شائع ہونے کے بعد id کبھی نہیں بدلتا اور کبھی دوبارہ استعمال نہیں ہوتا۔ بائٹس میں تبدیلی ایسیٹ کے اندراج میں `version` بڑھاتی ہے۔ متبادل آنے پر `deprecated: true` اور اختیاری طور پر `replacedBy` مقرر ہوتا ہے۔ موجودہ حوالوں سے ہمیشہ ایسیٹ ملتا ہے، اس لیے محفوظ سیشنز اور شیئر کیے ہوئے لنکس برسوں کام کرتے رہتے ہیں۔

### 5. URL موڈ بنیادی حیثیت رکھتا ہے

ہر ان پٹ URL پیرامیٹر کے طور پر بیان ہو سکتا ہے، اس لیے لنک ہی مکمل فائل ہے:

```
https://lolly.tools/t/qr-code?url=https://example.com&ecl=H
```

CLI اپنے آرگومنٹس سے وہی URL اسٹیٹ بناتا ہے اور وہی پائپ لائن چلاتا ہے، اس لیے CLI ایپ سے مختلف نہیں ہو سکتا۔ `engine/src/url-mode.ts` URL اسٹیٹ پارس اور سیریلائز کرتا ہے۔ مخصوص نام (`format`، `width`، `dpi`، `c2pa`، `z` اور دیگر) کبھی ٹول کو نہیں دیے جاتے۔ [مخصوص URL پیرامیٹرز](/info/url-parameters.html) ان سب کو درج کرتا ہے۔ ایسیٹ ان پٹس `id` کے ذریعے منتقل ہوتے ہیں اور ٹیمپلیٹ بھرنے سے پہلے `host.assets.get()` سے حاصل کیے جاتے ہیں۔

### 6. اسٹوریج برج کے ذریعے ہوتا ہے

ویب ایپ IndexedDB، Tauri فائل سسٹم اور CLI میموری استعمال کرتا ہے۔ ٹولز کو صرف `host.state.save(slot, data)` اور `host.state.load(slot)` نظر آتے ہیں، کبھی `localStorage` نہیں۔ لوگ اکاؤنٹ کے بغیر ہر ٹول کے لیے کئی نام والے سیشنز رکھ سکتے ہیں۔ چونکہ برج رابطے کا واحد مقام ہے، اس لیے یہ اسٹیٹ بھی منتقل کیا جا سکتا ہے۔ `shells/web/src/data-transfer.ts` اسٹیٹ کو ایک `lolly-backup` فائل میں ایکسپورٹ کرتا ہے جو کسی بھی دوسری انسٹالیشن پر امپورٹ ہو جاتی ہے ([ڈیٹا کی منتقلی](/info/data-transfer.html))۔ [Sync](/info/sync.html) یہی بنڈل اس اسٹوریج پر بھیجتا ہے جسے صارف چنتا ہے۔

### 7. پختگی کے ٹیگز ٹول کی حیثیت بتاتے ہیں

ہر ٹول `status: official | community | experimental` متعین کرتا ہے۔ گیلری اسٹیٹس کے مطابق ترتیب دیتی ہے۔ تجرباتی ٹولز ڈیفالٹ طور پر اپنے ایکسپورٹس پر واٹر مارک لگاتے ہیں: رن ٹائم واٹر مارک آن کرتا ہے، جب تک کال کرنے والا `watermark: false` نہ دے۔ ڈیوائس پر کام کرنے والے ٹولز مستثنیٰ ہیں۔ ٹیم کا اپنا کیٹلاگ عمل ان ٹیگز کے اوپر کام کرتا ہے۔

### 8. مینی فیسٹ میں ان پٹس کی ٹائپ متعین ہوتی ہے

ان پٹ ایک `type` متعین کرتا ہے: `text`، `longtext`، `number`، `boolean`، `color`، `select`، `asset`، `date`، `time`، `datetime-local`، `url`، `blocks`، `vector`، `table` یا `file`۔ ہوسٹ ہر ٹائپ کا کنٹرول رینڈر کرتا ہے، اس لیے ٹولز کنٹرول کا کوڈ نہیں لکھتے۔ کسی بھی ان پٹ میں `bindToProfile` ہو سکتا ہے۔ تین ٹائپس سب سے اہم ہیں:

- **`asset`**، `filter` اور `allowUpload` کے ساتھ، ایسیٹ سسٹم کا برج ہے۔ `allowUpload: false` سلاٹ کو لائبریری ایسیٹس تک محدود کرتا ہے۔ صارف کے اپ لوڈز کی ساخت بھی لائبریری کی `AssetRef` جیسی ہے۔
- **`blocks`** ایک دہرایا جانے والا فیلڈ گروپ ہے جسے سائیڈ پینل میں ایڈٹ کیا جاتا ہے اور Meeting Planner، Wayfinding، Diagrams اور دوسرے اسے استعمال کرتے ہیں۔ رینڈر کیے ہوئے بلاک پر کلک کرنے سے اس کی قطار فوکس پاتی ہے۔
- **`file`** ڈیوائس پر کام کرنے والی یوٹیلیٹیز، مثلاً Lolly Strip Hidden Data اور Compress، کے لیے صارف کی اپنی فائل میموری میں رکھتا ہے، اور **`vector`** اعداد کے مقررہ سیٹ کو ایک کنٹرول میں گروپ کرتا ہے۔

### 9. ٹیمپلیٹس منطق سے خالی ہیں

ٹیمپلیٹس Handlebars میں ہوتے ہیں، اس لیے غیر ڈویلپرز انہیں لکھ سکتے ہیں۔ `{{x}}` حروف ایسکیپ کرتا ہے اور `{{{x}}}` واضح طور پر چنا گیا اختیار ہے۔ منطق `hooks.js` میں ہوتی ہے، جہاں اس کا جائزہ لیا جا سکتا ہے۔ بہت سے ٹیمپلیٹس ہک کے بنائے ہوئے مارک اپ کے لیے `{{{` استعمال کرتے ہیں، اس لیے ہر ہک کو فراہم کیے جانے والے مواد کے حروف ایسکیپ کرنے ہوں گے۔ ہیلپرز `default`، `upper`، `lower`، `eq`، `markdown`، `asset`، `framing` اور `media` ہیں، اور متعلقہ `.ics`، `.vcf` اور `.csv` ٹیمپلیٹس کے لیے `icsStamp`، `rfcText`، `csvCell` اور `arrow` بھی ہیں۔ [ٹیمپلیٹس اور رینڈرنگ](/info/tool-rendering.html) ان کی تفصیل دیتا ہے۔

### 10. ٹولز دوسرے ٹولز کو ملاتے ہیں

ٹول دوسرے ٹول کا رینڈر ایمبیڈ کر سکتا ہے، بغیر کسی ٹول سے دوسرے میں امپورٹ کیے۔ انجن اس امتزاج کو حل کرتا ہے۔ مینی فیسٹ `composes: [{ id, tool, inputs }]` متعین کر سکتا ہے اور `{{asset <id>}}` سے ذیلی ٹول رکھ سکتا ہے۔ قابل منتقلی ایمبیڈ URL (`https://lolly.tools/tool/<id>.svg?…`) ذیلی ٹول کو مقامی طور پر رینڈر کرتا ہے؛ Lolly Design اسی طرح لائیو QR کوڈ یا چارٹ رکھتا ہے۔ SVG ذیلی رینڈر، SVG یا PDF پیرنٹ میں ویکٹر رہتا ہے۔ ذیلی رینڈرز درمیانی نتائج ہیں اور ان پر کبھی واٹر مارک یا اسٹیمپ نہیں لگتا۔ جو شیل ذیلی ٹول رینڈر نہ کر سکے، وہ سلاٹ خالی چھوڑ دیتا ہے اور پیرنٹ پھر بھی رینڈر ہوتا ہے۔ [امتزاج اور برانڈ اوورلیز](/info/tool-composition.html) میں تفصیل ہے۔

## ہم نے کیا نہ کرنے کا فیصلہ کیا

- **ٹیمپلیٹس میں من مانی JavaScript نہیں۔** منطق `hooks.js` میں ہوتی ہے۔
- **کوئی لازمی ایسیٹ سرور نہیں۔** لوگ ایپ میں Assets میں اپنی فائلیں شامل کرتے ہیں اور کام سیشن کے طور پر آگے دیتے ہیں: ان پٹس اور سیٹنگز کے لیے شیئر لنک، اور اپ لوڈز بھی ساتھ بھیجنے ہوں تو `.lolly` فائل۔ شیئر کیا ہوا سیشن ٹول کے انتخابی مینو میں ٹیمپلیٹ بن سکتا ہے۔ جو تنظیم ضابطوں کے تحت کیٹلاگ چاہتی ہے، وہ Lolly Work کا کیٹلاگ، منظوریاں اور پالیسیاں استعمال کر سکتی ہے، یا git میں برانڈ پیک سنبھال کر وہیں تبدیلیوں کا جائزہ لے سکتی ہے۔
- **رسائی پر لازمی کنٹرول نہیں۔** اوپن ایپ ڈیفالٹ طور پر عوامی ہے۔ پختگی کے ٹیگز اور واٹر مارکس برانڈ کا خطرہ ظاہر کرتے ہیں۔ ٹیم کو ضرورت ہو تو تنظیمی سائن ان، کردار اور پالیسی Lolly Work سے ملتے ہیں۔
- **کوئی مرکزی ڈیٹا بیس نہیں۔** صارف کا اسٹیٹ ہر ڈیوائس پر رہتا ہے اور اختیاری Sync اسے صارف کے چنے ہوئے اسٹوریج پر کاپی کرتا ہے، کبھی Lolly ڈیٹا بیس میں نہیں۔
- **ٹولز اور انجن کے درمیان مشترک کوڈ پاتھ نہیں۔** انجن اور کمیونٹی ٹولز اوپن سورس ہیں۔ نجی `brands/suse/` جیسے برانڈ پیک میں اس کی اپنی شرائط کے تحت اپنے ٹولز اور کیٹلاگ ہوتے ہیں۔ کوئی ٹول `engine/` سے امپورٹ نہیں کرتا، اس لیے یہ تقسیم واضح رہتی ہے۔

## ایک رینڈر کا لائف سائیکل

کوئی `https://lolly.tools/t/qr-code?url=https://example.com&ecl=H` کھولتا ہے:

1. **آغاز۔** ویب ایپ IndexedDB کھولتی ہے، کیپیبلٹی برج بناتی ہے اور ٹول اور ایسیٹ کیٹلاگز سنک کرتی ہے، یا آف لائن ہونے پر انہیں کیش سے لوڈ کرتی ہے۔
2. **روٹ۔** پاتھ `qr-code` کے لیے ٹول ویو منتخب کرتا ہے اور کوئری اس کی ابتدائی قدریں ہوتی ہے۔
3. **لوڈ۔** `loadTool`، `tool.json` لاتا ہے، اسے اسکیما کے مطابق جانچتا ہے اور ٹیمپلیٹ، اسٹائلز اور ہکس لاتا ہے۔
4. **لنک پارس کرنا۔** `parseUrlState` پیرامیٹرز کو ان پٹ قدروں میں بدلتا ہے۔ `?logo=lolly/logo/primary` جیسا ایسیٹ حوالہ غیر حل شدہ `{ id }` بن جاتا ہے۔
5. **رن ٹائم شروع کرنا۔** `createRuntime(tool, host, initialValues)` پروفائل ڈیٹا، ڈیفالٹس اور لنک سے ان پٹ ماڈل بناتا ہے، ایسیٹ حوالوں سے ایسیٹس حاصل کرتا ہے، ہکس لوڈ کرتا ہے اور `onInit` کال کرتا ہے۔
6. **رینڈر۔** شیل رن ٹائم کو سبسکرائب کرتا ہے، ماڈل سے کنٹرولز ڈرا کرتا ہے اور بھرا ہوا ٹیمپلیٹ `#tool-canvas` میں لکھتا ہے۔
7. **تعامل۔** ٹائپ کرنے سے `runtime.setInput` کال ہوتا ہے، جو پابندیاں لاگو کرتا ہے، `onInput` کال کرتا ہے، ٹیمپلیٹ دوبارہ بھرتا ہے اور پھر ڈرا کرتا ہے۔
8. **ایکسپورٹ۔** **Download**، `runtime.export(node, format)` کال کرتا ہے اور شیل کا `host.export` فائل بناتا ہے: راسٹر، DOM واکر سے ویکٹر، PDF، دستاویز یا `schemas/tool.schema.json` کے دیگر فارمیٹس میں سے کوئی۔ طبعی اکائیاں فارمیٹ کے مطابق تبدیل ہوتی ہیں۔ جہاں فارمیٹ انہیں رکھ سکتا ہو، وہاں میٹا ڈیٹا اور Content Credentials ایمبیڈ ہوتے ہیں۔ تجرباتی ٹولز کا واٹر مارک ہوسٹ سے آتا ہے، ٹول سے نہیں۔ [ٹیمپلیٹس اور رینڈرنگ](/info/tool-rendering.html) اور [فائل ایکسپورٹ کریں](/info/exporting.html) ایکسپورٹ کے مرحلے کی تفصیل دیتے ہیں۔
