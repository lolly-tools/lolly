# Ask Lolly

输入一个问题，Ask Lolly 会用这些指南中涵盖该问题的章节原文来回答，并注明出处页面，附带一个直达该章节的 **Open in docs** 链接。不生成任何内容：答案是在你的设备上检索、引用并标注出处的。

在引用的章节下面是应用中与同一问题匹配的位置：一个工具、一个实用工具、一个已保存的项目、一个目录素材、一项设置或应用的一个页面。每一行只负责导航。答案中的任何内容都不会更改设置、打开文件或替你行事，与[搜索](/info/search.html)遵循的规则相同。

## 提出问题

在视图底部的问题输入框中输入，然后按 Enter。短于两个字符的内容会被忽略。答案堆叠在输入框上方，最新的在最后，你可以继续提问。

![Ask Lolly，打开且为空：视图底部的问题输入框，以及说明答案来自文档的提示](/t/url-shot?url=%2F%23%2Fask&width=1200&height=820&waitMs=2200&format=svg&walker=1&filename=ask-view)

每个问题都是独立回答的：之前的问题不会带入上下文，所以在关于导出的问题之后问 “what about PDF?”，会被读作只关于 PDF 的问题。每次都请问完整的问题。

问题的第一个词决定答案以什么打头：

| 你以此开头 | 打头的内容 |
|---|---|
| *where*、*find*、*open*、*show*、*go to*、*goto*、*take*、*jump*、*navigate*、*switch* | 应用中匹配的位置 |
| *make*、*create*、*generate*、*build*、*design*、*convert*、*resize*、*compress*、*remove*、*strip*、*export*、*render*、*add* | 匹配的工具 |
| 其他任何词，包括 *how do I* 和 *what is* | 文档章节，这是默认值 |

两部分总是都会被检索，所以误读问题只会让答案重新排序，而不会丢掉一半答案。

匹配会去掉常见的疑问词（*how*、*do*、*I*、*the*、*my*），按章节覆盖了你剩余词语的数量排序，再按匹配的位置排序：标题比正文更重要。匹配基于子串，忽略大小写和重音，所以拼写错误不会被纠正。没有匹配时，Ask 会如实说明并指向文档索引，而不是编造答案。

**Better matching** 是可选的。在你收到第一个答案后，Ask 可以提供一个小型匹配模型及其下载大小，帮助把问题匹配到用不同词语描述同一件事的指南。只有在你同意时才会下载，在这台设备上运行，并且只改变哪些章节排在前面：答案仍是文档自己的原文。你也可以从 **Settings → Preferences → Available offline** 下载它，在那里它被列为 **Ask matching model**（[离线可用](/info/dashboard.html#available-offline)）。

## 返回的内容

答案卡片按固定顺序组装：

1. **章节本身**，从文档源渲染：段落、列表、表格、代码和引用，应用内链接和 `/info` 链接均可点击。较长的章节会被 **Show more** 截断，点击后就地展开。图片会被去掉，指向其他网站的链接渲染为纯文本而不是锚点。
2. **出处**：*页面 › 标题*，以及指向该章节的 **Open in docs** 链接。
3. **文档中的更多内容**：最多四个其他匹配的章节，以链接形式列出。
4. **应用内的行**，位于与搜索相同的分组标题之下。

完整文本来自每个文档页面发布在 `/info/<slug>.md` 的纯 markdown 副本，而这些副本只有英文。在其他语言中，以及在少数不是由 markdown 构建的页面上，答案会回退为搜索索引中保存的简短摘录，而不是整个章节。无论哪种情况，出处和 **Open in docs** 链接都在，指向你所用语言的页面。

## 它在哪里

路由是 `#/ask`。它没有标签页，在 Utilities 网格中也没有方块；入口是搜索栏和地址本身。

- <!--i:search--> **从搜索进入。** 每个结果面板的最底部，在其他分组找到的具体结果之下，都有一行 **Ask Lolly: *your query***。它以 `#/ask?q=…` 的形式移交问题，视图在到达时提问一次。移交的词语以小写形式到达，标点被去掉，如有需要，请在问题输入框中修改。
- <!--i:link--> **从链接进入。** `#/ask?q=how%20do%20I%20export%20a%20transparent%20png` 会打开视图并已提出该问题。哈希只是入口的种子：你之后输入的问题会就地回答，绝不会改写地址。

搜索栏在这个视图中让位，因为问题输入框使用 Enter，返回按钮会把你带回你来的地方。

屏幕上的答案在本次会话中保留：如果你离开再回来，它们仍在，重新加载则会清除。没有任何内容写入存储，所以没有需要管理的历史记录。

## 离线

答案由文档站点已发布的两个静态文件组装而成：每种语言的搜索索引和页面的 markdown 副本。两者都按名称获取，所以一旦缓存，Ask 在没有网络时也能继续工作。在应用中阅读指南时会随之缓存它们，[离线可用](/info/dashboard.html#available-offline)下的 **Guides & docs** 一次下载就可获得整个站点，包括截图。

没有它们时，答案的文档部分就是不出现，也不会报错。应用内的行仍会出现，因为它们是对设备上已有的数据进行匹配的。

## 隐私

你的问题绝不会离开设备。匹配在本地对按名称获取的文件运行，所以你输入的内容不是任何请求的一部分；没有服务器能看到它，没有账号与之关联，重新加载后也没有任何记录。应用会获取或发送的完整内容，请参见[隐私政策](/info/privacy.html)。
