# Lolly 如何工作

Lolly 工具保存着一种文件的规则：版面、字体、颜色，以及其他人可以更改哪些部分。你、同事、脚本或 AI 代理填写字段，每个文件都能做对。本页展示各方分别做什么，以及从工具到成品文件的四条路径。

## 一个工具，你的规则，众多文件

品牌规则存在于工具中，而不是它生成的每个文件里。把工具做对一次，所有输出都会继承同样的字体、颜色和间距，无论是一张卡片，还是一张涵盖十几种语言的电子表格里的所有行。

![一个填写了一个字段的字标工具：字体、颜色和间距在制作该工具时就已确定](/info/shots/aud-rules-in-the-tool.svg)

做第一百个文件的人只需输入文字。如何检查成果、由谁检查，仍由你决定。Lolly 让值得检查的东西更少，让下一个文件做起来更快。

## 谁会接触工具

跟随一张活动卡片穿过一个组织，会出现三双手。每一双都建立在上一双的基础之上。

![设计师在工具中一次性设定规则；开发者通过脚本运行它，任何人都可以填写其字段；两者都生成成品文件](/info/diagrams/concepts/asset-relay.svg)

::: timeline
- <!--i:pentool--> **设计师设定规则。** 他们在 Design 中用品牌的字体和颜色排好卡片，然后选择哪些字段保持开放。这只做一次，所以再也不用有人手工为卡片做本地化。
- <!--i:code--> **开发者扩展工具。** 同一个工具通过命令行在夜间脚本中运行，所以新图表或新语言版本无需任何人重新打开设计就会到来。
- <!--i:people--> **任何人都能填写。** 一位在飞机上的销售代表，没有网络，也没受过设计培训，打开工具，为明天的会议做出卡片。
:::

开发者步骤中的新图表就是像这样的渲染结果，由一串数据和几项设置生成，无需任何人打开设计文件：

![一张带标题的堆叠面积图，三个系列用冷色调调色板分层，坐标轴、图例和标题都由模板而非手工放置](/t/url-shot?url=%2F%23%2Ftool%2Fchart%3FchartType%3Darea%26stackMode%3Dstacked%26palette%3Dcool%26heading%3DProduct%2520mix%2520by%2520quarter%26full&width=1440&height=900&dpi=192&waitMs=2600&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-lifecycle-chart)

销售代表轻松的一分钟，全靠设计师的用心和开发者的脚本才得以实现。每个角色用的都是同一个工具，而不是各自一个独立的产品。

## 通往文件的四条路径

每条路径都在同一个工具上运行同一个引擎，所以脚本生成的文件与你在应用中预览的一致。

![URL 参数和命令行参数变成同一个输入模型，通过一个共享的运行时和导出桥接运行](/info/diagrams/concepts/one-render-path.svg)

- <!--i:people--> **在应用中，一次一个。** 打开工具，填写字段，按下 **Export**。[制作你的第一个文件](/info/make-something.html)带你走一遍。
- <!--i:layers--> **在应用中，一次多个。** [批量生成](/info/batch.html#make-many-versions-of-one-design)（`#/batch`）接受粘贴或导入的表格，为每一行渲染一个成品文件。
- <!--i:cpu--> **通过脚本或 AI 代理。** [CLI](/info/cli.html) 无界面地运行工具，[MCP 服务器](/info/mcp.html)让代理发现并运行工具。指向工具的链接同样携带其输入，所以链接就是一个完整的请求。
- <!--i:server--> **通过你所在组织的服务器。** [Lolly Work](/info/organisation.html) 在服务器上按你所在组织的登录和工具政策进行渲染，保留可恢复的作业，并保存输出以供下载或经批准的交付。

一项作业能走哪条路径，取决于工具的格式和主机的能力：有些格式需要浏览器，所以命令行会把它们交给浏览器层。[用 CLI 渲染](/info/cli-rendering.html)列出了哪些格式在哪里渲染。

## 什么在哪里运行

制作、编辑和导出都在你的设备上运行，无需账号。需要服务器的功能，例如同步或把文件发送到已连接的服务，只有在你使用该功能时才会连接。使用 Lolly Work 时，共享项目、实时团队编辑、审批和服务器作业使用你所在组织的服务器。[什么在哪里运行](/info/compare.html#what-runs-where)把这两部分并排对比。
