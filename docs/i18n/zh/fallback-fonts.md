# 备用字体

设计系统的字体往往只覆盖世界上的部分文字系统。Lolly Demo 的标题使用 Outfit，正文使用 SUSE，这两个字体都没有西里尔字母、希腊字母、阿拉伯文、希伯来文、天城文、孟加拉文、泰文、中文、日文或韩文。当文档中含有设计系统的字体无法绘制的字母时，Lolly 会用开放的 Noto 字体绘制这些字母，这样导出就能把它们保留为矢量轮廓，而不是把文字变成图片。

设计系统的字体始终优先，顺序按设计系统列出的顺序。Outfit 没有越南文字母，所以越南文标题会从 SUSE 取得它们，SUSE 是 Lolly Demo 列表中的下一个字体。备用字体只绘制上述字体都无法绘制的字符，所以品牌字体保留它拥有的每个字母、数字和符号，即使它们位于另一种文字的单词之中。拥有某个汉字的品牌字体也会保留该汉字。

## 内置了什么

十五个字体，全部来自 Google Fonts 的固定提交，全部采用 SIL Open Font License 1.1。每个文件旁标出了它的下载大小。

| 文字系统 | 字体 | 版本 | 下载 |
|---|---|---|---|
| 阿拉伯文，包括乌尔都文和波斯文字母 | Noto Sans Arabic | 2.012 | 206 KB |
| 希伯来文 | Noto Sans Hebrew | 3.001 | 37 KB |
| 天城文（印地语、马拉地语、尼泊尔语） | Noto Sans Devanagari | 2.007 | 147 KB |
| 孟加拉文 | Noto Sans Bengali | 3.011 | 136 KB |
| 泰文 | Noto Sans Thai | 2.002 | 61 KB |
| 西里尔文 | Noto Sans，西里尔字母 | 2.015 | 112 KB，斜体 129 KB |
| 希腊文 | Noto Sans，希腊字母 | 2.015 | 75 KB，斜体 81 KB |
| 拉丁文，包括越南文和其他带重音的字母 | Noto Sans，拉丁字母 | 2.015 | 309 KB，斜体 342 KB |
| 简体中文，GB 2312 字符 | Noto Sans SC | 2.004 | 1.9 MB |
| 繁体中文，Big5 字符 | Noto Sans TC | 2.004 | 3.6 MB |
| 日文，Shift_JIS 字符 | Noto Sans JP | 2.004 | 2.1 MB |
| 韩文，所有谚文音节和 KS X 1001 字符 | Noto Sans KR | 2.004 | 2.4 MB |

每个字体的字重轴都完整保留，所以设计要求的每一种字重仍然可以绘制，粗体的中文、日文或韩文标题也是粗体。Noto Sans 字体的字宽轴固定为正常宽度，这使每个文件缩小一半；中文、日文和韩文字体没有字宽轴。Noto Sans 按文字系统拆分，所以一个西里尔文单词只下载西里尔字母。轮廓就是上游的轮廓，没有改动。

这些字体存放在同一个共享文件夹 `community/fallback-fonts` 中，从 `/catalog/packs/fallback-fonts/` 提供给每个设计系统，与 emoji 套组的共享方式相同。`scripts/import-fallback-fonts.ts` 根据 `scripts/data/fallback-fonts.json` 中固定的上游字体构建这些文件，用记录的 SHA-256 检查每个上游文件，并把许可协议文本写在字体旁边。

## 中文、日文和韩文

一个完整的中文、日文或韩文字体有 9.6 MB 到 17.8 MB，所以这些字体都被裁剪为其读者日常使用的国家字符集，再加上连续文本中的标点、假名、全角形式和符号：

- 简体中文：GB 2312，6,763 个常用汉字及其符号，共 7,522 个字符。
- 繁体中文：Big5，13,053 个汉字及其符号，共 13,629 个字符。不包含香港增补字符集。
- 日文：按 Windows 和网页读取方式的 Shift_JIS，即 JIS X 0208 加上 髙 和 﨑 这类名字所需的 NEC 和 IBM 增补字符，所有假名和半角片假名，共 7,432 个字符。
- 韩文：全部 11,172 个谚文音节和 KS X 1001，含其 4,888 个汉字，共 17,082 个字符。

这四个字体不含拉丁字母、希腊字母和西里尔字母，因为设计系统的字体和上述字体会绘制它们。字符集读取自 Encoding Standard 在固定提交处的索引文件，所以重新构建会得到相同的文件。

中文、日文和韩文共用大部分字符，但各自对其中许多字符的写法不同。同一个字符 直 在中文中是一种写法，在日文中是另一种。所以，一段文本中所有共用字符取自这些字体中的一个，绝不会取自两个，Lolly 按以下顺序选择该字体：

1. 该段文本的语言，取自其元素的 `lang`，或文档中离它最近的外层元素的 `lang`。工具的语言设置（例如证书的 Language）会设定它。Lolly 自己界面的语言和设计系统的语言不算，所以文档对每个人导出的结果都相同。
2. 该段文本的文字：出现假名表示日文，出现谚文表示韩文。当该段文本本身两者都没有时，会读取整个文档，所以日文文档中仅由汉字构成的标题会以日文绘制。同时含有假名和谚文的文档在这一步无法确定。
3. 在该段文本中，或者在文档中，出现只有繁体中文使用的字符，例如 體 或 說，就表示繁体中文，除非同一文本中也含有只有简体中文使用的字符。
4. 否则，简体中文。

所选字体没有的字符，绝不会取自其他三个字体。它会保持为图片，如下文所述。所选字体缺少的假名或谚文，例如标为日文的行中的韩文词，仍然可以取自日文或韩文字体，但只限于该字体不会绘制该行任何共用字符的情况。

在页面上，含有其中两种语言的画布会列出两个字体，浏览器用第一个字体绘制共用字符。导出则用各自的字体绘制每一段文本。

## 字体何时下载

只有当文档含有设计系统的任何字体都无法绘制的字符时，才会下载东西。英文文档，或设计系统所覆盖的任何语言的文档，从不下载备用字体。英文行中的符号，例如 ★ 或 ※，从不下载中文、日文或韩文字体。

文档第一次需要时，Lolly 只下载那一个字体，对应那一种文字，并把它保存在你的设备上。日文文档只下载日文字体，2.1 MB；繁体中文文档则下载 3.6 MB 的繁体字体。此后这种文字可以离线绘制，整理目录时字体也会保留。该字体与目录自己的文件放在一起，绝不在你上传的字体之中，所以它不会出现在你的品牌字体列表里。

命令行、终端应用和 MCP 服务器从磁盘读取同样的文件，所以不需要下载。

## 在页面上和在导出中

页面使用与导出相同的备用字体。如果不这样，浏览器会用系统字体绘制这些字母，而导出使用 Noto，包含它们的行在两者之间宽度会不同。Lolly 只在该画布上，把备用字体添加到设计系统字体列表的末尾，位于设计系统自己的字体之后、任何系统字体之前。自己设定了字体列表的工具，无论设在样式中还是元素上，备用字体都放在同一位置：在该列表给出的字体之后、任何系统字体之前。设计系统已覆盖的画布，字体列表与以前完全相同。

当字体列表以系统字体开头，例如 `system-ui` 或 Helvetica 时，页面不会改动该列表，因为导出用设计系统的字体绘制这些文字，而页面不是。

在 PDF 中，无论你选择哪种文字设置，这些文字都会变成用备用字体绘制的轮廓，因为实时的 PDF 文字无法携带嵌入字体所缺少的文字。在 SVG、EMF、EPS、DXF 和 WMF 中，只要文字被转换为轮廓，它们就会变成轮廓；文字保持实时时，则像以前一样由阅读者自己的字体绘制。当备用字体绘制了导出的一部分时，导出面板会显示类似这样的提示：

> 日文文字使用 Noto Sans JP 绘制，因为此设计系统的字体没有这些字母。

命令行会把同一句话作为提示打印出来。

## 什么仍然是图片

四种国家字符集之外的字符没有备用字体。生僻字，例如 𠮷、增补字符集为香港添加的字符，以及没有备用字体的文字系统，例如泰米尔文、埃塞俄比亚文或叙利亚文，处理方式都相同。在 PDF 中，含有这类字符的行会作为 300 dpi 的图片放入，导出面板会列出这些文字系统。在 SVG 中，该段文本保持为实时文字，由阅读者自己的字体绘制。

## 导出前的检查

Lolly Design 的 **Before you export** 卡片，以及 `lolly check` 的 `render` 检查，会报告没有任何字体能绘制的文字。它们像导出一样计入备用字体，依据同样的每个字体所含字符列表，所以备用字体能绘制的文字不会被报告。没有备用字体的文字系统，例如泰米尔文，以及超出国家字符集的中文、日文或韩文字符，仍然会被报告，因为导出会把它们绘制为图片或实时文字。检查从目录读取这些列表，不下载任何字体。

## 许可协议和署名

每个备用字体都采用 SIL Open Font License 1.1，每个目录条目都记录该许可协议以及许可协议文本的哈希，所以[创作版权与署名](/info/creative-rights.html)中的权利规则会像读取任何其他字体的许可协议一样读取它。许可协议文本与字体放在一起。Noto Sans 文件没有声明保留字体名称。中文、日文和韩文字体来自 Adobe，保留名称 Source；裁剪后的文件保留其 Noto 名称，并不使用该名称。

该许可协议说明，其条款不适用于用这些字体制作的文档。导出只包含它所用字母的绘制轮廓，与设计系统自己的字体一样，Lolly 不为备用字体添加字体程序、署名行或新的 content credential 条目。
