# Lolly 与品牌门户

_最后核查：2026 年 9 月 28 日。_

Lolly 与 [lolly.work](https://lolly.work) 合在一起，涵盖团队使用品牌门户所做的创作与治理工作流：已批准的资产、锁定的模板、访问控制、审核和分发。在选择人们如何查找品牌资产以及制作新资产时，可将这一组合方案与 Bynder、Frontify、Marq 或 Brandfolder 对比。

## 创作与组织服务

Lolly 的引擎和应用负责生成文件。模板、设计令牌和允许的输入界定了使用者可以修改的内容，渲染可以留在他们自己的设备上。独立使用的 Lolly 无需账号。

lolly.work 是同一项目中的组织服务，维护于[独立的仓库](https://github.com/lolly-tools/lolly-work)，与 Lolly 并行部署。它增加了身份、共享存储、策略、审批和报告。两部分均以 MPL-2.0 开源。这种分离使个人可以独立使用 Lolly，组织则可在自己掌控的基础设施上运行组合方案。

## 组合方案提供的能力

| 需求 | Lolly + lolly.work |
|---|---|
| 登录与预配 | OIDC 单点登录、多个身份提供方、SCIM 2.0 用户预配与组成员关系，以及会撤销现有会话的账号停用。仅支持 SAML 的身份提供方可通过 Keycloak 等 OIDC 桥接连接。 |
| 已批准的模板 | Lolly 定义模板的可编辑输入；lolly.work 应用组可见性和输入策略，用以锁定值、限制选项或隐藏控件。 |
| 共享资产库 | 实例自有的上传、集合、自定义元数据和受访问控制的目录，以及读取现有 DAM 和存储库的连接器。 |
| 审核 | 有序的审批步骤、符合条件的审批人组、法定人数规则和职责分离；审核可管控目录提交以及向组织目标的交付。 |
| 资产历史与可用性 | 实例自有资产的版本与回滚、保留与冻结、定时可用、过期和撤销。所连接的提供方保留各自的源历史。 |
| 报告 | 资产使用和下载计数、工具与导出活动、仪表盘和审计追踪。使用情况归因遵循部署的遥测策略；默认的归因设置需要征得同意。 |
| 分发 | 会过期、可撤销的链接，共享集合，访客访问，以及向已配置的组织目的地交付。 |

[lolly.work 运维指南](https://github.com/lolly-tools/lolly-work/tree/main/docs)介绍了这些功能及其配置。它们是现成可用的能力，而不是需要围绕 Lolly 另行搭建系统才能获得的功能。

## 选择门户工作流

成熟的门户提供托管服务、支持和丰富的 DAM 工作流。例如，[Frontify 的企业级 DAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management) 将资产发现、访问控制、审批工作流和分发结合在一起。请对比你所需的具体审核与权利工作流：Lolly 提供元数据、访问和可用性控制，而法务审查与许可义务仍需组织自己的流程。其审批链是顺序式的，不对任意分支的工作流建模。

Lolly 技术栈更年轻，其部署限制记录在 [lolly.work 状态页](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md)中。尤其需要注意，公共 lolly.work 站点是评估用的沙盒环境。长期运行的组织部署需要持久化存储和运维人员。自托管没有按席位计算的软件许可费用；但基础设施和管理仍需花钱。

现有的 DAM 也可以继续作为事实来源。lolly.work 的目录连接器会将其已批准的资产提供给 Lolly，人们在 Lolly 中按组织的规则创建新文件。这是一种集成选择；当组织希望自行管理这些工作流时，也可以使用 Lolly 自带的素材库和审批功能。
