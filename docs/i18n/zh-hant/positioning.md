# Lolly 的比較定位

Lolly 做到了今日創意工具做不到的事,以及它刻意留給那些工具去做的事。

若要看逐一工具的比較版本,針對 Canva、Adobe、Figma、渲染 API 與線上轉換工具各有一頁,請見[Lolly 逐一工具比較](/info/compare.html)。每一頁都說明了對方工具做得更好的地方,以及 Lolly 改以何種方式取代。

> **試行狀態:** Lolly 是一個封閉試行的原型,還不是成品,其安全性目前正在接受 SUSE 嚴格的基礎架構強化,為企業規模的使用做準備。[採用與治理](/info/adoption-governance.html#status)頁面說明了目前的狀態。

## 今日的工具

下方每個環形圖評分的是某個產品類別**以目前實際發佈的狀態**(而非行銷宣傳)完整交付某項能力的程度 - 每個類別都以其最佳代表產品來評分。Lolly 也是用同一把尺來評分:它拿到了整張表中唯一的紅色環,原因是成熟度。點開列名稱可看到評分背後的理由。各欄依上方的整體完整度列排序 - 即已評分列的平均值,不含花費列。

現今各創意工具的功能完整度，調查於 2026 年 8 月。評分標準：0 分表示不具備，25 分表示需以變通方式達成，50 分表示有實際功能但受限或不完整，75 分表示強大但有但書，100 分表示核心能力。

**評分說明。** Lolly 的評分假設其發佈的聲明屬實,這也是為什麼成熟度是它唯一的紅色環:封閉試行中、安全強化進行中、尚未經過稽核。Research 讓好幾格分數有所變動。

Canva 的評分依每列以其家族中最佳的成員來計算,因為它擁有 Affinity 與 Cavalry(兩者皆於 2025 年 10 月起免費提供)。離線與裝置端渲染評 75 分,靠的是 Affinity - 一套仍需要已驗證帳號、也帶有遙測的桌面套件,這也是 Adobe 同樣被扣分的原因 - 而 Canva 自身的離線模式只能編輯先前已同步過的設計,僅限單一裝置,視窗也有限。自動填入評 50 分:功能屬實,但僅限企業版、非同步、只支援文字與圖片。當 Buzz 推出試算表填入功能後(免費測試版,2026 年 8 月),Figma 的大量生成評分從 25 分升至 50 分。

整張表遵循一條規則:凡涉及你的內容或身分的列,要拿到滿分(100)必須有一項無須帳號、也無雲端前提即可使用的能力;描述產品本身的列(成熟度、易用性)不受此規則限制。這條規則讓 Adobe 在來源溯源(provenance)一項上被扣分:目前發佈範圍最廣的 C2PA 支援(Photoshop、Lightroom、Premiere、Firefly)可在本機與雲端簽署,但一律需要 Adobe 帳號與身分,所以評 75 分。同一條規則也讓渲染 API 在大量生成與自動化上被封頂扣分。

Lolly 的來源溯源評 75 分,反映的是裝置端離線簽署:架構上更為穩固,但尚未經過稽核,而且裝置金鑰在標準驗證器中會顯示為未經驗證,除非有身分機構或組織自有的 CA 為其背書。Penpot 的 50 分是透過官方的 Lolly Export 外掛取得:採用同一套引擎簽署,選擇性加入,並揭露為 Lolly 自有的功能。Penpot 也拿下了整張表中唯一超出常規尺度的環 - 裝置端渲染 90 分 - 瀏覽器畫布、儲存到你自己主權可控的雲端(甚至是一台筆電)、私人匯出;與 Lolly 的差別只在於多了一道伺服器跳轉。Cloudinary 有自己獨立的一欄:它是一套媒體管線(數位資產管理、轉換 API、CDN),也是唯一一個發佈了 C2PA 支援的雲端欄位(50 分,因為 fl_c2pa 是在交付時簽署,證明的是「由 Cloudinary 交付」,而非「由你製作」)。

即時協作則反過來:Figma 訂下了規模基準(200 位編輯者同時在線),而 Lolly 一對一、氣隙隔離(air-gapped)的 P2P 協作評為「部分」。價格是一項標明為推測值的估計:以真實座位組合計算牌價,刻意估得寬鬆,用於呈現規模而非用於採購。渲染 API 在限制條件上評 75 分:範本是鎖定的,沒有品牌治理層。

差距在於:目前沒有任何已發佈的產品是「以限制條件優先」且能離線運作、無須帳號、渲染路徑中也沒有伺服器的 - 也沒有任何競品複製了這條「無帳號」的準則。Lolly 現在也推出了自有的開放式畫布 - **Design**,一個可直接操作的自由畫布 - 但其上的顏色、字型與資產都遵循品牌全域設定,所以即使是自由編排,依然維持限制條件優先。

Lolly 目前**仍不是**一套不受限制的設計套件;設計師仍會繼續使用 Illustrator 與 Figma 來進行客製化的工作 - 而當那份工作需要變成一項受治理、可重現的資產時,Design 工具的[匯入設計](/info/design-import.html)功能會把完成的 Figma、Penpot、Illustrator、InDesign 或 PDF 檔案帶入畫布,成為可編輯、符合品牌規範的方塊。

## 適合用它做的事

- 快速生成可操作化的創意資產(活動用磚塊、徽章、簽名檔、警示)
- 在開放式畫布(Design)上進行自由排列,同時各項元件 - 顏色、字型、圖示、圖片 - 都必須維持符合品牌全域設定
- 匯入一份完成的 Figma、Penpot、Illustrator、InDesign 或 PDF 設計(Design 工具的匯入設計功能),使其能以每種 Lolly 格式進行編輯、治理與確定性地重新渲染
- 「填三個欄位、拿到完成資產」這類一對多的流程 - 包括在 `/pro` 批次網格中,從試算表/CSV 進行大量批次作業(貼上或匯入資料列,每列產出一項完成資產,以 zip 壓縮檔下載)
- 持續運作、週期性的品牌化輸出
- 品牌表現的集中控管比表現彈性更重要的情境

Deck Studio 很能衡量這裡的能力上限:一整份投影片組以資料形式宣告,在畫布上即時排版,再匯出為原生可編輯的 PowerPoint。

## 不適合用它做的事

- 客製化或旗艦級的主打內容(大型看板廣告、重要影片)
- 真正需要設計師操刀的獨特宣傳活動
- 需要完全跳脫品牌系統的發想工作 - Lolly 的開放式畫布仍會讓顏色、字型與資產遵循品牌全域設定,而這正是它的重點所在

## 以機率的方式創新,以確定的方式規模化

多數「AI 創意」的推銷詞把模型放錯了那條古老界線的一側。抄寫員與泥金裝飾師早就確立了界線該落在哪裡:你在草稿階段自由發揮,那裡任何嘗試都可以進行,也沒有任何東西是定案的;然後你才走向印刷機,印刷機之所以令人卻步,正是因為它會定案。草稿才是藝術所在之處。印刷機則是藝術得以流傳的方式。兩種工具,兩種任務,各自以自己的方式富有創造力,而印刷出來的成品之所以值得信賴,是因為印刷機每一次印刷都信守承諾。

Lolly 是印刷機,不是草稿。你可以把任何東西帶進發想階段 - 一個模型、一位設計師、一張餐巾紙 - 但當一個構想必須變成一萬件資產時,它就要經過某個每次渲染結果都相同、且輸入內容任何人都能讀懂回溯的東西。這正是上面這場比較真正的重點:不在於誰有更好的生成器,而在於誰能讓那個「定案」的步驟可重現。

## 核准工具，而非檔案

市面上其他每一項工具產生的都是一個必須經過檢查的*檔案* - 品牌經理在 Slack 討論串中確認、法務審查免責聲明、再改一輪、再審一次。Lolly 把核准往**上游移動一步**。品牌規則 - 精確的十六進位色碼、已授權的字型檔、出血邊界、間距 - 直接寫死在工具的 HTML 與 CSS 中，因此範本*不可能*產出偏離品牌的成品。真正負責強制執行的是版面配置本身。

於是你不再核准產出的成品，而是核准**產生這些成品的工具**。核准一次，之後這項工具產出的每一個成品都因其架構而預先獲得核准 - 不需要人力介入，不需要審核流程，不論數量多大。

這才是確定性引擎真正帶來的改變：它不是舊有核准流程的加速版，而是徹底移除了這道流程。對創意團隊來說，這是護欄，而非取代 - 你依然投出那顆球（資料、文案、圖片），而程式碼就是保齡球道兩側的護欄，讓每一次投擲都不會滾進溝裡。

![製作人唯一的工作：輸入文字。字體、顏色與間距早在工具核准時就已經定案](/t/url-shot?url=%2F%23%2Ftool%2Fwordmark%3Ftext%3DApproved&width=1440&height=900&dpi=192&waitMs=2000&walker=1&format=svg&dark=1&filename=aud-approve-the-tool)

| 舊式的成品核准方式 | Lolly 式的工具核准方式 |
|---|---|
| 每個完成的檔案都要逐一檢查 | 工具只需檢查一次 |
| 需求 → 設計師製作 → 品牌審查 → 法務審查 → 修改 → 再審 | 改一個參數 → 完成的成品 |
| 設計師、品牌經理、法務與提出需求者都要參與 | 只需製作人一人 |
| 每件成品耗時數天 | 每件成品僅需數秒 |
| 一萬件成品 = 一萬次審核流程 | 一萬件成品 = 零次（範本早已核准） |

## 這帶來的獨特價值

- **在情境中安全地釋放大膽的設計潛力。** 工具能在寫死的護欄之內，表達大膽前衛的設計構想。

- **軟體定義的內容自動化，直接產出最終成品。** 輸入 → 完成的檔案。不需要「從設計工具存檔後再自行後製」。
- **工具可以組合工具。** 一項工具能內嵌另一項工具的算繪結果，並將其作為單一完成成品的一部分回傳，且工具與工具之間毫無程式碼耦合 - 這是目前市面上任何開放式畫布或 DAM 範本產品都不具備的基本能力。
- **供應商中立。** 完整的功能與成本控制權。開放原始碼引擎。工具與成品都是 git 追蹤的內容，而非鎖在某家 SaaS 廠商的資料庫裡。

## 內容主權

前一節加總起來的結果有個名字：主權。你的媒體流程運行在你自己擁有的硬體上。你的品牌 - 代符（token）、字型、標誌，以及執行這些規範的工具 - 都存放在你握有的檔案裡、由你掌控的版本控制系統中，而非某家廠商附帶「匯出」按鈕的資料庫裡。算繪發生在你眼前的裝置上，因此成品的存在從不需要經過第三方，從輸入到完成檔案的整條路徑都是開放原始碼且可供檢視的。就算所有 SaaS 設計廠商明天全部消失，Lolly 的部署也不會受到任何影響。

這對任何作品理應比訂閱方案更長久的人都很重要：無論是相片書存放在那台筆電上的家長，還是品牌資料庫受採購規範約束的公家機關。對組織而言 - 公家機關、受監管產業，任何品牌是策略性資產而非裝飾品的單位 - 「我們的內容存放在哪裡、誰能關掉它」是治理問題，而非個人偏好。這裡所說的主權是架構本身的特性，而非為了合規才加上的代管功能，[隱私權政策](/info/privacy.html)與[自行驗證](/info/verify-yourself.html)這兩個頁面的存在，就是為了讓你能親自查核這項主張，而非全憑信任。

這一切底下有一個承諾，以承諾而非功能的姿態陳述：**只要是在你的裝置上算繪，就永遠免費。** 引擎、殼層、工具、格式 - 整條裝置端的創作路徑都是開放原始碼，而且會一直維持如此。這項承諾有其機制作為後盾：已發布的版本所採用的授權方式使其無法被收回，也不存在任何貢獻者合約能在日後重新授權這份作品。整個界線可以濃縮成一句話：凡是在你的裝置上算繪的一切，永遠免費且開放原始碼；跨網路協調人與機器則是另一個獨立控制平面 [lolly.work](https://lolly.work) 的工作。
