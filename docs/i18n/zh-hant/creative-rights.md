# 創作權利與署名

你應該能使用其他人製作的好作品，而不必成為授權專家，也不必悄悄略過製作作品的人。所以 Lolly 會保留它所繪製的每件作品的來源，讀取為其記錄的授權，算出該授權對你實際進行的使用有什麼要求，完成程式能做的部分，並告訴你只有你能做的部分。

這一切都不是法律建議，也不是對你專案的裁定。Lolly 記錄事實，套用一小組從授權自己的法律文本讀出的規則，並顯示它的推演過程。有條件的授權是正常、被允許的選擇。它絕不會被呈現為壞掉的素材。

## 你會在哪裡遇到這些

表情符號組是最常見的情況。Twemoji 是 CC BY 4.0，所以含有表情符號的標題匯出時會註明圖稿來源，而你無須再做任何事。兩個 OpenMoji 組都是 CC BY-SA 4.0，所以以品牌處理重新著色其中一個字符屬於改作，而分享該改作時會要求你一次性挑選相容的授權。Fluent（MIT）、Noto 與 Blobmoji（兩者皆為 Apache 2.0）也已登記，每個都依其自身已審閱的授權解析。

選擇一組絕不會被阻擋，而組合控制項會在你選擇之處顯示授權。同樣的規則也適用於目錄插畫、LUT、字型與任何其他已記錄的作品。

## 三個彼此獨立的事實

「CC BY 4.0」、「這次使用需要署名」和「署名已經在你剛下載的檔案裡」是三種不同的陳述，Lolly 會將它們分開處理：

- **證據**是來源宣告的內容，依發現時的樣子記錄，附上是誰說的以及在哪裡讀到。之後的匯入絕不會覆寫較早的記錄。
- **義務**是已審閱的規則針對一次使用、一條交付路線與一群受眾，從該證據得出的結論。在分享時才適用的條件，在你私下工作時仍維持為有條件的。
- **交付**是完成的位元組實際帶有的內容，透過讀回來測量。只有在讀取者於交付的檔案中找到署名之後，Lolly 才會說署名已包含在內。

## 你看到什麼，以及該做什麼

相同的文字出現在匯出面板、Verify、命令列與機器結果中，大致依你遇到的頻率排序。

| 你看到的 | 它的意思 |
|---|---|
| Source credits will be included. | 署名已準備好，且路線可以攜帶署名。尚未寫入任何東西，所以這不是成功訊息。 |
| Credits included in this file's metadata. | 交付的位元組已被讀回，憑證已驗證，且每個必要的來源都在憑證中找到。 |
| Credits and credentials are in the download package. | 署名以隨附檔案的形式與成品一起傳遞。傳給別人時請把它們放在一起。 |
| If you share this adaptation, it needs a compatible licence. | ShareAlike 來源被更動了，而結果要去的地方不只是私人使用。選擇是一個動作，而不是每個放置處一個對話框。 |
| Add this credit to the post description. | 所選的路線既不帶憑證，也沒有可讀的署名，所以署名文字要由你貼上。 |
| No required credit under the recorded CC0 dedication. | 該宣告不要求任何東西。仍提供禮貌性的署名。 |
| Source licence not recorded. | 這個來源沒有記錄任何東西。這是要填補的空缺，不是對作品不利的發現。這絕不是作品可以自由傳遞的證據。 |
| Conditions recorded, not yet interpreted. | 識別碼已被辨識，其條件已列出，但這裡沒有任何規則讀取它們。沒有自動通過，也沒有自動禁止。 |
| Two licence declarations disagree. | 兩筆記錄指名不同的授權，而沒有任何東西選出適用哪一項授權。 |
| The credits are not in the file that was delivered. | 署名曾被承諾，讀回時卻沒有找到，而檔案仍是你的。請再次匯出，或手動使用署名文字。 |

Lolly 絕不說「copyright verified」、「legally safe」、「fully cleared」或「rights cleared」，產品中任何地方也沒有單一的綠色授權徽章。這些字眼會宣稱任何程式都無法檢查的事。

## 始終歸你所有的部分

- **你的授權選擇由你決定。** 認領檔案將過去合而為一的三種狀態分開：未宣告公開授權、明確的保留所有權利聲明，以及實際的公開授權。Lolly 只為後兩者寫入權利行，而且絕不取自你的個人資料。
- **你的作品不會被替你重新授權。** 來源的條款與你自己的輸出宣告是獨立的記錄。ShareAlike 條件適用於它所管轄的改作，而不是自動適用於你製作的其他一切。
- **私人作品仍可使用。** 在分享時才適用的條件，會在分享出現在視野時提出。這裡沒有任何東西變成匯入禁令，也沒有授權問卷擋在你與你自己的檔案之間。
- **決定依其自身的事實被記住。** 你記錄的每個選擇都蓋有一個指紋，來自它所針對的作品、使用、路線與受眾。更改組合、處理方式、格式或受眾，問題就會再被問一次。沒有籠統的「忽略授權」開關，因為把警告點掉無法交付署名，也無法授予許可。
- **你的詳細資料與第三方的署名是分開的。** 移除你自己的個人中繼資料不會移除被署名的藝術家，而必要的署名絕不是匯出你聯絡資料的藉口。

## Lolly 在各處做什麼

- **在目錄中。** 作品的資料頁顯示其來源與創作者、標準的授權名稱（下方保留原始標籤）、有記錄時可複製的署名，以及說明使用它需要什麼的一行。圖塊陳述要求；它絕不宣稱匯出已完成。
- **在匯出面板中。** 一旦渲染使用了已記錄的作品，Source credits 卡片就會出現在 Content protection 內，位於你為自己的匯出選擇的 Licence 旁邊。它顯示狀態、位於 Details 後面的署名文字、Copy credit 按鈕，以及需要做決定時的行內卡片。決定絕不是阻擋式的對話框：還有待辦動作的下載仍會繼續。
- **在檔案中。** 放置了已記錄作品的匯出，為每件不同的作品寫入一個 Content Credentials 來源素材成分，綁定到其公開位址上的原始位元組，並帶有創作者、授權及其連結、來源、修訂版與更動。Lolly 簽署的是它所觀察到的內容。它絕不代表上游藝術家簽署聲明，而 Verify 會說明發生的是這兩者中的哪一種。
- **在套件中。** 無法容納憑證的下載（例如 `.lottie` 動畫）會將署名以 `CREDITS.txt` 與 `credits.json` 放在套件內。它們在寫入後被讀回，並且不宣稱它們有已簽署的憑證。
- **寫入之後。** 交付的位元組會在任何東西說署名已包含在內之前被讀回。未通過驗證的憑證不算作已交付的署名。
- **在可編輯的 `.lolly` 檔案中。** 只有在已審閱的授權記錄了傳遞來源的許可時，位元組才會傳遞。套件的 `CREDITS.txt` 列出傳遞了什麼、依何種授權，以及什麼被保留與其原因。未記錄的授權會被保留。你仍可刻意納入被保留的內容，而署名檔案會記錄這是你的選擇。
- **在 Verify 中。** Sources 面板列出檔案記錄的每個來源，附有計算出的摘要、署名、Copy credit 按鈕、只在你要求時才開啟的 Open source 連結，以及所檢查內容的明示限制。只有在你挑選使用方式時才會出現 Check for this use 問題，且回答這個問題不會擷取任何東西。
- **當你移除中繼資料時。** 移除會告訴你檔案不再攜帶多少來源署名，提供署名文字，並提供將署名放在另一個檔案中的乾淨檔案。被移除的位元組絕不會被重新蓋印。

::: details Lolly 已審閱的授權
規則版本 `rights-rules-2026-09-13.2`。每條規則都是從授權自己的法律文本讀出的，其來源章節在這裡以及 `engine/src/rights-profiles.ts` 中規則旁邊都有引註。版本與移植版依記錄保留：CC BY 3.0 的宣告保留它自己的版本，而不會因為應用程式的選擇器偏好 4.0 就被回報為 4.0。

| 授權 | 它對 Lolly 能進行的使用有什麼要求 | 讀自 |
|---|---|---|
| CC BY 4.0 | 創作者、標題、著作權聲明、授權名稱與連結、來源連結以及更動的標示，各在來源有提供時。不排除任何使用，包括商業使用。 | [Legal code](https://creativecommons.org/licenses/by/4.0/legalcode.en)，第 2(a)(1) 與 3(a) 節 |
| CC BY-SA 4.0 | 相同的署名。此外，如果你分享改作，它必須以相容的授權發布：CC BY-SA 4.0、Free Art License 1.3 或 GPL-3.0-or-later，這是單向的。這三者以資料形式取自 Creative Commons 清單，絕不依名稱比對。 | [Legal code](https://creativecommons.org/licenses/by-sa/4.0/legalcode.en)，第 3(a) 與 3(b) 節；[相容授權清單](https://creativecommons.org/compatible-licenses/) |
| CC0 1.0 | 沒有任何要求。該宣告不帶條件，所以 Lolly 提供禮貌性的署名，絕不將其呈現為必要。 | [宣告](https://creativecommons.org/publicdomain/zero/1.0/legalcode.en)，第 2 與 3 節；關於署名的 [CC FAQ](https://creativecommons.org/faq/) |
| CC-PDDC | 沒有任何要求。記錄的是斷言本身與誰做的，因為認證是單方的陳述而非證明。 | [宣告與認證](https://creativecommons.org/licenses/publicdomain/)各段 |
| Apache License 2.0 | 來源的聲明，以及 NOTICE 檔案的署名文字，隨散布的作品一起傳遞。執行階段使用沒有要求。要求聲明文字、而作品卻沒有帶的授權，會被回報為缺口。 | [Apache License 2.0](https://www.apache.org/licenses/LICENSE-2.0)，第 4 節，條件 1 至 4 |
| MIT | 著作權行與許可聲明隨副本與重要部分一起傳遞。執行階段與參考使用沒有要求。 | [MIT](https://opensource.org/license/mit)，許可聲明條件 |
| SIL OFL 1.1 | 以該字型渲染文字，對文字沒有任何要求。傳遞字型檔案則需附上授權、著作權聲明與保留名稱規則。 | [OFL 1.1](https://openfontlicense.org/open-font-license-official-text/)，條件 2、3 與 5；關於文件的 [OFL FAQ](https://openfontlicense.org/ofl-faq/) |

**已記錄，未詮釋。** CC BY-NC、CC BY-ND 以及 NC-SA 和 NC-ND 組合已被辨識，其條件已列出，但這裡沒有任何規則讀取它們。它們回報 `licence.unknown`，並附上指名條件的一行。商業情境無法從價格或帳號判讀，而每個組合文本都需要自己的審閱，規則才會讀取該文本。

還有三種同樣誠實的回答，但它們都不代表許可：

- `LicenseRef-` 識別碼會原樣回傳。它指向一份儲存的定義，絕不會因為拼法就成為專有的。
- 沒有東西能辨識的宣告會以未解析的形式回傳，並保留原始文字。
- `A OR B` 是權利人提供的選擇，所以每個選項都會回傳，且都不會被選定。`A AND B` 是累加的，這些規則記錄它，而不是把兩個設定檔一起解讀。
:::

::: details 在命令列與透過 MCP
當評估有必要的署名或問題時，渲染會在標準錯誤輸出上印出 `Rights:` 區塊。它帶有狀態、以 `code - summary` 表示的每個問題一行、交付檔案被讀回的結果，以及要貼上的署名文字。

```
Rights: actions-required
  licence.adaptation-choice - If you share this adaptation, it needs a compatible licence.
  Credential intact. It records 1 source. The exporter recorded it; the source did not sign a credential of its own.
  Credits included in this file's metadata.
  "water wave (OpenMoji Color 17.0.0)" by Vanessa Boutzikoudi (OpenMoji), CC BY-SA 4.0 https://creativecommons.org/licenses/by-sa/4.0/, source https://raw.githubusercontent.com/hfg-gmuend/openmoji/f9fc506a3f913be9897ab0181d611d4c910a4104/color/svg/1F30A.svg, changes: recoloured.
```

這裡署名在檔案中，而在檔案被分享之前，仍有授權決定待做。無論如何，檔案都會寫出。

| 狀態 | 含義 | 退出碼 |
|---|---|---|
| `ready` | 沒有任何事項需要人工處理。 | 0 |
| `actions-required` | 在檔案被分享之前，仍有一項決定尚待做出。檔案依然會被寫入。 | 4 |
| `use-not-covered` | 一條經過稽核的規則判定，該授權不涵蓋這一次使用。 | 4 |
| `unknown` | 唯一的問題是空白：一份未被記錄的授權，或是尚未被解讀的條件。 | 0 |
| `delivery-failed` | 由回執設定，而不是由評估設定：承諾提供的署名沒有在交付的位元組中被找到。匯出面板會顯示這一狀態；命令列則會在其回讀那一行報告同樣的事實。 | 不列印 |

退出碼 4 是這個 CLI 在保護性檢查說不的時候已經給的代碼。它不是 3，後者表示「在另一個 runner 上重試」，因為授權決定會在每個 runner 上等著。

`--rights=private` 表示這次渲染不會交付給任何人。這個區塊依然會列印，署名依然可以複製；退讓的只是那條以分享為前提的條件，同時也不會記錄任何交付聲明。這裡沒有用來忽略某項條件的標誌：`--rights=ignore` 屬於用法錯誤。

問題代碼穩定且機器可讀，與翻譯後的文字無關：`attribution.source-missing`、`attribution.delivery-missing`、`licence.adaptation-choice`、`licence.use-not-covered`、`licence.grant-conflict`、`licence.unknown`、`source.redistribution-unknown`、`credential.ingredient-missing`。

透過 MCP，`lolly_verify` 回傳 `rights` 酬載，包含摘要、每個已記錄來源一列，以及明示的限制。無瀏覽器的 `lolly_render` 回傳 `status`、`issues`、`credits`、`fingerprint`，以及透過讀回位元組測量的 `creditsInFile` 旗標。
:::

::: details 規則存放在哪裡
五個引擎模組，全都是純粹的：沒有網路、沒有時鐘、沒有檔案系統。規則資料有版本並存在儲存庫中，絕不是擷取來的。

| 模組 | 它保存什麼 |
|---|---|
| `engine/src/rights-profiles.ts` | 識別碼表、極簡的 SPDX 運算式讀取器、附有引註的已審閱設定檔，以及署名可印出的連結的唯一規則。 |
| `engine/src/rights-evaluate.ts` | 分類、問題、署名計畫與指紋。具決定性：相同的事實以不同順序給出相同的答案。 |
| `engine/src/rights-attribution.ts` | 可讀的署名、隨附檔案、來源素材成分，以及寫入後測量的回條。 |
| `engine/src/rights-companion.ts` | 套件署名的讀回（ZIP 型下載內的 `CREDITS.txt` 與 `credits.json`），確認署名而不宣稱有已簽署的憑證。 |
| `engine/src/rights-report.ts` | 將已驗證的憑證讀回成 Verify 提出的三個問題。 |

`tests/fixtures/rights/` 中的預期檔案是依據授權文本而非評估器的輸出撰寫的，其 README 引註了每項預期背後的章節。
:::

## 這尚未做到的事

- **沒有確認任何目的地。** Lolly 準備說明文字。連接器接受請求並不證明署名到達了讀者，這裡也沒有任何東西承諾之後的上傳、螢幕截圖或轉碼會保留隱藏的中繼資料。
- **原生中繼資料署名欄位不是由計畫寫入的。** 署名在 Content Credentials 與可讀文字中傳遞。IPTC 與 XMP 的逐來源署名欄位尚未從署名計畫填入。
- **更正與撤回尚未建置。** 為已記錄的作品補上缺少的創作者或本機更正，以及撤回記錄，目前都沒有介面。
- **連接的提供者尚未建置。** 購買的圖庫素材、自訂許可與提供者帳號沒有匯入路徑，所以它們的授權只能被記錄為你自己的陳述。
- **組織政策尚未與這些結果合併。** 匯出政策與授權條件目前是分開的，而組織的核准不是權利人的許可。
- **有幾條交付路線尚未在這條路徑上。** 下載目錄原件、批次 ZIP、Send 與 Copy image 目前不評估也不攜帶這些署名。裁切、調色、加框的副本、Download as 轉換與影片剪輯則會：有已記錄授權但本身沒有 Content Credentials 的來源，會作為未簽署的來源素材成分帶著它的署名一起傳遞，LUT 依其自身授權署名而絕不算作圖片的署名，而無法攜帶其來源要求之署名的檔案則不會被儲存。目前沒有任何東西會讀回這些檔案，所以它們的署名是已寫入，而非已確認。Retouch、單張圖片去背與放大，以及音訊擷取，只保留來源自己的憑證。
