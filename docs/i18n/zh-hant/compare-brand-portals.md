# Lolly 與品牌門戶

_最後核查：2026 年 9 月 28 日。_

Lolly 與 [lolly.work](https://lolly.work) 合在一起，涵蓋團隊使用品牌門戶所做的創作與治理工作流：已批准的資產、鎖定的模板、訪問控制、稽核和分發。在選擇人們如何查詢品牌資產以及製作新資產時，可將這一組合方案與 Bynder、Frontify、Marq 或 Brandfolder 對比。

## 創作與組織服務

Lolly 的引擎和應用負責生成檔案。模板、設計令牌和允許的輸入界定了使用者可以修改的內容，渲染可以留在他們自己的裝置上。獨立使用的 Lolly 無需賬號。

lolly.work 是同一專案中的組織服務，維護於[獨立的倉庫](https://github.com/lolly-tools/lolly-work)，與 Lolly 並行部署。它增加了身份、共享儲存、策略、審批和報告。兩部分均以 MPL-2.0 開源。這種分離使個人可以獨立使用 Lolly，組織則可在自己掌控的基礎設施上執行組合方案。

## 組合方案提供的能力

| 需求 | Lolly + lolly.work |
|---|---|
| 登入與預配 | OIDC 單點登入、多個身份提供方、SCIM 2.0 使用者預配與組成員關係，以及會撤銷現有會話的賬號停用。僅支援 SAML 的身份提供方可透過 Keycloak 等 OIDC 橋接連線。 |
| 已批准的模板 | Lolly 定義模板的可編輯輸入；lolly.work 應用組可見性和輸入策略，用以鎖定值、限制選項或隱藏控制元件。 |
| 共享資產庫 | 例項自有的上傳、集合、自定義後設資料和受訪問控制的目錄，以及讀取現有 DAM 和儲存庫的聯結器。 |
| 稽核 | 有序的審批步驟、符合條件的審批人組、法定人數規則和職責分離；稽核可管控目錄提交以及向組織目標的交付。 |
| 資產歷史與可用性 | 例項自有資產的版本與回滾、保留與凍結、定時可用、過期和撤銷。所連線的提供方保留各自的源歷史。 |
| 報告 | 資產使用和下載計數、工具與匯出活動、儀表盤和審計追蹤。使用情況歸因遵循部署的遙測策略；預設的歸因設定需要徵得同意。 |
| 分發 | 會過期、可撤銷的連結，共享集合，訪客訪問，以及向已配置的組織目的地交付。 |

[lolly.work 運維指南](https://github.com/lolly-tools/lolly-work/tree/main/docs)介紹了這些功能及其配置。它們是現成可用的能力，而不是需要圍繞 Lolly 另行搭建系統才能獲得的功能。

## 選擇門戶工作流

成熟的門戶提供託管服務、支援和豐富的 DAM 工作流。例如，[Frontify 的企業級 DAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management) 將資產發現、訪問控制、審批工作流和分發結合在一起。請對比你所需的具體稽核與權利工作流：Lolly 提供後設資料、訪問和可用性控制，而法務審查與許可義務仍需組織自己的流程。其審批鏈是順序式的，不對任意分支的工作流建模。

Lolly 技術棧更年輕，其部署限制記錄在 [lolly.work 狀態頁](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md)中。尤其需要注意，公共 lolly.work 站點是評估用的沙盒環境。長期執行的組織部署需要持久化儲存和運維人員。自託管沒有按席位計算的軟體許可費用；但基礎設施和管理仍需花錢。

現有的 DAM 也可以繼續作為事實來源。lolly.work 的目錄聯結器會將其已批准的資產提供給 Lolly，人們在 Lolly 中按組織的規則建立新檔案。這是一種整合選擇；當組織希望自行管理這些工作流時，也可以使用 Lolly 自帶的素材庫和審批功能。
