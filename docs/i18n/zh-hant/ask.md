# Ask Lolly

輸入問題，Ask Lolly 會以涵蓋該問題的這些指南章節逐字回答，並註明出處頁面，還附有直達該章節的 **Open in docs** 連結。沒有任何內容是生成的：答案是在你的裝置上擷取、引用並註明出處的。

在引用的章節下方，是應用程式中與同一問題相符的地方：工具、Utility、已儲存的專案、目錄素材、設定或應用程式的頁面。每一列都只負責導覽。答案中沒有任何東西會更改設定、開啟檔案或代你行動，與[搜尋](/info/search.html)遵循的規則相同。

## 提出問題

在檢視底部的問題欄位中輸入，然後按 Enter。短於兩個字元的內容會被忽略。答案堆疊在欄位上方，最新的在最後，你可以繼續提問。

![開啟且空白的 Ask Lolly：檢視底部的問題欄位，以及說明答案來自文件的備註](/t/url-shot?url=%2F%23%2Fask&width=1200&height=820&waitMs=2200&format=svg&walker=1&filename=ask-view)

每個問題都獨立回答：先前的問題不會帶入脈絡，所以在關於匯出的問題之後問「那 PDF 呢？」，會被當作只與 PDF 有關的問題。每次都請問完整的問題。

你問題的第一個字決定什麼排在答案最前面：

| 你以什麼開頭 | 什麼排在最前面 |
|---|---|
| *where*、*find*、*open*、*show*、*go to*、*goto*、*take*、*jump*、*navigate*、*switch* | 應用程式中相符的地方 |
| *make*、*create*、*generate*、*build*、*design*、*convert*、*resize*、*compress*、*remove*、*strip*、*export*、*render*、*add* | 相符的工具 |
| 其他任何開頭，包括 *how do I* 與 *what is* | 文件章節，這是預設 |

兩半一律都會被擷取，所以誤判的問題只會重新排列答案，而不會遺失一半的答案。

比對會捨去常見的疑問詞（*how*、*do*、*I*、*the*、*my*），並依章節涵蓋你其餘多少個字來排序，其次是它們在哪裡相符：標題比內文更重要。比對是以子字串進行，不分大小寫與重音符號，所以錯字不會被更正。當沒有任何相符時，Ask 會直說，並指向文件索引，而不是編造答案。

**Better matching** 是選用的。在你的第一個答案之後，Ask 可以提供一個小型比對模型（附有下載大小），幫助把問題與使用不同用詞指稱同一件事的指南配對。它只在你同意時才下載，在這部裝置上執行，只改變哪些章節排在最前面：答案仍然是文件自己的文字。你也可以從 **Settings → Preferences → Available offline** 下載它，在那裡它列為 **Ask matching model**（[Available offline](/info/dashboard.html#available-offline)）。

## 回傳什麼

答案卡片以固定順序組成：

1. **章節本身**，由文件原始檔渲染：段落、清單、表格、程式碼與引言，應用程式內與 `/info` 的連結皆可使用。長的章節會以 **Show more** 截短，點擊後就地展開。圖片會被省略，連到其他網站的連結會呈現為純文字而非錨點。
2. **出處**：*頁面 › 標題*，以及指向該確切章節的 **Open in docs** 連結。
3. **文件中的更多內容**：最多四個其他相符的章節，以連結呈現。
4. **應用程式內的列**，位於與搜尋相同的群組標題之下。

完整文字來自每個文件頁面在 `/info/<slug>.md` 發布的純 Markdown 對應版本，而這些版本僅有英文。在其他語言中，以及在少數不是由 Markdown 建置的頁面上，答案會退而使用保存在搜尋索引中的簡短摘錄，而不是整個章節。無論哪種情況，出處與 **Open in docs** 連結都在，指向你自己語言的頁面。

## 它在哪裡

路由是 `#/ask`。它沒有分頁，在 Utilities 格線中也沒有圖塊；進入的方式是搜尋列和位址本身。

- <!--i:search--> **從搜尋進入。** 每個結果面板最底部、在其他群組找到的任何具體結果之下，都有一列 **Ask Lolly: *your query***。它以 `#/ask?q=…` 交出問題，而檢視在抵達時會詢問一次問題。交過來的文字會以小寫抵達並去掉標點，所以如果需要，請在問題欄位中調整。
- <!--i:link--> **從連結進入。** `#/ask?q=how%20do%20I%20export%20a%20transparent%20png` 會開啟已問了該問題的檢視。雜湊只是進入時的種子：之後你輸入的問題會就地回答，絕不改寫位址。

搜尋列在此檢視中讓位，因為問題欄位接管 Enter，而返回按鈕會帶你回到來時的地方。

螢幕上的答案會保留到本次工作階段結束：如果你導覽離開再回來，它們仍然在，重新載入則會清除。不會寫入任何儲存空間，所以沒有需要管理的歷史記錄。

## 離線

答案是由文件網站已發布的兩個靜態檔案組合而成：各語言的搜尋索引，以及該頁面的 Markdown 對應版本。兩者都以名稱擷取，所以一旦它們被快取，Ask 在沒有連線時也能繼續運作。在應用程式中閱讀指南時會逐步快取它們，而 [Available offline](/info/dashboard.html#available-offline) 下的 **Guides & docs** 一次下載就會取得整個網站，包括螢幕截圖。

沒有它們，答案的文件那一半就只是不會出現，也不會有錯誤。應用程式內的列仍然會出現，因為那些是與裝置上已有的資料比對的。

## 隱私

你的問題絕不會離開裝置。比對在本機針對依名稱擷取的檔案執行，所以你輸入的內容不屬於任何請求；沒有伺服器看到它，沒有附屬的帳號，重新載入後也沒有任何記錄。應用程式曾經擷取或傳送的完整清單，請見[隱私政策](/info/privacy.html)。
