# Lolly 如何運作

Lolly 工具保存了一種檔案的規則：版面、字型、色彩，以及其他人可以更改哪些部分。你、同事、指令碼或 AI 代理填寫欄位，每個檔案就會正確產出。本頁說明誰負責什麼，以及從工具到完成檔案的四條路線。

## 一個工具、你的規則、許多檔案

品牌規則存在工具中，而不是在它製作的每個檔案裡。把工具做對一次，每個輸出就會繼承相同的字型、色彩與間距，無論是一張卡片，還是十幾種語言的一整份試算表資料列。

![只填了一個欄位的字標工具：字型、色彩與間距在工具製作時就已確定](/info/shots/aud-rules-in-the-tool.svg)

製作第一百個檔案的人只需要輸入文字。如何檢查成果、由誰檢查，仍由你決定。Lolly 讓值得檢查的東西變小，也讓下一個檔案做得更快。

## 誰會接觸工具

跟著一張活動卡片走過一個組織，會出現三雙手。每一雙都建立在前一雙之上。

![設計師在工具中一次訂好規則；開發者從指令碼執行它，任何人都能填寫它的欄位；兩者都製作出完成的檔案](/info/diagrams/concepts/asset-relay.svg)

::: timeline
- <!--i:pentool--> **設計師訂好規則。** 他們用品牌的字型與色彩在 Design 中排好卡片版面，然後選擇哪些欄位保持開放。他們只做這一次，之後就沒有人需要手動在地化這張卡片。
- <!--i:code--> **開發者擴展工具。** 同一個工具經由命令列在夜間指令碼中執行，因此新的圖表或新的語言版本無需任何人重新開啟設計就會產出。
- <!--i:people--> **任何人都能填寫。** 在飛機上沒有網路、也沒受過設計訓練的業務代表，開啟工具，就能製作明天會議要用的卡片。
:::

## 通往檔案的四條路線

每條路線都在同一個工具上執行同一個引擎，因此指令碼製作的檔案與你在應用程式中預覽的檔案相符。

![URL 參數與命令列引數成為相同的輸入模型，經由同一個共用的執行階段與匯出橋接執行](/info/diagrams/concepts/one-render-path.svg)

- <!--i:people--> **在應用程式中，一次一個。** 開啟工具、填寫欄位，然後按下 **Export**。[製作你的第一個檔案](/info/make-something.html)會帶你做一個。
- <!--i:layers--> **在應用程式中，一次很多個。** [Batch](/info/batch.html#make-many-versions-of-one-design)（`#/batch`）接受貼上或匯入的表格，為每一列渲染一個完成的檔案。
- <!--i:cpu--> **從指令碼或 AI 代理。** [CLI](/info/cli.html) 以無頭方式執行工具，[MCP 伺服器](/info/mcp.html)讓代理探索並執行工具。工具的連結也帶有它的輸入，所以連結就是一份完整的請求。
- <!--i:server--> **經由你組織的伺服器。** [Lolly Work](/info/organisation.html) 在伺服器上依你組織的登入與工具政策渲染，保留可繼續的工作，並保管輸出以供下載或核准的交付。

工作可以走哪條路線，取決於工具的格式以及主機能做什麼：有些格式需要瀏覽器，因此命令列會把它們交給瀏覽器層級。[用 CLI 渲染](/info/cli-rendering.html)列出哪些格式在哪裡渲染。

## 什麼在哪裡執行

製作、編輯與匯出都在你的裝置上執行，不需要帳號。需要伺服器的功能，例如同步或將檔案傳送到已連接的服務，只在你使用該功能時才會連線。有了 Lolly Work，共用專案、即時團隊編輯、核准與伺服器工作則使用你組織的伺服器。[什麼在哪裡執行](/info/compare.html#what-runs-where)把這兩部分並排比較。
