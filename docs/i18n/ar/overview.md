# بنية Lolly

![أيقونة Lolly - قطعة حلوى مصاصة كبيرة خضراء وبيضاء](/info/icon.svg)

هذه الصفحة لمن يغيّرون شيفرة Lolly: كيف تتكامل المحركات والواجهات وحزم الأدوات، وأين يعيش كل منها في المستودع، والالتزامات التي تقيّد كل تغيير. وإذا أردت أن تعرف ما يفعله Lolly ومن يستخدمه، فاقرأ [كيف يعمل Lolly](/info/how-lolly-works.html) أولاً.

رفيقان يتعمقان أكثر. [`engine/README.md`](../engine/README.md) هو خريطة المحرك وحدة بوحدة، مولَّدة من الشيفرة. ويقرأ [نموذج التهديد وحدود الثقة](/info/threat-model.html) البنية نفسها بوصفها حدود ثقة، وهو الصفحة لأي سؤال عما يعتبره المحرك غير موثوق.

## الصورة الكبيرة

الأدوات بيانات في الأعلى. المحرك في الوسط لا يعرف شيئاً عن أي منصة. الواجهات في الأسفل تنفذ عقداً واحداً، وتوفر الفهارس المحتوى.

![تقدم الأدوات بياناً وقالباً وخطافات للمحرك المشترك. تنفذ واجهات الويب وTauri والطرفية جسر القدرات HostV1 وتقرأ الأدوات والأصول من الفهارس.](/info/diagrams/concepts/platform-layers.svg)

إذا كان يمكنك وصفه ببيانات خالصة وHandlebars، فمكانه **المحرك**. وإذا لمس DOM أو نظام الملفات أو الشبكة أو أي واجهة متصفح أو نظام تشغيل، فمكانه **المضيف**، جانب الواجهة من الجسر. المحرك مفتوح المصدر، ولا يدخل المحرك أي شيء يعرف علامة أو منصة بعينها.

## بنية المستودع

Lolly مستودع واحد. كل مجلد أدناه مجلد عادي فيه، عدا `brands/suse`، وهو وحدة git فرعية **خاصة** تحمل حزمة أدوات SUSE وفهرسها، ولا يجلبها نسخ عام. وأي الحزم يقرؤها بناء هو ملف تعريف محتوى (`profiles.json`)، يُحَل لكل عملية بدلاً من التبديل عالمياً. يحتوي [دليل البناء](/info/build-guide.html) أمر الاستنساخ وكيف يُودع تغيير داخل الحزمة الخاصة.

| المجلد | ما يحتويه |
|---|---|
| `engine/` | النواة المستقلة عن المنصة: المحمّل ووقت التشغيل والمدخلات والقوالب ووضع URL والوحدات ووحدات الصيغ |
| `shells/` | تطبيق الويب وتطبيقا Tauri لسطح المكتب والجوال وCLI وTUI وإضافة المتصفح |
| `packages/` | حزمة تطوير مؤلفي الأدوات (`@lolly-tools/core`) وأجزاء Node المشتركة للواجهات ومحوّل الوثائق وغيرها |
| `community/` | الأدوات المستقلة عن العلامة، إضافة إلى حزم الإيموجي المشتركة |
| `brands/` | حزم العلامات: `lolly-demo` (Lolly Demo، نظام التصميم الذي يشغّله lolly.tools) و`lolly-start` (البداية الفارغة) و`suse` الخاصة |
| `services/` | خدمات MCP والشهادات وPenpot الاختيارية، والشيفرة المشتركة للخادم بينها |
| `schemas/` | مخطط JSON لبيانات الأدوات وإدخالات الأصول ومراجع الأصول |
| `scripts/`, `tests/`, `docs/`, `api/` | سكربتات البناء والفهرس ومجموعة اختبارات المحرك وهذه الوثائق وحزم الخوادم بلا خادم المولَّدة |

::: details ملفات المحرك والواجهة التي ستقابلها أولاً
```
engine/src/
  index.ts          public surface: loader, runtime, template, inputs, url-mode
  loader.ts         fetches and validates tool files
  runtime.ts        orchestrates one mounted tool, from load to export
  template.ts       Handlebars hydration and annotateTemplate
  inputs.ts         manifest to runtime input model
  url-mode.ts       URL to input state and back
  validate.ts       JSON Schema validation of manifests
  compose.ts        nested tool renders (composes)
  embed.ts          portable lolly.tools embed URLs
  bridge/host-v1.ts type re-export of the @lolly-tools/core contract

shells/web/src/
  main.ts           boot and routing
  bridge/           the web implementations of the host APIs
  catalog/sync.ts   boot-time catalog sync and offline cache
  views/            the gallery, tool, projects, free canvas and the other views
  pro/              Batch (#/batch)

shells/cli/         bin/lolly.ts (entry), src/run.ts (headless render), src/bridge.ts
shells/tui/         src/main.tsx (the full-screen app), src/bridge.ts
```
:::

لا يوجد مجلد `tools/` أو `catalog/` في جذر المستودع. يجيب `packages/node-shell/src/content-roots.ts` عن "أين تعيش الأداة `<id>`" و"أين الفهرس" من `profiles.json` عند السؤال. ولا يُكتب زوج حقيقي `tools/` و`catalog/` إلا في مخرج بناء، مثل `dist/` أو حمولة RPM أو صورة حاوية، لأن المتصفح يجلب هذين المسارين عبر HTTP.

## أين يعمل Lolly

تستخدم كل واجهة المحرك نفسه وملفات الأدوات نفسها.

- **تطبيق الويب.** تطبيق ويب تقدمي يعمل دون اتصال بمجرد أن يخزّن عامل الخدمة (service worker) فيه الأدوات والأصول. لا يحتاج إلى حساب؛ وتعيش الحالة في IndexedDB على كل جهاز. يخدم تخطيط متجاوب واحد سطح المكتب والهاتف: وعلى الهاتف تصبح عناصر التحكم ورقة وتُفتح عناصر التصدير من حبة عائمة.
- **تطبيقات سطح المكتب والجوال.** حزم Tauri من تطبيق الويب نفسه، بمربعات حوار ملفات أصلية وحالة في نظام الملفات واستخدام كامل دون اتصال.
- **CLI.** يحمّل `lolly <tool-id> --input=value --output=file.png` المحرك نفسه في DOM دون واجهة ويكتب الملف. هو وضع URL عبر ناقل مختلف، وليس تنفيذاً منفصلاً. راجع [CLI](/info/cli.html).
- **TUI.** تطبيق طرفية بملء الشاشة يعتمد لوحة المفاتيح أولاً، يعيد استخدام جسر CLI ويحتفظ بالجلسات المحفوظة على القرص (في مجلد تطبيق سطح المكتب نفسه عند تثبيت التطبيق، وإلا تحت `~/.lolly`) ولا يبدأ متصفحاً محدود النطاق دون واجهة إلا عندما تحتاج إليه صيغة. راجع [TUI](/info/tui.html).

![عرض سطح المكتب المقسوم: عناصر التحكم المولَّدة من البيان على اليسار، واللوحة الحية على اليمين](/t/url-shot?url=%2F%23%2Ftool%2Fchart&width=1440&height=900&dpi=192&waitMs=2200&walker=1&format=svg&filename=aud-web-split)

لا تحتاج الأداة نفسها بعرض هاتف إلى تخطيط ثانٍ: تصبح عناصر التحكم ورقة في الأعلى وتحتل المعاينة الشاشة.

![مقطع صوتي مصوّر (audiogram) على شاشة بعرض 430px: ورقة عناصر التحكم فوق، والعمل المربع المنجز تحت، وحبة التصدير العائمة](/t/url-shot?url=%2F%23%2Ftool%2Faudiogram%3Faudio%3Dlolly%2Floops%2Ffireplace-loop%26title%3DField%2520notes%26subtitle%3DEpisode%252012%26style%3Dwave&width=430&height=900&dpi=192&waitMs=3200&css=%23ag-wave%7Bdisplay%3Anone!important%7D.ag-ph%7Bdisplay%3Ablock!important%7D&walker=1&format=svg&rasterDpi=110&dark=1&filename=ov2-phone-audiogram)

يأتي تطبيق الويب أيضاً مع **Batch** (`#/batch`، `shells/web/src/pro/`)، وهو شبكة بأسلوب جدول بيانات تعرض صفوفاً كثيرة دفعة واحدة عبر أداة واحدة أو أدوات كثيرة؛ ويغطي [Batch وMulti-edit](/info/batch.html#make-many-versions-of-one-design) Batch. ويرسم **Settings → Capabilities** خريطة كل ما تعلن المنصة أنها تستطيع فعله.

## الالتزامات المعمارية

هذه القرارات محسومة. تغيير أي منها مهمة كبرى، لأنها تشكّل كل قرار آخر في قاعدة الشيفرة.

### 1. أدوات تعريفية (declarative)، مع مخرج طوارئ إجرائي (imperative)

الأداة بيان (`tool.json`) وقالب (`template.html`) و`hooks.js` اختياري. **يعلن البيان المدخلات**، لا القالب: لا تُستنتج المدخلات من رموز Handlebars. معظم الأدوات بيان وقالب فقط، وهذا ما يتيح لغير المطورين تأليفها.

![حزمة عناصر تحكم Street Map: قائمة مدن منسدلة وقائمة اختيار سمة ومنزلقات الوزن ومشغّلات الألوان، كل منها مرسوم من سطر في البيان](/t/url-shot?url=%2F%23%2Ftool%2Fstreet-map%3Fcity%3Damsterdam&width=1440&height=900&dpi=192&waitMs=2400&walker=1&format=svg&css=%23tool-canvas%7Bdisplay%3Anone%7D&cropSelector=%23tool-inputs&dark=1&filename=ov2-street-map-controls)

الأدوات التي تحسب قيماً، مثل ترميز QR أو تشكيل المخططات، تضيف خطافات (hooks): دوال دورة حياة مسماة يستدعيها وقت التشغيل مع حقن جسر القدرات. الخطافات عقد قابلية نقل لا صندوق أمان، وتعمل ضمن ميزانية زمنية. والأدوات التي ثبت خلو خطافاتها من متغيرات الصفحة العامة تحمل `isolate: true` وتعمل في Worker. يحتوي [خطافات الأدوات](/info/tool-hooks.html) دورة الحياة والميزانيات، ويقول [نموذج التهديد](/info/threat-model.html) ما الذي يحتويه المنفّذ داخل الصفحة وما لا يحتويه.

### 2. الأدوات والأصول بيانات، لا شيفرة مُجمَّعة

يجلب تطبيقا الويب وTauri فهرسي الأدوات والأصول عند الإقلاع ويخزّنانهما مؤقتاً ويعملان بما هو موجود، فلا تحتاج أداة أو أصل جديد إلى إصدار تطبيق. تُفحص بايتات الأصول بـ SHA-256، ويقود `id` الأصل و`version` إبطال ذاكرة التخزين المؤقت.

### 3. جسر القدرات هو الواجهة الوحيدة التي تراها الأدوات

لا تلمس الأدوات DOM خارج قالبها أبداً، ولا تستدعي `fetch` مباشرة، ولا تقرأ نظام الملفات. تستدعي دوال `host.*` ذات الإصدار. التعريف المعتمد للعقد هو `packages/core/src/host-v1.ts`، أي حزمة مؤلفي الأدوات `@lolly-tools/core`، فيستطيع طرف ثالث البناء عليه دون الاعتماد على المحرك؛ ويعيد `engine/src/bridge/host-v1.ts` تصدير أنواعه.

| الواجهة المطلوبة | ما تفعله |
|---|---|
| `host.profile` | تفاصيل المستخدم؛ تعبّئ المدخلات مسبقاً عبر `bindToProfile` |
| `host.assets` | استعلامات الفهرس وحل الأصول ومنتقي المضيف |
| `host.state` | حفظ وتحميل خانات المدخلات: IndexedDB على الويب ونظام الملفات في Tauri والذاكرة في CLI |
| `host.clipboard` | كتابة نص أو صورة إلى الحافظة، مع بدائل بحسب المنصة |
| `host.export` | تحويل هدف العرض إلى نقاط أو تسلسله، ومسار تحويل الملفات على الجهاز |
| `host.log` | تسجيل مستوياتي إلى المضيف |

كل واجهة أخرى اختيارية وإضافية: `tokens` و`text` و`color` و`geom` و`pdf` و`compose` و`media` و`recorder` وكثير غيرها. يسرد بيان الأداة تحت `requires` الواجهات الاختيارية التي تستدعيها خطافاتها دون فحص مسبق، والمضيف الذي يفتقد واحدة يرفض تركيب الأداة؛ وتكتشف الخطافات البقية. وتحتاج بعضها، مثل `recorder`، قدرة جهاز تعلنها الأداة أيضاً. يسردها `packages/core/src/host-v1/apis.ts` كلها ويوثق [Host API](/info/host-api.html) كل واحدة. إضافة دالة إصدار فرعي؛ وإزالة واحدة أو تغييرها إصدار رئيسي، ويستمر v1 في العمل عند صدور v2.

### 4. معرّفات الأصول للأبد

`lolly/logo/primary` عقد. وما إن يُنشر، لا يتغير المعرّف ولا يُعاد استخدامه أبداً. يرفع تغيير البايتات `version` في إدخال الأصل، ويضبط الاستبدال `deprecated: true` واختيارياً `replacedBy`، فتُحَل المراجع القائمة دائماً. وهذا ما يُبقي الجلسات المحفوظة وروابط المشاركة تعمل لسنوات.

### 5. وضع URL درجة أولى

كل مدخل قابل للتعبير كمعامل URL، فالرابط ملف منجز:

```
https://lolly.tools/t/qr-code?url=https://example.com&ecl=H
```

غيّر معاملاً فيصبح لديك ملف مختلف. هذه اللوحة كلها لون بذرة واحد وانسجام وعدد خطوات:

![تسع خطوات عبر أربعة تدرجات لونية، كلها منبثقة من لون البذرة الواحد المحمول في الرابط](/t/url-shot?url=%2F%23%2Ftool%2Fcolor-palette%3Fseed%3De0521a%26harmony%3Dtetrad-4%26steps%3D9%26full&width=1440&height=900&dpi=192&waitMs=2000&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-url-palette)

يبني CLI حالة URL نفسها من وسائطه ويشغّل خط المعالجة نفسه، فلا يستطيع CLI الانحراف عن التطبيق. يحلل `engine/src/url-mode.ts` ويسلسل؛ وتُحجز أسماء (`format` و`width` و`dpi` و`c2pa` و`z` وغيرها) فلا تُمرَّر إلى أداة أبداً، ويسردها [معاملات URL المحجوزة](/info/url-parameters.html) كلها. وتسافر مدخلات الأصول بـ `id` وتُحَل عبر `host.assets.get()` قبل أن يمتلئ القالب.

### 6. التخزين يمر عبر الجسر

يستخدم تطبيق الويب IndexedDB، وTauri نظام الملفات، وCLI الذاكرة. ترى الأدوات `host.state.save(slot, data)` و`host.state.load(slot)` فقط، ولا ترى `localStorage` أبداً. يستطيع الناس الاحتفاظ بعدة جلسات مسماة لكل أداة دون حساب. ولأن الجسر هو الفاصل الوحيد، فإن هذه الحالة قابلة للنقل أيضاً: يقرؤها `shells/web/src/data-transfer.ts` إلى ملف `lolly-backup` واحد يُستورد على أي تثبيت آخر ([نقل البيانات](/info/data-transfer.html))، وترسل [المزامنة](/info/sync.html) الحزمة نفسها إلى تخزين يختاره الشخص.

### 7. علامات النضج تقول ما هي الأداة

تعلن كل أداة `status: official | community | experimental`. يرتّب المعرض بحسب الحالة، وتضع الأدوات التجريبية علامة مائية على تصديراتها افتراضياً: يشغّل وقت التشغيل العلامة المائية ما لم يمرر المستدعي `watermark: false`، وتُستثنى الأدوات التي تعمل على الجهاز. وأي عملية يضعها فريق حول الفهرس تقوم فوق هذا.

### 8. المدخلات مكتوبة الأنواع في البيان

يعلن المدخل `type`: `text` أو `longtext` أو `number` أو `boolean` أو `color` أو `select` أو `asset` أو `date` أو `time` أو `datetime-local` أو `url` أو `blocks` أو `vector` أو `table` أو `file`. يعرض المضيف عنصر تحكم لكل نوع، فلا تكتب الأدوات شيفرة عناصر تحكم، ويمكن لأي مدخل أن يحمل `bindToProfile`. ثلاثة منها الأثقل وزناً:

- **`asset`**، مع `filter` و`allowUpload`، هو الجسر إلى نظام الأصول. يقصر `allowUpload: false` الخانة على أصول المكتبة، وتتشارك الملفات التي يرفعها المستخدم شكل `AssetRef` مع المكتبة.
- **`blocks`** مجموعة حقول متكررة تُحرَّر في لوحة جانبية، تستخدمها Meeting Planner وWayfinding وDiagrams وغيرها. النقر على كتلة معروضة يركّز صفها.
- يحتفظ **`file`** بملف المستخدم نفسه في الذاكرة للأدوات المساعدة على الجهاز مثل Strip Hidden Data وCompress، ويجمع **`vector`** مجموعة ثابتة من الأرقام في عنصر تحكم واحد.

### 9. القوالب بلا منطق

القوالب هي Handlebars، اختيرت ليتمكن غير المطورين من كتابتها: `{{x}}` يهرّب، و`{{{x}}}` اشتراك صريح. يعيش المنطق في `hooks.js`، حيث هو صريح وقابل للمراجعة. تستخدم قوالب كثيرة `{{{` لشيفرة ترميز حسبها خطاف، لذا يجب على كل خطاف أن يهرّب ما يسلّمه. المساعدات هي `default` و`upper` و`lower` و`eq` و`markdown` و`asset` و`framing` و`media`، إضافة إلى `icsStamp` و`rfcText` و`csvCell` و`arrow` لقوالب `.ics` و`.vcf` و`.csv` الشقيقة. يغطيها [القوالب والعرض](/info/tool-rendering.html).

### 10. الأدوات تركّب أدوات

يمكن لأداة أن تضمّن عرض أداة أخرى دون استيراد من أداة إلى أخرى؛ يحل المحرك التركيب. ويمكن لبيان أن يعلن `composes: [{ id, tool, inputs }]` ويضع الابن بـ `{{asset <id>}}`، ويعرض عنوان تضمين قابل للنقل (`https://lolly.tools/tool/<id>.svg?…`) الابن محلياً، وهكذا يضع Design رمز QR حياً أو مخططاً. يبقى الابن SVG متجهاً في أب SVG أو PDF. الأبناء وسطاء، لا يُوضع عليهم علامة مائية ولا ختم، والواجهة التي لا تستطيع عرض واحد تترك الخانة فارغة بينما يُعرض الأب. يحتوي [التركيب وتراكبات العلامة](/info/tool-composition.html) التفاصيل.

## ما اخترنا ألا نفعله

- **لا JavaScript عشوائية في القوالب.** يعيش المنطق في `hooks.js`.
- **لا خادم أصول إلزامي.** يضيف الناس ملفاتهم الخاصة إلى Assets في التطبيق ويسلّمون العمل جلسةً: رابط مشاركة للمدخلات والإعدادات، وملف `.lolly` عندما تسافر الملفات المرفوعة أيضاً. يمكن لجلسة مشتركة أن تصبح قالباً في منتقي أداة. والمؤسسة التي تريد فهرساً محكوماً تستطيع استخدام فهرس Lolly Work وموافقاته وسياساته، أو إدارة حزمة العلامة في git ومراجعة التغييرات هناك.
- **لا ضبط وصول مفروض.** التطبيق المفتوح عام افتراضياً، وتحمل وسوم النضج والعلامات المائية مخاطر العلامة. ويأتي تسجيل دخول المؤسسة والأدوار والسياسة من Lolly Work عندما يريدها فريق.
- **لا قاعدة بيانات مركزية.** تعيش حالة المستخدم على كل جهاز، وتنسخها المزامنة الاختيارية إلى تخزين يختاره الشخص، لا إلى قاعدة بيانات Lolly أبداً.
- **لا مسار شيفرة مشترك بين الأدوات والمحرك.** المحرك والأدوات المجتمعية مفتوحة المصدر، وتحمل حزمة علامة مثل `brands/suse/` الخاصة أدواتها وفهرسها بشروطها الخاصة. لا تستورد أداة من `engine/`، فيبقى الفصل نظيفاً.

## دورة حياة عرض واحد

يفتح شخص `https://lolly.tools/t/qr-code?url=https://example.com&ecl=H`:

1. **الإقلاع.** يفتح تطبيق الويب IndexedDB ويبني جسر القدرات ويزامن فهرسي الأدوات والأصول، أو يحمّلهما من ذاكرة التخزين المؤقت عند عدم الاتصال.
2. **المسار.** يختار المسار عرض الأداة لـ `qr-code`، مع الاستعلام قيماً أولية له.
3. **التحميل.** يجلب `loadTool` الملف `tool.json` ويتحقق منه مقابل المخطط ويجلب القالب والأنماط والخطافات.
4. **تحليل الرابط.** يحوّل `parseUrlState` المعاملات إلى قيم مدخلات. ويصبح مرجع أصل مثل `?logo=lolly/logo/primary` `{ id }` غير محلول.
5. **بدء وقت التشغيل.** يبني `createRuntime(tool, host, initialValues)` نموذج المدخلات من بيانات الملف الشخصي والإعدادات الافتراضية والرابط، ويحل مراجع الأصول ويحمّل الخطافات ويستدعي `onInit`.
6. **العرض.** تشترك الواجهة في وقت التشغيل وترسم عناصر التحكم من النموذج وتكتب القالب المملوء في `#tool-canvas`.
7. **التفاعل.** تستدعي الكتابة `runtime.setInput`، الذي يطبق القيود ويستدعي `onInput` ويملأ القالب مجدداً ويعيد الرسم.
8. **التصدير.** يستدعي **Download** الدالة `runtime.export(node, format)`، وينتج `host.export` في الواجهة الملف: نقطي أو متجه من ماشي DOM أو PDF أو مستند أو إحدى الصيغ الأخرى في `schemas/tool.schema.json`. تُحوَّل الوحدات الفيزيائية لكل صيغة، وتُضمَّن البيانات الوصفية وContent Credentials حيث تستطيع الصيغة حملها. وتحصل الأدوات التجريبية على علامتها المائية من المضيف لا من الأداة. يغطي [القوالب والعرض](/info/tool-rendering.html) و[تصدير ملف](/info/exporting.html) خطوة التصدير.

![لوحة التصدير التي يفتحها ?options: زوج اسم الملف والصيغة وحجم الإخراج وعناصر التحكم التي تكتب الملف](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26options&width=1440&height=900&dpi=192&waitMs=2200&cropSelector=.export-popup&walker=1&format=svg&dark=1&filename=aud-export-popup)

تعمل دورة الحياة نفسها في Tauri، وفي CLI بـ DOM دون واجهة، حيث يذهب الإخراج إلى ملف أو stdout.
