# Lolly comparé, outil par outil

Lolly couvre le travail créatif, d'une simple conversion sur l'appareil à la production d'assets d'une organisation encadrée. Ces pages comparent les workflows que prend en charge chaque produit, son mode de déploiement et les limites qui comptent pour choisir une solution.

_Dernière vérification : 28 septembre 2026._

## Un projet, deux parties déployées séparément

**Lolly** est le moteur, les applications et les outils pour créer, modifier, convertir et exporter. Il s'exécute sur ton appareil, fonctionne hors ligne une fois les ressources nécessaires disponibles, et ne demande aucun compte pour une utilisation autonome.

**[lolly.work](https://lolly.work)** est le service d'organisation du projet, maintenu dans le [dépôt lolly-work](https://github.com/lolly-tools/lolly-work). Il fournit le SSO, le provisionnement SCIM, les rôles et les politiques, les catalogues et projets partagés, les validations, la collaboration de travail, les rapports d'usage, les journaux d'audit et le rendu côté serveur. Les deux parties sont open source sous MPL-2.0. Une organisation héberge lolly.work à côté de Lolly et décide des services à activer.

Les comparaisons portent sur **Lolly + lolly.work**. Les fonctionnalités qui nécessitent le service d'organisation sont signalées explicitement. L'utilisation autonome garde les fichiers sur l'appareil ; choisir les projets partagés, la collaboration de travail, le rendu serveur ou la livraison envoie les données concernées aux services configurés. Le site public lolly.work est un bac à sable ; consulte le [guide de déploiement](https://github.com/lolly-tools/lolly-work/blob/main/docs/install.md) et l'[état actuel](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md) pour un déploiement en organisation.
