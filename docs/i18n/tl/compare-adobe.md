# Lolly at Adobe

_Huling sinuri: 28 Setyembre 2026._

Hinahawakan ng Lolly ang pag-edit at conversion ng imahe, layout, paulit-ulit na brand production, print output at Content Credentials. Dinadagdagan ng [lolly.work](https://lolly.work) ang creative workflow na iyon ng identity ng organisasyon, shared na asset, mga approval at automated na server production.

## Kung saan sila nagtatagpo

Parehong sumusuporta sa gawain tulad ng pag-resize ng mga imahe, pag-compose ng mga layout at pag-export sa mga propesyonal na format. Sinusuportahan ng Lolly ang PDF/X, CMYK at raster output na mataas ang bit depth, kasama ang [mga capability na partikular sa format](/info/formats.html). Kino-convert at nililinis ng mga on-device utility nito ang mga file nang hindi ina-upload ang mga ito.

Sinasaklaw ng mga espesyalistang application ng Adobe ang malawak na creative workflow. Halimbawa, ang [Photoshop](https://www.adobe.com/products/photoshop.html) ay nagbibigay ng detalyadong tool para sa pag-edit ng larawan, selection, masking at compositing. Ihambing ang mga editing operation na kailangan ng gawain mo sa mga tool ng Lolly; maaaring magkaiba ang kailangan ng paulit-ulit na brand asset at ng masalimuot na retouch.

## Creation at mga organisation service

Tumatakbo ang standalone na Lolly nang walang Adobe account o Lolly account, gamit ang parehong engine sa browser, desktop app at CLI. Ginagawang paulit-ulit ng mga template at design token ang mga output, at ginagawa ng [Share with rules](/info/create-a-tool.html) na tool ang isang disenyo na maaaring punan ng ibang tao.

Ang lolly.work ay hiwalay na serbisyo sa loob ng proyektong Lolly, open source sa ilalim ng MPL-2.0 tulad ng mga creative app. Nagbibigay ito ng SSO, SCIM, shared na catalogue at proyekto, mga approval, access policy, mga audit record at server rendering. Maaaring patakbuhin ng isang organisasyon ang dalawang bahagi nang mag-isa at ikonekta ang mga umiiral na asset library. Nananatili sa device ang lokal na paggawa; ang shared na gawain at mga server job ay gumagamit ng mga naka-configure na serbisyo.

## Content Credentials at identity

Maaaring pirmahan ng Lolly sa mismong device ang mga sinusuportahang export, na may Content Credentials na pinapagana ng user. Pinatutunayan ng key na nabuo sa device ang integridad ng lagda ng file; kailangan pa ring pagkatiwalaan ng verifier ang lumagda bago magpakita ng na-verify na identity. Maaaring gamitin ng organisasyon ang sarili nitong certificate authority at ipamahagi ang root nito sa mga verifier nito. Sinusuportahan din ng lolly.work ang server signing gamit ang naka-configure na certificate at key ng organisasyon.

Dahil dito, parehong magagamit ang personal na pagpirma at pagpirma ng organisasyon sa loob ng solusyong Lolly. Tingnan ang [Content Credentials Identity](/info/content-credentials-identity.html), ang [gabay sa pagpirma ng lolly.work](https://github.com/lolly-tools/lolly-work/blob/main/docs/c2pa.md) at ang [pangkalahatang-ideya ng pinagsamang solusyon](/info/compare.html). Hindi nagdaragdag ng Lolly watermark o provenance metadata ang mga on-device transform utility.
