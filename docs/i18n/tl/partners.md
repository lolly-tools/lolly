# Pakikipagtulungan sa mga partner

Maraming piraso ang may dalawang brand, tulad ng logo ng sponsor sa event poster, alok ng reseller sa ilalim ng pangalan ng gumawa, pinagsamang anunsyo o case study na isinulat kasama ang supplier. Para sa magkabilang panig ang pahinang ito.

Sa pahinang ito, ang **pangunahing brand** ay ang brand na ginagamit ang design system sa paggawa ng piraso, at ang **partner** ang isa pang brand sa piraso. Puwedeng gumawa ng piraso ang alinmang panig. Inihahambing ng [Mga arkitektura ng brand](/info/brand-architectures.html#co-branding) ang co-branding sa ibang mga kaayusan ng brand.

<!--i:eti-info-->
## Paano pinangangasiwaan ng Lolly ang dalawang brand ngayon

- **Isang design system ang gumuguhit ng bawat piraso.** Umiiral ang mga kulay, type at patakaran ng pangunahing brand. Ipinapasok ang mark ng partner bilang artwork: isang larawan mula sa Assets, o custom na mark na iniingatan sa design system.
- **Naipapasa ang brand bilang file.** May dalang mga token, font at logo ang design-system file (`.lolly`). May dalang isang tapos na layout kasama ang mga input na pinapayagan mo ang reusable na tool na ginawa gamit ang **Share with rules**. Naipapasa ang mga brand skill bilang sarili nilang mga file.
- **Puwede ring magkaroon ng address ang brand.** Naglalathala ang [brand page](/info/brand-page.html) ng mga logo, kulay, type at patakaran para basahin ng partner, kasama ang mga token at skill para sa mga tool nila.
- **Mga patakaran lang ng pangunahing brand ang chine-check ng Lolly.** Hindi alam ng Lolly ang mga patakaran ng partner, tulad ng clear space o minimum na laki, kaya i-check ang mga iyon laban sa mga gabay ng partner. Sa Lolly Work partner programme, hawak ng partner kit ng kumpanya ang mga patakaran nito, at chine-check ng Lolly Design ang mga mark ng kumpanya laban sa kit.
- **Tumatakbo sa Lolly Work ang buong programa ng mga partner.** Kapag gumagawa ang mga reseller, distributor o ibang partner ng mga piraso sa brand mo sa iyong Lolly Work, ibinibigay lang ng partner programme sa bawat partner na kumpanya ang mga tool, file at template na pinili mo. Iniingatan ng programa ang mga logo at detalye ng kumpanya, ipinapasok ang mga ito sa mga template mo at itinatala ang kumpanya sa bawat file. Ang [Magpatakbo ng partner programme](/info/manage/run-a-partner-programme.html) ang gabay para sa team na nagpapatakbo nito.

## Ibahagi ang brand mo sa partner

### Piliin kung ano ang ipapadala

### Gumawa ng template na may parehong brand

Pinapanatili ng reusable na tool ang mga bahagi ng bawat partner sa layout mo. Ang pinapayagan mo lang ang mababago ng partner.

1. Sa Lolly Design, gawin ang piraso sa design system mo. Gumuhit ng image box para sa logo ng partner, at mag-iwan ng espasyo sa paligid ng kahon ayon sa kailangan ng layout.
2. Piliin ang **Share with rules** sa File menu. Piliin ang image box at piliin ang **Make editable**. Sa **Rules** nito, payagan ang mga upload na pamalit, itakda ang minimum na laki sa pixel at ang mga format ng upload na tinatanggap mo (SVG kung puwede). Itakda ang **Image fit** ng kahon sa **Contain (fit inside)** para manatili sa loob ng kahon ang malapad o matangkad na logo.
3. Gawing mae-edit din ang pangalan o alok ng partner, na may limitasyon sa bilang ng character.
4. Pindutin ang **Preview** at subukan ang napakalapad na logo, napakatangkad na logo at mahabang pangalan.
5. Piliin ang **Share .lolly**, at magsulat ng tagubilin para sa partner: aling bersyon ng logo nila ang ia-upload, tulad ng full-colour na horizontal na logo para sa light na background.

Idina-drop ng partner ang file sa Lolly, sinusuri ang trust prompt, pinupunan ang mga input at dina-download ang mga format na pinayagan mo ([Gamitin ang tapos na tool](/info/create-a-tool.html#use-the-finished-tool)). ### Ibigay sa agent ang mga brand skill mo

Ginagabayan ng mga skill ang mga tao at agent. Chine-check ng Lolly ang mga patakaran ng organisasyon.

- Sa Lolly Design System Setup, buksan ang **Skills** room (`#/start?area=skills`), pumili ng skill at pindutin ang **Download skill (.zip)**. Nakaturo sa Lolly mo ang mga catalog link ng folder, at itinatala ng `lolly.json` nito kung saan galing ang kopya. Inilalagay ng **Copy as one file** ang parehong text sa clipboard para sa chat window.
- Mula sa terminal, isinusulat ng `lolly system skill <name> --into=<dir>` ang parehong folder ([Sa folder para sa lokal na agent tool](/info/brand-skills.html#in-a-folder-for-a-local-agent-tool)).
- Inililista ng sarili mong machine ang mga skill na may markang `internal` pati ang mga `public`, kaya piliin kung alin ang ipapadala ([Mga public at internal na skill](/info/brand-skills.html#public-and-internal-skills)).
- Para sa design system na walang sariling skill, gumagawa ang Lolly ng baseline mula sa mga token at patakaran ng organisasyon nito, at inililista ng room ang baseline.
- Hindi kusang nag-a-update ang kopya. Kapag nag-publish ka ng bagong rebisyon ng skill, ipadala ulit ang folder.

## Gumawa gamit ang brand na ibinigay sa iyo

Para sa partner na tumatanggap ng design-system file. Kapag may partner programme ang nangungunang brand sa sarili nitong Lolly Work, doon ka mag-sign in: bumubukas ang home mo sa card ng kompanya mo at sa mga template na inilathala para sa iyo ([Ang nakikita ng mga partner](/info/manage/run-a-partner-programme.html#what-partners-see)).

1. **Buksan ang file.** I-drop ang file sa Lolly o pindutin ang **Open**; tinatanggap din ng **Add from…** sa Lolly Design System Setup ang file. Inililista ng preview ang laman ng file bago may maisulat. Nagdaragdag ang design-system file ng hiwalay na design system sa pangalan ng nangungunang brand at ginagawa itong aktibo. Nananatili sa device ang sarili mong design system. Ang file na kumokonekta sa app sa sariling Lolly ng nangungunang brand ay naglilista muna ng mga epekto sa buong device mo; sakop ng [Gamitin ang Lolly sa organisasyon mo](/info/organisation.html) ang ganoong uri ng file.
2. **Kilalanin ang brand.** Sa Lolly Design System Setup, ipinapakita ng **Board** ang laman ng design system, nasa **Logos** ang mga marka nito at inililista ng **Rules** ang mga patakaran ng organisasyon na chine-check ng Lolly. Ipinapakita ng **Skills** ang baseline na ginagawa ng Lolly mula sa mga token at patakaran; dumarating bilang hiwalay na mga file ang sariling mga skill ng nangungunang brand, kung ipapadala nila ang mga ito.
3. **Magpalipat-lipat ng brand.** Pinapalitan ng **Settings → Preferences → Design systems** ang design system para sa buong device, at may strip ng mga cover sa **Settings → Design system** na mapagpipilian. Tapusin ang gawa para sa isang brand bago ka lumipat.
4. **Ilagay ang sarili mong marka.** I-upload ang logo mo sa **Assets**, kung saan iniaalok ito sa bawat design system, o idagdag ito bilang **custom mark** sa design system ng nangungunang brand (**Logos** room, **Custom marks**), kung saan sumasama ito sa file ng design system na iyon. Read-only ang design system na may lock, kaya gamitin ang Assets doon. Nasa [Ilagay ang marka ng partner](#place-a-partner-s-mark) ang mga dapat i-check.
5. **Mag-check bago mag-export.** Sa Lolly Design, inililista ng **Before you export** card ng export panel ang mga natuklasan kaugnay ng mga patakaran ng nangungunang brand, sa bawat layer ([Bago ka mag-export](/info/design.html#before-you-export)). Ipinapakita ng **Design system** card ang design system na itinatala ng file.
6. **Ibalik ang gawa.** Ipadala ang na-export na file, o ang mae-edit na design bilang `.lolly` ([Pagbabahagi ng gawa mo](/info/using.html#sharing-your-work)). Bumubukas ang design sa alinmang design system na aktibo, kaya binubuksan ng nangungunang brand ang gawa mo habang aktibo ang sarili nilang design system.

::: note Hindi nag-a-update ang design-system file
Ang design-system file ay kopya ng brand sa araw ng pag-export. Walang nag-a-update sa kopya.
:::

Kapag nagpadala ang nangungunang brand ng mas bagong file, buksan ito sa parehong paraan. Pagkatapos, tingnan kung aling design system ang aktibo sa **Settings → Preferences → Design systems**, at alisin doon ang mas lumang kopya kapag hindi mo na ito kailangan.

## Ilagay ang marka ng partner

| Paraan | Mga hakbang | Pinakabagay sa |
| --- | --- | --- |
| Larawan sa Assets | I-drop ang file sa upload area ng **Assets**, saka piliin ito sa image field ng tool, o sa Lolly Design gamit ang **Image** mula sa add menu ng rail | Mga minsanang gawa. Sa device nakalaan ang upload, kaya iniaalok ito alinman ang aktibong design system |
| Custom na marka | **Logos** room, **Custom marks**: mag-type ng pangalan para sa marka, saka **Choose file…** | Partner na madalas mong katrabaho. Sa design system nakalaan ang marka at sumasama ito sa file nito |
| Tapos na lockup | Gawin ang lockup mula sa parehong marka sa drawing tool mo, saka idagdag ito bilang custom na marka | Lockup na may "kasama ang" o "sa pakikipagtulungan sa" na paulit-ulit ginagamit |

::: check Bago ka mag-export, i-check ang marka
- **Ang tamang file.** Gamitin ang file na ibinigay ng partner, SVG kung mayroon. Lumalabo kapag na-print ang logo na kinopya mula sa web page o slide.
- **Ang tamang bersyon para sa background.** Gumamit ng reverse o iisang kulay na bersyon sa madilim o maraming detalye na background, kapag may ganoon sa mga gabay ng partner.
- **Mga proporsyon.** Itakda ang **Image fit** ng image box sa **Contain (fit inside)**, at hinding-hindi mababanat ang marka.
- **Clear space at laki.** Mag-iwan ng espasyo sa paligid ng marka ayon sa mga gabay ng partner, at panatilihing mas malaki ang marka sa minimum na laki nila. Wala sa dalawa ang sinusukat ng Lolly.
- **Aling brand ang nangunguna.** Itakda ang laki ng dalawang marka ayon sa mga gabay ng parehong brand kung alin ang nangunguna.
- **Mga karapatan.** Ipinapakita ng Lolly ang lisensyang nakatala para sa catalog asset. Walang tala ng lisensya ang file na ikaw mismo ang nag-upload, at *Licence not recorded* ang nakasulat sa mga detalye nito, kaya itago kasama ng sarili mong mga tala ang pahintulot ng partner na gamitin ang marka nila ([Mga karapatan at credit sa malikhaing gawa](/info/creative-rights.html)).
:::

### Ibigay sa agent ang mga skill ng bawat brand

Kapag agent ang gumagawa, ibigay sa agent ang mga skill ng parehong brand nang walang pagbabago, at sabihin kung aling brand ang nangunguna. Pinapanatili ng mga skill ng bawat brand ang sarili nilang mga pangalan at id. Hindi pinagsasama ng Lolly ang mga skill ng dalawang brand o nagpapasya kung aling brand ang mananaig.

## Mga logo wall para sa sponsor at event

Inaayos ng [Lolly Logo Wall](/#/tool/logo-wall) tool ang mga logo sa pantay na grid para sa sponsor board, partner slide o press backdrop. Sa event, karaniwang ang host ang nangungunang brand: ginagawa ang wall sa design system ng host, at nakalagay bilang artwork sa wall ang logo ng bawat sponsor.

1. Buksan ang Lolly Logo Wall at i-drop ang mga logo sa **Logos**. May sariling set ng mga kontrol ang bawat logo.
2. Bigyan ang bawat logo ng **Tier**, tulad ng "Gold partners". May sariling mga row ang bawat tier, ayon sa pagkakasunod ng unang paglitaw ng mga tier, sa ilalim ng sariling heading; ino-off ng **Tier headings** ang mga heading. Kapag nakatakda ang **Tier sizes** sa **Step down**, may isang dagdag na logo sa bawat row ng bawat mas mababang tier, kaya mas malaki ang tingin sa mas matataas na tier. Ina-adjust ng **Presence** at **Size %** ang isang logo sa loob ng tier nito.
3. Panatilihing naka-on ang **Balance sizes**. Itinatakda ng Lolly Logo Wall ang laki ng bawat logo ayon sa optical weight nito, kaya lumiliit ang mabigat na logo at lumalaki ang magaan, at pantay ang tingin sa bawat tier.
4. Kino-crop ng **Trim margins** ang bawat logo hanggang sa artwork nito. I-off ang opsyon kapag kasama na sa file ng logo ang clear space na hinihingi ng may-ari nito.
5. Inaalis ng **Remove white backgrounds** ang puting kahon na madalas kasama ng logo na kinopya mula sa slide.
6. Itakda ang **Columns**, spacing at padding sa ilalim ng **Layout**. Nagsisimula ang **Background** sa surface colour ng design system mo.
7. Para sa wall na iisang kulay, i-on ang **Render all as vector** at piliin ang **Ink colour**, o itakda ang **Filter** ng isang logo sa **Greyscale**. Gumamit lang ng bersyong iisang kulay kung pinapayagan ito ng mga gabay ng bawat sponsor.
8. Para sa press backdrop, piliin ang **Grid**, **Brick** o **Checker** sa ilalim ng **Step & repeat**, at itakda ang bilang ng **Rows**.

I-export ang wall bilang PNG, SVG, PDF o CMYK PDF para sa print. Magtakda ng ibang laki at hugis sa export panel, tulad ng patayong 1080 x 1920 na story o A4 na page, at muling inaayos ng canvas ang wall para punuin ang hugis na iyon, na may mas kaunti o mas maraming logo sa bawat row. Tugma ang export sa canvas. Para ilagay ang wall sa poster, piliin ang **Image** mula sa add menu ng rail sa Lolly Design, gumuhit ng frame at piliin ang Lolly Logo Wall sa **Tools** tab ng picker ([Mga tool sa loob ng design](/info/design.html#tools-inside-a-design)). Para sa mga caption sa pagitan ng mga logo, ang **Dynamic layout** na nakatakda sa **grid** sa Lolly Design ay may isang image box bawat logo ([Layout sa Lolly Design](/info/design-layout.html#dynamic-layouts)).

Sa terminal, binubuo ng `lolly run logo-wall logos/*.png --output=wall.svg` ang wall mula sa folder ng mga larawan, at binubuo ng CSV na may mga column na `logo` at `tier` ang wall na may mga tier. Hindi kailangan ng SVG at PNG ng browser ([Sponsor wall na may mga tier](/info/cli-rendering.html#a-sponsor-wall-with-tiers)).

Kapag nag-publish ang sponsor ng [brand page](/info/brand-page.html), kinukuha ng `lolly run logo-wall --logos-from=<address or folder>` ang kasalukuyan nilang logo para sa surface at inilalabas ang sinasabi ng page nila tungkol sa paggamit. Ulitin ang flag para sa bawat sponsor.

Hindi alam ng Lolly Logo Wall ang mga patakaran ng sinumang sponsor. Itinatakda ng Tiers at Presence ang mga laki kaugnay ng isa't isa, hindi ang minimum na laki ng sponsor, at walang nagche-check ng clear space sa pagitan ng magkakatabi. I-check ang tapos na wall ayon sa mga gabay ng bawat sponsor sa laki na ipi-print o ipapakita ito.

## Ang hindi pa nagagawa ng Lolly

- Iginuguhit ang isang gawa sa iisang design system. Ang mga kulay, type at patakaran ng partner ay hindi design system sa loob ng gawa, at larawan ang marka ng partner.
- Sa labas ng Lolly Work partner programme, hindi iniimbak o chine-check sa app ang mga patakaran ng partner: clear space, minimum na laki at pinapayagang treatment tulad ng iisang kulay o reverse.
- Ang partner kit, isang maliit na pack ng mga logo, kulay at patakaran ng partner para gamitin sa gawa ng ibang brand, ay dumarating lang sa app sa pamamagitan ng Lolly Work partner programme. Sa ibang sitwasyon, tumatakbo mula sa terminal ang check ng kit: sinusukat ng `lolly check --kit=<file>` ang mga marka ng partner sa dokumento ng Lolly Design ([I-check ang muling ginawa](/info/cli-decks.html#check-the-recreation)).
- Hindi gumagawa ang Lolly ng lockup mula sa dalawang marka para sa ayos na "kasama ang", "sa pakikipagtulungan sa" o "ng". Magdagdag ng tapos na lockup bilang custom na marka.
- Iisang design system ang aktibo para sa buong device, kaya hindi puwedeng magkatabing bukas ang dalawang brand.
- Walang kasamang brand skill ang design-system file na na-export mula sa app, kaya ipadala ang mga iyon bilang hiwalay na mga file.
- Larawan sa row nito ang logo na kinuha mula sa brand page, at hindi naaalala ng row ang page. Walang nagpapakita kung sino ang nag-publish ng page, kaya ikaw mismo ang mag-check ng address.
- Hindi makuha ng hosted na web app ang page ng ibang brand, dahil mga nakapangalan na host lang ang pinapayagan ng Content Security Policy nito. Kunin ang logo sa terminal, o i-save ang file at idagdag ito sa **Assets**.
