# Pakikipagtulungan sa mga partner

Logo ng sponsor sa poster ng event, alok ng reseller sa ilalim ng pangalan ng gumawa, magkasanib na anunsyo, case study na isinulat kasama ang supplier: maraming materyal ang may dalawang brand. Para sa magkabilang panig ang pahinang ito. Sakop nito kung ano ang ipapadala kapag ibinahagi mo ang brand mo sa partner, kung paano gumawa sa brand na ipinadala sa iyo ng iba, kung paano ilagay ang mark ng partner, kung paano gumawa ng logo wall para sa mga sponsor o event, at kung ano ang hindi pa ginagawa ng Lolly.

Pareho ang kahulugan ng dalawang salita sa buong pahinang ito. Ang **pangunahing brand** ay ang brand na ang design system ang ginagamit sa paggawa ng materyal, at ang **partner** ay ang isa pang brand sa materyal. Puwedeng gumawa ng materyal ang alinmang panig. Ipinapakita ng [Mga brand architecture](/info/brand-architectures.html#co-branding) kung paano nauugnay ang co-branding sa iba pang paraan ng pag-aayos ng mga organisasyon sa kanilang mga brand.

## Paano hinahawakan ng Lolly ang dalawang brand ngayon

- **Isang design system ang gumuguhit ng bawat materyal.** Umiiral ang mga kulay, type at house rules ng pangunahing brand. Pumapasok ang mark ng partner bilang artwork: isang larawan mula sa Assets, o isang custom mark na nakatago sa isang design system.
- **Naglalakbay ang brand bilang file.** Dala ng isang design-system file (`.lolly`) ang mga token, font at logo. Dala ng reusable tool na ginawa gamit ang **Share with rules** ang isang tapos na layout kasama ang mga input na pinapayagan mo. May sariling mga file ang brand skills.
- **Mga rules lang ng pangunahing brand ang sinusuri ng Lolly.** Hindi nito alam ang mga rules ng partner, gaya ng clear space o minimum na laki, kaya suriin ang mga iyon ayon sa sariling mga alituntunin ng partner.

## Ibahagi ang brand mo sa partner

### Piliin kung ano ang ipapadala

| Ipapadala | Paano | Matatanggap ng partner | Angkop para sa |
| --- | --- | --- | --- |

### Gumawa ng co-branded na template

Pinapanatili ng reusable tool ang materyal ng bawat partner sa loob ng layout mo, dahil ang pinapayagan mo lang ang binabago ng partner.

1. Sa Design, gawin ang materyal sa design system mo. Gumuhit ng image box kung saan ilalagay ang logo ng partner, at iwanan ang espasyo sa paligid ng box na kailangan ng layout.
2. Piliin ang **Share with rules** sa File menu. Piliin ang image box at piliin ang **Make editable**. Sa **Rules** nito, payagan ang mga kapalit na upload, magtakda ng minimum na laki sa pixel at ng mga format ng upload na tinatanggap mo (SVG kung maaari). Itakda ang sariling **Image fit** ng box sa **Contain (fit inside)**, na pinapanatili sa loob ng box ang malapad o mataas na logo.
3. Gawin ding editable ang pangalan o alok ng partner, na may limitasyon sa bilang ng karakter.
4. Pindutin ang **Preview** at subukan ang napakalapad na logo, napakataas na logo at mahabang pangalan.
5. Piliin ang **Share .lolly**, at sumulat ng mga tagubilin para sa partner: aling bersyon ng logo nila ang ia-upload, gaya ng full-colour na pahalang na logo para sa maliwanag na background.

Ilalagay ng partner ang file sa Lolly, babasahin ang trust prompt, pupunan ang mga input at ida-download ang mga format na pinayagan mo ([Gamitin ang tapos na tool](/info/create-a-tool.html#use-the-finished-tool)). Pinapanatili ng Lolly ang logo sa loob ng box na iginuhit mo. Hindi nito binabasa ang sariling clear-space rule ng partner, kaya ang espasyong iniwan mo sa paligid ng box ang espasyong makukuha ng logo.

### Ibigay sa agent ang brand skills mo

Ang skills ay gabay para sa mga tao at agent; ang house rules ang sinusuri ng Lolly.

- Sa Design System Setup, buksan ang **Skills** room (`#/start?area=skills`), pumili ng skill at pindutin ang **Download skill (.zip)**. Tumuturo sa Lolly mo ang mga catalog link ng folder, at nakatala sa `lolly.json` nito kung saan galing ang kopya. Inilalagay ng **Copy as one file** ang parehong text sa clipboard para sa chat window.
- Mula sa terminal, isinusulat ng `lolly system skill <name> --into=<dir>` ang parehong folder ([Sa isang folder para sa lokal na agent tool](/info/brand-skills.html#in-a-folder-for-a-local-agent-tool)).
- Ang skill na may markang `internal` ay nakalista sa sarili mong makina kasama ng mga `public`, kaya piliin kung alin ang ipapadala ([Public at internal na skills](/info/brand-skills.html#public-and-internal-skills)).
- Ang design system na walang sariling skills ay may baseline na isinusulat ng Lolly mula sa mga token at house rules nito, at nililista rin ng room ang baseline.
- Hindi nag-a-update ang kopya nang kusa. Kapag naglathala ka ng bagong revision ng skill, ipadala muli ang folder.

## Gumawa sa brand na ibinigay sa iyo

Para sa partner na tumatanggap ng design-system file.

1. **Buksan ang file.** Ihulog ang file sa Lolly o pindutin ang **Open**; tinatanggap din ng **Add from…** sa Design System Setup ang file. Inililista ng preview ang laman ng file bago may isulat. Nagdaragdag ang design-system file ng hiwalay na design system sa ilalim ng pangalan ng pangunahing brand at ginagawa itong aktibo, at nananatili sa device ang sarili mong design system. Ang file na sa halip ay nag-uugnay sa app sa sariling Lolly ng pangunahing brand ay naglilista muna ng mga epekto sa buong device mo; sinasaklaw ng [Gamitin ang Lolly sa iyong organisasyon](/info/organisation.html) ang ganoong uri ng file.
2. **Tingnan ang brand.** Sa Design System Setup, ipinapakita ng **Board** ang laman ng design system, hawak ng **Logos** ang mga mark nito, at inililista ng **Rules** ang house rules na sinusuri ng Lolly. Ipinapakita ng **Skills** ang baseline na isinusulat ng Lolly mula sa mga token at rules; dumarating bilang hiwalay na mga file ang sariling skills ng pangunahing brand, kung ipapadala nila.
3. **Lumipat sa pagitan ng mga brand.** Pinapalitan ng **Settings → Preferences → Design systems** ang design system para sa buong device, at may strip ng mga cover ang **Settings → Design system** na mapaglilipatan. Tapusin ang materyal ng isang brand bago lumipat.
4. **Ilagay ang sarili mong mark.** I-upload ang logo mo sa **Assets**, kung saan iniaalok ito sa bawat design system, o idagdag ito bilang **custom mark** sa design system ng pangunahing brand (**Logos** room, **Custom marks**), kung saan sumasama ito sa file ng design system na iyon. Read-only ang design system na may lock, kaya gamitin doon ang Assets. May mga pagsusuri sa [Ilagay ang mark ng partner](#place-a-partner-s-mark).
5. **Suriin bago mag-export.** Sa Design, inililista ng **Before you export** card ng export panel ang mga natuklasan laban sa house rules ng pangunahing brand, bawat layer ([Bago ka mag-export](/info/design.html#before-you-export)). Ipinapakita ng **Design system** card ang design system na itinatala ng file.
6. **Ibalik ang gawa.** Ipadala ang na-export na file, o ang editable na design bilang `.lolly` ([Pagbabahagi ng gawa mo](/info/using.html#sharing-your-work)). Nagbubukas ang design sa alinmang design system ang aktibo, kaya bubuksan ng pangunahing brand ang sa iyo na aktibo ang sarili nilang design system.

Ang design-system file ay kopya ng brand sa araw na na-export ito, at walang nag-a-update sa kopya. Kapag nagpadala ang pangunahing brand ng mas bagong file, buksan ang bagong file sa parehong paraan. Pagkatapos, tingnan kung aling design system ang aktibo sa **Settings → Preferences → Design systems**, at alisin doon ang mas lumang kopya kapag tapos ka na rito.

## Ilagay ang mark ng partner

| Paraan | Mga hakbang | Pinakamainam para sa |
| --- | --- | --- |
| Larawan sa Assets | Ihulog ang file sa upload area sa **Assets**, saka piliin ito sa image field ng tool, o sa Design gamit ang **Image** mula sa add menu ng rail | Mga one-off na materyal. Nabibilang sa device ang upload, kaya iniaalok ito anuman ang aktibong design system |
| Isang custom mark | **Logos** room, **Custom marks**: mag-type ng pangalan para sa mark, saka **Choose file…** | Partner na madalas mong katrabaho. Nabibilang ang mark sa design system at sumasama sa file nito |
| Isang tapos na lockup | Gawin ang lockup mula sa dalawang mark sa drawing tool mo, saka idagdag ito bilang custom mark | "Kasama ang" o "in partnership with" na lockup na paulit-ulit na ginagamit |

Bago ka mag-export, suriin ang mark:

- **Ang tamang file.** Gamitin ang file na ibinigay ng partner, SVG kung mayroon. Lumalabo kapag ipinrint ang logo na kinopya mula sa web page o slide.
- **Ang tamang bersyon para sa background.** Gumamit ng reverse o one-colour na bersyon sa madilim o magulong background, kung nag-aalok ng ganoon ang mga alituntunin ng partner.
- **Mga proporsyon.** Itakda ang **Image fit** ng image box sa **Contain (fit inside)**, at hindi kailanman iuunat ang mark.
- **Clear space at laki.** Iwanan ang espasyong hinihingi ng mga alituntunin ng partner sa paligid ng mark, at panatilihing mas malaki sa minimum nilang laki ang mark. Wala sa dalawa ang sinusukat ng Lolly.
- **Aling brand ang nangunguna.** Sukatin ang dalawang mark para sundin ang mga alituntunin ng parehong brand kung alin ang nangunguna.
- **Mga karapatan.** Ipinapakita ng Lolly ang lisensyang nakatala para sa asset ng catalogue. Walang tala ng lisensya ang file na ikaw mismo ang nag-upload, at mababasa sa mga detalye nito ang *Hindi naitala ang lisensya*, kaya itago ang pahintulot ng partner na gamitin ang mark nila kasama ng sarili mong mga tala ([Creative rights and credits](/info/creative-rights.html)).

Ibinibigay ng [design-system record](/info/exporting.html#the-design-system-record) ng isang export ang design system at colourway ng pangunahing brand. Hindi nito itinatala ang brand ng partner.

### Ibigay sa agent ang skills ng bawat brand

Kapag agent ang gumagawa, ibigay sa agent ang skills ng pangunahing brand at ang skills ng partner nang buo, at sabihin sa agent kung aling brand ang nangunguna. Pinapanatili ng skills ng bawat brand ang kani-kanilang pangalan at id. Hindi pinagsasama ng Lolly ang skills ng dalawang brand o nagpapasya kung aling brand ang mananaig, at house rules lang ng pangunahing brand ang sinusuri nito.

## Mga logo wall para sa sponsor at event

Inaayos ng [Lolly Logo Wall](/#/tool/logo-wall) tool ang tambak ng mga logo sa pantay na grid, para sa sponsor board, partner slide o press backdrop. Sa isang event, kadalasang ang host ang pangunahing brand: ginagawa ang wall sa design system ng host, at nakapuwesto ang logo ng bawat sponsor sa wall bilang artwork.

1. Buksan ang Logo Wall at ihulog ang mga logo sa **Logos**. May sariling set ng mga kontrol ang bawat logo.
2. Bigyan ang bawat logo ng **Tier**, gaya ng "Gold partners". May sariling mga hanay ang bawat tier, ayon sa pagkakasunod na unang lumitaw ang mga tier, sa ilalim ng sarili nitong heading; pinapatay ng **Tier headings** ang mga heading. Kapag nasa **Step down** ang **Tier sizes**, isang logo pa ang kasya sa bawat hanay ng bawat mas mababang tier, kaya mas malaki ang tingin sa mas matataas na tier. Napapagalaw pa rin ng **Presence** at **Size %** ang isang logo sa loob ng tier nito.
3. Iwanang naka-on ang **Balance sizes**. Sinusukat ng Logo Wall ang bawat logo ayon sa optical weight nito, kaya lumiliit ang mabigat na logo at lumalaki ang magaan, at pantay ang tingin sa bawat tier.
4. Pinuputol ng **Trim margins** ang bawat logo hanggang sa artwork nito. I-off ang option kapag kasama na sa file ng logo ang clear space na hinihingi ng may-ari nito.
5. Inaalis ng **Remove white backgrounds** ang puting kahon na madalas kasama ng logo na kinopya mula sa slide.
6. Itakda ang **Columns**, espasyo at padding sa ilalim ng **Layout**. Nagsisimula ang **Background** bilang kulay ng surface ng design system mo.
7. Para sa one-colour na wall, i-on ang **Render all as vector** at piliin ang **Ink colour**, o itakda ang **Filter** ng isang logo sa **Greyscale**. Gumamit lang ng one-colour na bersyon kung pinapayagan ito ng mga alituntunin ng bawat sponsor.
8. Para sa press backdrop, piliin ang **Grid**, **Brick** o **Checker** sa ilalim ng **Step & repeat**, at itakda ang bilang ng **Rows**.

I-export ang wall bilang PNG, SVG, PDF o CMYK PDF para sa print. Magtakda ng ibang laki at hugis sa export panel, gaya ng mataas na 1080 x 1920 na story o A4 na pahina, at ipapakita ng canvas ang wall na inayos muli para punuin ang hugis na iyon, na may mas kaunti o mas maraming logo sa bawat hanay. Ang export ay ang wall na nasa canvas. Para ilagay ang wall sa poster, piliin ang **Image** mula sa add menu ng rail sa Design, gumuhit ng frame at piliin ang Logo Wall sa **Tools** tab ng picker ([Mga tool sa loob ng design](/info/design.html#tools-inside-a-design)). Para sa mga caption sa pagitan ng mga logo, may hawak na isang image box bawat logo ang **Dynamic layout** na nakatakda sa **grid** sa Design ([Layout sa Design](/info/design-layout.html#dynamic-layouts)).

Sa terminal, binubuo ng `lolly run logo-wall logos/*.png --output=wall.svg` ang wall mula sa folder ng mga larawan, at binubuo ng CSV na may mga column na `logo` at `tier` ang wall na may mga tier. Hindi kailangan ng browser ang SVG at PNG ([Sponsor wall na may mga tier](/info/cli-rendering.html#a-sponsor-wall-with-tiers)).

Hindi alam ng Logo Wall ang mga rules ng anumang sponsor. Ang Tiers at Presence ay nagtatakda ng mga laki kaugnay ng isa't isa, hindi ng minimum na laki ng sponsor, at walang sumusuri sa clear space sa pagitan ng magkakatabi. Suriin ang tapos na wall laban sa mga alituntunin ng bawat sponsor sa laking ipiprint o ipapakita ito.

## Ano ang hindi pa ginagawa ng Lolly

- Iginuguhit ang materyal sa isang design system. Hindi design system sa loob ng materyal ang mga kulay, type at rules ng partner, at larawan ang mark ng partner.
- Hindi iniingatan o sinusuri ang mga rules ng partner: clear space, minimum na laki at mga pinapayagang treatment gaya ng one colour o reverse. House rules lang ng pangunahing brand ang sinusuri ng Lolly.
- Wala pang partner kit: magaang pack na maglalaman ng mga logo, kulay at rules ng partner para gamitin sa loob ng gawa ng ibang brand.
- Hindi gumagawa ang Lolly ng lockup mula sa dalawang mark para sa "with", "in partnership with" o "by" na ayos. Idagdag ang tapos na lockup bilang custom mark.
- Isang design system ang aktibo para sa buong device, kaya hindi puwedeng magkatabing bukas ang dalawang brand.
- Ang design-system file ay kopya ng brand sa panahong na-export ito, at walang nag-a-update sa kopya. Hindi nagdadala ng brand skills ang design-system file na na-export mula sa app, kaya ipadala ang mga iyon bilang sariling mga file.
- Itinatala ng export ang design system at colourway ng pangunahing brand, hindi ang brand ng partner.
