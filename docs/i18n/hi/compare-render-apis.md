# Lolly और रेंडरिंग API

_अंतिम जाँच: 5 नवंबर 2026।_

अगर आप आज API से टेम्पलेट द्वारा इमेज बनाते हैं, तो यह पेज बताता है कि वह उत्पादन खुद चलाने पर क्या बदलता है: अपने डिवाइस पर, CI में या अपने नियंत्रण वाले सर्वर पर। [होस्टेड रेंडर API से आएँ](/info/work-move-from-render-api.html) में इसका तरीका है।

## होस्टेड रेंडरिंग API क्या बेहतर करते हैं

[Bannerbear](https://www.bannerbear.com/) और [Placid](https://placid.app/) प्रबंधित सेवाएँ हैं, और यह एक असली फ़ायदा है। आप अनुरोध भेजते हैं और सर्वर कोई और चलाता है, उन्हें चालू रखता है और लोड सँभालता है।

- **चलाने को कुछ नहीं।** न सर्वर, न डेटाबेस, न स्टोरेज, न अपडेट, न क्षमता योजना।
- **होस्टेड टेम्पलेट एडिटर**, अपनाने के लिए तैयार टेम्पलेट के साथ।
- **एक API से ज़्यादा तरह के आउटपुट।** दोनों वीडियो और PDF एंडपॉइंट प्रकाशित करते हैं, और Bannerbear एनिमेटेड आउटपुट, WebP और AVIF, स्क्रीनशॉट और AI बैकग्राउंड हटाना भी दस्तावेज़ित करता है।
- **उनके अपने इंटीग्रेशन और समर्थन।**

अगर यही व्यवस्था आप चाहते हैं, तो वे सेवाएँ एक ठोस चुनाव हैं।

## सेल्फ-होस्टिंग से क्या मिलता है

- **आपकी सामग्री आपके सिस्टम पर रहती है।** इनपुट, एसेट और आउटपुट आपके चुने इन्फ्रास्ट्रक्चर पर रहते हैं। डिवाइस पर या CI में रेंडर करने के लिए किसी सेवा की ज़रूरत नहीं।
- **नियम टूल में रहते हैं।** रंग, टाइप, लोगो और लॉक इनपुट आपके [design system](/info/brand-studio.html) से आते हैं, इसलिए कॉल करने वाला केवल वही बदल सकता है जो आप अनुमति दें। [Lolly Work](/info/compare.html#what-runs-where) हर अनुरोध पर टूल दृश्यता और इनपुट नीतियाँ लागू करता है।
- **हर जगह वही टूल।** टूल लैपटॉप पर, CI जॉब में या सर्वर पर उन्हीं इनपुट से रेंडर होता है, और लोग ऐप में वही टूल संपादित कर सकते हैं।
- **आपके पास रहने वाले रिकॉर्ड।** [रेंडर रसीदें](/info/work-renders.html#evidence-and-identity), ऑडिट ट्रेल, और Content Credentials जहाँ आप हस्ताक्षर पहचान कॉन्फ़िगर करें।
- **ओपन सोर्स और कोई मीटर नहीं।** आप कोड चलाते हैं, और आप जिसके लिए भुगतान करते हैं वह आपका अपना इन्फ्रास्ट्रक्चर है।

वे सेवाएँ आपके लिए जो काम करती हैं, वह आप अपने ऊपर लेते हैं। टिकाऊ सर्वर को स्थायी डेटाबेस और आउटपुट स्टोरेज चाहिए, और जिन टूल को ब्राउज़र चाहिए उन्हें Chromium वर्कर चाहिए। [Install Lolly Work](/info/work-install.html) दोनों बताता है।

## काम कैसे मेल खाते हैं

| काम | होस्टेड रेंडरिंग API | Lolly |
|---|---|---|
| डेटा से टेम्पलेट भरना | टेम्पलेट और उसकी लेयर का नाम देता API अनुरोध | टूल और उसके इनपुट का नाम देता [URL](/info/url-mode.html), [CLI](/info/cli.html) या [सर्वर API](/info/work-automation-api.html) |
| तालिका से कई फ़ाइलें | बैच और संग्रह | आपके डिवाइस पर [Batch](/info/batch.html), या सर्वर पर [रेंडर बैच](/info/work-renders.html#batches-with-durable-rows) |
| नतीजे का इंतज़ार या पोल | पोलिंग, या सिंक्रोनस विकल्प | टिकाऊ रेंडर जिन्हें आप पोल करते हैं, या तुरंत रेंडर |
| पूरा होने पर वेबहुक कॉल | हाँ | आपके अनुमत ओरिजिन पर [हस्ताक्षरित कॉलबैक](/info/work-renders.html) |
| डायनामिक इमेज URL | हाँ | [शेयर लिंक और `/render` URL](/info/url-mode.html) |
| टेम्पलेट संपादित करना | होस्टेड एडिटर | आपके डिवाइस पर [Design](/info/using.html) |
| एजेंट | दोनों MCP सर्वर प्रकाशित करते हैं | [MCP](/info/mcp.html), Lolly Work पर टोकन की नीति के तहत संगठन एंडपॉइंट के साथ |

Lolly के अपने आउटपुट प्रकार [Exporting](/info/exporting.html) में सूचीबद्ध हैं। आज Work सर्वर पर टिकाऊ रेंडर SVG, PNG, JPG और PDF बनाते हैं, और [वीडियो डिवाइस, CLI और MCP पर रहता है](/info/work-renders.html#production-still-checks-and-permitted-repairs)।

## क्या साथ आता है, और क्या नहीं

| | Bannerbear V5 | Bannerbear V2 | Placid |
|---|---|---|---|
| आपके अनुरोध | Work का माइग्रेशन API वही रूप लेता है | वही | वही |
| आपके टेम्पलेट | संपादन योग्य दस्तावेज़ों के रूप में **Import** होते हैं, उन लेयर प्रकारों को छोड़कर जिनका कोई पुष्ट स्कीमा नहीं | केवल फ़ील्ड नाम और प्रीव्यू। हर एक दोबारा बनाएँ | केवल फ़ील्ड नाम और प्रीव्यू। हर एक दोबारा बनाएँ |
| मौजूदा डायनामिक URL | समर्थित नहीं | समर्थित नहीं | हस्ताक्षरित URL होस्ट बदलने के बाद भी चलते हैं, आपके पुराने निजी टोकन के साथ |
| वेबहुक | पंजीकृत वेबहुक समर्थित नहीं | `webhook_url` काम करता है | `webhook_success` काम करता है |
| WebP और AVIF आउटपुट | नाम लेकर अस्वीकृत | उपलब्ध नहीं | WebP नाम लेकर अस्वीकृत |
| एनिमेशन, वीडियो, संग्रह, स्क्रीनशॉट | माइग्रेशन API पर नहीं | माइग्रेशन API पर नहीं | माइग्रेशन API पर नहीं |

यह सब हर विक्रेता के सार्वजनिक दस्तावेज़ों से बनाया गया है और किसी लाइव खाते पर चलाया नहीं गया है। अगर आपके पास खाता है तो [माइग्रेशन गाइड](/info/work-move-from-render-api.html#check-it-on-your-own-account) में एक छोटी जाँच-सूची है।

आना सब-कुछ-या-कुछ-नहीं नहीं है। आप एक टेम्पलेट ला सकते हैं और बाकी जहाँ हैं वहीं रख सकते हैं, और [Lolly छोड़ना](/info/work-move-from-render-api.html#leave-lolly-too) भी उतना ही खुला है: टूल सादी फ़ाइलें हैं और CLI उन्हें बिना सर्वर के रेंडर करता है।

## सेवा कौन चलाता है

Lolly के साथ व्यक्ति स्थानीय रूप से रेंडर करता है, या टीम अपने इन्फ्रास्ट्रक्चर पर Lolly Work चलाती है। सर्वर जॉब सबमिट करना उसके इनपुट और आवश्यक एसेट उस इंस्टेंस को भेजता है, जो डिवाइस पर चलने वाले रास्ते से अलग है।

Bannerbear और Placid अपने स्वामियों के ट्रेडमार्क हैं। यह पेज बताता है कि उत्पाद कहाँ ओवरलैप करते हैं, उनके सार्वजनिक दस्तावेज़ों से, और किसी से संबद्ध नहीं है।
