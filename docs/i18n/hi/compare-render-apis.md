# Lolly और रेंडरिंग API

_आखिरी जाँच: 5 नवंबर 2026।_

अगर आप API के ज़रिए टेम्पलेट से इमेज बनाते हैं, तो यह पेज बताता है कि उस उत्पादन को अपने डिवाइस पर, CI में या अपने नियंत्रण वाले सर्वर पर चलाने से क्या बदलता है। [होस्ट किए गए रेंडर API से आएँ](/info/work-move-from-render-api.html) में इसके चरण हैं।

<!--i:eti-award-->
## होस्ट किए गए रेंडरिंग API क्या बेहतर करते हैं

[Bannerbear](https://www.bannerbear.com/) और [Placid](https://placid.app/) प्रबंधित सेवाएँ हैं: आप अनुरोध भेजते हैं और कोई और सर्वर चलाता है।

- **आपको कुछ चलाना नहीं पड़ता।** न सर्वर, न डेटाबेस, न स्टोरेज, न अपडेट और न क्षमता की योजना।
- **होस्ट किया गया टेम्पलेट संपादक**, अनुकूलित करने के लिए तैयार टेम्पलेट के साथ।
- **एक API से ज़्यादा तरह के आउटपुट।** दोनों वीडियो और PDF एंडपॉइंट प्रकाशित करते हैं और Bannerbear एनिमेटेड आउटपुट, WebP और AVIF, स्क्रीनशॉट और AI से बैकग्राउंड हटाने का दस्तावेज़ीकरण भी देता है।
- **उनके अपने इंटीग्रेशन और सहायता।**

अगर आप ऐसी ही व्यवस्था चाहते हैं, तो वे सेवाएँ अच्छा विकल्प हैं।

<!--i:eti-home-->
## अपने सर्वर पर होस्ट करने से क्या मिलता है

- **आपकी सामग्री आपके सिस्टम पर रहती है।** इनपुट, एसेट और आउटपुट आपके चुने इंफ़्रास्ट्रक्चर पर रहते हैं। डिवाइस पर या CI में रेंडरिंग को किसी सेवा की ज़रूरत नहीं है।
- **नियम टूल में रहते हैं।** रंग, टाइप, लोगो और लॉक किए इनपुट आपके [design system](/info/brand-studio.html) से आते हैं, इसलिए कॉल करने वाला केवल वही बदल सकता है जिसकी आप अनुमति दें। [Lolly Work](/info/compare.html#what-runs-where) हर अनुरोध पर टूल की दृश्यता और इनपुट नीतियाँ लागू करता है।
- **हर जगह वही टूल।** टूल लैपटॉप पर, CI जॉब में या सर्वर पर उन्हीं इनपुट से रेंडर करता है। लोग ऐप में उसी टूल को संपादित कर सकते हैं।
- **रिकॉर्ड आपके पास रहते हैं।** [रेंडर रसीदें](/info/work-renders.html#evidence-and-identity), ऑडिट ट्रेल और जहाँ आप हस्ताक्षर की पहचान कॉन्फ़िगर करें वहाँ Content Credentials।
- **ओपन सोर्स और उपयोग के हिसाब से कोई शुल्क नहीं।** आप कोड चलाते हैं और केवल अपने इंफ़्रास्ट्रक्चर का भुगतान करते हैं।

वे सेवाएँ आपके लिए जो काम करती हैं, उसे आप खुद संभालते हैं। टिकाऊ सर्वर को स्थायी डेटाबेस और आउटपुट स्टोरेज चाहिए। जिन टूल को ब्राउज़र चाहिए, उन्हें Chromium वर्कर चाहिए। [Lolly Work इंस्टॉल करें](/info/work-install.html) दोनों का विवरण देता है।

## कामों की तुलना

| काम | होस्ट किया गया रेंडरिंग API | Lolly |
|---|---|---|
| डेटा से टेम्पलेट भरना | टेम्पलेट और उसकी लेयर के नाम वाला API अनुरोध | टूल और उसके इनपुट के नाम वाला [URL](/info/url-mode.html), [CLI](/info/cli.html) या [सर्वर API](/info/work-automation-api.html) |
| तालिका से कई फ़ाइलें | बैच और संग्रह | आपके डिवाइस पर [बैच](/info/batch.html) या सर्वर पर [रेंडर बैच](/info/work-renders.html#batches-with-durable-rows) |
| परिणाम के लिए इंतज़ार या पोल करना | पोलिंग या सिंक्रोनस विकल्प | टिकाऊ रेंडर जिन्हें आप पोल करते हैं या तत्काल रेंडर |
| पूरा होने पर वेबहुक कॉल करना | हाँ | आपके अनुमत ऑरिजिन पर [हस्ताक्षरित कॉलबैक](/info/work-renders.html) |
| डायनामिक इमेज URL | हाँ | [साझा लिंक और `/render` URL](/info/url-mode.html) |
| टेम्पलेट संपादित करना | होस्ट किया गया संपादक | आपके डिवाइस पर [Design](/info/using.html) |
| एजेंट | दोनों MCP सर्वर प्रकाशित करते हैं | [MCP](/info/mcp.html), Lolly Work पर टोकन की नीति के तहत संगठन के एंडपॉइंट के साथ |

Lolly के अपने आउटपुट प्रकार [एक्सपोर्ट करना](/info/exporting.html) में सूचीबद्ध हैं। आज Work सर्वर पर टिकाऊ रेंडर SVG, PNG, JPG और PDF बनाते हैं और [वीडियो डिवाइस, CLI और MCP पर रहता है](/info/work-renders.html#production-still-checks-and-permitted-repairs)।

| आपके टेम्पलेट | जिन लेयर प्रकारों का स्कीमा पुष्ट नहीं है उन्हें छोड़कर, संपादन योग्य दस्तावेज़ों के रूप में **Import** करें | केवल फ़ील्ड के नाम और प्रीव्यू। हर एक को फिर बनाएँ | केवल फ़ील्ड के नाम और प्रीव्यू। हर एक को फिर बनाएँ |
| मौजूदा डायनामिक URL | समर्थित नहीं | समर्थित नहीं | होस्ट बदलने के बाद भी हस्ताक्षरित URL आपके पुराने निजी टोकन के साथ काम करते रहते हैं |
| वेबहुक | पंजीकृत वेबहुक समर्थित नहीं हैं | `webhook_url` काम करता है | `webhook_success` काम करता है |
| WebP और AVIF आउटपुट | नाम से अनुरोध करने पर अस्वीकार | उपलब्ध नहीं | WebP का नाम से अनुरोध करने पर अस्वीकार |
| एनिमेशन, वीडियो, संग्रह, स्क्रीनशॉट | माइग्रेशन API पर नहीं | माइग्रेशन API पर नहीं | माइग्रेशन API पर नहीं |

::: note सार्वजनिक दस्तावेज़ों से बनाया गया
इसे हर विक्रेता के सार्वजनिक दस्तावेज़ों से बनाया गया है और किसी लाइव खाते पर चलाया नहीं गया है। अगर आपके पास खाता है, तो [स्थानांतरण गाइड](/info/work-move-from-render-api.html#check-it-on-your-own-account) में छोटी जाँच सूची है।
:::

आप एक टेम्पलेट स्थानांतरित कर सकते हैं और बाकी जहाँ हैं वहीं रख सकते हैं। [Lolly छोड़ना](/info/work-move-from-render-api.html#leave-lolly-too) भी उतना ही खुला है: टूल साधारण फ़ाइलें हैं और CLI उन्हें बिना सर्वर के रेंडर करता है।

## सेवा कौन चलाता है

Lolly के साथ व्यक्ति स्थानीय रूप से रेंडर करता है या टीम अपने इंफ़्रास्ट्रक्चर पर Lolly Work चलाती है। सर्वर जॉब अपने इनपुट और ज़रूरी एसेट उस इंस्टेंस पर भेजता है। डिवाइस पर चलने वाला मार्ग ऐसा नहीं करता।

Bannerbear और Placid अपने मालिकों के ट्रेडमार्क हैं। यह पेज उनके सार्वजनिक दस्तावेज़ों के आधार पर बताता है कि उत्पाद कहाँ एक जैसा काम करते हैं और दोनों में से किसी से संबद्ध नहीं है।
