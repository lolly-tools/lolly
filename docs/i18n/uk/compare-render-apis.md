# Lolly і API рендерингу

_Остання перевірка: 28 вересня 2026._

Lolly генерує ресурси із шаблонів і даних на вашому пристрої, в CI або через серверний API [lolly.work](https://lolly.work). Спільне рішення охоплює автоматизований рендеринг, а також ідентифікацію, політики та доставку навколо виробничих завдань організації.

## Де вони перетинаються

[Bannerbear](https://www.bannerbear.com/) і [Placid](https://placid.app/) генерують зображення та інші медіа із шаблонів через API та інтеграції. Lolly використовує той самий підхід «шаблон плюс вхідні дані», а подавати завдання можна через [режим URL](/info/url-mode.html), [CLI](/info/cli.html), пакетну сітку та серверні кінцеві точки.

## Що надає lolly.work

lolly.work - це окремо розгорнутий організаційний сервіс у проєкті Lolly. Він запускає рушій Lolly за API, застосовує політики видимості інструментів і вхідних даних та віддає відрендерені файли й підписані посилання для спільного доступу. Його [відновлюваний сервіс рендерингу](https://github.com/lolly-tools/lolly-work/blob/main/docs/renders.md) підтримує окремі завдання й пакети, ідемпотентне подання, статус, обмежену кількість повторних спроб, скасування та збереження результатів. Перервана робота може продовжитися після перезапуску сервера, якщо налаштовано постійне сховище.

Сервер використовує швидкий шлях рендерингу SVG/PNG та необов'язковий воркер Chromium для інструментів, яким потрібен браузер. Автоматизація автентифікується сервісними токенами, а готовий результат можна надіслати через [кероване доставлення](https://github.com/lolly-tools/lolly-work/blob/main/docs/delivery.md) до цілей організації. Налаштована ідентичність підписання вмикає підписання C2PA для підтримуваного серверного виводу.

## Хто запускає сервіс

Bannerbear і Placid пакують рендеринг у керовані сервіси з власною інфраструктурою та інтеграціями. З Lolly окрема людина може рендерити локально, а команда - запускати lolly.work на власній інфраструктурі. Обидва репозиторії Lolly мають відкритий код за MPL-2.0; самостійний хостинг не передбачає плати за програмну ліцензію за кожен рендеринг, але обчислення, сховище й експлуатація залишаються витратами, які слід планувати.

Публічний сайт lolly.work - це пісочниця для оцінювання, а не зобов'язання щодо виробничого хостингу. Тривалий сервіс потребує постійної бази даних і сховища результатів; інструментам, залежним від браузера, потрібен воркер Chromium. [Посібник зі встановлення](https://github.com/lolly-tools/lolly-work/blob/main/docs/install.md) і [сторінка стану](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md) описують ці вимоги та поточні обмеження.

Локальний рендеринг і рендеринг у CI залишаються доступними без організаційного сервісу. Подання серверного завдання надсилає його вхідні дані та потрібні ресурси на цей інстанс; це відрізняється від шляху на пристрої. Дивіться [огляд спільного рішення](/info/compare.html).

Bannerbear і Placid є торговельними марками їхніх власників. Ця сторінка описує, де рішення перетинаються, і не пов'язана ні з одним із них.
