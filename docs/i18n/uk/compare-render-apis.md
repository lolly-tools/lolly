# Lolly і API рендерингу

_Остання перевірка: 5 листопада 2026._

Якщо ви сьогодні генеруєте зображення з шаблонів через API, ця сторінка каже, що зміниться, коли ви самі запустите це виробництво: на власному пристрої, у CI або на сервері під вашим контролем. [Перехід з хостованого API рендерингу](/info/work-move-from-render-api.html) описує, як це зробити.

## Що розміщені API рендерингу роблять краще

[Bannerbear](https://www.bannerbear.com/) та [Placid](https://placid.app/) є керованими сервісами, і це справжня перевага. Ви надсилаєте запит, а сервери запускає, підтримує й навантаження обробляє хтось інший.

- **Нічого обслуговувати.** Жодного сервера, бази даних, сховища, оновлень чи планування потужностей.
- **Хостований редактор шаблонів** із готовими шаблонами для адаптації.
- **Більше видів виводу з одного API.** Обидва публікують кінцеві точки для відео та PDF, а Bannerbear також документує анімований вивід, WebP і AVIF, знімки екрана та ШІ-вилучення тла.
- **Власні інтеграції та підтримка.**

Якщо вам потрібна саме така схема, ці сервіси є слушним вибором.

## Що дає самостійне розміщення

- **Ваш контент лишається у ваших системах.** Вхідні дані, ресурси й результати живуть на інфраструктурі, яку ви вибрали. Рендеринг на пристрої чи в CI не потребує жодного сервісу.
- **Правила живуть в інструменті.** Кольори, шрифти, логотипи та заблоковані вхідні дані походять із вашої [дизайн-системи](/info/brand-studio.html), тож викликач може змінити лише те, що ви дозволили. [Lolly Work](/info/compare.html#what-runs-where) застосовує видимість інструментів і політики вхідних даних до кожного запиту.
- **Той самий інструмент усюди.** Інструмент рендерить на ноутбуці, у завданні CI чи на сервері з тих самих вхідних даних, а люди можуть редагувати той самий інструмент у застосунку.
- **Записи, які ви тримаєте.** [Квитанції рендерингу](/info/work-renders.html#evidence-and-identity), слід аудиту та Content Credentials там, де ви налаштували ідентичність підпису.
- **Відкритий код і без лічильника.** Ви запускаєте код, а платите лише за власну інфраструктуру.

Ви берете на себе роботу, яку ці сервіси виконують за вас. Довговічному серверу потрібні постійна база даних і сховище виводу, а інструментам, що потребують браузера, потрібен робітник Chromium. [Встановлення Lolly Work](/info/work-install.html) описує і те, і те.

## Як співвідносяться завдання

| Завдання | Хостований API рендерингу | Lolly |
|---|---|---|
| Заповнити шаблон даними | Запит API з назвою шаблону та його шарів | [URL](/info/url-mode.html), [CLI](/info/cli.html) або [серверний API](/info/work-automation-api.html) з назвою інструмента та його вхідних даних |
| Багато файлів із таблиці | Пакети та колекції | [Batch](/info/batch.html) на вашому пристрої або [пакети рендерингу](/info/work-renders.html#batches-with-durable-rows) на сервері |
| Чекати або опитувати результат | Опитування або синхронний варіант | Довговічні рендери, які ви опитуєте, або негайний рендер |
| Викликати вебгук після завершення | Так | [Підписані зворотні виклики](/info/work-renders.html) на дозволені вами джерела |
| Динамічна URL зображення | Так | [Посилання для поширення та URL `/render`](/info/url-mode.html) |
| Редагувати шаблон | Хостований редактор | [Design](/info/using.html) на вашому пристрої |
| Агенти | Обидва публікують сервер MCP | [MCP](/info/mcp.html), з endpoint організації за політикою токена в Lolly Work |

Власні види виводу Lolly перелічено в [Експорті](/info/exporting.html). На сервері Work сьогодні довговічні рендери створюють SVG, PNG, JPG і PDF, а [відео лишається на пристрої, у CLI та MCP](/info/work-renders.html#production-still-checks-and-permitted-repairs).

## Що переноситься, а що ні

| | Bannerbear V5 | Bannerbear V2 | Placid |
|---|---|---|---|
| Ваші запити | API міграції Work приймає ту саму форму | Те саме | Те саме |
| Ваші шаблони | **Імпортуються** як редаговані документи, окрім типів шарів без підтвердженої схеми | Лише назви полів і попередній перегляд. Перебудуйте кожен | Лише назви полів і попередній перегляд. Перебудуйте кожен |
| Наявні динамічні URL | Не підтримуються | Не підтримуються | Підписані URL продовжують працювати після зміни хоста, зі старим приватним токеном |
| Вебгуки | Зареєстровані вебгуки не підтримуються | `webhook_url` працює | `webhook_success` працює |
| Вивід WebP і AVIF | Відхиляється за назвою | Не пропонується | WebP відхиляється за назвою |
| Анімації, відео, колекції, знімки екрана | Немає в API міграції | Немає в API міграції | Немає в API міграції |

Усе це створено за публічною документацією кожного постачальника й не запускалося на живому обліковому записі. [Посібник із переходу](/info/work-move-from-render-api.html#check-it-on-your-own-account) має короткий контрольний список, якщо він у вас є.

Перехід не є «все або нічого». Ви можете перенести один шаблон і лишити решту де є, а [вихід із Lolly](/info/work-move-from-render-api.html#leave-lolly-too) так само відкритий: інструменти це прості файли, і CLI рендерить їх без сервера.

## Хто запускає сервіс

З Lolly окрема людина рендерить локально, або команда запускає Lolly Work на власній інфраструктурі. Подання серверного завдання надсилає його вхідні дані та потрібні ресурси до цього екземпляра, що відрізняється від шляху на пристрої.

Bannerbear і Placid є торговими марками своїх власників. Ця сторінка описує, де продукти перетинаються, за їхньою публічною документацією, і не пов'язана з жодним із них.
