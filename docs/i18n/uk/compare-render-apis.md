# Lolly і API рендерингу

_Востаннє перевірено: 5 листопада 2026 року._

Якщо ви генеруєте зображення із шаблонів через API, ця сторінка пояснює, що змінюється, коли ви запускаєте це створення на власному пристрої, у CI або на сервері, який контролюєте. [Перехід із хмарного API рендерингу](/info/work-move-from-render-api.html) наводить кроки.

<!--i:eti-award-->
## Що хмарні API рендерингу роблять краще

[Bannerbear](https://www.bannerbear.com/) та [Placid](https://placid.app/) є керованими сервісами: ви надсилаєте запит, а хтось інший обслуговує сервери.

- **Нічого обслуговувати.** Немає сервера, бази даних, сховища, оновлень чи планування потужності.
- **Хмарний редактор шаблонів** із шаблонами, готовими до адаптації.
- **Більше типів виводу з одного API.** Обидва публікують кінцеві точки для відео та PDF, а Bannerbear також документує анімований вивід, WebP і AVIF, знімки екрана та видалення фону за допомогою ШІ.
- **Власні інтеграції та підтримка.**

Якщо вам підходить такий підхід, ці сервіси є вдалим вибором.

<!--i:eti-home-->
## Що дає розгортання на власному сервері

- **Ваш вміст залишається у ваших системах.** Вхідні дані, ресурси та результати зберігаються на вибраній вами інфраструктурі. Рендеринг на пристрої або в CI не потребує сервісу.
- **Правила містяться в інструменті.** Кольори, шрифти, логотипи та заблоковані вхідні дані походять із вашої [дизайн-системи](/info/brand-studio.html), тож той, хто робить виклик, може змінити лише те, що ви дозволили. [Lolly Work](/info/compare.html#what-runs-where) застосовує видимість інструментів і політики вхідних даних до кожного запиту.
- **Той самий інструмент скрізь.** Інструмент рендерить із тих самих вхідних даних на ноутбуці, у завданні CI або на сервері. Люди можуть редагувати той самий інструмент у застосунку.
- **Записи у вашому розпорядженні.** [Квитанції рендерингу](/info/work-renders.html#evidence-and-identity), журнал аудиту та Content Credentials там, де ви налаштували ідентичність підписувача.
- **Відкритий код без плати за обсяг.** Ви запускаєте код і платите лише за власну інфраструктуру.

Ви берете на себе роботу, яку ці сервіси виконують за вас. Для довготривалої роботи сервера потрібні постійна база даних і сховище результатів. Інструментам, які потребують браузера, потрібен виконавець Chromium. [Встановлення Lolly Work](/info/work-install.html) описує обидва аспекти.

## Зіставлення завдань

| Завдання | Хмарний API рендерингу | Lolly |
|---|---|---|
| Заповнити шаблон даними | Запит API із зазначенням шаблону та його шарів | [URL](/info/url-mode.html), [CLI](/info/cli.html) або [серверний API](/info/work-automation-api.html) із зазначенням інструмента та його вхідних даних |
| Багато файлів із таблиці | Пакети та колекції | [Пакетна обробка](/info/batch.html) на вашому пристрої або [пакети рендерингу](/info/work-renders.html#batches-with-durable-rows) на сервері |
| Чекати на результат або опитувати стан | Опитування або синхронний варіант | Стійкі до збоїв рендери з опитуванням або негайний рендер |
| Викликати вебхук після завершення | Так | [Підписані зворотні виклики](/info/work-renders.html) до дозволених вами джерел |
| Динамічна URL-адреса зображення | Так | [Посилання для спільного доступу та URL-адреси `/render`](/info/url-mode.html) |
| Редагувати шаблон | Хмарний редактор | [Design](/info/using.html) на вашому пристрої |
| Агенти | Обидва публікують сервер MCP | [MCP](/info/mcp.html) із кінцевою точкою організації, що підпорядковується політиці токена в Lolly Work |

Власні типи виводу Lolly перелічено в розділі [Експорт](/info/exporting.html). На сервері Work наразі стійкі до збоїв рендери створюють SVG, PNG, JPG і PDF, а [відео залишається на пристрої, у CLI та MCP](/info/work-renders.html#production-still-checks-and-permitted-repairs).

## Що переноситься, а що ні

| | Bannerbear V5 | Bannerbear V2 | Placid |
|---|---|---|---|
| Ваші запити | API міграції Work приймає ту саму структуру | Так само | Так само |
| Ваші шаблони | **Import** як редаговані документи, крім типів шарів без підтвердженої схеми | Лише назви полів і попередній перегляд. Відтворіть кожен заново | Лише назви полів і попередній перегляд. Відтворіть кожен заново |
| Наявні динамічні URL-адреси | Не підтримуються | Не підтримуються | Підписані URL-адреси продовжують працювати після зміни хоста з вашим старим приватним токеном |
| Вебхуки | Зареєстровані вебхуки не підтримуються | `webhook_url` працює | `webhook_success` працює |
| Вивід WebP і AVIF | Відхиляється за назвою | Не пропонується | WebP відхиляється за назвою |
| Анімації, відео, колекції, знімки екрана | Недоступні в API міграції | Недоступні в API міграції | Недоступні в API міграції |

::: note Створено за публічною документацією
Це створено за публічною документацією кожного постачальника й не запускалося зі справжнім обліковим записом. Якщо ви маєте обліковий запис, [посібник із переходу](/info/work-move-from-render-api.html#check-it-on-your-own-account) містить короткий перелік перевірок.
:::

Ви можете перенести один шаблон, а решту залишити там, де вони є. [Вихід із Lolly](/info/work-move-from-render-api.html#leave-lolly-too) так само відкритий: інструменти є звичайними файлами, а CLI рендерить їх без сервера.

## Хто запускає сервіс

З Lolly окрема людина рендерить локально або команда запускає Lolly Work на власній інфраструктурі. Серверне завдання надсилає свої вхідні дані та потрібні ресурси до цього екземпляра. Шлях на пристрої цього не робить.

Bannerbear і Placid є торговельними марками своїх власників. Ця сторінка описує, де можливості продуктів збігаються, за їхньою публічною документацією й не пов'язана з жодним із них.
