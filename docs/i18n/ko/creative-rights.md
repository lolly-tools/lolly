# 창작물의 권리와 출처 표시

라이선스 전문가가 되지 않아도, 작품을 만든 사람을 슬그머니 지우지 않아도 다른 사람이 만든 좋은 작품을 사용할 수 있어야 해요. 그래서 Lolly는 그리는 모든 작품의 출처를 보관하고, 기록된 라이선스를 읽고, 실제 사용 방식에 그 라이선스가 무엇을 요구하는지 파악해요. 그런 다음 프로그램이 할 수 있는 부분은 처리하고 사용자만 할 수 있는 부분은 알려줘요.

::: note 이 내용은 법률 자문이 아니에요
사용자 프로젝트에 대한 판정도 아니에요. Lolly는 사실을 기록하고, 라이선스의 법률 원문에서 읽어 낸 소수의 규칙을 적용하며, 그 과정을 보여줘요. 조건이 있는 라이선스는 정상적이고 허용되는 선택이에요. 결함이 있는 에셋으로 표시하지 않아요.
:::

## 어디서 마주치나요

이모지 세트가 일상적인 사례예요. Twemoji는 CC BY 4.0이므로 이모지가 있는 제목을 내보내면 아트워크의 출처 표시가 함께 담겨요. OpenMoji의 두 세트는 모두 CC BY-SA 4.0이므로 글리프 하나를 브랜드에 맞춰 다른 색으로 바꾸면 개작에 해당하고, 그 개작물을 공유할 때는 호환되는 라이선스를 한 번 선택해야 해요. Fluent(MIT), Noto와 Blobmoji(둘 다 Apache 2.0)도 등록돼 있으며, 각각 검토된 해당 라이선스에 따라 처리돼요.

세트 선택은 절대 차단되지 않으며, 세트 컨트롤은 선택하는 곳에서 라이선스를 보여줘요. 카탈로그 일러스트, LUT, 글꼴, 그 밖의 기록된 작품에도 같은 규칙이 적용돼요.

## 구분해서 보관하는 세 가지 사실

"CC BY 4.0", "이 용도에는 출처 표시가 필요해요", "방금 다운로드한 파일에 출처 표시가 들어 있어요"는 서로 다른 세 가지 진술이며, Lolly는 이를 구분해요.

- **근거**는 출처가 밝힌 내용을 발견한 그대로, 누가 말했고 어디에서 읽었는지와 함께 기록한 것이에요. 나중에 가져온 내용이 이전 기록을 덮어쓰는 일은 없어요.
- **의무**는 검토된 규칙이 하나의 용도, 하나의 전달 경로, 하나의 대상에 대해 그 근거를 해석한 결과예요.
- **전달**은 완성된 바이트를 다시 읽어 실제로 무엇이 담겼는지 확인한 결과예요. Lolly는 리더가 전달된 파일에서 출처 표시를 찾은 뒤에만 출처 표시가 포함됐다고 말해요.

![기록된 출처 근거와 선택한 용도를 검토된 규칙에 입력해요. 내보내기에서 출처 표시를 준비한 다음, 전달 확인이 완성된 바이트를 읽어 어떤 출처 표시를 찾았고 무엇이 더 필요한지 보고해요.](/info/diagrams/concepts/rights-evidence-to-delivery.svg)

## 표시되는 내용과 해야 할 일

내보내기 패널, Lolly Verify, 명령줄, 기계용 결과에 같은 문구가 표시돼요. 아래는 대략 자주 마주치는 순서예요.

| 표시되는 내용 | 의미 |
|---|---|
| 출처 표시가 포함될 예정이에요. | 출처 표시가 준비됐고 경로가 이를 담을 수 있어요. 아직 아무것도 쓰지 않았으므로 성공 메시지는 아니에요. |
| 이 파일의 메타데이터에 출처 표시가 포함돼 있어요. | 전달된 바이트를 다시 읽었고, 자격 증명을 검증했으며, 필요한 모든 출처를 자격 증명에서 찾았어요. |
| 다운로드 패키지에 출처 표시와 자격 증명이 들어 있어요. | 출처 표시는 결과물의 동반 파일로 함께 전달돼요. 다른 사람에게 전달할 때 함께 보관하세요. |
| 이 개작물을 공유하려면 호환되는 라이선스가 필요해요. | ShareAlike 출처가 변경됐고, 결과를 개인 용도 외의 곳에 사용하려 해요. 선택은 한 번이면 되고, 배치할 때마다 대화상자가 뜨지는 않아요. |
| 이 출처 표시를 게시물 설명에 추가하세요. | 선택한 경로에는 자격 증명도 읽을 수 있는 출처 표시도 담기지 않으므로 직접 출처 표시 텍스트를 붙여넣어야 해요. |
| 기록된 CC0 기증 선언에 따르면 출처 표시 의무가 없어요. | 이 기증 선언은 아무것도 요구하지 않아요. 그래도 예의상 쓸 수 있는 출처 표시를 제공해요. |
| 출처의 라이선스가 기록되지 않았어요. | 이 출처에 대해 기록된 것이 없어요. 채워야 할 빈틈이지 작품에 불리한 판단이 아니에요. 작품을 자유롭게 전달해도 된다는 근거는 절대 아니에요. |
| 조건이 기록됐지만 아직 해석되지 않았어요. | 식별자를 인식했고 조건을 나열했지만, 여기에는 이를 읽는 규칙이 없어요. 자동 허용도 자동 금지도 아니에요. |
| 두 라이선스 선언이 서로 달라요. | 두 기록이 서로 다른 라이선스를 명시하며, 어느 이용 허락이 적용되는지는 아직 정해지지 않았어요. |
| 전달된 파일에 출처 표시가 없어요. | 출처 표시를 넣겠다고 했지만 다시 읽어도 찾지 못했고, 파일은 그대로 사용자에게 있어요. 다시 내보내거나 출처 표시 텍스트를 직접 사용하세요. |

Lolly는 작품에 권리 주장이 없거나 법적으로 안전하게 사용할 수 있다고 말하지 않으며, 제품 어디에도 모든 것을 판단하는 단일한 녹색 라이선스 배지가 없어요. 어느 프로그램도 이 두 가지를 확인할 수 없어요.

## 사용자에게 남는 것

- **라이선스 선택은 사용자 몫이에요.** 파일에 대한 권리를 선언할 때 예전에는 하나였던 세 상태를 구분해요. 공개 라이선스 미선언, 명시적인 모든 권리 보유 고지, 실제 공개 라이선스 이용 허락이에요. Lolly는 마지막 두 경우에만 권리 문구를 쓰며, 프로필을 근거로 쓰지는 않아요.
- **작품의 라이선스를 대신 바꾸지 않아요.** 출처의 조건과 사용자 결과물의 선언은 별도의 기록이에요. ShareAlike 조건은 그 조건이 규율하는 개작물에 적용되며, 사용자가 만든 나머지 모든 것에 자동으로 적용되지는 않아요.
- **개인 작업은 계속 사용할 수 있어요.** 공유할 때 적용되는 조건은 공유를 고려할 때 제시해요. 어떤 내용도 가져오기 금지가 되지 않으며, 라이선스 설문이 사용자와 자신의 파일 사이를 가로막지 않아요.
- **결정은 그 결정의 근거가 된 사실과 함께 기억돼요.** 기록하는 모든 선택에는 대상 작품, 용도, 경로, 수신 대상의 지문이 찍혀요. 세트, 처리 방식, 형식, 수신 대상을 바꾸면 다시 물어요. 경고를 닫는다고 출처 표시를 전달하거나 이용을 허락할 수는 없으므로, 일괄적인 "라이선스 무시" 스위치는 없어요.
- **사용자 정보는 제삼자의 출처 표시와 분리돼요.** 자신의 개인 메타데이터를 제거해도 출처에 표시된 아티스트는 제거되지 않으며, 필수 출처 표시를 핑계로 사용자 연락처를 내보내는 일은 없어요.

## 각 위치에서 Lolly가 하는 일

- **카탈로그에서.** 작품의 정보 화면에는 출처와 창작자, 정식 라이선스 이름과 그 아래에 보존된 원래 표기, 기록된 경우 복사 가능한 출처 표시, 사용 시 요구 사항을 알리는 한 줄이 표시돼요. 타일은 요구 사항을 명시하며, 내보내기가 완료됐다고 주장하지 않아요.
- **내보내기 패널에서.** 렌더링에 기록된 작품이 사용되면 Content protection 안에 Source credits 카드가 나타나고, 내보낼 작품에 선택하는 Licence 옆에 표시돼요. 상태, Details 안의 출처 표시 텍스트, Copy credit 버튼, 결정이 필요할 때의 인라인 카드를 보여줘요. 결정을 요구하는 대화상자가 작업을 막지는 않아요. 할 일이 남아 있어도 다운로드는 진행돼요.
- **파일에서.** 기록된 작품을 배치한 내보내기는 서로 다른 작품마다 Content Credentials 출처 구성 요소 하나를 기록해요. 이는 공개 주소의 원본 바이트에 연결되고, 창작자, 라이선스와 그 링크, 출처, 개정 버전, 변경 사항을 담아요. Lolly는 관찰한 내용에 서명해요. 원작 아티스트를 대신해 주장에 서명하지 않으며, Lolly Verify는 둘 중 어느 일이 있었는지 알려줘요.
- **패키지에서.** `.lottie` 애니메이션처럼 자격 증명을 담을 수 없는 다운로드는 패키지 안에 `CREDITS.txt`와 `credits.json`으로 출처 표시를 담아요. 이 파일들은 작성 후 다시 읽으며, 서명된 자격 증명이라고 주장하지 않아요.
- **작성 후에.** 출처 표시가 포함됐다고 말하기 전에 전달된 바이트를 다시 읽어요. 검증에 실패한 자격 증명은 출처 표시가 전달된 것으로 보지 않아요.
- **편집 가능한 `.lolly` 파일에서.** 검토된 라이선스에 출처 재전달 허락이 기록돼 있거나, 행에 소유자 자신의 조건이 담겨 있거나, 작품의 권리에 대해 라이선스, 권리 기록, 출처 표시가 전혀 없으면 바이트가 함께 전달돼요. 마지막 경우에는 보내는 사람이 기록된 라이선스 없이 전달되는 작품을 확인하고, `CREDITS.txt`는 파일을 여는 사람에게 재사용 전에 조건을 확인하라고 안내해요. 기록됐지만 아직 해석되지 않은 라이선스의 작품은 제외되며, 라이선스 없이 권리자만 기록된 작품이나 카탈로그 기록을 읽을 수 없었던 작품도 제외돼요. 제외된 콘텐츠도 의도적으로 포함할 수 있고, 출처 표시 파일은 그것이 사용자의 선택이었다고 기록해요. 팩의 `CREDITS.txt`는 무엇이 어떤 라이선스로 전달됐는지, 무엇이 어떤 이유로 제외됐는지 나열해요.
- **Lolly Verify에서.** Sources 패널은 파일에 기록된 모든 출처를 계산된 요약, 출처 표시, Copy credit 버튼, 요청할 때만 열리는 Open source 링크, 명시된 검사 범위의 한계와 함께 나열해요. Check for this use 질문은 용도를 선택할 때만 나타나며, 답하기 위해 외부에서 아무것도 가져오지 않아요.
- **메타데이터를 제거할 때.** 제거하면 파일에서 빠지는 출처 표시 수를 알려주고, 출처 표시 텍스트와 출처 표시를 별도 파일에 담은 정리된 파일을 제공해요. 제거된 바이트에 다시 스탬프를 찍는 일은 없어요.

**소유자 자신의 표장.** 소유자가 로고를 공개 라이선스로 제공하는 일은 드물어요. 권리 기록에 `own-work`와 소유자, 조건이 명시된 행은 `.lolly` 파일과 [브랜드 페이지](/info/brand-page.html#publish-your-own-marks)에 담겨 전달될 수 있어요. "소유자가 공개함, 공개 라이선스는 아님"으로 전달되며, 조건이 파일 옆에 놓여요. 이는 카탈로그에 명시된 내용을 읽은 것이에요. Lolly는 표장의 소유자를 확인하지 않아요. 소유자가 없거나 조건이 비어 있거나 선언이 없는 기록은 계속 제외되며, 이런 기록이 없는 다른 사람의 표장도 제외돼요.

**기록하지만 해석하지는 않아요.** CC BY-NC, CC BY-ND, NC-SA 및 NC-ND 조합은 인식되고 조건이 나열되지만, 여기에는 이를 읽는 규칙이 없어요. 조건을 명시하는 한 줄과 함께 `licence.unknown`으로 보고돼요. 상업적 맥락은 가격이나 계정만으로 알 수 없으며, 각 조합의 원문은 규칙이 읽기 전에 별도 검토가 필요해요.

허락을 뜻하지 않는 세 가지 정직한 답변이 더 있어요.

- `LicenseRef-` 식별자는 그대로 반환돼요. 저장된 정의를 가리키며, 표기만으로 독점 라이선스가 되지는 않아요.
- 아무것도 인식하지 못하는 선언은 파싱되지 않은 상태로 반환되며, 원래 텍스트가 보존돼요.
- `A OR B`는 권리자가 제시한 선택이므로 모든 대안이 반환되고 어느 것도 선택되지 않아요. `A AND B`는 누적 적용이며, 이 규칙은 두 프로필을 함께 읽는 대신 이를 기록해요.
:::

::: details 명령줄과 MCP에서
평가 결과에 필수 출처 표시나 문제가 있으면 렌더링은 표준 오류에 `Rights:` 블록을 출력해요. 이 블록에는 상태, 문제별 `code - summary` 한 줄, 전달된 파일을 다시 읽은 결과, 붙여넣을 출처 표시 텍스트가 담겨요.

```
Rights: actions-required
  licence.adaptation-choice - If you share this adaptation, it needs a compatible licence.
  Credential intact. It records 1 source. The exporter recorded it; the source did not sign a credential of its own.
  Credits included in this file's metadata.
  "water wave (OpenMoji Color 17.0.0)" by Vanessa Boutzikoudi (OpenMoji), CC BY-SA 4.0 https://creativecommons.org/licenses/by-sa/4.0/, source https://raw.githubusercontent.com/hfg-gmuend/openmoji/f9fc506a3f913be9897ab0181d611d4c910a4104/color/svg/1F30A.svg, changes: recoloured.
```

여기서는 출처 표시가 파일에 있지만, 파일을 공유하기 전에 라이선스를 결정해야 해요.

| 상태 | 의미 | 종료 코드 |
|---|---|---|
| `ready` | 사람이 처리할 일이 없어요. | 0 |
| `actions-required` | 파일을 공유하기 전에 결정할 일이 남아 있어요. 파일은 그대로 작성돼요. | 4 |
| `use-not-covered` | 검토된 규칙에 따르면 라이선스가 이 용도를 허용하지 않아요. | 4 |
| `unknown` | 문제는 누락뿐이에요. 라이선스가 기록되지 않았거나 조건이 해석되지 않았어요. | 0 |
| `delivery-failed` | 평가가 아니라 영수증으로만 설정돼요. 전달된 바이트에서 약속한 출처 표시를 찾지 못했어요. 내보내기 패널에는 이 상태가 표시되고, CLI는 대신 다시 읽은 결과 줄에 같은 사실을 보고해요. | 출력되지 않음 |

종료 코드 4는 보호 검사가 거부할 때 이 CLI가 이미 반환하는 코드예요. 어떤 러너에서도 라이선스 결정은 기다리고 있으므로, "다른 러너에서 재시도"를 뜻하는 3은 쓰지 않아요.

`--rights=private`는 이 렌더링 결과를 누구에게도 전달하지 않는다는 뜻이에요. 블록은 여전히 출력되고 출처 표시도 복사할 수 있어요. 공유할 때 적용되는 조건만 해제되며, 전달했다는 주장은 기록되지 않아요. 조건을 무시하는 플래그는 없어요. `--rights=ignore`는 사용법 오류예요.

문제 코드는 번역된 문구와 무관하게 고정돼 있고 기계가 읽을 수 있어요. `attribution.source-missing`, `attribution.delivery-missing`, `licence.adaptation-choice`, `licence.use-not-covered`, `licence.grant-conflict`, `licence.unknown`, `source.redistribution-unknown`, `credential.ingredient-missing`예요.

MCP에서 `lolly_verify`는 요약, 기록된 출처별 한 행, 명시된 한계를 담은 `rights` 페이로드를 반환해요. 브라우저 없이 실행되는 `lolly_render`는 `status`, `issues`, `credits`, `fingerprint`와 바이트를 다시 읽어 측정한 `creditsInFile` 플래그를 반환해요.
:::

::: details 규칙이 있는 곳
엔진 모듈 다섯 개는 모두 순수해요. 네트워크, 시계, 파일시스템을 사용하지 않아요. 규칙 데이터는 버전이 지정돼 저장소에 있으며, 외부에서 가져오지 않아요.

| 모듈 | 담긴 내용 |
|---|---|
| `engine/src/rights-profiles.ts` | 식별자 표, 최소한의 SPDX 표현식 리더, 인용을 포함한 검토된 프로필, 출처 표시에 출력할 수 있는 링크에 대한 단일 규칙이에요. |
| `engine/src/rights-evaluate.ts` | 분류, 문제, 출처 표시 계획, 지문이에요. 결정적으로 동작하므로 같은 사실은 순서가 달라도 같은 답을 내요. |
| `engine/src/rights-attribution.ts` | 읽을 수 있는 출처 표시, 동반 파일, 출처 구성 요소, 작성 후 측정한 영수증이에요. |
| `engine/src/rights-companion.ts` | 패키지 출처 표시(ZIP 기반 다운로드 안의 `CREDITS.txt`와 `credits.json`)를 다시 읽는 기능이에요. 서명된 자격 증명이라고 주장하지 않고 출처 표시를 확인해요. |
| `engine/src/rights-report.ts` | 검증된 자격 증명을 다시 읽어 Lolly Verify가 묻는 세 질문으로 보여줘요. |

`tests/fixtures/rights/`의 기대값 파일은 평가기의 출력이 아니라 라이선스 원문을 바탕으로 작성됐으며, 해당 README는 각 기대값의 근거 조항을 인용해요.
:::

## 아직 하지 못하는 것

- **어떤 목적지도 확인되지 않아요.** Lolly는 캡션을 준비해요. 커넥터가 요청을 받아들였다고 해서 출처 표시가 독자에게 도달했다는 증거가 되지는 않으며, 이후 업로드, 스크린샷, 트랜스코딩에서도 숨겨진 메타데이터가 유지된다고 약속하지 않아요.
- **계획으로 네이티브 메타데이터의 출처 표시 필드를 작성하지 않아요.** 출처 표시는 Content Credentials와 읽을 수 있는 텍스트로 전달돼요. IPTC와 XMP의 출처별 표시 필드는 아직 출처 표시 계획으로 채우지 않아요.
- **수정과 철회 기능은 구현되지 않았어요.** 기록된 작품에 누락된 창작자나 로컬 수정 사항을 추가하거나 기록을 철회하는 인터페이스가 없어요.
- **연결된 제공자 기능은 구현되지 않았어요.** 구매한 스톡, 별도 허락, 제공자 계정에는 가져오기 경로가 없으므로, 그 이용 허락은 사용자 자신의 진술로만 기록할 수 있어요.
- **조직 정책은 이 결과와 결합되지 않아요.** 현재 내보내기 정책과 라이선스 조건은 별개이며, 조직의 승인은 권리자의 허락이 아니에요.
- **여러 전달 경로는 아직 이 처리 경로에 포함되지 않아요.** 카탈로그 원본 다운로드, 일괄 ZIP, Send, Copy image는 아직 이 출처 표시를 평가하거나 담지 않아요. 자르기, 색보정, 프레임을 씌운 사본, Download as 변환, 동영상 편집은 처리해요. 라이선스가 기록돼 있고 자체 Content Credentials가 없는 출처는 출처 표시와 함께 서명되지 않은 출처 구성 요소로 전달되고, LUT의 출처 표시는 사진의 라이선스가 아니라 자체 라이선스에 따라 이뤄지며, 출처가 요구하는 출처 표시를 담을 수 없는 파일은 저장되지 않아요. 이 파일들을 다시 읽는 기능은 아직 없으므로 출처 표시는 작성된 것이지 확인된 것은 아니에요. Retouch, 단일 이미지 배경 제거와 업스케일링, 오디오 추출은 출처 자체의 자격 증명만 유지해요.
