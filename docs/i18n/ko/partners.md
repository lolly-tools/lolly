# 파트너와 작업하기

많은 작품에는 두 브랜드가 함께 들어가요. 행사 포스터의 후원사 로고, 제조사 이름으로 내놓는 리셀러의 제안, 공동 발표, 공급업체와 함께 작성한 사례 연구 등이에요. 이 페이지는 양쪽 모두를 위한 안내예요.

이 페이지에서 **주도 브랜드**는 작품을 만드는 데 쓰는 디자인 시스템의 브랜드이고, **파트너**는 작품에 들어가는 다른 브랜드예요. 어느 쪽이든 작품을 만들 수 있어요. [브랜드 구조](/info/brand-architectures.html#co-branding)에서 공동 브랜딩을 다른 브랜드 구성 방식과 비교해요.

<!--i:eti-info-->
## 현재 Lolly가 두 브랜드를 다루는 방식

- **작품마다 하나의 디자인 시스템으로 그려요.** 주도 브랜드의 색상, 서체, 조직 규칙이 적용돼요. 파트너 로고는 아트워크로 들어가요. Assets의 그림이거나 디자인 시스템에 보관된 맞춤 로고예요.
- **브랜드는 파일로 전달돼요.** 디자인 시스템 파일(`.lolly`)에는 토큰, 글꼴, 로고가 담겨요. **Share with rules**로 만든 재사용 가능한 도구에는 허용한 입력이 있는 완성된 레이아웃 하나가 담겨요. 브랜드 스킬은 별도 파일로 전달돼요.
- **브랜드에도 주소를 둘 수 있어요.** [브랜드 페이지](/info/brand-page.html)는 파트너가 읽을 로고, 색상, 서체, 규칙과 파트너의 도구용 토큰과 스킬을 게시해요.
- **Lolly는 주도 브랜드의 규칙만 검사해요.** Lolly는 보호 여백이나 최소 크기 같은 파트너의 규칙을 모르므로, 파트너의 가이드라인과 대조해 확인하세요. Lolly Work 파트너 프로그램에서는 회사의 파트너 키트에 해당 규칙이 담기며, Lolly Design이 키트에 맞춰 회사 로고를 검사해요.
- **파트너 프로그램 전체는 Lolly Work에서 운영해요.** 리셀러, 유통업체, 다른 파트너가 내 Lolly Work에서 내 브랜드로 작품을 만들 때, 파트너 프로그램은 각 파트너 회사에 내가 선택한 도구, 파일, 템플릿만 제공해요. 프로그램은 회사의 로고와 세부 정보를 보관하고, 이를 내 템플릿에 채워 넣으며, 각 파일에 회사를 기록해요. [파트너 프로그램 운영하기](/info/manage/run-a-partner-programme.html)는 이를 운영하는 팀을 위한 가이드예요.

## 파트너와 브랜드 공유하기

### 보낼 것 고르기

| 보낼 것 | 방법 | 파트너가 받는 것 | 적합한 경우 |
| --- | --- | --- | --- |
| 디자인 시스템 파일 | [Lolly Design System Setup](/info/brand-studio.html#move-a-brand-between-devices) 상단 막대의 **Export** | 전환해서 쓸 수 있는 디자인 시스템에 담긴 내 토큰, 글꼴, 로고, 테마 환경설정 | 내 브랜드로 많은 작품을 만드는 파트너 |
| 재사용 가능한 도구 | Lolly Design의 **Share with rules**([규칙과 함께 디자인 공유하기](/info/create-a-tool.html)) | 파트너의 이름과 로고처럼 허용한 입력이 있는 완성된 레이아웃 하나. 파일에 해석된 색상, 글꼴, 이미지가 담기므로 파트너의 디자인 시스템이 고정된 아트워크의 스타일을 바꿀 수 없어요 | 각 파트너가 내용을 채우는 공동 브랜드 전단지, 배지, 배너 |
| 브랜드 스킬 | **Skills** 화면의 **Download skill (.zip)** 또는 **Copy as one file** | 파트너의 직원과 에이전트가 쓸 내 문서화된 기준 | 에이전트가 작업의 일부를 맡는 위 두 경우 |
| 브랜드 페이지 | Lolly Design System Setup의 **Publish a brand page** 또는 `lolly system publish`로 호스팅할 폴더를 만들어요([브랜드 페이지](/info/brand-page.html)) | 하나의 주소에 있는 내 현재 로고, 색상, 서체, 규칙과 파트너의 도구용 토큰과 스킬. 로고와 글꼴 파일은 권한이 허용할 때 표시되고, 제외된 항목은 페이지에 나열돼요 | 파일을 보내지 않는 사람과 공유할 때 |
| 토큰 | 스튜디오의 **More** 메뉴에 있는 **Tokens (.json)** | 글꼴과 로고 없는 순수 디자인 토큰 문서 | 파트너 자체의 디자인 도구나 빌드 |

::: warning 파일에 글꼴도 함께 담겨요
추가한 글꼴은 디자인 시스템 파일에 함께 담기므로, 라이선스가 해당 파일의 전달을 허용하는지 확인하세요.
:::

재사용 가능한 도구는 라이선스가 포함을 제한하는 이미지를 넣기 전에 확인을 요청해요([미리보고 공유하기](/info/create-a-tool.html#preview-and-share)).

### 공동 브랜드 템플릿 만들기

재사용 가능한 도구는 모든 파트너의 작업물이 정해 둔 레이아웃을 따르게 해요. 파트너는 허용한 것만 바꿀 수 있어요.

1. Lolly Design에서 자신의 디자인 시스템으로 작업물을 만드세요. 파트너의 로고를 넣을 곳에 이미지 박스를 그리고, 레이아웃에 필요한 여백을 박스 주위에 남겨 두세요.
2. File menu에서 **Share with rules**를 선택하세요. 이미지 박스를 선택하고 **Make editable**을 선택하세요. 박스의 **Rules**에서 교체용 이미지 업로드를 허용하고, 최소 픽셀 크기와 허용할 업로드 형식(가능하면 SVG)을 설정하세요. 박스의 **Image fit**을 **Contain (fit inside)**으로 설정하면 가로로 넓거나 세로로 긴 로고도 박스 안에 들어가요.
3. 파트너의 이름이나 제안 내용도 글자 수 제한을 두고 편집 가능하게 하세요.
4. **Preview**를 누르고 아주 넓은 로고, 아주 긴 로고, 긴 이름을 넣어 보세요.
5. **Share .lolly**를 선택하고, 밝은 배경용 풀 컬러 가로형 로고처럼 어떤 버전의 로고를 업로드해야 하는지 파트너를 위한 안내를 작성하세요.

파트너는 파일을 Lolly에 끌어다 놓고, 신뢰 여부를 묻는 안내를 검토하고, 입력란을 채운 뒤 허용한 형식으로 다운로드해요([완성된 도구 사용하기](/info/create-a-tool.html#use-the-finished-tool)). Lolly는 그려 둔 박스 안에 로고를 유지해요. Lolly는 파트너의 최소 여백 규칙을 읽지 않으므로, 로고의 여백은 박스 주위에 남겨 둔 공간뿐이에요.

### 에이전트에게 브랜드 스킬 전달하기

스킬은 사람과 에이전트를 안내해요. Lolly는 조직의 작업 규칙을 검사해요.

- Lolly Design System Setup에서 **Skills** 룸(`#/start?area=skills`)을 열고, 스킬을 고른 뒤 **Download skill (.zip)**을 누르세요. 폴더의 카탈로그 링크는 자신의 Lolly를 가리키며, `lolly.json`에는 사본을 가져온 곳이 기록돼요. **Copy as one file**은 채팅 창에 쓸 수 있도록 같은 텍스트를 클립보드에 넣어요.
- 터미널에서 `lolly system skill <name> --into=<dir>`를 실행하면 같은 폴더가 생성돼요([로컬 에이전트 도구용 폴더로 받기](/info/brand-skills.html#in-a-folder-for-a-local-agent-tool)).
- 자신의 기기에는 `internal`로 표시된 스킬과 `public` 스킬이 모두 나열되므로, 보낼 스킬을 고르세요([공개 스킬과 내부 스킬](/info/brand-skills.html#public-and-internal-skills)).
- 자체 스킬이 없는 디자인 시스템에서는 Lolly가 토큰과 조직의 작업 규칙으로 기본 스킬을 작성하고, 룸에 그 기본 스킬이 나열돼요.
- 사본은 저절로 업데이트되지 않아요. 스킬의 새 개정판을 게시하면 폴더를 다시 보내세요.

## 전달받은 브랜드로 작업하기

디자인 시스템 파일을 받은 파트너를 위한 내용이에요. 주도 브랜드가 자체 Lolly Work에서 파트너 프로그램을 운영한다면 그곳에 로그인하세요. 홈에 회사 카드와 자신에게 공개된 템플릿이 나타나요([파트너에게 보이는 것](/info/manage/run-a-partner-programme.html#what-partners-see)).

1. **파일을 여세요.** 파일을 Lolly에 끌어다 놓거나 **Open**을 누르세요. Lolly Design System Setup의 **Add from…**에서도 파일을 받을 수 있어요. 미리보기는 무엇이든 기록하기 전에 파일에 담긴 내용을 나열해요. 디자인 시스템 파일은 주도 브랜드의 이름으로 별도 디자인 시스템을 추가하고 활성화해요. 자신의 디자인 시스템은 기기에 남아요. 앱을 주도 브랜드의 자체 Lolly에 연결하는 파일이라면 기기 전체에 미치는 영향을 먼저 나열해요. 이런 파일은 [조직에서 Lolly 사용하기](/info/organisation.html)에서 다뤄요.
2. **브랜드를 둘러보세요.** Lolly Design System Setup의 **Board**는 디자인 시스템에 담긴 내용을 보여주고, **Logos**에는 로고가 있으며, **Rules**는 Lolly가 검사하는 조직의 작업 규칙을 나열해요. **Skills**는 Lolly가 토큰과 규칙으로 작성한 기본 스킬을 보여줘요. 주도 브랜드의 자체 스킬은 보내 주는 경우 별도 파일로 받아요.
3. **브랜드를 전환하세요.** **Settings → Preferences → Design systems**는 기기 전체의 디자인 시스템을 바꾸고, **Settings → Design system**에는 전환할 수 있는 커버 목록이 있어요. 전환하기 전에 한 브랜드의 작업물을 마무리하세요.
4. **자신의 로고를 배치하세요.** 로고를 **Assets**에 업로드하면 모든 디자인 시스템에서 쓸 수 있어요. 또는 주도 브랜드의 디자인 시스템에 **사용자 지정 로고**로 추가하면(**Logos** 룸, **Custom marks**) 해당 디자인 시스템 파일에 함께 담겨요. 자물쇠가 표시된 디자인 시스템은 읽기 전용이므로 Assets를 사용하세요. [파트너 로고 배치하기](#place-a-partner-s-mark)에 확인 사항이 있어요.
5. **내보내기 전에 확인하세요.** Lolly Design의 내보내기 패널에 있는 **Before you export** 카드는 주도 브랜드의 작업 규칙에 대한 검사 결과를 레이어별로 나열해요([내보내기 전 확인](/info/design.html#before-you-export)). **Design system** 카드는 파일에 기록되는 디자인 시스템을 보여줘요.
6. **작업물을 돌려보내세요.** 내보낸 파일이나 편집 가능한 디자인을 `.lolly`로 보내세요([작업물 공유하기](/info/using.html#sharing-your-work)). 디자인은 현재 활성화된 디자인 시스템으로 열리므로, 주도 브랜드는 자신의 디자인 시스템이 활성화된 상태에서 받은 디자인을 열어요.

::: note 디자인 시스템 파일은 업데이트되지 않아요
디자인 시스템 파일은 내보낸 날의 브랜드 사본이에요. 사본을 업데이트하는 기능은 없어요.
:::

주도 브랜드가 새 파일을 보내면 같은 방법으로 여세요. 그런 다음 **Settings → Preferences → Design systems**에서 활성화된 디자인 시스템을 확인하고, 이전 사본이 더 이상 필요 없으면 그곳에서 제거하세요.

## 파트너 로고 배치하기

| 방법 | 단계 | 적합한 경우 |
| --- | --- | --- |
| Assets의 이미지 | **Assets**의 업로드 영역에 파일을 끌어다 놓은 뒤 도구의 이미지 필드에서 선택하거나, Lolly Design의 레일 추가 메뉴에서 **Image**를 선택하세요 | 일회성 작업물. 업로드한 파일은 기기에 속하므로 활성화된 디자인 시스템과 관계없이 제공돼요 |
| 사용자 지정 로고 | **Logos** 룸, **Custom marks**: 로고 이름을 입력한 다음 **Choose file…**을 선택하세요 | 자주 함께 작업하는 파트너. 로고는 디자인 시스템에 속하며 해당 파일에 함께 담겨요 |
| 완성된 로고 조합 | 드로잉 도구에서 두 로고를 조합한 뒤 사용자 지정 로고로 추가하세요 | 반복해서 사용하는 "함께" 또는 "협력" 로고 조합 |

::: check 내보내기 전에 로고를 확인하세요
- **올바른 파일.** 파트너가 제공한 파일을 사용하고, SVG가 있다면 SVG를 쓰세요. 웹페이지나 슬라이드에서 복사한 로고는 인쇄하면 흐려져요.
- **배경에 맞는 버전.** 파트너 가이드라인에 있다면 어둡거나 복잡한 배경에는 반전 버전이나 단색 버전을 사용하세요.
- **비율.** 이미지 박스의 **Image fit**을 **Contain (fit inside)**으로 설정하면 로고가 찌그러지지 않아요.
- **여백과 크기.** 파트너 가이드라인에서 요구하는 여백을 로고 주위에 남기고, 로고를 최소 크기보다 크게 유지하세요. Lolly는 둘 다 측정하지 않아요.
- **어느 브랜드가 주도하는지.** 어느 브랜드가 주도하는지에 관한 두 브랜드의 가이드라인에 맞춰 로고 크기를 정하세요.
- **권리.** Lolly는 카탈로그 에셋에 기록된 라이선스를 보여줘요. 직접 업로드한 파일에는 라이선스 기록이 없고 세부 정보에 *Licence not recorded*라고 표시되므로, 파트너 로고 사용 허가는 자신의 기록과 함께 보관하세요([창작물의 권리와 크레딧](/info/creative-rights.html)).
:::

내보낸 파일의 [디자인 시스템 기록](/info/exporting.html#the-design-system-record)은 주도 브랜드의 디자인 시스템과 컬러웨이를 알려줘요. 파트너의 브랜드는 기록하지 않지만, Lolly Work 파트너 프로그램에서는 예외로 작업물이 속한 파트너 회사와 프로그램도 기록해요.

### 각 브랜드의 스킬을 에이전트에게 전달하기

에이전트가 작업할 때는 두 브랜드의 스킬을 그대로 전달하고, 어느 브랜드가 주도하는지 알려주세요. 각 브랜드의 스킬은 자체 이름과 id를 유지해요. Lolly는 두 브랜드의 스킬을 합치거나 어느 브랜드를 우선할지 결정하지 않아요.

## 후원사 및 행사 로고 월

[Lolly Logo Wall](/#/tool/logo-wall) 도구는 후원사 보드, 파트너 슬라이드, 언론용 백월에 쓸 로고를 균일한 격자로 배치해요. 행사에서는 보통 주최 측이 주도 브랜드예요. 주최 측의 디자인 시스템으로 로고 월을 만들고, 각 후원사 로고를 아트워크로 배치해요.

1. Lolly Logo Wall을 열고 **Logos**에 로고를 끌어다 놓으세요. 각 로고에 자체 컨트롤이 생겨요.
2. 각 로고에 "Gold partners" 같은 **Tier**를 지정하세요. 등급은 처음 나타난 순서대로 자체 제목 아래에 전용 행을 가져요. **Tier headings**로 제목을 끌 수 있어요. **Tier sizes**를 **Step down**으로 설정하면 낮은 등급일수록 행마다 로고가 하나씩 더 들어가므로, 높은 등급이 더 크게 보여요. **Presence**와 **Size %**는 해당 등급 안에서 로고 하나를 조정해요.
3. **Balance sizes**를 켜 두세요. Lolly Logo Wall은 시각적 무게에 따라 로고 크기를 정해서, 무거운 로고는 줄이고 가벼운 로고는 키워 각 등급이 균일하게 보이게 해요.
4. **Trim margins**는 각 로고를 아트워크 경계에 맞춰 잘라요. 로고 파일에 소유자가 요구하는 여백이 이미 포함되어 있다면 이 옵션을 끄세요.
5. **Remove white backgrounds**는 슬라이드에서 복사한 로고에 흔히 딸려 오는 흰색 박스를 제거해요.
6. **Layout**에서 **Columns**, 간격, 패딩을 설정하세요. **Background**는 디자인 시스템의 표면 색상으로 시작해요.
7. 단색 로고 월을 만들려면 **Render all as vector**를 켜고 **Ink colour**를 고르거나, 로고 하나의 **Filter**를 **Greyscale**로 설정하세요. 각 후원사 가이드라인이 허용하는 경우에만 단색 버전을 사용하세요.
8. 언론용 백월이라면 **Step & repeat**에서 **Grid**, **Brick**, **Checker** 중 하나를 고르고 **Rows** 수를 설정하세요.

로고 월을 PNG, SVG, PDF 또는 인쇄용 CMYK PDF로 내보내세요. 내보내기 패널에서 세로로 긴 1080 x 1920 스토리나 A4 페이지처럼 크기와 형태를 바꾸면, 캔버스가 각 행의 로고 수를 줄이거나 늘려 새 형태에 맞게 다시 배치해요. 내보내기 결과는 캔버스와 같아요. 포스터에 로고 월을 넣으려면 Lolly Design의 레일 추가 메뉴에서 **Image**를 선택하고, 프레임을 그린 뒤 선택기의 **Tools** 탭에서 Lolly Logo Wall을 고르세요([디자인 안의 도구](/info/design.html#tools-inside-a-design)). 로고 사이에 캡션을 넣으려면 Lolly Design에서 **Dynamic layout**을 **grid**로 설정해 로고마다 이미지 박스 하나씩 배치하세요([Lolly Design의 레이아웃](/info/design-layout.html#dynamic-layouts)).

터미널에서 `lolly run logo-wall logos/*.png --output=wall.svg`를 실행하면 이미지 폴더로 로고 월을 만들고, `logo`와 `tier` 열이 있는 CSV를 사용하면 등급별 로고 월을 만들어요. SVG와 PNG에는 브라우저가 필요 없어요([등급이 있는 후원사 로고 월](/info/cli-rendering.html#a-sponsor-wall-with-tiers)).

후원사가 [브랜드 페이지](/info/brand-page.html)를 게시했다면, `lolly run logo-wall --logos-from=<address or folder>`가 배경에 맞는 최신 로고를 가져오고 페이지에 있는 사용 안내를 출력해요. 후원사마다 이 플래그를 반복하세요.

Lolly Logo Wall은 후원사의 규칙을 알지 못해요. Tiers와 Presence는 로고 간 상대적인 크기를 정하며 후원사의 최소 크기를 설정하지 않고, 이웃한 로고 사이의 여백을 검사하는 기능도 없어요. 완성된 로고 월을 실제 인쇄하거나 표시할 크기로 놓고 각 후원사 가이드라인에 맞는지 확인하세요.

## Lolly가 아직 하지 못하는 것

- 작업물은 하나의 디자인 시스템으로 그려져요. 파트너의 색상, 서체, 규칙은 작업물 안에서 별도 디자인 시스템이 되지 않고, 파트너 로고는 이미지예요.
- Lolly Work 파트너 프로그램 밖에서는 앱이 파트너 규칙을 보관하거나 검사하지 않아요. 여백, 최소 크기, 단색이나 반전처럼 허용된 표현 방식이 여기에 해당해요.
- 파트너 키트는 다른 브랜드의 작업물 안에서 쓰도록 파트너의 로고, 색상, 규칙을 담은 가벼운 패키지이며, Lolly Work 파트너 프로그램을 통해서만 앱에 들어와요. 그 밖의 경우에는 터미널에서 키트 검사를 실행해요. `lolly check --kit=<file>`이 Lolly Design 문서의 파트너 로고를 측정해요([재현 결과 확인하기](/info/cli-decks.html#check-the-recreation)).
- Lolly는 두 로고로 "함께", "협력", "제작" 관계를 나타내는 조합을 생성하지 않아요. 완성된 로고 조합을 사용자 지정 로고로 추가하세요.
- 기기 전체에서 디자인 시스템 하나가 활성화되므로, 두 브랜드를 나란히 열 수 없어요.
- 앱에서 내보낸 디자인 시스템 파일에는 브랜드 스킬이 담기지 않으므로, 스킬은 별도 파일로 보내세요.
- 브랜드 페이지에서 가져온 로고는 해당 행의 이미지일 뿐이고, 행에는 페이지 정보가 남지 않아요. 페이지 게시자를 표시하는 기능이 없으므로 주소를 직접 확인하세요.
- 호스팅된 웹 앱의 Content Security Policy는 지정된 호스트만 허용하므로, 다른 브랜드의 페이지를 가져올 수 없어요. 터미널에서 로고를 가져오거나, 파일을 저장한 뒤 **Assets**에 추가하세요.
