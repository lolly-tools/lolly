# 조직에서 Lolly 사용하기

조직은 자체 Lolly를 운영할 수 있어요. 조직이 선택한 도구와 디자인 시스템을 갖춘 같은 앱이에요. 이 페이지는 접속 방법, 로그인, 로그인한 뒤 달라지는 점을 보여줘요.

::: note 조직에서 받아야 할 것
조직의 Lolly 웹 주소, 또는 조직이 만든 `.lolly` 설정 파일이에요. lolly.tools 자체는 조직에 연결되지 않아요.
:::

## 브라우저에서

조직이 알려준 주소를 열어요. 페이지에서 로그인하라고 하면 **Sign in**을 누르고 열리는 로그인 페이지를 따라가세요. 그 후에는 조직의 도구와 디자인 시스템을 갖춘 평범한 Lolly처럼 동작해요.

lolly.tools에서 시작할 수도 있어요. **Settings**를 열고 **Lolly instance** 카드에서 **Open a workspace**를 누른 뒤 주소를 입력하고 **Open this instance**를 누르세요. 브라우저는 lolly.tools에서 다른 Lolly의 도구를 불러올 수 없으므로 조직 자체 주소로 이동해요.

## 데스크톱 또는 모바일 앱에서

앱은 번들된 도구로 시작해요. 연결하려면 **Settings**를 열고 **Lolly instance** 카드에서 **Change**를 누르세요. 시트가 **Where should Lolly get its tools?**라고 물어요.

1. **Lolly 인스턴스에 연결**을 고르세요.
2. 조직의 웹 주소를 입력하고 **확인하고 연결하기**를 누르세요.
3. **이 인스턴스 사용하기**를 누르세요. 다음 화면인 **데이터 가져오기 (선택 사항)**은 Lolly 백업에서 저장된 작업을 옮겨 와요. 없다면 **건너뛰기**를 누르세요.
4. 앱이 요청하면 로그인하세요.

연결된 인스턴스의 도구는 앱 자체의 도구와 같은 신뢰 수준으로 실행되므로, 신뢰하는 인스턴스에만 연결하세요. 조직에 따라서는 대신 앱을 대신 연결해 주는 `.lolly` 설정 파일을 보내올 수도 있어요.

나중에 전환하려면 **Change**를 다시 누르거나 같은 카드의 **Leave**를 사용하세요.

### 코드로 로그인하기

데스크톱과 모바일 앱에서는 조직의 Lolly가 코드 로그인을 지원하면 로그인 화면에 짧은 코드도 제공돼요. **Open sign-in in browser**를 누르고 그곳에서 로그인해 코드를 승인하세요. 또는 이미 로그인한 휴대폰이나 컴퓨터에서 표시된 주소를 열고 코드를 입력하세요. 코드는 약 10분간 유지돼요.

## 거기서 달라지는 점

- **일부 컨트롤은 미리 설정돼 있어요.** 조직이 관리하는 컨트롤에는 **Managed by**와 조직 이름, 또는 **Managed by your organisation**이 표시돼요. 고정된 컨트롤은 바꿀 수 없고, 메뉴는 선택지 일부만 제공할 수 있으며, **Set by**로 시작하는 줄은 어떤 규칙이 왜 적용되는지 알려줄 수 있어요. 일부 컨트롤은 아예 표시되지 않아요.
- **일부 디자인 시스템은 잠겨 있어요.** 조직이 제공하는 디자인 시스템에는 잠금이 표시되고 읽기 전용으로 유지돼요. 변경을 시험하려면 **Settings → Preferences → Design systems**에서 편집 가능한 사본을 만드세요.
- **조직의 도구만 나열돼요.** 조직이 제공하지 않는 도구는 전혀 표시되지 않아요.
- **공유 프로젝트.** 조직이 프로젝트를 공유하면 **Projects**에 **Team projects** 타일이 표시돼요. 이 세션은 조직의 서버에 있어요. 하나를 열어 작업하거나, 가능하면 **Share**에서 [업무 collab](/info/collaborate.html#work-collabs-with-lolly-work-optional)을 시작하세요.
- **일부 내보내기는 승인이 필요할 수 있어요.** 조직이 승인을 요구하는 곳에서는 **Request approval**이 **Download**를 대신하며, 도구가 제공하는 형식이 줄어들 수 있어요.

### 어디에 무엇이 남는가

::: cols
## 이 기기

- 직접 저장한 것(단, [Sync](/info/sync.html)를 켠 경우 제외)
- 직접 만든 디자인 시스템
- 만들고 다운로드한 모든 것

## 조직의 서버

- 로그인 신원과 기기 정보
- 팀 프로젝트, 공유 세션, 업무 collab의 실시간 편집
- 공유 라이브러리에 업로드한 에셋
- 승인 요청과 승인된 전달
- 조직이 켠 경우 사용 이벤트
:::

[개인정보](/info/privacy.html#organisation-services-with-lolly-work)에서 서버가 저장하는 것과 그 데이터를 관리하는 주체를 나열해요.

## Lolly Work가 더하는 것

조직의 서버는 같은 오픈 소스 프로젝트의 조직용 소프트웨어인 **Lolly Work**를 실행해요. 혼자 사용할 때는 앱에 업무 계정도 Lolly Work도 필요하지 않아요.

::: details Lolly Work가 더할 수 있는 것
조직이 Lolly와 함께 [Lolly Work](https://github.com/lolly-tools/lolly-work)를 호스팅하며 켤 기능을 선택해요.

- **로그인과 접근.** 조직 싱글 사인온, 그룹 기반 권한, 관리형 프로필 필드. 관리자는 SCIM으로 계정을 프로비저닝하고 비활성화할 수 있어요.
- **공유 작업.** 팀 프로젝트, 공유 세션, 조직의 서버를 통한 실시간 편집이 가능한 [업무 collab](/info/collaborate.html#work-collabs-with-lolly-work-optional).
- **공유 에셋 라이브러리.** 접근 규칙, 버전, 검토가 있는 업로드된 에셋, 컬렉션, 연결된 라이브러리.
- **검토와 전달.** 승인 단계, 만료 또는 폐기가 가능한 관리형 링크, 조직이 허용한 목적지로의 전달.
- **관리.** 인스턴스의 원격 측정 정책에 따른 사용량 보고와 관리되는 동작의 감사 기록.

서비스를 설정하는 경우 [배포](/info/deployment.html#organisation-services-with-lolly-work)부터 시작하세요. [lolly.work](https://lolly.work)의 공개 데모는 샌드박스이므로, 보관해야 하는 작업에는 조직 자체 주소를 사용하세요.
:::

## 나가기

**Settings**의 **Lolly instance** 카드에서 **Leave**를 누르면 조직의 디자인 시스템, 도구, 카탈로그가 제거돼요. 직접 만든 작업물은 남아요. 조직의 도구로 만든 것은 다시 연결하기 전까지 열리지 않아요.

조직에 저장한 것은 접근 및 보관 정책에 따라 조직에 남아요. 나가거나 이 기기를 지워도 서버의 사본은 삭제되지 않아요. 조직 자체 주소의 브라우저에서는 나갈 것이 없으니, 대신 다른 주소를 여세요.

## 누구에게 물어봐야 할까

무엇이 조직의 서버에 전달되는지, 누가 조직의 공유 프로젝트를 볼 수 있는지, 어떤 설정이 고정되어 있는지는 조직이 정해요. 조직의 Lolly를 운영하는 사람에게 물어보세요. [프라이버시](/info/privacy.html)에는 Lolly 자체가 여러분의 데이터로 무엇을 하는지가 나와 있어요.
