# Lolly 작동 방식

Lolly 도구에는 한 종류의 파일에 대한 규칙이 담겨 있어요. 레이아웃, 서체, 색상, 다른 사람이 바꿀 수 있는 부분이에요. 사용자, 동료, 스크립트, AI 에이전트 중 누가 입력란을 채워도 모든 파일은 그 규칙을 따라요.

<!--i:eti-repeat-->
## 도구 하나에 정한 규칙으로 수많은 파일 만들기

브랜드 규칙은 도구 안에 있어요. 도구를 한 번 설정하면 카드 한 장부터 열두 언어로 된 스프레드시트의 여러 행까지 모든 출력에 같은 서체, 색상, 간격이 적용돼요.

![입력란 하나가 채워진 워드마크 도구: 도구를 만들 때 서체, 색상, 간격이 정해졌어요](/info/shots/aud-rules-in-the-tool.svg)

백 번째 파일을 만드는 사람은 글만 입력해요. 작업물을 어떻게 확인하고 누가 확인할지는 사용자가 정해요. Lolly를 쓰면 확인할 것이 줄고 다음 파일을 더 빠르게 만들 수 있어요.

<!--i:eti-users-->
## 도구를 사용하는 사람들

조직의 세 역할이 하나의 캠페인 카드로 작업해요.

![디자이너가 도구에 규칙을 한 번 정하면 개발자는 스크립트로 실행하고 누구나 입력란을 채울 수 있어요. 두 방식 모두 완성된 파일을 만들어요](/info/diagrams/concepts/asset-relay.svg)

::: timeline
- <!--i:pentool--> **디자이너가 규칙을 정해요.** Lolly Design에서 브랜드의 서체와 색상으로 카드를 배치하고 수정할 수 있는 입력란을 골라요. 이 작업은 한 번만 하므로 이후에는 누구도 카드를 손으로 현지화할 필요가 없어요.
- <!--i:code--> **개발자가 도구를 대규모로 실행해요.** 같은 도구를 명령줄로 야간 스크립트에서 실행해요. 아무도 디자인을 다시 열지 않아도 새 차트나 다른 언어의 새 버전이 만들어져요.
- <!--i:people--> **누구나 입력란을 채워요.** 디자인 교육을 받지 않은 영업 담당자도 네트워크가 없는 비행기 안에서 도구를 열어 내일 회의에 쓸 카드를 만들어요.
:::

개발자가 만든 새 차트는 아래처럼 데이터 문자열과 몇 가지 설정으로 렌더링한 결과예요.

![제목이 있는 누적 영역 차트. 세 데이터 계열이 차가운 색상의 띠로 표시되고, 축과 범례와 제목은 손으로 배치하지 않고 템플릿이 배치해요](/t/url-shot?url=%2F%23%2Ftool%2Fchart%3FchartType%3Darea%26stackMode%3Dstacked%26palette%3Dcool%26heading%3DProduct%2520mix%2520by%2520quarter%26full&width=1440&height=900&dpi=192&waitMs=2600&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-lifecycle-chart)

영업 담당자가 잠깐 만에 작업을 끝낼 수 있는 것은 디자이너의 규칙과 개발자의 스크립트 덕분이에요. 모든 역할이 같은 도구로 일해요.

## 파일을 만드는 네 가지 경로

어느 경로든 같은 도구를 같은 엔진으로 실행하므로 스크립트가 만든 파일은 앱에서 미리 보는 것과 같아요.

![URL 매개변수와 명령줄 인수가 같은 입력 모델로 바뀌어 하나의 공통 런타임과 내보내기 브리지를 거쳐요](/info/diagrams/concepts/one-render-path.svg)

- <!--i:people--> **앱에서 하나씩.** 도구를 열고 입력란을 채운 다음 **Export**를 누르세요. [첫 파일 만들기](/info/make-something.html)에서 하나를 만드는 과정을 안내해요.
- <!--i:layers--> **앱에서 한꺼번에 여러 개.** [Lolly Batch](/info/batch.html#make-many-versions-of-one-design)(`#/batch`)는 붙여넣거나 가져온 표를 받아 행마다 완성된 파일 하나를 렌더링해요.
- <!--i:cpu--> **스크립트나 AI 에이전트에서.** [CLI](/info/cli.html)는 도구를 화면 없이 실행하고, [MCP 서버](/info/mcp.html)는 에이전트가 도구를 찾아 실행할 수 있게 해요. 도구 링크에도 입력이 담기므로 링크 하나가 완전한 요청이에요.
- <!--i:server--> **조직의 서버를 통해.** [Lolly Work](/info/organisation.html)는 조직의 로그인 및 도구 정책에 따라 서버에서 렌더링하고, 다시 시작할 수 있는 작업을 보관하고, 다운로드하거나 승인된 방식으로 전달할 수 있도록 출력을 보관해요.

작업에 쓸 수 있는 경로는 도구의 형식과 호스트가 할 수 있는 일에 따라 달라요. 브라우저가 필요한 형식은 명령줄이 브라우저 계층에 넘겨요. [CLI로 렌더링하기](/info/cli-rendering.html)에서 각 형식이 어디서 렌더링되는지 확인할 수 있어요.

## 무엇이 어디에서 실행되나요

만들기, 편집, 내보내기는 계정 없이 기기에서 실행돼요. Sync나 연결된 서비스로 파일 보내기처럼 서버가 필요한 기능은 그 기능을 쓸 때만 연결돼요. Lolly Work에서는 공유 프로젝트, 팀의 실시간 편집, 승인, 서버 작업에 조직의 서버를 사용해요. [무엇이 어디에서 실행되나요](/info/compare.html#what-runs-where)에서 두 부분을 나란히 비교해요.
