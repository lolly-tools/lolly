# Lolly의 작동 방식

Lolly 도구는 한 종류의 파일에 대한 규칙, 즉 레이아웃, 글꼴, 색상, 다른 사람이 바꿀 수 있는 부분을 담고 있어요. 사용자, 동료, 스크립트, AI 에이전트가 필드를 채우면 모든 파일이 올바르게 나와요. 이 페이지는 누가 무엇을 하는지, 그리고 도구에서 완성된 파일까지의 네 가지 경로를 보여줘요.

## 하나의 도구, 사용자의 규칙, 많은 파일

브랜드 규칙은 만들어지는 각 파일이 아니라 도구에 있어요. 도구를 한 번 제대로 만들면 카드 한 장이든 열두 개 언어의 행으로 가득한 스프레드시트든 모든 결과물이 같은 글꼴, 색상, 간격을 물려받아요.

![필드 하나가 채워진 워드마크 도구: 글꼴, 색상, 간격은 도구를 만들 때 정해졌어요](/info/shots/aud-rules-in-the-tool.svg)

백 번째 파일을 만드는 사람은 단어만 입력해요. 작업을 어떻게 확인하고 누가 확인할지는 계속 사용자가 결정해요. Lolly는 확인할 대상을 더 작게 만들고, 다음 파일을 더 빠르게 만들게 해요.

## 도구를 만지는 사람들

조직 안에서 캠페인 카드 한 장을 따라가면 세 쌍의 손이 나타나요. 각각 앞사람의 작업 위에 쌓아요.

![디자이너가 도구에서 규칙을 한 번 정하고, 개발자가 스크립트로 실행하고, 누구나 필드를 채워요. 모두 완성된 파일을 만들어요](/info/diagrams/concepts/asset-relay.svg)

::: timeline
- <!--i:pentool--> **디자이너가 규칙을 정해요.** 브랜드의 글꼴과 색상으로 Design에서 카드를 배치한 뒤 열어 둘 필드를 골라요. 한 번만 하면 되므로 카드를 손으로 다시 현지화할 필요가 없어요.
- <!--i:code--> **개발자가 도구를 확장해요.** 같은 도구가 명령줄을 통해 야간 스크립트에서 실행되므로, 디자인을 다시 열지 않아도 새 차트나 새 언어 버전이 나와요.
- <!--i:people--> **누구나 채워요.** 네트워크도 없고 디자인 교육도 받지 않은 비행기 안의 영업 담당자가 도구를 열어 내일 회의용 카드를 만들어요.
:::

개발자 단계의 새 차트는 이것과 같은 렌더링으로, 아무도 디자인 파일을 열지 않고 데이터 문자열과 몇 가지 설정으로 만들어요.

![세 계열이 차가운 팔레트로 나뉜 제목 있는 누적 영역 차트: 축, 범례, 제목이 모두 손이 아니라 템플릿으로 배치돼요](/t/url-shot?url=%2F%23%2Ftool%2Fchart%3FchartType%3Darea%26stackMode%3Dstacked%26palette%3Dcool%26heading%3DProduct%2520mix%2520by%2520quarter%26full&width=1440&height=900&dpi=192&waitMs=2600&walker=1&format=svg&cropSelector=%23tool-canvas&dark=1&filename=ov2-lifecycle-chart)

담당자의 수월한 1분은 디자이너의 정성과 개발자의 스크립트가 있어서 가능해요. 모든 역할이 각자 다른 제품이 아니라 같은 도구로 일해요.

## 파일까지의 네 가지 경로

모든 경로가 같은 도구에서 같은 엔진을 실행하므로, 스크립트가 만든 파일은 앱에서 미리 본 파일과 일치해요.

![URL 매개변수와 명령줄 인수가 같은 입력 모델이 되어 하나의 공유 런타임과 내보내기 브리지를 거쳐요](/info/diagrams/concepts/one-render-path.svg)

- <!--i:people--> **앱에서 한 번에 하나씩.** 도구를 열고, 필드를 채운 뒤 **Export**를 눌러요. [첫 파일 만들기](/info/make-something.html)에서 하나를 안내해요.
- <!--i:layers--> **앱에서 한꺼번에 많이.** [Batch](/info/batch.html#make-many-versions-of-one-design)(`#/batch`)는 붙여넣거나 가져온 표를 받아 행마다 완성된 파일 하나를 렌더링해요.
- <!--i:cpu--> **스크립트나 AI 에이전트에서.** [CLI](/info/cli.html)는 도구를 헤드리스로 실행하고, [MCP 서버](/info/mcp.html)는 에이전트가 도구를 찾고 실행하게 해요. 도구 링크에도 입력값이 담기므로 링크는 완전한 요청이에요.
- <!--i:server--> **조직의 서버를 통해.** [Lolly Work](/info/organisation.html)는 조직의 로그인과 도구 정책에 따라 서버에서 렌더링하고, 이어서 실행할 수 있는 작업을 유지하며, 출력물을 다운로드나 승인된 전달을 위해 보관해요.

작업이 어떤 경로를 쓸 수 있는지는 도구의 형식과 호스트가 할 수 있는 일에 따라 달라요. 일부 형식은 브라우저가 필요하므로 명령줄이 이를 브라우저 계층에 넘겨요. [CLI로 렌더링하기](/info/cli-rendering.html)에서 어떤 형식이 어디서 렌더링되는지 나열해요.

## 어디서 무엇이 실행되는가

만들기, 편집, 내보내기는 계정 없이 기기에서 실행돼요. Sync나 연결된 서비스로 파일 보내기처럼 서버가 필요한 기능은 그 기능을 쓸 때만 연결돼요. Lolly Work에서는 공유 프로젝트, 실시간 팀 편집, 승인, 서버 작업이 조직의 서버를 써요. [어디서 무엇이 실행되는가](/info/compare.html#what-runs-where)에서 두 부분을 나란히 비교해요.
