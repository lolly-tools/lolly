# 내보내기 및 형식

도구에서 완성된 파일을 얻는 방법 - 올바른 형식 선택, 출력 크기 설정, 각 옵션이 하는 일. 다른 모든 것과 마찬가지로 **내보내기는 사용자 기기에서 일어나요**. 아무것도 업로드되지 않아요.

## 내보내기 작동 방식

미리보기가 *곧* 파일이에요. 내보낼 때 호스트는 그 캔버스를 선택한 형식으로 렌더링해서 다운로드를 건네주거나(또는 클립보드에 넣어줘요). 도구는 제작자가 선언한 형식만 제공하며, 선택기는 브라우저가 만들 수 없는 형식은 숨겨요([비디오](#video) 참고).

파일을 만드는 경로는 세 가지예요. 대부분의 도구는 캔버스를 선택한 형식으로 **렌더링**해요. 텍스트 및 데이터 형식(HTML, MD, TXT, JSON, CSV, ICS, VCF)은 그림에서 래스터화되는 대신 도구의 콘텐츠에서 **생성**돼요. 그리고 개인정보 보호 유틸리티(예: *숨겨진 데이터 제거*)는 세 번째 경로를 사용해요. 사용자가 선택한 파일이 기기에서 바이트 단위로 변환되어 그대로 돌려받아요 - 캔버스도 없고, 워터마크도, 출처 메타데이터 추가도 없어요. 이미 사용자 자신의 파일이니까요.

내보내기 컨트롤의 동작들이에요.

- <!--i:download--> **다운로드** - 파일을 저장해요(기본 동작).
- <!--i:photos--> **복사** - 이미지를 클립보드에 넣어 Slack, 이메일, 문서에 바로 붙여넣을 수 있어요. 브라우저가 이미지를 복사할 수 없는 경우 대신 다운로드하고 알려줘요.
- <!--i:folder--> **저장** - 현재 디자인을 라이브러리에 저장된 도구 세션으로 보관해요.
- <!--i:link--> **공유** - **공유 대화상자**를 열어요. 디자인을 재현하는 복사 가능한 링크, 방문 시 토글(전체화면, 내보내기 패널, 열 때 다운로드 또는 복사), 그리고 전체 상태를 압축된 토큰에 담는 선택적 **최단 링크**를 제공해요([URL 모드](/info/url-mode.html) 참고).

(이 중 어떤 것이 표시될지는 도구 제작자가 선택해요. 기본 세트는 복사, 다운로드, 저장이에요.)

![내보내기 패널 - 형식, 크기, 복사 / 다운로드 / 저장 / 공유 동작](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26options&width=1440&height=900&dpi=192&waitMs=2000&format=svg&walker=1&dark=1&filename=export-panel)

공유는 도구 위에 열리며, 링크는 이미 만들어져 있고 그 아래 방문 시 토글이 있어요.

### 여러 개를 한 번에 렌더링하기

단일 내보내기는 파일 하나지만, 한 번에 **여러 개**를 렌더링할 수 있어요 - 각각 하나의 `.zip`으로 전달돼요.

- <!--i:folder--> **프로젝트 → 폴더 렌더링**은 폴더(및 하위 폴더)에 저장된 모든 세션을 중첩된 zip 하나로 내보내요. **선택 항목 렌더링**은 다중 선택에 대해 같은 일을 해요. 저장된 세션 하나는 자체 파일로 바로 렌더링돼요. Batch나 Pro가 필요 없어요 - [Lolly 사용하기 → 프로젝트](/info/using.html) 참고.
- <!--i:layers--> **Batch (Pro)**는 입력 세트의 그리드를 렌더링해요 - 하나의 템플릿의 모든 변형을 한 번에.

저장된 세션은 프로젝트에서 도구 링크로 다시 공유할 수도 있어요(저장된 입력값에서 도구 URL을 재구성해요). 그래서 링크를 열면 정확히 같은 설정으로 다시 열려요.

## 크기 및 인쇄 단위

기본적으로 내보내기는 도구의 네이티브 픽셀 크기를 사용해요. 도구가 **치수**를 노출하는 경우, 너비 × 높이와 **단위**를 설정할 수 있어요.

- **px** (기본값) - 정확한 픽셀.
- **mm · cm · in · pt · pc** - 물리적/인쇄 크기. 물리적 단위를 사용하면 **DPI**도 설정해요(인쇄용 기본값 **300**). 엔진은 형식별로 올바르게 변환해요 - **PDF**는 그 크기의 실제 페이지가 되고, **래스터**는 DPI에 맞는 픽셀 수로 렌더링되며(해상도도 삽입돼요), **SVG**는 px viewBox와 함께 물리적 단위를 유지해요.

더 높은 해상도의 래스터를 얻으려면 더 큰 너비/높이를 입력하거나, 물리적 단위를 선택하고 DPI를 높이세요(픽셀 = 크기 × DPI). 원클릭 배율 토글은 없어요.

예: 너비 `210`, 높이 `297`, 단위 `mm` → A4 페이지.

## 타임드 컴포지션의 스틸컷

**시간 기반 구성** - Design의 [Sequence](/info/using.html#timeline-sequence) 타임라인이나 타임라인 기반 아트보드 - 은 움직이는 대상이므로, 정지 이미지로 내보낼 때는 '어느 순간인가?'라는 질문에 답해야 합니다. 규칙은 예상하신 그대로입니다: **재생 헤드 위치의 프레임**. 원하는 그림이 나올 위치에 재생 헤드를 놓고 내보내세요. 보이는 그대로가 결과물입니다.

한 순간 이상을 원할 때는 출력 크기 옆에 **프레임** 필드가 나타나요(타임드 컴포지션에서만, 그리고 스틸 형식 - PNG, JPG, WebP, SVG, PDF - 에서만). 재생 헤드 프레임만 원하면 `1`로 두세요. 값을 올리면 시퀀스 전체에 걸쳐 균등한 간격으로 샘플링된 그만큼의 스틸을 얻어요.

- **래스터와 SVG**는 하나의 **zip**으로 돌아와요 - `<name>-01.png`, `-02.png` 등으로.
- **PDF**는 그 개수만큼의 페이지로 이루어진 **단일 문서**로 돌아와요.

스토리보드, 썸네일 시트, 검토용 컨택트 시트, 또는 비디오 편집본에서 바로 잘라낸 소셜 캐러셀에 유용해요.

샘플링은 각 구간의 끝이 아니라 **중간 지점**에서 이루어져요. 시퀀스의 첫 순간은 아직 페이드인이 끝나지 않은 등장 전환인 경우가 많고, 마지막 순간은 모든 클립이 끝난 뒤의 상태이기 때문이에요 - 끝점 샘플링이라면 프레임 두 개를 거의 빈 화면에 낭비하게 돼요. 개수는 **64**로 제한되어 있고(컨택트 시트는 사람이 읽기 위한 것이니까요), 필드에 말이 안 되는 값을 입력하면 내보내기가 실패하는 대신 `1`로 되돌아가요. 각 프레임은 일반적인 스틸이므로 Content Credentials, 임프린트, 물리적 단위, DPI 모두 단일 내보내기와 정확히 똑같이 동작해요.

**프레임** 필드가 오늘날 시트를 얻는 방법이에요. 엔진은 이에 대응하는 `cuts` URL 매개변수를 예약해 두었지만, 아직 어떤 셸도 링크에서 이를 읽지 않아서 공유된 링크는 항상 재생 헤드 프레임으로 다시 열려요 - [URL 모드](/info/url-mode.html#contact-sheets-cuts) 참고.

## 다중 페이지 PDF

일부 도구는 단일 아트워크 대신 **여러 페이지로 구성된 PDF 문서**를 만듭니다 - 표지, 필요한 만큼 여러 페이지에 걸쳐 흐르는 콘텐츠, 그리고 뒤표지가 하나의 파일에 모두 담깁니다(*Booklet* 도구 참조). 각 페이지는 해당 페이지의 박스 크기에 맞춘 **진짜 PDF 페이지**이므로, 리더와 프린터는 하나의 긴 이미지가 아니라 실제 페이지를 받습니다.

- **콘텐츠에서 페이지 생성.** 텍스트와 이미지 블록을 추가하면 블록이 채워지면서 새 페이지가 자동으로 생성되고, 어떤 블록이든 강제로 새 페이지에서 시작하게 할 수 있어요.
- **실제 페이지 크기.** A4, US Letter 또는 A5(세로 - 2단 레이아웃은 이에 맞춰 만들어졌어요) 중에서 선택하세요 - 모든 페이지와 내보낸 PDF는 정확히 그 크기로 렌더링돼요.

여러 페이지 PDF는 RGB 문서이며 재단선/도련 표시를 포함하지 않습니다 - 이는 위에서 설명한 단일 페이지 **Print PDF** 경로에 해당하는 항목입니다. 다만 모든 PDF 내보내기와 동일한 **PDF/X-4 메타데이터**(페이지 박스, XMP, 문서 ID, 프로필이 내장된 sRGB 출력 의도)는 그대로 담기며, **Content Credentials**(아래 참조)도 제공합니다 - *Booklet* 도구에서는 이 옵션이 기본으로 선택되어 있습니다.

## 여러 개를 한 번에 만들기

Lolly에는 대량으로 작업하는 세 가지 뚜렷한 방법이 있고, 각각 다른 문제를 해결해요 - 일괄 편집은 각 도구가 새로 만드는 것이 아니라 플랫폼의 일급 기능이에요.

- <!--i:document--> **디자인 하나 × 행으로 이루어진 표 → 다중 페이지 문서 하나.** `table` 입력이 있는 도구(*Battlecards* 같은)는 모든 행을 자동으로 페이지로 바꿔요 - 스프레드시트에서 표를 붙여넣으면 덱 크기의 PDF를 얻어요. 진짜 일괄 편집기는 여전히 스프레드시트예요. 거기서 열 개 행을 고치고 다시 붙여넣으세요. 도구 자체는 페이지를 관리하지 않아요.
- <!--i:layers--> **디자인 하나 × 데이터 파일 → 여러 개의 개별 파일.** `/pro` 배치 그리드는 CSV를 받아서 *행마다* 내보내기 하나를 렌더링해요 - 이름표, 인증서, 각각 파일 하나씩.
- <!--i:sliders--> **서로 다른 여러 에셋을 나란히 편집하기.** *Multi-edit*는 여러 개의 저장된 세션을 한 화면에 열어서 서로 다른 디자인들을 조율하며 손볼 수 있게 해요.

경험칙: 같은 디자인의 행들이 **하나의 문서**에 속한다면 → 표 기반 도구, 행들이 **개별 파일**로 나가야 한다면 → `/pro`, 같은 수정이 필요한 **서로 다른 디자인**이라면 → multi-edit. (계획 중인 "미디어 결합" 렌더링 옵션이 앞의 둘을 연결할 예정이에요 - 같은 형식의 내보내기를 하나의 PDF, 하나의 비디오, 또는 교정용 컨택트 시트로 이어붙이는 방식으로요.)

## PowerPoint (PPTX)

Design, Markdown Slides, Booklet, Doc Studio, Chart, Diagrams는 **PowerPoint 덱**으로 내보낼 수 있습니다 - 페이지당 슬라이드 하나입니다. 목적은 픽셀 단위로 완벽한 스크린샷이 아니라, 동료에게 실제로 **편집하고 에셋을 추출할 수 있는** 덱을 건네는 것입니다. 그래서 각 페이지는 네이티브 객체로 분해됩니다:

- <!--i:font--> **텍스트**는 실제 **편집 가능한 PowerPoint 텍스트 상자**가 됩니다 - 레이아웃의 글꼴 크기, 색상, 굵기, 기울임꼴, 정렬이 그대로 반영되어 PowerPoint에서 오타를 고치거나 스타일을 다시 지정할 수 있습니다.
- <!--i:pentool--> **벡터**(로고, 아이콘, SUSE 마크)는 **실제 SVG 그림**으로 삽입됩니다 - 어떤 크기에서도 선명함을 유지하며, PowerPoint에서 *도형으로 변환*도 가능합니다.
- <!--i:photos--> **이미지**는 원본 해상도 그대로 각각 추출 가능한 개별 그림으로 전달되며(`cover` 방식으로 잘린 히어로 이미지는 자른 영역 뒤에 전체 이미지를 그대로 유지하므로 다시 프레이밍할 수 있습니다), 이미지에 적용된 처리(필터, 블렌드)도 충실하게 반영됩니다.
- <!--i:layers--> **배경, 테두리, 구분선**은 실제 사각형/선 도형이 됩니다.

![PowerPoint를 선택한 내보내기 패널: 페이지당 슬라이드 하나, 텍스트와 도형은 편집 가능하게 유지됨](/t/url-shot?url=%2F%23%2Ftool%2Fdeck-studio%3Foptions&width=1440&height=900&dpi=192&waitMs=2500&drive=click%3A%5Bdata-fmt-trigger%5D%3Bwait%3A400%3Bclick%3A%5Bdata-fmt%3D%22pptx%22%5D%3Bwait%3A800&cropSelector=.export-popup&walker=1&format=svg&dark=1&filename=exp-pptx)

레이아웃은 의도적으로 근사치입니다 - 목표는 고정된 스크린샷이 아니라 충실하고 재사용 가능한 **콘텐츠**입니다. 워커가 네이티브로 표현할 수 없는 것(복잡하게 필터링되거나 마스킹된 영역)은 그림으로 삽입되어 아무것도 손실되지 않습니다. 덱은 첫 페이지에서 가져온 단일 슬라이드 크기를 가집니다.

PowerPoint는 가져오는 경로로도 쓰입니다. 업로드 가능한 위치 어디든 `.pptx` 파일을 놓고 원하는 슬라이드를 고르세요 - 각 슬라이드는 배치하거나, 보정하거나, 위에 작업을 쌓아갈 수 있는 에셋이 됩니다. **Markdown Slides**는 Markdown으로부터 새로운 덱을 작성하며(브랜드가 적용된 `.pptx` 템플릿도 함께 제공합니다), **Rebrand** 유틸리티는 기존 덱을 제자리에서 다시 테마 적용합니다 - 테마 팔레트, 하드코딩된 색상과 글꼴을 바꾸되 차트, SmartArt, 애니메이션은 건드리지 않고 `.pptx`로 돌려줍니다. [디자인 가져오기 → 덱과 문서](/info/design-import.html#decks-and-documents)를 참고하세요.

## Penpot

SVG를 내보낼 수 있는 도구라면 어떤 것이든 **Penpot 파일**(`.penpot`)도 내보낼 수 있습니다 - 단순히 보기만 하는 것이 아니라 Penpot에서 계속 편집할 수 있는 상태의 문서입니다.

- <!--i:layout--> **Design**에서는 각 프레임이 Penpot **Board**가 되고, 그 안의 모든 박스는 사각형, 타원, 텍스트, 이미지, 패스 등 각자 편집 가능한 도형으로 그대로 옮겨지며, 결과물은 다시 드래그해서 꺼낼 수 있는 재사용 가능한 **Component**로 Assets 패널에 나타납니다.
- <!--i:pentool--> 렌더링 결과가 **순수 기하 도형**인 도구 - QR Code, Street Map, Wordmark, Palette Lab 같은 벡터 도구 - 에서는 모든 패스, 사각형, 텍스트 런, 그라디언트가 같은 방식으로 각자 편집 가능한 도형으로 옮겨집니다.
- <!--i:font--> 렌더링을 **HTML**로 구성하는 도구에서는 **텍스트가 텍스트로 유지됩니다** - 아웃라인도 평면 이미지도 아닌, 줄마다 편집 가능한 Penpot 텍스트 객체 하나가 됩니다. Penpot에 대응하는 구조가 없는 아트워크 - 복잡한 일러스트레이션, 라이브 캔버스 - 는 독립된 이미지로 그대로 실려 가므로, 그 주변의 텍스트와 박스를 평면화하는 일이 없습니다. Penpot이 충실하게 분리할 수 없는 레이아웃 전체라도 완전한 품질의 하나의 그림으로는 옮겨 갈 수 있으므로, 어떤 것도 누락되지 않습니다.
- <!--i:palette--> 도형이 **브랜드 토큰에서 상속받은** 색상이나 글꼴은 파일 안에서 그 토큰에 **연결된 상태**로 유지됩니다: Penpot의 Tokens 패널에서 토큰을 바꾸면 이를 상속하는 모든 도형이 함께 다시 칠해지고, 일회성 리터럴 색상은 그대로 그 자리에 남습니다. 브랜드의 색상과 타이포그래피는 **Assets** 패널에도 실리고, 전체 디자인 토큰 세트는 **Tokens** 패널에 실립니다 - Lolly 자체 팔레트가 쓰는 것과 같은 DTCG 토큰 세트입니다. Penpot은 그로부터 자기 사본을 유지합니다: Tokens 패널에서 이루어진 편집은 저절로가 아니라 [Brand Studio의 가져오기](/info/design-import.html)를 통해 브랜드로 다시 반영됩니다.

| 만든 것 | Penpot에서는 |
|---|---|
| 텍스트 | 편집 가능한 텍스트 객체 - 오타 수정이나 스타일 재적용 가능 |
| 도형, 패스, 그라디언트, 이미지 | 각자 편집 가능한 벡터 도형 |
| 브랜드 토큰에서 가져온 색상이나 글꼴 | 실시간 토큰 연결 - 토큰을 편집하면 이를 상속하는 모든 도형에 반영됨 |
| 전체 디자인 | Assets 패널의 재사용 가능한 Component |
| 복잡한 일러스트레이션이나 라이브 캔버스 | 독립된 이미지로 삽입되며, 주변의 편집 가능한 콘텐츠는 그대로 유지됨 |

![Penpot을 선택한 내보내기 패널: .penpot 파일과, 다운로드 옆의 Send to Penpot](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26options&width=1440&height=900&dpi=192&waitMs=2000&drive=click%3A%5Bdata-fmt-trigger%5D%3Bwait%3A400%3Bclick%3A%5Bdata-fmt%3D%22penpot%22%5D%3Bwait%3A800&cropSelector=.export-popup&walker=1&format=svg&dark=1&filename=exp-penpot)

파일을 열려면 Penpot을 실행해 프로젝트를 선택하고 **Import**를 고르세요. 내보내기 패널에서 Penpot에 로그인되어 있다면 **Send to Penpot**이 이 단계를 대신 처리해 줍니다 - 그 자리에서 프로젝트를 선택하면 파일이 곧바로 그 안으로 들어갑니다.

## SCORM(강좌 패키지)

Design 덱은 **SCORM 패키지**로 내보낼 수 있습니다 - Moodle, Canvas, Blackboard든 사내 LMS든, 학습 관리 시스템이 가져올 수 있는 zip 파일입니다. 형식 선택기에서 **SCORM (LMS)**을 고르면 내보내기는 다음을 기록합니다:

- <!--i:layout--> **슬라이드** - 아트보드당 이미지 하나로, 아트보드가 허용하는 곳에서는 벡터로, 허용하지 않는 곳에서만 픽셀로 저장됩니다.
- <!--i:play--> 자막 트랙이 딸린 **내레이션 영상** - 온디바이스 음성이 읽어 주는 발표자 노트로, [Presenting](/info/create/using.html#presenting)이 재생하는 것과 정확히 동일합니다.
- <!--i:file--> 슬라이드를 순서대로 넘기고 영상을 재생하며, 모든 LMS가 지원하는 버전인 SCORM 1.2 런타임을 통해 완료 상태를 LMS에 보고하는 **실행 페이지**.
- <!--i:font--> 덱이 사용하는 글꼴 - 오프라인에서도 실행 페이지가 동일하게 렌더링되도록 합니다.

## DXF (재단 파일)

벡터 도구(Brand Lockup, QR Code, Street Map, Wayfinding Signage, Pose Geeko, 로고 락업, Diagram Builder)는 **DXF**로 내보낼 수 있어요 - 레이저 커터, 비닐 플로터, CNC/CAD 소프트웨어가 읽는 AutoCAD R12 교환 형식이에요. 기하 정보는 **밀리미터 단위의 윤곽 패스**로 기록되고(곡선은 세밀한 허용 오차로 평탄화돼요), 텍스트는 패스로 윤곽선화되며, 색상은 가장 가까운 AutoCAD Color Index로 매핑돼요(이는 보통 커터의 도구/작업을 결정해요). DXF는 선화(line-art) 전용이에요 - 사진이나 필터가 적용된 영역은 절단 경로 형태가 없어서 제외되며(Lolly가 경고해요), 래스터 콘텐츠를 유지해야 한다면 SVG/PDF를 사용하세요.

Street Map은 가장 명확한 사례입니다: 전체 디자인이 이미 선(strokes)이므로 모든 도로와 운하가 손실 없이 재단 경로가 됩니다.

## 애니메이션 SVG

모션 도구(Animated Ad, Lottie Ad)는 **애니메이션 SVG**를 내보낼 수 있습니다 - 독립적인 *벡터* 애니메이션입니다. 각 프레임을 픽셀로 샘플링하는 GIF/APNG/WebP와 달리, 애니메이션 SVG는 벡터 스냅샷을 CSS 키프레임과 함께 쌓아 올리므로 **코덱이나 외부 런타임 없이 어떤 크기로도 확대**됩니다 - 브라우저 탭이나 `<img>`에서 재생됩니다. 텍스트는 윤곽선으로 유지되어 어디서나 렌더링됩니다. 애니메이션 형식과 동일한 **Duration**/프레임 속도 컨트롤을 공유하며, (프레임당 비트맵보다 무거우므로) 기본 프레임 속도가 더 낮습니다.

## 투명도

이를 지원하는 도구는 **투명 배경** 토글(예: *No BG*)을 제공합니다. 투명도는 PNG, WebP, AVIF, SVG(정지 및 애니메이션), APNG, 애니메이션 WebP에서 유지됩니다. JPG와 PDF는 항상 불투명하며, TIFF는 흰색으로 평탄화됩니다(HDR 경로에서는 검은색으로 - 아래 참조).

## 색상 공간

구분해서 알아둘 만한 두 가지 다른 질문: Lolly가 **읽고 사고할 수 있는** 색상 공간은 무엇이고, **쓰는** 색상 공간은 무엇인가.

**읽기.** 색상이 기록되는 모든 곳 - 도구의 스타일시트, 가져온 SVG의 페인트, 디자인 토큰 값, CSS 축약형 안의 그림자나 그러데이션 - 에서 Lolly는 **CSS Color 4** 어휘 전체를 읽습니다: `#hex`, `rgb()`, `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, CSS 명명 색상, 그리고 사전 정의된 공간 - `srgb`, `srgb-linear`, `display-p3`, `a98-rgb`, `prophoto-rgb`, `rec2020`, `xyz-d50`, `xyz-d65` - 안의 `color()`, `none` 키워드로 쓰인 구성 요소까지 포함합니다. 하나의 파서가 전체 플랫폼에서 이를 수행하므로 브라우저와 모든 내보내기 워커가 색상 문자열의 의미에 대해 일치합니다.

이는 들리는 것보다 더 중요합니다. 브라우저는 최신 CSS를 최신 CSS로 해석하기 때문입니다. `color-mix(in oklab, …)`를 쓰면 Chrome은 `oklab(…)`를 계산하고, `oklch()`로 저장된 브랜드 토큰을 사용하면 내보내기 워커가 보는 것은 바로 그 리터럴 값입니다. 이런 형식의 색상은 제외되지 않고 올바르게 읽힙니다 - `rgb()`만 이해하던 워커는 브랜드 색상 텍스트를 검정으로 내보내고, 색이 있는 패널과 표 구분선을 잃었으며, `oklch(0.7 0.1 200) 0px 2px 4px`를 0.7 by 0.1의 그림자 오프셋으로 잘못 읽었습니다.

**사고 방식.** 색상 연산은 원시 채널이 아니라 지각적으로 이루어져요. 팔레트 도출, 램프, 조화, 대비는 모두 **OKLCH/OKLab**에서 실행되고, 색역을 벗어난 색상은 채널을 잘라내는 대신 CSS Color 4 자체의 색역 매핑 알고리즘 - 지각 거리 검사를 동반한 채도 감소 - 으로 범위 안에 들어와요. 그래서 선명한 색상은 밋밋해진 색이 아니라 실제로 받아들일 만한 가장 가까운 색으로 자리잡아요. 그레이디언트는 선택한 색 공간(기본값은 OKLab, 또는 `oklch`, `lab`, `lch`, `srgb`, `srgb-linear`, `hsl`이며, 극좌표 공간에는 색상 이동 방향도 지정할 수 있어요)에서 보간되고, 혼합은 **프리멀티플라이드**로 처리되어 투명으로 페이드될 때 도중에 검은색 쪽으로 어두워지지 않고 올바른 색을 유지해요. 미리보기와 내보내기 워커 모두 하나의 보간기를 사용하므로, 원뿔형(conic) 그레이디언트가 화면에서는 한 방식으로, 내보낸 파일에서는 다른 방식으로 혼합되는 문제가 사라졌어요.

**쓰기.** 출력은 입력보다 의도적으로 좁습니다. 파일은 그것을 여는 모든 프로그램이 읽을 수 있어야 하고, 공간은 숫자가 실제로 그 공간으로 변환되었을 때만 출력에 *선언*되기 때문입니다. 화면 및 웹 형식은 **sRGB**로 기록되고 그렇게 태그됩니다. 인쇄 형식은 지정된 인쇄 조건(아래 참조)에 대한 **CMYK**로 기록됩니다. HDR 경로는 **Rec.2100 PQ**입니다(위 참조). 넓은 색역의 색상이 내보내기에 도달하면 잘못 표시되는 대신 sRGB로 매핑됩니다 - `color(display-p3 …)`를 벡터 파일로 그대로 전달하는 것은 계획된 확장 기능이지, 오늘의 내보내기가 수행한다고 주장하는 것이 아닙니다. OKLab으로 작성된 그러데이션은 나가는 길에 일반 sRGB 정지점으로 *구워지며*, sRGB가 지각 곡선에서 눈에 띄게 벗어나는 지점에만 추가 정지점이 삽입됩니다. SVG `<linearGradient>`와 PDF 축 방향 셰이딩에는 그 의도를 전달할 보간 공간 설정이 없기 때문입니다. 하나의 작성된 값, 세 개의 렌더러, 드리프트 없음.

## 색상 프로필

색상 관리 앱(인쇄소, Photoshop, 브라우저)에서 색상이 충실하게 재현되도록, 내보내기는 **색상 프로필로 태그**됩니다:

- **PNG / JPG**는 미리보기가 실제로 렌더링되는 색상 공간인 내장 **sRGB** ICC 프로필을 포함하므로 아무것도 추측할 필요가 없습니다. (태그만 지정하며, 픽셀 자체는 다시 인코딩되지 않습니다.)
- **인쇄용 PDF(CMYK)**는 *OutputIntent*에 목표 **인쇄 조건**(기본값 *Coated FOGRA39*)을 선언하여 RIP/인쇄소에 CMYK 잉크를 어떻게 읽어야 하는지 알려줍니다. 측정된 잉크 값이 있는 브랜드 색상 견본은 정확히 변환되고, 다른 색상은 표준 장치 변환을 사용합니다. 이 선언은 하나의 *이름*일 뿐입니다: Lolly에는 CMYK 프로필이 포함되어 있지 않으며, PDF/X-4는 프로필이 내장되기를 원하므로, 명명된 조건은 PDF/X-4 준수를 주장하지 않고 출력 의도만 기록합니다. 자신의 CMYK 프로필을 불러와 색상 프로필 컨트롤에서 **Embed** 행을 선택하면 그것이 파일의 *DestOutputProfile*로 내장됩니다 - 이 시점에서 PDF는 실제로 PDF/X-4가 될 수 있으며, 파일의 나머지 부분이 허용하는 한 그렇게 주장합니다. 세 가지 요소는 출력 의도를 유지하면서도(RIP는 여전히 이를 원함) 그 주장을 보류시킵니다: CMYK 변환이 처리하지 못한 RGB 아트워크, `prov` 증명 여백 크레딧 텍스트(내장되지 않은 표준 글꼴로 그려지며, X-4는 이에 대한 예외를 두지 않음), 그리고 **Strong** 비밀번호(X-4는 암호화를 금지함). 선언되는 조건은 그 프로필에서 읽어옵니다: 프로필이 등록된 이름을 증명하는 경우 그 이름을, 그렇지 않은 경우 프로필 자체의 이름으로 `Custom`을 사용하므로, 파일이 다른 측정값을 담은 채 하나의 인쇄 조건 이름을 주장하는 일은 없습니다.
- **인쇄용 TIFF(CMYK)**는 태그되지 않은 **DeviceCMYK** 픽셀을 기록하고, 프로필을 내장하는 대신 동일한 인쇄 조건을 TIFF 메타데이터(*ImageDescription*)에 출처로 기록합니다. 동일한 색상 프로필 컨트롤이 두 CMYK 형식을 모두 구동합니다 - TIFF는 인쇄 프로필을 전혀 내장할 수 없으므로, **Embed** 행은 그 프로필 자체의 이름만 그곳에 기록합니다.
- **TIFF(RGB)**는 일반적인 무압축 sRGB 형제입니다 - 아카이브 또는 편집기 왕복용으로 선택한 DPI에서의 무손실 래스터이며, 출처는 동일한 TIFF 메타데이터에 기록됩니다. 투명도는 흰색으로 평탄화됩니다(이 프로필은 알파를 지원하지 않음). CMYK TIFF와 마찬가지로 브라우저가 TIFF를 미리보기할 수 없고 모바일 다운로드가 막다른 골목에 이르므로 데스크톱 전용입니다.
- **SVG**, **EMF**, **EPS**, **DXF**는 해상도 및 프로필과 무관한 벡터로 내장된 프로필이 없습니다 - SVG의 색상은 일반 sRGB, EMF와 EPS의 색상은 장치 RGB(그리고 **EPS(CMYK)**는 naive DeviceCMYK를 기록함), **DXF**는 가장 가까운 AutoCAD Color Index를 담습니다. (SVG, EPS, DXF는 PDF와 마찬가지로 모든 텍스트를 벡터 경로로 윤곽선화하므로 글꼴이 설치되지 않은 곳에서도 결과가 렌더링됩니다. EMF는 대신 기본적으로 텍스트를 LIVE 상태로 유지합니다 - Office와 Google Slides에서 선택 및 편집이 가능한 실제 메타파일 텍스트 레코드이며, 형식이 표현할 수 없는 텍스트 실행만 윤곽선으로 대체됩니다. 내보내기 패널의 "Outline fonts" 옵션은 모든 곳에서 경로를 강제합니다.) **SVG**는 또한 HTML의 CSS `box-shadow`를 재현합니다 - 각 외부 그림자는 박스 뒤에 그려지며, 브라우저와 일치하도록 오프셋/확산 및 가우시안 블러가 적용되고, 내부 그림자는 동일한 방식으로 박스 안쪽에 그려집니다.

이는 자동으로 처리되며 - 조정할 설정이 없습니다. 썸네일과 미리보기는 크기를 작게 유지하기 위해 태그를 생략합니다. 하나의 프로필만은 *선택 사항*입니다. 단순히 레이블을 붙이는 것이 아니라 픽셀 자체를 바꾸기 때문입니다 - 아래 **HDR** 참조.

## HDR (밝은 색상)

일반적인 내보내기는 sRGB입니다: 흰색은 흰색이고, 채도가 높은 브랜드 색상도 화면의 일반적인 흰색만큼만 밝습니다. HDR을 지원하는 디스플레이에서는 그 위로 훨씬 많은 여유 공간이 있으며, 내보내기 패널의 **HDR** 카드가 이를 활용합니다 - 브랜드 색상과 흰색 텍스트가 최대 밝기 쪽으로 끌어올려져 실제로 *빛나게* 되며, 어두운 영역은 어둡게 유지되어 그 빛에 대비를 부여합니다.

![내보내기 패널에서 켜진 HDR 카드, 그 아래로 드러난 White / Reach / Dark lift / Focus 다이얼](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26format%3Dpng%26hdr%3D1%26options&width=1440&height=900&dpi=192&waitMs=2000&format=svg&cropSelector=.export-hdr&walker=1&dark=1&filename=exp-hdr-card)

- **형식.** 신호를 실을 수 있는 래스터 형식: **PNG**, **JPG**, **AVIF**, **TIFF**. (WebP는 제외 - 8비트이며 작동하는 HDR 디코드 경로가 없어서, PQ WebP는 그냥 어둡게 보일 뿐입니다. 벡터와 PDF에는 HDR 모델 자체가 없습니다.)
- **기본값은 꺼짐**, 컬러 태깅과 달리 픽셀 자체를 바꾸는 작업이므로 선택 시에만 적용됩니다. 카드를 체크하거나, 공유 링크에 `hdr=1`을 전달하세요.
- **실제로 기록되는 내용.** 픽셀은 **Rec.2100 PQ**로 다시 인코딩됩니다 - SMPTE ST 2084(PQ) 전달 곡선을 쓰는 BT.2020 원색이며 - 컨테이너에는 컬러 매니지드 앱이 이를 그렇게 읽어야 함을 알 수 있도록 일치하는 신호가 함께 실립니다: `cicp` 태그가 포함된 생성된 **ICC v4 프로필**(JPG, TIFF), **`cICP` 청크**(PNG), 또는 재작성된 `colr` 박스(AVIF)입니다. 부스트는 **지각적(OKLab) 명도**를 기준으로 적용되므로 중간 이상의 색상은 최고 밝기까지 끌어올려지고 어두운 색상은 뭉개지기보다 차분하게 유지되며, 색조를 보존합니다 - 브랜드 그린은 더 밝아질 뿐 민트색으로 변하지 않습니다.
- **조절 항목.** 카드를 켜면 드러나는 네 가지: **White**(최고 밝기 상한, 400~2000니트), **Reach**(밝기 확산이 톤을 얼마나 깊이까지 내려가는지), **Dark lift**(어두운 영역을 얼마나 밝히는지 - `0`이면 어둡게 유지) 그리고 **Focus**(부스트가 유지하는 색상 풍부함의 정도). 이들은 압축된 튜닝 값과 같은 매개변수에 실립니다 - `hdr=1600-60-0-50`은 White 1600, Reach 60, Dark lift 0, Focus 50을 뜻하므로, 링크만으로 튜닝된 룩을 재현할 수 있습니다.
- **어디에서 보이는가.** HDR 디스플레이의 컬러 매니지드 뷰어: Apple 기기의 Preview/Quick Look/Safari, HDR 모니터의 Chrome. 일반 SDR 화면에서는 파일이 그냥 평범한 이미지로 보입니다.
- **배포 전에 알아둘 점.** 업로드한 것을 **재인코딩**하며 HDR 신호를 제거하는 플랫폼이 많습니다 - 소셜 네트워크, 메시징 앱, 일부 CMS - 이 경우 이미지가 어둡거나 흐릿하게 보일 수 있습니다. HDR은 대상 환경을 직접 제어할 수 있는 곳(직접 만드는 사이트, 비디오 월, 밝은 패널에서 보여줄 덱)에서 사용하고, 모든 것의 기본값으로 삼지 마세요.
- **투명도.** PNG와 AVIF는 알파 채널을 유지하며, JPG는 언제나처럼 불투명합니다. **TIFF** 경로는 SDR 경로의 흰색이 아니라 **검은색**으로 평탄화됩니다 - PQ에서는 흰색이 10,000니트 코드이므로, 흰색으로 평탄화하면 모든 가장자리에 눈부신 후광이 둘러지게 됩니다.
- **터미널에서도 같은 바이트.** `--export=png`나 `--export=jpg`와 함께 쓰는 `--hdr=1`은 [CLI](/info/cli.html)에서도 16비트 Rec.2100 PQ PNG와 ISO 21496-1 게인맵 JPEG를 브라우저가 아니라 동일한 엔진 인코더로 기록합니다 - 그래서 `<svg>` 네이티브 도구가 경로 어디에도 Chromium 없이 HDR 파일을 만들어내며, PNG는 웹 셸의 결과물과 바이트 단위로 동일합니다. AVIF와 TIFF는 당분간 웹 셸 전용 내보내기로 남습니다.

## 비디오

애니메이션 도구는 **MP4**, **WebM**, **GIF**로 모션을 내보내며 - 제공되는 경우 **APNG**, **애니메이션 WebP**, 또는 벡터 형식인 **애니메이션 SVG**(위 참조)로도 내보낼 수 있습니다. 표시되는 비디오 컨테이너는 브라우저에 따라 다릅니다 - 선택기는 실제로 녹화할 수 있는 것만 보여줍니다:

| 브라우저 | 표시 |
|---|---|
| Safari / iOS | **MP4** |
| Firefox | **WebM** |
| Chrome / Edge 126+ / Android | **MP4와 WebM** |
| 이전 버전 Chrome | **WebM** |

GIF는 어디서나 작동합니다(채팅/이메일에 적합하며, 비디오보다 크고 색상 수가 적습니다). 애니메이션 도구는 또한 **Wait**(녹화 전 애니메이션이 안정되기까지 기다리는 초 단위 시간)와 **Duration**(클립 길이)를 제공합니다.

> 브라우저가 녹화할 수 없는 컨테이너를 요청하는 공유 `?format=…` 링크는 다른 형식으로 정상적으로 대체되며 그에 맞게 파일 이름이 지정됩니다.

**소리.** 비디오 내보내기는 무음이 아닙니다. 도구는 클립 아래에 **배경 음악**을 깔 수 있습니다 - 카탈로그의 오디오 애셋을 클립 길이에 맞춰 반복하거나 잘라내며, 페이드인/아웃, 볼륨, 영상 자체 소리 아래로 자동 덕킹이 적용됩니다 - 그리고 녹화 도구는 영상의 라이브 오디오를 파일까지 그대로 전달합니다. **MP4**와 **WebM**은 믹스된 트랙을 유지합니다. GIF와 애니메이션 이미지 형식(APNG, 애니메이션 WebP, 애니메이션 SVG)은 본질적으로 무음입니다.

## 오디오

일부 도구는 비디오 트랙으로서가 아니라 **오디오 단독**으로 내보냅니다. **Voice Recorder**는 실시간 레벨 미터와 부드러운 코칭으로 마이크 녹음을 캡처한 다음 **MP3**(기본값, 브라우저에서 트랜스코딩됨)로 저장하거나, 브라우저가 녹화한 네이티브 컨테이너 - **M4A**(AAC), **OGG**, **WebM**(Opus) - 로 저장합니다. 다른 모든 것과 마찬가지로 인코딩은 기기에서 이루어집니다 - 아무것도 업로드되지 않습니다.

*가져오는* 오디오도 마찬가지로 폭넓게 지원됩니다. 애셋 선택기는 **MP3**, **WAV**, **OGG**/**Opus**, **M4A**/**AAC**, **FLAC**(바이트 단위로 그대로 유지되고 기기에서 디코딩됨), **MIDI**(`.mid` - 가져올 때 작은 온디바이스 신디사이저 트랙으로 변환됨), 그리고 **트래커 모듈** - **MOD**, **XM**, **IT**, **S3M**, **STM**, **MTM**(번들 플레이어가 기기에서 디코딩하는 몇 킬로바이트 크기의 곡 데이터)을 지원합니다. 이들 중 어느 것이든 비디오 내보내기의 **배경 음악**이 되거나 Neurospicy Mode의 앰비언트 플레이어에서 재생될 수 있습니다.

오디오는 아래의 `format=` / `--export=` 파이프라인의 *일부*입니다: `wav`, `mp3`, `m4a`, `opus`는 일반적인 형식 id이므로 오디오 전용 내보내기도 PNG만큼 공유 가능하고 스크립트로 처리할 수 있습니다. 출력되는 것은 소리뿐이며 이미지는 없습니다.

## 출처와 워터마크

형식이 지원하는 경우, 내보내기는 소프트웨어, 출처, 도구 이름, 프로필 크레딧 라인 등 **출처 메타데이터**를 네이티브로 내장한 채 전달됩니다(PNG iTXt, JPEG EXIF, PDF info, SVG `<metadata>`, GIF comment). 이는 저작자 표시일 뿐이며 아무것도 업로드되지 않습니다. **Experimental** 도구는 여기에 더해 눈에 보이는 워터마크를 찍으며, 이는 호스트가 적용하므로 도구를 편집해도 제거할 수 없습니다.

**Lolly Imprint.** 래스터 내보내기는 또한 Lolly 고유의 **눈에 보이지 않는 픽셀 워터마크**인 *Lolly Imprint*를 담고 있으며, Content Credentials와 마찬가지로 **기본적으로 켜져 있습니다**. 크레덴셜과 출처 메타데이터가 픽셀과 *나란히* 이동하며 다시 저장하거나 스크린샷을 찍거나 메타데이터를 제거하면 사라지는 것과 달리, Imprint는 픽셀 *안에* 존재하며 재압축에도 살아남습니다 - 따라서 이미지의 사본을 나중에도 Lolly로 만들어졌다고 인식할 수 있습니다. 이는 암호학적 보증이 아니라 내구성 있는 힌트이며, 존재 여부만 나타낼 뿐입니다(개인 데이터는 담지 않음). **PNG, JPG, WebP, AVIF, TIFF, BMP**에, 그리고 **PDF나 PPTX**에 합성된 Lolly가 렌더링한 래스터에도 실립니다 - Lolly 자신이 렌더링한 것에만 실리며, *사용자가* 삽입한 이미지에는 절대 실리지 않습니다. 내보내기 패널에서 **Lolly Imprint** 카드를 체크 해제하거나 공유 링크에 `imprint=0`을 전달하면 건너뛸 수 있습니다. (AVIF의 재인코딩 생존율은 아직 검증되지 않았으며, PDF/PPTX 감지는 내장된 Lolly 래스터만 다룹니다.) [/verify](/verify)가 이를 기기에서 감지합니다 - [Content Credentials Identity](/info/content-credentials-identity.html#the-lolly-imprint) 참조.

**내구성 있는 크레덴셜.** Imprint 옆에는 두 번째의 더 무거운 마크가 있습니다: **Durable credential**은 온디바이스 신경망 모델(TrustMark 형식)을 사용해 Lolly의 id를 픽셀 *안에* 기록하므로 "made with Lolly" 링크는 메타데이터 제거, 재인코딩, TrustMark를 인식하는 도구(뿐 아니라 Lolly 자체)에 의한 재판독에서도 살아남습니다. **기본적으로 꺼져 있습니다** - 순수 JavaScript인 Imprint와 달리 내보낼 때마다 신경망 처리가 필요하고 모델을 한 번 다운로드해야 하므로 조용히 부과되는 비용이 아니라 의도적인 옵트인입니다. 래스터 전용(**PNG, JPG, WebP, AVIF, TIFF**)이며 내보내기 패널에서 체크하거나 공유 링크에서 `durable=1`로 전달합니다. 데스크톱 및 모바일 앱에서는 오프라인에서 모델을 가져올 출처가 없으므로 이 카드가 아무 동작도 하지 않는 상태로 표시되는 대신 아예 숨겨집니다.

**콘텐츠 보호.** 내보내기 패널에서 *비밀번호 보호*, **C2PA Credentials**, **Lolly Imprint**, **Durable credential**은 하나의 접힌 형식 인식형 **Content protection** 그룹으로 통합되어, 파일의 출처와 보호 옵션이 한 곳에 모입니다 - 이 그룹은 선택한 형식에 적용되는 카드만 표시하고, 하나도 적용되지 않으면 완전히 숨겨집니다. 인쇄 마크는 의도적으로 여기에 포함되지 않습니다: 이는 보호가 아니라 인쇄 제작 지오메트리이므로, **Print marks & bleed** - 재단선 여백 측정값(밀리미터)에 Crop, Registration, Bleed, Colour bars, Stamp details를 더한 것 - 은 인쇄 형식에서 독자적인 최상위 카드를 유지합니다.

![PNG 내보내기에서 열린 Content protection 그룹, 여기에 적용되는 카드만 표시함](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26format%3Dpng%26imprint%3D1%26options&width=1440&height=900&dpi=192&waitMs=2000&walker=1&format=svg&cropSelector=.export-protection&dark=1&filename=exp-content-protection)

**내보내기 전(인쇄 사전 점검).** 프로필의 기능 플래그에서 **Print preflight**(`export-preflight`)를 켜세요 - **기본적으로 꺼져 있으므로** 채팅 메시지용 PNG를 내보내는 개인이 인쇄 사전 검사 결과에 갑자기 맞닥뜨리는 일이 없으며, 배포 관리 콘솔([lolly.work](https://lolly.work))은 자사 구성원에 대해 이를 기본으로 켜둘 수 있습니다 - 그러면 인쇄 규칙이 작업에 대해 알려줄 진짜 내용이 있을 때마다 패널 하단, 버튼 바로 위에 **Before you export** 카드가 나타납니다: 형식, 크기, 여백, 그다음 재단 및 여백 영역, 잉크 커버리지, 판 수와 페이지 수를, 제목 옆에 판정과 함께 보여줍니다. 이는 다른 설정에 대한 진술이지 또 하나의 설정이 아니므로 모든 설정 아래에 위치하며, 내보내기를 절대 막지 않습니다. 인쇄소가 곧 보게 될 것을 미리 알려줄 뿐입니다.

**비용, 요율표에서 계산됨.** 사전 점검 아래 - 맨 마지막, 버튼 위 - 에는 동일한 수치를 금액으로 바꾸는 카드가 있으며, 누군가가 제공한 가격에서만 계산합니다. 이는 사전 점검 패스가 계산한 값을 읽습니다. 사전 점검 카드 자체가 켜져 있는지 여부와 관계없이 말이죠. 두 가지가 참이어야 합니다: 작업에 가격표가 가격을 매길 수 있는 무언가(판, 시트, 면적, 페이지, 변형 행, 출력 파일)가 있어야 하고(단순한 로고 PNG는 절대 표시되지 않음), **그리고** **요율표**가 있어야 합니다. 요율표는 인쇄소로부터 받은 JSON 가격표입니다. 기본 빌드는 이를 포함하지 않으며 앱 내에서 불러올 방법도 없습니다: 배포판이 제공하는 카탈로그 애셋으로 도착하거나, 셀프호스터나 관리 콘솔이 켜는 선택적 요율표 확장을 통해 제공됩니다. 요율표가 없으면 아무것도 표시되지 않습니다 - 프롬프트도, 빈 표도 없습니다.

전체가 세워진 규칙은 **절대 돈을 지어내지 않는다**는 것입니다. 모든 수치는 사용자가 제공한 요율에 Lolly가 센 수량을 곱한 값입니다 - `4 plate × €35.00` - 그리고 총액은 그 수치와 같은 문장에서 자신의 출처 이름을 밝힙니다: 카드가 명시한 발행자와 카드가 밝힌 요율의 기준일. 기본 통화도, 자리표시자도, 누락된 가격을 대신하는 0도 없습니다. 파일이 자기 자신에 대해 말하는 내용은 인용 발언으로 남습니다: *"파일에 따르면: … Lolly는 이를 검증하지 않았습니다."*

정직하게 계산할 수 없을 때는 작업 표가 회색으로 흐려지거나 채워진 수치로 저하되는 대신 **사라집니다**:

- 카드가 가격을 매길 수 없는 항목은 **총액 없음**을 의미합니다 - 몇 개가 가격이 매겨지지 않았는지 알리는 헤드라인만 표시됩니다. 부분 합계는 더 작은 답이 아니라 틀린 답입니다.
- 정확한 개수가 아니라 상한선인 수량은 소계에도 **"up to"**가 함께 이어져, 상한이 고정된 수치로 세탁되지 않습니다.
- 유효기간이 지난 요율은 *이 요율을 그대로 사용*을 누르기 전까지 **개수만** 표시됩니다 - 그런 다음 만료일이 수치와 함께 표시되어, 만료된 총액이 현재 것으로 읽힐 수 없습니다.
- **링크**를 통해 열리면 금액은 이 기기에서 요청하기 전까지 숨겨집니다. 카드도 그 공개 조작도 URL에 담기지 않습니다 - CLI가 `--rate-card=<file.json>`을 링크 매개변수가 아니라 로컬 파일 플래그로 받는 이유와 같습니다.

이 카드는 크롬(chrome)일 뿐 콘텐츠가 아닙니다: 모든 내보내기 단계에서 제거되므로 다운로드하는 파일의 픽셀을 한 개도 움직일 수 없습니다. 그리고 이는 산술일 뿐, 견적이 아닙니다 - 견적을 줄 수 있는 것은 오직 사용자의 인쇄소뿐입니다.

**합성된 렌더링.** 도구가 다른 도구의 출력을 삽입하는 경우(예: *Event Name Badge*가 *QR Code*를 삽입) 중첩된 렌더링은 상위 항목의 내보내기에 인라인으로 삽입됩니다 - SVG와 PDF에서는 **진짜 벡터**로 유지되며 PNG/JPG/WebP에서는 선명하게 래스터화됩니다. 삽입된 자식은 중간 산물입니다: 워터마크도 없고 자체 출처도 *없으며*, 오직 완성된 상위 애셋만 이를 가집니다. (합성은 SVG와 래스터 형식에 적용됩니다. HTML/MD/TXT는 합성할 수 없습니다.)

## 비밀번호 보호

두 가지 독립적인 잠금 방식이 있으며, 둘 다 전적으로 온디바이스에서 처리돼요.

**PDF 열기 암호** - 내보내기 패널의 *비밀번호 보호* 카드는 두 가지 등급을 제공해요.

![PDF 내보내기에서 펼쳐진 비밀번호 보호 카드. 비밀번호 필드와 두 가지 잠금 등급이 표시됨](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26format%3Dpdf%26password%3Ddemo%26options&width=1440&height=900&dpi=192&waitMs=2000&walker=1&format=svg&cropSelector=.export-pdfpass&dark=1&filename=exp-pdf-password)

- **Standard** - 기본적인 40비트 잠금(RC4)이에요. *어떤* PDF 앱에서도 열리지만, 가벼운 억제책일 뿐 실제 보호가 아니라서 공유 링크에 그대로(평문으로, 설계상) 담길 수 있어요. RGB `pdf` 전용이에요.
- **Strong** - AES-256(PDF 2.0)이에요. 비밀번호는 내보내기 시점에 입력하며 링크에는 **절대** 포함되지 않아요. 최신 PDF 앱(Acrobat / Preview 2018년경 이후)에서만 열리고, 구형 앱은 파일이 손상됐다고 표시할 수 있어요. Strong은 **인쇄 / CMYK PDF**와 **배치 zip 안의 각 PDF**에도 적용돼요(배치 확인 대화상자에서 비밀번호를 수집해요). PDF/X-4는 암호화를 허용하지 않기 때문에 Strong으로 잠근 인쇄 PDF는 CMYK, 마크, 출력 의도는 유지하되 PDF/X-4 준수 표시는 잃어요.

두 등급 모두 Content Credentials와 상호 배타적이에요(암호화된 PDF는 크리덴셜을 담을 수 없어요).

**다운로드 잠금(zip 전체 + 다층 방어)** - **ZIP** 내보내기(도구의 여러 형식을 묶는 내보내기 패널의 *ZIP* 형식), **폴더** 다운로드(Projects → Download), 또는 **일괄 그리드**는 하나의 비밀번호로 zip 전체를 두 가지 등급으로 잠글 수 있어요.

- **Standard** - 전통적인 **ZipCrypto**예요. Windows 탐색기 내장 압축 풀기를 포함한 *모든* 압축 해제 도구에서 열리지만 약한 방식(억제책)이에요. 비밀번호가 `?password=` 공유 링크에 담길 수 있어요.
- **Strong** - **AES-256**(WinZip AE-2)이에요. 강력하지만 Windows 탐색기 내장 압축 풀기에서는 **열리지 않아요** - 받는 사람은 7-Zip / WinZip / Keka / macOS가 필요해요. 내보내기 시점에 입력하며 링크에는 절대 포함되지 않아요.

내보내기 패널의 동일한 *비밀번호 보호* 카드가 PDF와 ZIP 잠금을 모두 담당하며, 선택한 형식에 맞춰 문구가 바뀌어요. 하나의 비밀번호가 이미지, SVG를 비롯한 PDF를 포함한 **모든** 구성원을 보호해요(zip 컨테이너만이 자체 잠금이 없는 비-PDF 파일을 보호할 수 있어요). 그리고 이건 **다층 방어**예요. zip 안의 모든 PDF도 같은 비밀번호로 *개별적으로* AES-256 잠금이 걸리기 때문에, zip이 풀린 뒤에도 PDF는 잠긴 채로 남아요. 프롬프트는 다운로드를 시작할 때 나타나며, 비밀번호를 비워두면 잠금이 없어요.

**비밀번호로 보호된 공유 링크** - 모든 공유 링크는 열 때 받는 사람에게 비밀번호를 요구하도록 암호화할 수 있어요. 링크 상태 전체가 비밀번호에서 파생된 키(PBKDF2)로 AES-256 암호화돼요. 암호문만 이동하므로 **비밀번호는 절대 링크에 포함되지 않고**, 복호화는 **받는 사람의 브라우저에서** 일어나요 - 링크를 서빙하는 서버는 URL의 암호문만 볼 뿐, 비밀번호도 복호화된 디자인도 보지 못해요. **Share** 대화상자에서 켤 수 있어요. 암호화된 링크는 Lolly에서만 *열* 수 있어요(그 경로는 프롬프트를 띄울 수 없으므로 이미지로 임베드할 수 없어요). [URL Mode → Encrypted links](/info/url-mode.html)를 참고하세요.

## Content Credentials(C2PA)

내보낸 파일은 **Content Credentials**를 담을 수 있어요 - 파일에 서명된 [C2PA](https://c2pa.org) 매니페스트가 임베드되어, 이 파일이 Lolly로 만들어졌고 그 이후 변경되지 않았음을 위변조 감지 방식으로 기록해요. 앞서 설명한 출처 메타데이터의 표준화 버전으로, 파일이 무엇으로, 언제, 누가, 어디서 만들었는지에 대한 암호학적 주장을 파일 바이트의 해시에 결속해요. 그래서 이후 어떤 편집도 C2PA를 인식하는 뷰어가 감지할 수 있어요. 이 표준은 [Content Authenticity Initiative](https://contentauthenticity.org)(Adobe, BBC, Microsoft, Nikon 등)가 관리하므로, Lolly가 기록하는 크리덴셜은 카메라, 뉴스룸, 크리에이티브 스위트가 채택하고 있는 것과 같은 것이에요.

![미리 체크된 C2PA Credentials 카드와 그 옆의 크리덴셜 유효 기간](/t/url-shot?url=%2F%23%2Ftool%2Fqr-code%3Furl%3Dhttps%3A%2F%2Flolly.tools%26format%3Dpng%26c2pa%3D30%26options&width=1440&height=900&dpi=192&waitMs=2000&format=svg&cropSelector=.export-c2pa%5Bdata-c2pa-only%5D&walker=1&dark=1&filename=exp-c2pa-card)

- **형식.** C2PA 임베딩을 지원하는 모든 컨테이너: **PDF**(RGB, 인쇄 모두), **PNG / Animated PNG**, **JPG**, **GIF**, **SVG**, **TIFF**(RGB, 인쇄), **WebP**(정지, 애니메이션), **AVIF**, **MP4**, **WebM**, 그리고 오디오 컨테이너인 **MP3**, **WAV**, **M4A**, **OGG/Opus** - 녹음되거나 합성된 음성 클립도 이미지와 같은 크리덴셜을 담고 나가요. **ZIP** 번들은 지원되는 각 구성원을 개별적으로 스탬프하며, **Animated SVG**가 크리덴셜을 얻는 것도 여기예요(내부적으로는 일반 SVG 문서이며, Animated SVG를 직접 내보낼 때는 별도 카드가 없어요). MP4, AVIF, M4A는 스펙의 BMFF 바인딩을, MP3는 ID3v2 매핑을 사용하므로 `c2patool`을 비롯한 C2PA 인식 뷰어가 이를 검증할 수 있어요. **WebM**과 **OGG/Opus**는 아직 표준화된 C2PA 매핑이 없어서, Lolly는 매니페스트를 각각 Matroska 첨부와 OpusTags 필드로 담아 나르며, Lolly의 자체 검증기(및 CLI)가 이를 확인해요. (`ico`, `eps`, `emf`, `dxf`, `bmp`, `pptx`, 오피스 형식과 텍스트/데이터 형식에는 C2PA 컨테이너가 없어요.)
- **기본으로 켜져 있음.** 내보내기 패널의 **C2PA Credentials** 카드는 거의 모든 도구에서 미리 선택돼 있어요 - 체크를 해제하면 단일 내보내기에서 크리덴셜을 건너뛸 수 있어요(또는 공유 링크에 `c2pa=off`를 전달해요). 도구는 매니페스트에서 이 기능을 완전히 제외할 수도 있어요.
- **기록되는 내용.** 파일을 만든 도구와 앱, 서명 시각, 내보내기 표면(브라우저 엔진 계열 + OS 계열 - 일부러 대략적으로만, 지문이 되지 않도록), 그리고 *Profile → Use my details*가 켜져 있을 때만 작업물의 저작자로서의 이름과 이메일이에요.
- **받는 사람이 보는 것.** 콘텐츠 크리덴셜을 확인하는 도구(Adobe 앱, `c2patool`, contentcredentials.org/verify)는 매니페스트를 읽고 주장을 표시해요. Lolly는 신뢰 목록의 인증서가 아니라 **기기에서** 생성한 키로 서명하기 때문에, 뷰어는 이를 *미검증* 크리덴셜로 표시해요. 구조와 위변조 감지는 진짜지만, 서명자 신원은 별도의 기관이 보증하지 않는 것뿐이에요. 이를 개선하려면 **검증된 신원**(Profile → Content Credentials)을 등록할 수 있어요. Lolly CA가 발급하는 단기 인증서가 서명 키가 기기를 벗어나지 않은 채로 이메일과 내보내기를 연결해요 - [Content Credentials Identity](/info/content-credentials-identity.html)를 참고하세요.
- **파일 확인하기.** Lolly는 자체 크리덴셜도 검증해요. [/verify](/verify)에 아무 파일이나 놓거나(또는 CLI에서 `lolly validate <file>`을 실행해) 온디바이스 리포트를 받아보세요 - 파일이 실제로 Lolly로 만들어졌고 그 이후 변경되지 않았는지가 첫머리에 표시돼요. 웹 Verify 화면은 크리덴셜을 훨씬 넘어서요. **AI 생성 콘텐츠**를 표시하고, **Lolly Imprint**를 감지하고, **SEAL** 서명과 (선택적으로) 서드파티 픽셀 워터마크를 확인하고 **숨겨진 데이터**를 드러내요 - 모두 온디바이스에서, 아무것도 업로드하지 않고요. [Content Credentials Identity → Beyond the credential](/info/content-credentials-identity.html#beyond-the-credential-what-else-verify-shows)을 참고하세요.
- **프라이버시.** 모든 과정이 기기에서 이뤄져요. 서명 키는 내보내기를 위해 생성되고 브라우저를 벗어나지 않으며, 아무것도 업로드되지 않고, 주장에는 이미 출처 메타데이터가 담고 있던 내용만 들어가요. 프라이버시 유틸리티(*본인 소유* 파일의 온디바이스 변환)는 절대 크리덴셜을 추가하지 않으며, *Strip Hidden Data*는 다른 임베드 메타데이터와 마찬가지로 C2PA 매니페스트도 제거해요.
- **상호작용.** PDF의 경우 Content Credentials와 **비밀번호 보호**(어느 등급이든 - 위 참고)는 상호 배타적이에요(암호화된 PDF는 크리덴셜 첨부를 담을 수 없어요). 크리덴셜은 완성된 바이트에 대한 최종 단계로 추가돼요 - DPI/EXIF/색상 프로필 스탬프, PDF/X 메타데이터, 인쇄 마크 이후에요.

## 휴대폰에서

내보내기 컨트롤은 떠 있는 **Render** 버튼 뒤에 있으며, 이를 누르면 **Export** 시트가 열려요 - 같은 형식, 크기, 복사, 다운로드, 공유가 터치에 맞게 크기 조정되어 있어요.

## 형식 참조

호스트가 렌더링할 수 있는 모든 id를 그룹별로 정리했어요. 이 값들은 URL의 `format=` 매개변수와 CLI의 `--export=` 플래그 값이기도 해요 - [URL Mode](/info/url-mode.html)와 [CLI](/info/cli.html)를 참고하세요. 도구는 작성자가 선언한 부분집합만 제공하므로, 선택 목록은 항상 이 목록보다 짧아요.

| 종류 | ID |
|---|---|
| 래스터 | `png` · `jpg`/`jpeg` · `webp` · `avif` · `tiff`(RGB TIFF) · `cmyk-tiff`(Print TIFF) · `bmp` · `ico` |
| 벡터 | `svg` · `svgz`(gzip 압축 SVG) · `emf` · `wmf` · `eps` · `eps-cmyk`(EPS CMYK) · `dxf`(커팅 파일) |
| 페이지 및 문서 | `pdf` · `pdf-cmyk`(Print PDF) · `pptx`(PowerPoint) · `scorm`(SCORM 강좌 패키지, zip) · `penpot`(Penpot 디자인 파일) · `docx`(Word) · `odt`(OpenDocument Text) |
| 모션 | `gif` · `apng`(Animated PNG) · `webp-anim`(Animated WebP) · `svg-anim`(Animated SVG) · `webm` · `mp4` |
| 오디오 | `wav` · `mp3` · `m4a` · `opus` |
| 텍스트 및 데이터 | `html` · `md` · `txt` · `json` · `csv` · `ics` · `vcf` · `css` · `scss` · `gpl`(GIMP 팔레트) |
| 번들 | `zip` |

공유 렌더 경로가 아니라 **도구 자체의 내보내기 훅**에서 나오는 id가 몇 가지 더 있어요. `ase`(Adobe Swatch Exchange, Palette Lab에서), `exr`과 `hdr`(Darkroom의 하이 다이나믹 레인지 래스터), `ttf` / `otf` / `woff`(Font Convert)예요. 이들도 형식 선택 - 선택 목록, `format=`, `--export=` - 방식은 같지만, 바이트는 도구가 직접 만들어요. Font Convert는 유일한 예외예요. *사용자*가 제공한 폰트 파일을 변환하는 것이라, 단순 URL로 렌더링할 대상이 없어요.
