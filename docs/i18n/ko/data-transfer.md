# 데이터 전송: `lolly-backup` 번들

백업 번들은 Lolly가 기기에 보관하는 개인 라이브러리를 옮겨요. 한 설치 환경에서 내보내고 파일을 옮긴 뒤(USB, AirDrop, 자신에게 보내는 이메일 또는 네트워크 공유) 다른 설치 환경에서 가져와요. 내보내기와 가져오기에는 서버가 필요 없고, 대상은 오프라인이어도 돼요.

이 문서는 백업을 다루는 셸, 도구, 스크립트를 만드는 사람을 위한 형식 사양이에요. 자신의 작업물을 옮기려면 [다른 기기로 작업물 옮기기](/info/find-your-work.html#move-your-work-to-another-device)를 읽어 보세요.

::: note 범위
번들이 담는 것은 카탈로그 도구가 아닌 *사용자 데이터*예요. 카탈로그 도구와 카탈로그 에셋은 별도로 동기화되며, 대상에 이미 있고 버전이 다르더라도 더 높은 버전이라고 가정해요. 사용자가 만든 도구는 `profile.json` 안에 담겨 전달돼요. 가져오기는 카탈로그 도구를 설치하거나 업그레이드하지 않아요.
:::

## 목표

- <!--i:box--> **모든 셸에서 하나의 형식.** 웹 앱, 데스크톱과 모바일 앱, 앞으로 나올 셸은 같은 외부 구조와 부분별 스키마를 공유해요. 선택적 부분은 각 셸의 기능에 따라 달라지며 지원하지 않는 부분은 보고돼요. 각 기능 브리지가 저장소 어댑터를 제공해요.
- <!--i:shieldcheck--> **전송 중 손상에 대응해요.** 전송 중 손상되거나 잘린 번들은 가져올 때 오류와 함께 실패하며 일부만 복원되는 일은 없어요.
- <!--i:clock--> **이 버전을 넘어 오래 유지돼요.** 이전 앱은 새 번들에서 인식하는 부분을 가져와요. 호환성을 깨는 형식은 명확히 거부해요.
- <!--i:check--> **안전하게 병합해요.** 이미 사용 중인 설치 환경으로 가져와도 번들에 없던 것은 지우지 않아요.

## 외부 구조

번들은 일반 `.zip`이에요. 어떤 방식으로 전송해도 그대로 유지되며, 어떤 압축 해제 도구로든 내용을 확인할 수 있어요.

다운로드 파일은 소유자의 이름을 따서 `LollyTools-<First>-<Last>-<YYYY-MM-DD>-<n>.zip`으로 이름이 붙어요. 예를 들면 `LollyTools-Ada-Lovelace-2026-06-26-1.zip`이에요. 이름과 성은 프로필에서 가져오며 설정하지 않았으면 빠져요. 프로필이 없으면 `LollyTools-2026-06-26-1.zip`, 이름만 있으면 `LollyTools-Ada-2026-06-26-1.zip`이 돼요. 이름과 성은 각각 파일 이름에 안전한 토큰으로 바뀌어요(유니코드 문자와 숫자는 유지하고 공백과 문장 부호는 제거하며 최대 32자). `<n>`은 날짜별, 기기별 순번이므로 같은 날 반복해서 내보내도 충돌하지 않고 순서가 유지돼요. `data-transfer.ts`의 `backupFilename()`이 이름을 만들어요. 이름은 zip의 내용을 바꾸지 않아요.

| 경로 | 필수 여부 | 내용 |
|---|---|---|
| `manifest.json` | 필수 | 형식 id, 버전, 개수, 부분별 무결성이에요. 리더는 이 파일을 먼저 읽어요. |
| `profile.json` | 설정된 경우 | 사용자의 `me` 기록: 이름, 연락처, 얼굴 사진 참조, 플래그와 폴더, Trash, 프로젝트 청사진, 사용자 템플릿과 사용자가 만든 도구, 즐겨찾기, 숨긴 도구, 언어와 이모지 선택이에요. `host.profile`로 읽어요. |
| `sessions.json` | 필수 | 저장된 모든 세션: 슬롯, 도구 id와 버전, 라벨, 썸네일(데이터 URL), 전체 입력 데이터예요. `host.state`로 읽어요. |
| `assets.json` | 필수 | 업로드한 각 에셋(이미지, 글꼴, 브랜드 토큰, 로고, 다운로드를 저장한 사본)의 메타데이터로, 각각 `assets/blobs/` 아래의 해당 바이트를 가리켜요. |
| `assets/blobs/<n>.<ext>` | 에셋별 | 에셋의 원시 바이트로, 대부분 이미 압축된 형식이므로 압축하지 않고 저장해요. 확장자는 표시용이며, `assets.json`의 MIME 유형이 기준이에요. |
| `assets/blobs/<n>.c2pa` | 있는 경우 | 정확한 바이너리 바이트로 추출한 Content Credentials이며, 에셋 기록의 `_credentialFile`이 참조해요. 기기 서명 키가 아니에요. |
| `design-systems.json` | 있는 경우 | 이 설치 환경에서 만들거나 추가한 디자인 시스템을 `{ active, records }` 형태로 담아요. [가져오기 규칙](#import-rules)을 참고하세요. |
| `file-history.json` | 선택 사항 | 버전이 있는 에셋 스냅샷, 완료된 파일 작업 보고서, 완전한 배치 매니페스트이며 자체 버전이 있어요. 셸 내부의 `fileHistory` 백업 어댑터가 제공해요. |
| `revision-history.json` | 선택 사항, 수동 백업 | 고정된 작업물 ID, 보관된 체크포인트, 썸네일, 순환 보관되는 복구 초안이에요. 지원되는 환경에서 `host.state.history.backup`이 제공해요. |
| `file-history/versions/` | 스냅샷별 | 현재 에셋이 여전히 있는지와 관계없이 이전 에셋 바이트와 추출된 자격 증명을 담아요. |
| `file-history/results/` | 완료된 작업별 | 정확한 출력 바이트예요. 변환을 위해 선택한 원본 파일은 보관하거나 포함하지 않아요. |
| `prefs.json` | 필수 | 사용자 소유의 로컬 환경설정: `theme`, `sidebarWidth`, `ct-metrics` 활동 집계예요. |
| `lolly.txt` | 필수 | Lolly 없이 zip을 여는 사람을 위한 읽을 수 있는 번들 요약(개수, 프로필, 파일 이름)이에요. 내보낼 때마다 다시 생성되고 가져올 때 인식되므로 건너뛴 부분으로 집계되지 않아요. 무결성 맵 뒤에 작성되므로 맵은 이 파일을 다루지 않아요. |

::: details 내보내기가 zip을 작성하는 방식
내보내기는 zip을 한 부분씩 작성해요(`shells/web/src/lib/zip-stream.ts`). 업로드, 저장된 결과, 저장된 에셋 버전은 전체가 아닌 4 MiB 조각으로 읽어요. 저장된 결과와 버전은 먼저 기록된 SHA-256과 대조해요. 그런 다음 각 파일을 읽어 체크섬과 무결성 다이제스트를 구하며, zip은 원래 위치의 파일을 참조해요.

다시 인코딩되는 것은 없어요. 모든 부분은 정확한 바이트와 다이제스트를 유지하므로 Content Credentials를 담은 파일도 서명이 적용되는 바이트를 유지해요. 부분과 시각이 같으면 zip은 이전의 메모리 내 작성기가 만든 것과 같지만, 16 MiB를 넘는 기록 파일은 조각으로 압축돼요. `tests/backup-streaming.test.ts`가 기록된 참조 다이제스트와 대조해 이를 확인해요.

Node에서 192 MiB의 합성 라이브러리로 측정했을 때, 백업을 마무리하는 데 라이브러리 외에 약 125~150 MiB가 필요했고 메모리 내 작성기는 약 850 MiB가 필요했어요(`node scripts/bench-backup-finalise.ts`). 가져오기는 여전히 전체 zip을 메모리로 읽어요.
:::

## `manifest.json`

```json
{
  "format": "lolly-backup",
  "formatVersion": 3,
  "minReader": 1,
  "app": "lolly",
  "exportedAt": "2026-06-22T09:30:00.000Z",
  "counts": { "profile": true, "sessions": 2, "userAssets": 4, "prefs": 3, "assetVersions": 1, "fileOperations": 1 },
  "integrity": {
    "profile.json": "sha256-…",
    "sessions.json": "sha256-…",
    "assets.json": "sha256-…",
    "assets/blobs/0.bin": "sha256-…",
    "file-history.json": "sha256-…",
    "file-history/versions/0.bin": "sha256-…",
    "file-history/results/0.bin": "sha256-…",
    "prefs.json": "sha256-…"
  }
}
```

| 필드 | 의미 |
|---|---|
| `format` | 항상 `lolly-backup`이에요. 이 값이 없는 파일은 "Lolly 백업이 아님"으로 거부돼요. |
| `formatVersion` | 이 번들을 **작성할 때** 쓴 구조예요. 부분의 구성이나 형태가 바뀔 때마다 올라가요. 리더는 이 필드로 가져오기 여부를 결정하지 **않아요**. |
| `minReader` | 이 번들을 **안전하게** 가져올 수 있는 최소 리더 버전이에요. 리더는 이 필드로 가져오기 여부를 결정해요. |
| `app` | 진단용으로 기록하는 생성 앱 id예요. |
| `exportedAt` | 번들이 생성된 시각의 ISO 타임스탬프예요. |
| `counts` | 표시와 타당성 확인을 위한, 작성기가 넣은 내용이에요. |
| `integrity` | 선택 사항이에요. `manifest.json`을 제외한 모든 부분을 **압축되지 않은** 바이트의 SRI 방식 `sha256-<base64>` 다이제스트에 매핑해요. |

## 버전 정책

두 개의 버전 번호 덕분에 이전 설치 환경을 배제하지 않고 형식을 확장할 수 있어요.

![번들 형식 변경에는 이전 리더가 무시할 수 있는 추가 변경과, 잘못 가져오면 손상이 생기는 호환성을 깨는 변경이 있어요. 추가 변경은 formatVersion을 올리고 minReader를 유지해요. 호환성을 깨는 변경은 formatVersion과 minReader를 모두 올려요. 리더는 minReader가 자신의 버전 이하일 때 가져와요.](/info/diagrams/concepts/backup-version-gate.svg)

- 리더는 `manifest.minReader`가 자신의 리더 버전 이하일 때 번들을 가져와요. 번들이 더 새 리더를 요구할 때만 "더 새 버전의 앱이 필요해요"라는 메시지로 거부해요.
- 새 선택적 부분이나 새 선택적 매니페스트 필드 같은 **추가** 변경은 `formatVersion`을 올리고 `minReader`는 그대로 둬요. 이전 앱도 인식하는 모든 부분을 가져오며, 인식하지 못하는 부분은 조용히 버리지 않고 건너뛰었다고 보고해요.
- 부분을 잘못 가져오면 데이터가 손상되거나 선택적 부분이 필수가 되는 **호환성을 깨는** 변경은 `minReader`를 올려요. 그러면 이전 앱은 처리할 수 없는 것을 가져오는 대신 명확히 거부해요. 이전 앱은 이때 번들을 명확히 거부해요.
- 향후 번들이 `formatVersion`은 설정하고 `minReader`는 생략하면 리더는 `formatVersion`을 기준으로 가져오기 여부를 결정하며 변경이 호환성을 깨는 것으로 처리해요.

::: note 작성자를 위한 간단한 기준
기존의 모든 리더가 추가한 내용을 무시해도 계속 올바르게 동작한다면 추가 변경이에요. `formatVersion`을 올리고 `minReader`는 그대로 두세요. 그렇지 않으면 `minReader`를 올리세요.
:::

## 무결성

`manifest.integrity`가 있으면 리더는 **무엇이든 쓰기 전에** 나열된 각 부분의 SHA-256을 확인해요. 불일치("무결성 검사 실패")나 누락된 부분("불완전함")이 있으면 가져오기가 중단되므로 부분 복원은 없어요. 전송 중 잘린 AirDrop, 첨부 파일을 다시 인코딩한 이메일 게이트웨이, 불량 USB 섹터 같은 전송 손상을 잡아내요.

무결성은 가능한 범위에서 처리돼요. Web Crypto를 사용할 수 있는 환경(모든 보안 브라우저 컨텍스트와 최신 Node)에서만 기록되며, 맵과 Web Crypto가 모두 있을 때만 확인해요. 무결성 기능이 생기기 전에 만든 번들처럼 맵이 없는 번들은 그대로 가져와요. "검증할 수 없음"을 "손상됨"으로 간주하지 않아요.

매니페스트는 자기 자신과 다시 생성된 `lolly.txt`를 모두 목록에서 제외해요.

## 가져오기 규칙

가져오기는 두 모드 중 하나로 실행돼요.

- **Merge**는 **Import data…**와 동기화의 첫 참여 단계인 **Bring it to this device**가 하는 일이에요. 대상의 데이터는 유지되고 번들 밖의 것은 건드리지 않아요.
- **Replace**는 기기 동기화가 기기들을 같은 상태로 유지하는 데 써요. 동기화된 사본의 프로필 기록, 환경설정, 세션, 이미지, 활성 디자인 시스템 선택을 가져와요. 마지막 동기화 이후 다른 기기가 삭제한 항목만 제거해요. 이전 사본을 복원할 때는 먼저 기기를 저장한 뒤 기기를 그 사본에 맞추고 사본에 없는 모든 것을 제거해요. [기기 동기화하기](/info/sync.html)에서 사용자에게 보이는 내용을 다뤄요.

병합은 데이터 종류마다 다음과 같이 처리해요.

| 데이터 | 대상에 이미 있는 경우 | 번들에만 있는 경우 |
|---|---|---|
| 세션(슬롯 기준)과 업로드한 이미지(id 기준) | 더 최근에 저장한 사본을 유지하므로 이전 백업이 새 작업물을 덮어쓰지 않아요. 시각이 같거나 알 수 없으면 대상의 사본을 유지해요. | 추가돼요 |
| 폴더 | 대상의 이름과 상위 폴더를 유지하고 번들에 있는 구성원 중 빠진 것을 폴더에 추가해요. 대상의 폴더에 정리된 세션은 그 폴더에 남아요. | 추가돼요 |
| 즐겨찾기(도구, 카탈로그 에셋, Projects 항목) | 합쳐져요 | 추가돼요 |
| 템플릿, Projects 템플릿, 사용자 도구(id 기준) | 대상의 기록을 유지해요. | 추가돼요 |
| Trash 항목 | 대상의 항목을 유지해요. | 추가되어 어느 한 설치 환경에서라도 복원할 수 있던 항목은 여전히 복원할 수 있어요. 폴더가 대상에서 다시 사용 중이거나 대상이 해당 Trash 슬롯을 이미 쓰는 항목은 제외돼요. |
| 다른 프로필 필드(이름, 연락처, 언어, 기능 플래그, 숨긴 도구, 기타 설정) | 대상의 값을 유지해요. | 대상의 필드가 비어 있으면 가져와요 |
| 환경설정(`prefs.json`) | 대상의 값을 유지해요. | 대상에 값이 없으면 기록해요 |
| 디자인 시스템(id 기준) | 번들의 기록이 대상의 기록을 대체해요. | 추가돼요. 번들의 활성 선택은 대상에 자체 디자인 시스템이 없을 때만 적용돼요. |
| 작업물 기록 | 더 최근에 저장된 사본을 현재 버전으로 유지하고, 다른 사본은 보호된 초안으로 보관해요. | 추가돼요 |

**저장된 세션은 이미지에 자동으로 다시 연결돼요.** 에셋 참조는 id로 유지돼요. `blob:` URL은 새로고침 후에 유지되지 않으므로 이미지가 복원된 뒤 브리지가 참조를 다시 확인해 연결해요.

**기록은 한 번 작성되면 바뀌지 않아요.** 에셋 버전과 작업 ID를 반복해서 가져와도 추가되는 것은 없으며, 이미 다른 바이트나 기록을 가리키는 ID는 덮어쓰지 않고 거부해요. 동일한 현재 에셋을 다시 가져오면 버전을 유지하며, 변경된 현재 에셋에는 다른 버전이 있어야 해요.

**작업물 기록에는 규칙이 몇 가지 더 있어요.** 대상이 해당 슬롯을 다른 작업물에 쓰고 있으면 작업물을 별개로 추가하며, 대상의 Trash에 있는 작업물은 그곳에 남아요. 체크포인트 id가 대상에서 다른 콘텐츠를 가리키면 대상의 것을 유지해요. 아카이브가 자체 검사를 통과하지 못하면 프로필, 세션, 에셋, 환경설정을 바꾸기 전에 가져오기가 중단되며, 동일한 내용을 반복해서 가져와도 저장 공간을 추가로 쓰지 않아요.

**요약은 처리 결과를 보고해요.** 모든 가져오기는 `profile`, `sessions`, `userAssets`, `prefs`, `skipped`, `failedAssets`를 반환해요.

- `failedAssets`는 기기 저장소가 가득 찬 경우처럼 복원할 수 없었던 업로드 에셋 수를 세요.
- `skipped`는 더 새 작성기가 만든 부분 중 이 빌드가 인식하지 못한 수를 세요. 앱은 개수를 보여줘요("… · 새 항목 N개 건너뜀").
- 파일 기록이 있으면 요약에 `assetVersions`, `fileOperations`, `fileBatches`, `failedHistory`가 추가돼요. 저장 공간 부족이나 변경 불가능한 ID의 충돌로 부분 복원이 일어날 수 있으며, 이때 앱은 사용자에게 원본 백업을 보관하라고 알려줘요.
- 작업물 기록이 있으면 이번 가져오기에서 추가한 것만 세는 `revisions`, `recoveryDrafts`와 각 작업물의 병합 방식을 나타내는 `added`, `kept`, `replaced`, `copies`, `hidden`이 추가돼요. `skippedCheckpoints`는 id가 대상에서 다른 콘텐츠를 가리키는 체크포인트 수를 세고, `historyLeftOut`은 기기의 기록 공간에 들어가지 못한 오래된 체크포인트와 초안 수를 세요.
- 대체 가져오기는 `removed`와 `failedRemovals`를 추가해요.

복원은 프로필, 세션, 에셋, 기록 저장소 전체에 걸친 단일 트랜잭션이 아니에요. 클라우드 동기화는 일부만 복원되거나 지원되지 않는 복원이 일어나면 적용된 리비전을 갱신하지 **않으므로**, 사본은 다시 시도할 수 있도록 남아요.

## 옮겨지지 않는 것

- **카탈로그 캐시**(내려받은 에셋 메타데이터와 블롭, 도구 인덱스)는 대상에서 다시 동기화해요.
- **카탈로그 도구와 카탈로그 에셋**은 대상에 있다고 가정해요. 사용자가 추가한 브랜드 토큰, 글꼴, 로고는 사용자 에셋이므로 함께 옮겨져요.
- **`blob:` 및 개체 URL**은 불러올 때 브리지가 다시 생성해요.
- **변환 원본, 활성 실행 리스, 기기 로컬 접근 또는 서명 비밀 정보.** 이들은 옮길 수 있는 기록이 아니에요. 저장된 결과는 사본이에요. 원본 소스가 백업됐다는 뜻은 아니에요.
- **내보내기 순번 카운터**는 `localStorage`의 일별 다운로드 이름 지정 카운터(`lolly-export-seq`)예요. `PREF_KEYS`에서 제외하므로 번들에 담겨 옮겨지는 일이 없어요.

저장 공간 표시도 같은 구분을 보여줘요. Saved sessions, My images, File results & versions는 번들에 들어가요. 에셋 캐시, 도구 미리보기, 오프라인 고정 항목은 다시 만들 수 있으므로 남겨 둬요.

## Lolly Work의 조직 데이터

이 번들은 기기의 개인 라이브러리를 백업해요. 번들은 **Lolly Work** 인스턴스의 백업이 아니에요. 조직 계정, 접근 정책, 공유 프로젝트, 카탈로그 버전, 승인, 렌더 작업, 감사 기록은 그 서비스가 보관해요. 공유 작업에 다시 접근하려면 재연결하고 로그인하세요. 개인 번들을 가져온다고 그 접근 권한이 생기지는 않아요.

운영자는 Lolly Work의 자체 가이드인 [백업과 복원](/info/work-operations.html#backup-and-restore), [Lolly Work 저장소와 데이터 수명 주기](/info/work-data-lifecycle.html)에 따라 서버 데이터를 백업, 보관, 삭제해요. 기기를 비우거나 내보내도 이런 서버 작업은 수행되지 않아요.

## 셸 간 이동

`data-transfer.ts`는 기능 브리지(`host.profile`, `host.state`, `host.assets`)와 공유 `localStorage` 환경설정만을 통해 읽고 써요. 같은 모듈이 웹, 데스크톱 앱, 모바일 앱에서 IndexedDB 또는 파일 시스템 저장소를 통해 공통 봉투 형식을 읽고 써요. 선택적 기록 부분은 해당 어댑터가 있는 곳에서만 나타나요. 가져오기는 지원되지 않는 부분을 건너뛰었다고 보고해요. 헤드리스 테스트 모음은 메모리 내 브리지로 공통 부분을 검사하며, 기록 트랜잭션에는 실제 브라우저 테스트도 있어요.

이 보장에 포함되지 않는 셸이 두 가지 있어요.

- **일회성 CLI**에는 옮길 것이 없어요. 상태는 메모리에 있고 한 번의 호출 동안만 유지돼요.
- **TUI**는 상태(세션, 폴더, 프로필)를 `~/.lolly`에 보관해요. Profile 보기는 자체적으로 더 단순한 백업 아카이브를 써요. 세션별 `saved-state/<slot>.json`과 `profile.json`, `folders.json`으로 구성되며 매니페스트, `formatVersion`, `minReader`, 무결성 맵이 없어요. 이 형식을 읽는 프로그램은 이름이 비슷해도(`lolly-backup-<stamp>.zip`) 그 아카이브를 "Lolly 백업이 아님"으로 거부해요. 두 형식을 통합하는 일은 알려진 미해결 과제예요.

## 아직 옮길 수 없는 것

새로운 종류의 이동 가능한 데이터는 나중에 추가 부분으로 합류할 수 있어요(새 `formatVersion`, 같은 `minReader`). 디자인 시스템은 이미 이 방식으로 `design-systems.json`과 사용자 에셋을 함께 옮겨요.

아직 옮겨지지 않는 데이터를 위해 두 이름이 예약돼 있어요.

- **`tokens.json`**은 그룹, 세트, 테마를 포함한 [W3C DTCG](https://tr.designtokens.org/format/) 디자인 토큰 문서를 담게 될 예정이며, 이는 [Penpot이 가져오고 내보내는](https://help.penpot.app/user-guide/design-systems/design-tokens/) 형식이에요. 사용자의 자체 브랜드 토큰은 `user/tokens/brand` 에셋으로 이미 `assets.json`에 담겨 옮겨지고, 디자인 시스템의 토큰은 해당 레코드와 함께 옮겨져요.
- **`penpot/`**는 수집한 Penpot 파일 또는 그중 Lolly 관련 부분을 도구로 제공하기 위해 예약돼 있어요.

## 기록 부분

두 기록 부분은 선택 사항이며 각자의 버전이 있어요.

::: details 생성 기록(v3)
생성 기록이 있는 웹 설치에서 수동으로 만든 백업에는 `revision-history.json`이 포함되며, 자체 `{ version: 1, documents, revisions, recoveries }` 스키마를 써요. 보관된 ID, 정규 입력 스냅샷, 버전 스탬프, 래스터 미리보기, 별도의 작성자 초안을 담아요. 기록 어댑터는 하나의 읽기 트랜잭션에서 현재 세션과 그 헤드를 캡처하며, `sessions.json`은 이전 버전 리더를 위해 같은 현재 스냅샷을 사용해요.

복원은 하나의 트랜잭션으로 아카이브를 커밋하기 전에 페이로드 SHA-256과 바이트 수, 식별자의 고유성, 문서와 헤드의 관계, 상위 이력, 타임스탬프, 미리보기 유형과 한도를 확인해요. 압축 정리된 부모 참조는 없을 수도 있어요. 기존 현재 작업은 알리지 않고 대체되지 않아요. 양쪽에 같은 창작물이 있으면 현재 상태로 남지 않는 쪽이 보호된 초안이 돼요.

아카이브의 전송 한도는 384 MiB예요. 보관된 체크포인트를 잘라내지 않고 저장 한도를 적용해요. 내보내기는 `revision-history.json`과 `sessions.json`을 청크로 쓰며, 한 번의 `JSON.stringify`와 같은 바이트를 생성하므로 파일 텍스트 전체를 메모리에 보관하지 않아요. 한도를 넘을 기록 파일은 넘는 순간 제외하고 그 뒤로는 크기만 계산해요. 그러면 가장 오래된 자동 체크포인트를 빼고 아카이브를 다시 만들며, 내보내기 요약에서 빠진 수를 `checkpointsLeftOut`으로 집계하거나 아카이브를 거부해요.

이 기능이 없는 셸은 일반 세션을 복원하고 기록 부분을 건너뛰었다고 보고해요. 네이티브 파일 시스템 기록은 어댑터가 영구적인 기록 트랜잭션을 제공할 때까지 지원되지 않아요. 비공개 collab의 게스트에게는 영구적인 기록이나 복구 아카이브가 없어요.

개인 스냅샷 동기화는 생성 기록을 제외해요. 기록이 있는 로컬 문서에 스냅샷을 적용하면 이전 작업 상태를 별도의 복구 초안으로 보관하고, 열린 편집기의 쓰기 토큰을 무효화해요. 변경 불가능한 체크포인트는 기기에 남아요. 스냅샷 교체 중에 로컬 기록을 보호하기 위한 것이에요. 동시에 진행된 여러 기기의 기록을 병합하지는 않아요.

과거 에셋 참조는 보관되지만, 렌더링은 여전히 대상의 기존 라이브러리에서 에셋을 찾아요. 이 아카이브는 아직 과거 에셋의 정확한 바이트나 과거 도구 렌더링을 보장하지 않아요. 에셋 버전과 파일 결과의 바이트는 별도의 백업 부분으로 옮겨져요.
:::

::: details 저장된 버전과 파일 결과(v2)
선택적 기록 부분은 `{ version: 2, assetVersions: [...], operations: [...], batches: [...] }`를 담으며, 리더는 배치가 없는 이전 history-v1 형태도 받아들여요. 각 스냅샷에는 안정적인 에셋 ID와 정확한 버전, 저장 시각, 바이트 길이, 16진수 SHA-256, 그리고 `_file`과 선택적 `_credentialFile`이 바이너리 부분을 가리키는 에셋 레코드가 있어요. 작업은 원본 파일 정보, 요청, 보고서, 타임스탬프, 선택적 결과 `_file`을 담아요. 저장소 백엔드 이름, OPFS 핸들, 실행 리스는 옮겨지지 않아요. history v1만 아는 리더는 가져오기 전에 새 기록 버전을 거부하므로, 배치 소속 정보가 알리지 않고 누락되지 않아요.

배치 매니페스트는 처리 전에 선택된 모든 소스를 기록하며, 한 번도 읽지 않은 파일, 취소된 항목, 결과 공간 예약 실패, 중단된 작업도 포함해요. 각 항목에는 안정적인 작업 ID, 소스 참조와 정보, 요청된 출력 이름, 최종 보고서가 있어요. 읽지 않은 소스에는 선언된 정보만 있고 만들어 낸 다이제스트는 없어요. 가져오기는 항목의 식별자와 함께 옮겨진 작업 보고서와의 일관성을 검증해요. 개별 결과가 삭제돼도 Lolly Batch 보고서는 남지만, 영수증이 있다고 출력 바이트가 여전히 저장돼 있다는 뜻은 아니에요.

- **검증이 먼저예요.** 프로필이나 에셋을 가져와 쓰기 전에 알려진 모든 기록 레코드, 보고서, 참조된 파일을 검증해요. 봉투 형식에 무결성 맵이 없어도 누락된 바이트나 SHA-256 불일치가 있으면 실패해요. 추출된 자격 증명은 바이트 배열로 유지되며, 숫자 키 개체로 직렬화하던 이전 작성 프로그램에서 가져온 것도 마찬가지예요.
- **실행 중인 작업.** 실행 중인 작업은 백업에서 결과 없이 실패 보고서를 가진 중단된 레코드가 돼요. 복원은 백그라운드 작업을 다시 시작하거나 활성 리스를 가져오지 않아요. 다시 시도하려면 원본 파일을 다시 선택해야 하며, 기록된 SHA-256이 있으면 대조해요.
- **저장소.** 복원된 결과는 IndexedDB에 바이트와 메타데이터를 함께 커밋해요. 일반적인 새 결과는 사용 가능하면 OPFS를 쓰고, 그렇지 않으면 IndexedDB를 써요. 가져오기가 기존 활성 작업을 대체하는 일은 없어요.
- **백업 한도.** 내보내기는 이 바이트를 아카이브로 스트리밍하지만, 복원은 여전히 메모리에서 전체 백업의 압축을 풀기 때문에 한도가 유지돼요. **기록 페이로드 256 MiB**, **기록 메타데이터 4 MiB**, 최대 **작업 100개**, **배치 100개**, **스냅샷 2,000개**예요. 내보내기는 너무 크거나 불완전한 기록을 명시적으로 거부하며 알리지 않고 제외하지 않아요. 오래된 로컬 사본을 삭제하기 전에 중요한 버전과 결과를 하나씩 내려받으세요. 이 한도는 휴대폰의 최대 메모리 사용량을 측정해서 보장한 값이 아니에요.
- **로컬 용량 한도.** 로컬 결과 기록의 한도는 512 MiB와 레코드 100개예요. 에셋 스냅샷에는 별도의 512 MiB 한도와 에셋당 과거 버전 최대 20개 제한이 있고, 추출한 자격 증명 바이트도 이 용량에 포함돼요. 복원은 이 한도를 지키며 기존 사용자 데이터를 알리지 않고 제거하지 않아요.
- **배치 메타데이터.** 로컬 배치 메타데이터에는 별도의 4 MiB 한도, 매니페스트 최대 100개, 배치당 항목 20개 제한이 있어요. 대기 중인 항목은 메타데이터 용량을 예약하며, 항목별 보고서 상한은 32 KiB예요. 이는 논리적 한도이지 브라우저 디스크 공간을 보장하는 것은 아니에요. 실제 할당량 실패가 표시되며, 메모리 내 보고서는 계속 내려받을 수 있어요. 배치 항목을 다시 시도하면 이전 보고서를 덮어쓰지 않고 새 배치를 만들어요. 배치 레코드를 삭제해도 개별 결과 바이트나 라이브러리 에셋은 삭제되지 않아요.
- **라이브러리의 결과.** 변환된 결과는 정규화나 재인코딩 없이 소스와 출력 해시, 작업 관계를 붙여 라이브러리에 추가할 수 있어요. 반복해서 추가하면 변경되지 않은 사본을 재사용하며, 편집된 사본은 절대 덮어쓰지 않아요. 래스터 이미지로 새 Lolly Design 문서를 시작할 수 있으며, 이 문서는 현재 라이브러리 에셋 ID를 사용해요. Lolly Design의 런타임과 URL 경로 전체에서 정확한 버전 고정을 강제하는 것은 별도의 작업이에요. SVG, HTML, PDF, ZIP 결과는 불투명한 파일 에셋으로 보관되며, 신뢰할 수 있는 대화형 또는 벡터 콘텐츠로 승격되지 않아요.
- **사용자가 보는 곳.** **Convert → Recent file operations**는 기록 사용량, 보고서, 다운로드, 버전 관리자를 보여주며, 버전 관리자는 삭제된 라이브러리 에셋의 이전 버전도 찾아요. 스냅샷을 복원하면 새 현재 버전을 만들고 선택한 스냅샷을 보관해요. **Settings → Preferences → Storage**는 결과와 버전을 버려도 되는 캐시와 따로 집계해요.
- **정리.** 명시적인 임시 파일 정리는 작업이 소유하고 참조되지 않은 바이트만 삭제해요. 현재 레코드는 자신의 파일을 보호하며, 최근 OPFS 파일에는 1시간의 유예 기간이 있어요. 저장된 결과와 에셋 스냅샷은 자동으로 지워지지 않아요.

이전 리더도 v2 봉투 형식(`minReader: 1`)을 받아들이고 아는 부분을 복원하며, 지원되지 않는 기록 부분은 건너뛴 것으로 집계해요. 기록을 완전히 복구하려면 `fileHistory` 어댑터가 있는 셸이 필요해요. 이는 셸 내부의 연결 지점이며 도구에 노출되는 `HostV1` 기능이 아니에요. 실제 두 기기 간 복원은 로컬 Chromium 검증 관문에서 다뤄요. 설치된 데스크톱, iOS, Android 앱의 복구는 아직 별도로 인수 검증해야 해요.
