# Lolly와 브랜드 포털

_최종 확인일: 2026년 9월 28일._

조직이 승인된 에셋을 Bynder, Frontify, Marq, Brandfolder에 보관한다면, 이 페이지는 그것을 Lolly와 Lolly Work를 합친 것과 비교해요. 사람들이 브랜드 에셋을 찾는 방법과, 그것으로 새 파일을 만드는 방법이에요.

## 기존 포털이 더 잘하는 것

기존 포털은 관리형 호스팅, 지원, 광범위한 에셋 관리 워크플로를 제공해요. 예를 들어 [Frontify의 엔터프라이즈 DAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management)은 에셋 검색, 접근 제어, 승인 워크플로, 배포를 결합해요. Lolly 스택은 더 젊고 승인 체인은 임의의 분기 워크플로가 아니라 순차적이에요. [Work 상태와 로드맵](/info/work-status.html)이 배포 한계를 기록해요.

## 겹치는 부분

둘 다 승인된 에셋, 잠긴 템플릿, 접근 제어, 검토, 배포를 다뤄요. Lolly는 파일을 만들어요. 템플릿, 디자인 토큰, 허용된 입력이 누군가 바꿀 수 있는 것을 정하고, 렌더링은 그들의 기기에 남을 수 있어요. Lolly Work는 조직이 관리하는 인프라에 신원, 공유 저장소, 정책, 승인, 보고를 더해요.

## Lolly와 Lolly Work가 제공하는 것

| 필요 | Lolly + Lolly Work |
|---|---|
| 로그인과 프로비저닝 | OIDC 싱글 사인온, 여러 신원 공급자, SCIM 2.0 사용자 프로비저닝과 그룹 멤버십, 기존 세션을 폐기하는 계정 비활성화. SAML 전용 신원 공급자는 Keycloak 같은 OIDC 브리지로 연결할 수 있어요. |
| 승인된 템플릿 | Lolly가 템플릿의 편집 가능한 입력을 정의하고, Lolly Work가 값을 잠그거나 선택지를 제한하거나 컨트롤을 숨기는 그룹 가시성 및 입력 정책을 적용해요. |
| 공유 에셋 라이브러리 | 인스턴스가 소유하는 업로드, 컬렉션, 사용자 지정 메타데이터, 접근 제어되는 카탈로그, 그리고 기존 DAM과 저장소 라이브러리를 읽는 커넥터. |
| 검토 | 순서가 있는 승인 단계, 자격 있는 승인자 그룹, 정족수 규칙, 업무 분리. 검토는 카탈로그 제출과 조직 대상으로의 전달을 관리할 수 있어요. |
| 에셋 이력과 가용성 | 인스턴스가 소유하는 에셋의 버전과 롤백, 보관과 보류, 예약된 가용성, 만료와 폐기. 연결된 공급자는 자체 소스 이력을 유지해요. |
| 라이선스와 크레딧 | Lolly는 파일이 쓰는 각 소스의 라이선스를 기록하고 표시해야 할 크레딧을 준비해요. [크리에이티브 권리와 크레딧](/info/creative-rights.html)이 기록하는 것과 크레딧이 쓰이는 곳을 설명해요. 권리를 해결하지는 않아요. |
| 보고 | 에셋 사용과 다운로드 수, 도구와 내보내기 활동, 대시보드, 감사 추적. 사용량 귀속은 배포의 원격 측정 정책을 따르며 기본 귀속 설정은 동의를 요구해요. |
| 배포 | 만료되고 폐기할 수 있는 링크, 공유 컬렉션, 게스트 접근, 구성된 조직 대상으로의 전달. |

[카탈로그와 콘텐츠](/info/work-catalog.html), [승인](/info/work-approvals.html), [정책과 거버넌스](/info/work-governance.html)가 이 기능과 구성을 설명해요.

## 기존 포털 유지하기

기존 DAM은 계속 신뢰할 수 있는 출처로 남을 수 있어요. Lolly Work의 카탈로그 커넥터가 승인된 에셋을 Lolly에서 사용할 수 있게 하고, 사람들은 거기서 조직의 규칙에 따라 새 파일을 만들어요. 이는 통합 선택이며, 조직이 직접 운영하고 싶을 때를 위해 Lolly 자체의 라이브러리와 승인이 있어요. [어디서 무엇이 실행되는가](/info/compare.html#what-runs-where)가 모든 비교가 공유하는 한계를 나열해요.

기능 비교는 [Lolly 비교](/info/positioning.html)를 참고하세요. 업체 이름은 비교하는 제품을 식별하며, Lolly는 그들과 제휴 관계가 아니에요.
