# Lolly와 브랜드 포털

_포지셔닝 업데이트: 2026년 10월 31일. 공급업체 기능 사례 확인: 2026년 9월 28일._

조직이 승인된 에셋을 Bynder, Frontify, Marq 또는 Brandfolder에 보관한다면, 이 페이지에서 해당 포털과 Lolly 및 Lolly Work 조합을 비교해요. 사람들이 브랜드 에셋을 찾는 방법과 그 에셋으로 새 파일을 만드는 방법을 다뤄요.

<!--i:eti-folder-shared-->
## 기존 포털 유지하기

기존 DAM을 기준 기록 시스템으로 유지할 수 있어요. Lolly Work의 카탈로그 커넥터는 라이브러리에서 선택한 부분을 Lolly에서 사용할 수 있게 하며, 사람들은 그곳에서 조직의 규칙에 따라 새 파일을 만들어요. DAM이 지원하는 원본 접근 제약과 Lolly Work의 노출 규칙이 접근을 관리해요. 최종 결과물 검토는 별도의 결정이에요.

[기존 DAM과 함께 Lolly 사용하기](/info/use-with-dam.html)에서 책임과 한계를 설명해요. [SUSE의 Brandfolder 경험](/info/suse-brandfolder.html)은 계획된 마이그레이션 전에 관리자의 변경 관리를 지원한 성공적인 통합을 기록해요.

Lolly의 목적은 제작에 대한 통제권과 시스템 선택의 자유를 포함한 [콘텐츠 주권](/info/content-sovereignty.html)이에요. 자체 라이브러리와 승인 기능은 이 기능들을 직접 운영하기로 선택한 조직을 위한 것이에요. [DAM 공급업체 및 구현 파트너를 위한 Lolly](/info/dam-partners.html)는 연결된 워크플로가 기존 기준 기록 시스템에 어떤 가치를 더할 수 있는지 설명해요.

<!--i:eti-award-->
## 기존 포털이 더 잘하는 것

기존 포털은 관리형 호스팅, 지원, 폭넓은 에셋 관리 워크플로를 제공해요. [Frontify의 엔터프라이즈 DAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management)은 에셋 탐색, 접근 제어, 승인 워크플로, 배포를 결합해요. Lolly 스택은 역사가 더 짧아요. 승인 체인은 순차적이며 임의로 분기할 수 없어요. [Lolly Work 현황과 로드맵](/info/work-status.html)에 배포상의 한계가 기록돼 있어요.

<!--i:eti-blend-->
## 겹치는 부분

둘 다 승인된 에셋, 잠긴 템플릿, 접근 제어, 검토, 배포를 다뤄요. Lolly는 파일을 만들어요. 템플릿, 디자인 토큰, 허용된 입력이 사용자가 바꿀 수 있는 것을 정하며, 렌더링은 기기 안에서 할 수 있어요. Lolly Work는 조직이 통제하는 인프라에 신원 관리, 공유 저장소, 정책, 승인, 보고를 추가해요.

## Lolly와 Lolly Work가 제공하는 것

| 요구 사항 | Lolly + Lolly Work |
|---|---|
| 로그인과 프로비저닝 | OIDC 통합 로그인, 여러 ID 공급자, SCIM 2.0 사용자 프로비저닝과 그룹 구성원 관리, 기존 세션을 취소하는 계정 비활성화를 제공해요. SAML만 지원하는 ID 공급자는 Keycloak 같은 OIDC 브리지를 통해 연결할 수 있어요. |
| 승인된 템플릿 | Lolly가 템플릿에서 편집 가능한 입력을 정의하고, Lolly Work가 그룹별 공개 범위와 값을 잠그거나 선택을 제한하거나 컨트롤을 숨기는 입력 정책을 적용해요. |
| 공유 에셋 라이브러리 | 인스턴스 소유 업로드, 컬렉션, 사용자 지정 메타데이터, 접근이 제어되는 카탈로그와 함께 기존 DAM 및 저장소 라이브러리를 읽는 커넥터를 제공해요. |
| 검토 | 순서가 있는 승인 단계, 자격을 갖춘 승인자 그룹, 정족수 규칙, 직무 분리를 제공해요. 검토는 카탈로그 제출과 조직 대상에 대한 전달을 관리할 수 있어요. |
| 에셋 이력과 사용 가능 여부 | 인스턴스 소유 에셋의 버전과 롤백, 보존과 보류, 사용 가능 기간 예약, 만료, 취소를 제공해요. 연결된 제공자는 자체 원본 이력을 유지해요. |
| 라이선스와 출처 표시 | Lolly는 파일이 사용하는 각 출처의 라이선스를 기록하고 필요한 출처 표시를 준비해요. [창작물의 권리와 출처 표시](/info/creative-rights.html)에서 기록하는 내용과 출처 표시가 작성되는 위치를 설명해요. 이용에 필요한 권리 허락을 확보해 주지는 않아요. |
| 보고 | 에셋 사용 및 다운로드 횟수, 도구 및 내보내기 활동, 대시보드, 감사 추적을 제공해요. 사용 활동을 사용자와 연결하는 방식은 배포 환경의 텔레메트리 정책을 따르며, 기본 연결 설정에는 동의가 필요해요. |
| 배포 | 만료와 취소가 가능한 링크, 공유 컬렉션, 게스트 접근, 구성된 조직 목적지로의 전달을 제공해요. |
| 공개 브랜드 페이지 | Lolly는 Lolly Design System Setup이나 명령줄에서 정적 [브랜드 페이지](/info/brand-page.html)를 작성해요. 사람을 위한 로고, 색상, 서체, 규칙, 예시와 에이전트를 위한 토큰, `DESIGN.md`, 스킬을 담아요. 사용자가 폴더를 호스팅하거나, 관리자가 Lolly Work에서 기본으로 꺼져 있는 [브랜드 페이지 호스팅](/info/work-design-system-administration.html#host-a-brand-page)을 켜요. |

[카탈로그와 콘텐츠](/info/work-catalog.html), [승인](/info/work-approvals.html), [정책과 거버넌스](/info/work-governance.html)에서 이 기능과 설정을 설명해요.

## 결합된 워크플로 평가하기

[이벤트 카드 제작 순서](/info/dam-production.html)를 사용해 자신의 라이브러리로 원본 접근, 허용된 편집, 결과물 검토, 전달을 테스트하세요. [무엇이 어디에서 실행되나요](/info/compare.html#what-runs-where)에 모든 비교가 공유하는 한계가 나열돼 있어요. 원본 연결만으로 공급업체와의 파트너십이나 모든 테넌트에 대한 적합성이 성립하지는 않아요.

[Lolly 비교](/info/positioning.html)에 기능 비교가 있어요. 공급업체 이름은 비교 대상 제품을 식별하기 위해 사용해요. Lolly는 해당 업체들과 제휴 관계가 없어요.
