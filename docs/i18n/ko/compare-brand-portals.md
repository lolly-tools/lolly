# Lolly와 브랜드 포털

_최종 확인일: 2026년 9월 28일._

Lolly와 [lolly.work](https://lolly.work)를 함께 쓰면 팀이 브랜드 포털에 기대하는 제작 및 거버넌스 워크플로, 즉 승인된 에셋, 잠긴 템플릿, 접근 제어, 검토, 배포를 다룰 수 있어요. 사람들이 브랜드 에셋을 찾고 새로 만드는 방식을 정할 때 이 통합 솔루션을 Bynder, Frontify, Marq, Brandfolder와 비교해 보세요.

## 제작과 조직용 서비스

파일을 만드는 것은 Lolly의 엔진과 앱이에요. 템플릿, 디자인 토큰, 허용된 입력이 무엇을 바꿀 수 있는지 정하고, 렌더링은 사용자의 기기에서 이뤄질 수 있어요. 단독 Lolly는 계정이 필요 없어요.

lolly.work는 같은 프로젝트 안의 조직용 서비스로, [별도 저장소](https://github.com/lolly-tools/lolly-work)에서 관리되며 Lolly와 함께 배포돼요. ID, 공유 스토리지, 정책, 승인, 보고를 더해요. 두 부분 모두 MPL-2.0 오픈 소스예요. 이렇게 분리되어 있어서 개인은 Lolly를 독립적으로 쓸 수 있고, 조직은 자체적으로 통제하는 인프라에서 통합 솔루션을 운영할 수 있어요.

## 통합 솔루션이 제공하는 것

| 필요 | Lolly + lolly.work |
|---|---|
| 로그인과 프로비저닝 | OIDC 싱글 사인온, 여러 ID 공급자, SCIM 2.0 사용자 프로비저닝과 그룹 멤버십, 기존 세션을 취소하는 계정 비활성화. SAML만 지원하는 ID 공급자는 Keycloak 같은 OIDC 브리지를 통해 연결할 수 있어요. |
| 승인된 템플릿 | Lolly가 템플릿의 편집 가능한 입력을 정의하고, lolly.work가 그룹별 표시 여부와 값을 잠그거나, 선택지를 제한하거나, 컨트롤을 숨기는 입력 정책을 적용해요. |
| 공유 에셋 라이브러리 | 인스턴스 소유 업로드, 컬렉션, 사용자 지정 메타데이터, 접근 제어가 적용된 카탈로그, 그리고 기존 DAM 및 스토리지 라이브러리를 읽는 커넥터. |
| 검토 | 순서가 있는 승인 단계, 승인 자격이 있는 승인자 그룹, 정족수 규칙, 업무 분리. 검토는 카탈로그 제출과 조직 대상으로의 전달을 관리할 수 있어요. |
| 에셋 이력과 제공 여부 | 인스턴스 소유 에셋의 버전 관리와 롤백, 보존과 보류, 예약된 제공, 만료, 취소. 연결된 공급자는 각자의 원본 이력을 유지해요. |
| 보고 | 에셋 사용 및 다운로드 횟수, 도구 및 내보내기 활동, 대시보드, 감사 추적. 사용 현황 귀속은 배포의 텔레메트리 정책을 따르며, 기본 귀속 설정은 동의가 필요해요. |
| 배포 | 만료되고 취소할 수 있는 링크, 공유 컬렉션, 게스트 접근, 구성된 조직 대상으로의 전달. |

[lolly.work 운영자 가이드](https://github.com/lolly-tools/lolly-work/tree/main/docs)에서 이러한 기능과 설정 방법을 설명해요. 이는 사용할 수 있는 기능이며, Lolly 주변에 다른 시스템을 따로 구축해야 하는 기능이 아니에요.

## 포털 워크플로 선택하기

기존 포털은 관리형 호스팅, 지원, 폭넓은 DAM 워크플로를 제공해요. 예를 들어 [Frontify의 엔터프라이즈 DAM](https://www.frontify.com/en/solution/enterprise-digital-asset-management)은 에셋 검색, 접근 제어, 승인 워크플로, 배포를 결합해요. 필요한 검토 및 권리 워크플로를 구체적으로 비교해 보세요. Lolly는 메타데이터, 접근, 제공 여부 제어를 제공하지만, 법적 승인과 라이선스 의무에는 여전히 조직의 프로세스가 필요해요. 승인 체인은 순차적이며, 임의로 분기하는 워크플로는 모델링하지 않아요.

Lolly 스택은 비교적 새로우며, [lolly.work 상태 페이지](https://github.com/lolly-tools/lolly-work/blob/main/docs/status.md)에 배포 제약이 기록되어 있어요. 특히 공개 lolly.work 사이트는 평가용 샌드박스예요. 지속적으로 운영하는 조직 배포에는 영구 스토리지와 운영자가 필요해요. 자체 호스팅에는 사용자 수에 따른 소프트웨어 라이선스 비용이 없지만, 인프라와 관리에는 여전히 비용이 들어요.

기존 DAM을 계속 기준 원본으로 둘 수도 있어요. lolly.work의 카탈로그 커넥터는 승인된 에셋을 Lolly에서 사용할 수 있게 하고, 사람들은 조직의 규칙에 따라 새 파일을 만들어요. 이는 통합 방식의 선택이에요. 조직이 이러한 워크플로를 직접 관리하고 싶다면 Lolly 자체 라이브러리와 승인 기능을 사용할 수 있어요.

기능 비교는 [Lolly 비교](/info/positioning.html)를, 이 비교 시리즈의 나머지는 [Lolly 도구별 비교](/info/compare.html)를 참고하세요. 업체 이름은 비교 대상 제품을 나타내기 위한 것이며, Lolly는 해당 업체들과 제휴 관계가 아니에요.
