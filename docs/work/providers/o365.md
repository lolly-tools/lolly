# Microsoft 365 / SharePoint (kind: `o365`)

Connect a SharePoint document library or a OneDrive folder, and its files appear in the Lolly
Work catalog for the groups you choose. Work reads through Microsoft Graph with an app you
register, and never writes to the library.

## What you need from Microsoft

- **An Entra ID app registration** with the delegated Graph permissions **`Files.Read.All`** and
  **`offline_access`**. A single-tenant app is fine: set `options.tenant` to your tenant id or
  domain.
- **The drive id** of the library or OneDrive (Graph `GET /drives/…`).
- The client id and secret are yours; `lw providers auth` captures the refresh token. Microsoft
  also allows public (PKCE) apps, which leave out `clientSecret`.

## Credential shape

The OAuth credential, captured rather than typed:

```json
{ "clientId": "…", "clientSecret": "…", "refreshToken": "…" }
```

```bash
lw providers auth acme-o365
```

[OAuth sources](README.md#kinds-with-a-registered-consent-flow-dropbox-gdrive-o365) explains the
consent step.

## instance.json / `lw providers add`

```json
{
  "id": "acme-o365",
  "kind": "o365",
  "label": "Acme SharePoint",
  "options": { "driveId": "b!aBcD…", "tenant": "acme.onmicrosoft.com", "itemPath": "Brand/Approved" },
  "exposure": { "groups": ["marketing"] }
}
```

| Option | What it does |
|---|---|
| `driveId` (required) | The library or OneDrive to read. |
| `tenant` | Your tenant id or domain. Use `common` only for a multi-tenant app. |
| `itemPath` | A folder under the drive root to federate. |

## Verify

```bash
lw providers auth acme-o365
lw providers health acme-o365
```

## Notes / limits

- **One folder level.** Listing reads only the files directly in the drive root or in
  `itemPath`. Subfolders are not walked, so files inside them are not federated.
- **Search covers the whole drive.** It ignores `itemPath`; exposure still decides which results
  a member sees.
- **Short-lived download links.** Graph's `@microsoft.graph.downloadUrl` is pre-authenticated
  and short-lived, so Work fetches it on each request and streams the file. API calls and
  paging cursors are pinned to `graph.microsoft.com`; the download follows Graph's short-lived
  redirect to its storage host.
