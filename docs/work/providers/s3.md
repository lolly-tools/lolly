# S3 / S3-compatible (kind: `s3`)

Connect a private bucket on AWS S3, MinIO, Ceph RGW or another S3-compatible store, and its
objects appear in the Lolly Work catalog for the groups you choose. The objects stay private:
Work signs every request afresh and streams the file. It never writes to the bucket.

## What you need from the store

- **A read-only access key pair** scoped to the bucket, and to the prefix if you set one. On
  AWS, an IAM user or role with a minimal policy:

  ```json
  {
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": ["arn:aws:s3:::acme-brand", "arn:aws:s3:::acme-brand/brand/*"]
    }]
  }
  ```

  On MinIO or Ceph, a read-only user or policy over the bucket. Do not grant write or delete.
- **The bucket name** and the **region**. SigV4 needs a region even where MinIO ignores the value.
- **The endpoint URL** for an S3-compatible store.

## Credential shape

One string: the access key id and the secret access key joined by a colon. Every bucket needs
one, even for a dry run.

```
"<accessKeyId>:<secretAccessKey>"
```

```bash
lw providers credential acme-s3     # prompts for the "<key>:<secret>" string
```

## instance.json / `lw providers add`

```json
{
  "id": "acme-s3",
  "kind": "s3",
  "label": "Acme MinIO",
  "options": { "bucket": "acme-brand", "region": "us-east-1", "endpoint": "https://minio.internal:9000", "prefix": "brand" },
  "exposure": { "groups": ["design"], "tier": "reference" }
}
```

| Option | What it does |
|---|---|
| `bucket` (required) | The bucket to federate. |
| `region` | Default `us-east-1`. |
| `endpoint` | The store's URL. Absent means AWS virtual-hosted addressing. |
| `prefix` | Federate only the keys under this prefix. |

The first folder below the prefix, or below the bucket root when there is no prefix, becomes
each object's **section**, which `exposure.includeSections` can scope on.

## Verify

```bash
lw providers preview --kind s3 --options '{"bucket":"acme-brand","region":"us-east-1"}'
lw providers health acme-s3
```

`s3 list 403` means one of two things: the policy lacks `s3:ListBucket` on the bucket ARN
(separate from the `/*` object ARN), or the secret or region is wrong. The driver reports only
the HTTP status, not the S3 error code.

## Notes / limits

- **No server-side search.**
- **No presigned links in the catalog.** Every request is signed when it is made, and a request
  for an object outside the configured prefix is refused.
- **Not the instance's own blob store.** This source reads a bucket. The instance's own
  [`blobs.driver: "s3"`](../catalog.md#where-instance-bytes-live) is where materialized copies
  are written, with its own credential in `LW_BLOBS_S3_CREDENTIAL`.
- **Zero dependencies.** The driver signs requests with its own SigV4 code, with no AWS SDK.
